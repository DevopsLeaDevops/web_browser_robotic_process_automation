ADR 0004：前端採用 React + TypeScript

Python 為主的工程中，Web UI 是唯一的 TypeScript 部分。

背景

管理介面最重要的頁面是步驟編輯器：拖拽排序、即時校驗、定位器候選切換，以及執行時逐步回放截圖。這類互動在純 Python 的 UI 框架裡很難做好。

決策

  • 前端使用 React + TypeScript + Vite，放在 apps/web。
  • 樣式沿用介面設計系統 v1.0 的 portal.css 與設計變數，不另選元件庫。
  • API 型別由 FastAPI 的 OpenAPI 生成，DSL 型別由 JSON Schema 生成，不手寫。

後果

好處

  • 生態成熟，複雜互動有現成方案。
  • 型別由後端生成，前後端不會各說各話。

代價

  • 團隊需要維護一份 TypeScript 程式碼；範圍嚴格限於 UI，業務邏輯都在後端。
  • CI 需要另外的 Node.js 工作流程（M8 加入）。

沒有選的方案

方案為什麼不選
NiceGUI、Streamlit純 Python，但複雜互動與多用戶下的效能受限。
Jinja2 + HTMX適合表單類頁面，不適合步驟編輯器。
Vue同樣可行；React 的拖拽與編輯器相關套件較多。
