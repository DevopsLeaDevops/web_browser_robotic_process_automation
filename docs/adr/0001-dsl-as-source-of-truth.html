ADR 0001：場景以聲明式 DSL 為唯一真實來源

場景存成受 schema 約束的資料，而不是程式碼。

已接受
日期
2026-10-09
影響範圍
rpa-core、所有生成方式、Web UI 編輯器、執行引擎
相關
場景 DSL（草案）

背景

場景會由三種方式產生（錄製、AI、手動編輯），要在網頁上可視化編輯、比較版本，並交給多個 worker 執行。

如果場景直接存成 Playwright 腳本，編輯器很難可靠地解析和改寫它，AI 的輸出也無法在執行前驗證；腳本可以做任何事，審核和安全邊界都不清楚。

決策

  • 場景以聲明式 DSL 描述：YAML 編寫、JSON 存儲。
  • DSL 以 Pydantic v2 模型定義，同一份定義導出 JSON Schema，供 AI 生成與前端使用。
  • DSL 帶有 schemaVersion，格式變更時提供遷移。
  • 可以匯出成 Playwright 程式碼給開發者參考，但匯出結果不能回寫成場景。
  • DSL 表達不了的情況使用受控的 script 步驟。

後果

好處

  • 編輯器、版本比較、審核都直接處理結構化資料。
  • AI 的輸出能被校驗，錯誤可以精確回饋給模型修正。
  • 執行層可替換，安全邊界由 DSL 決定。

代價

  • 表達能力受限，需要逃生門，並在審核時標示。
  • 要自行維護 DSL 規格與版本遷移。

沒有選的方案

方案為什麼不選
直接存 Playwright 腳本無法可靠地可視化編輯，執行前無法校驗，安全邊界不清楚。
流程圖 JSON（低程式碼平台常見）本質相同，但難以手寫和在 Git 中比較；YAML DSL 兼顧兩者。
採購現成 RPA 平台授權成本高，生成與客製化受限。
