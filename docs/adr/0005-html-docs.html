ADR 0005：文檔以 HTML 撰寫並套用 Portal 樣式

除非必要，不使用 Markdown；文檔本身就是一個可以直接部署的靜態網站。

已接受
日期
2026-10-09
影響範圍
docs/ 下所有文檔
相關
文檔與 ADR 寫作方式

背景

專案負責人要求文檔易讀、易理解、重點突出，並且之後能直接做成文檔網站。Markdown 只能表達線性的文字，難以做出並排比較、狀態標籤、規格清單這類重點突出的版面。

決策

  • 文檔以手寫 HTML 放在 docs/，套用介面設計系統的 portal.css。
  • 導覽集中在 docs/assets/nav.js，由 docs-shell.js 產生；頁面只寫內容。
  • 不使用靜態網站產生器，不需要建置，直接開檔或用任何靜態伺服器即可瀏覽。
  • 只有倉庫根目錄的 README.md 保留 Markdown，因為 GitHub 首頁需要它。
  • CI 檢查每個頁面的結構、導覽登記與連結。

後果

好處

  • 離線可讀，風格與產品一致。
  • docs/ 原樣就能部署為文檔網站（GitHub Pages 或內部靜態伺服器）。

代價

  • 手寫 HTML 比 Markdown 冗長；以頁面範本和自動檢查降低出錯機會。
  • 在 GitHub 網頁上看到的是原始碼，需要部署或下載後瀏覽。

沒有選的方案

方案為什麼不選
Markdown難以做出重點突出的版面，與要求不符。
Markdown + MkDocs 等產生器寫作方便，但需要建置流程，風格難與產品一致。
