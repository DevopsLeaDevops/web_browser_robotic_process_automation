ADR 0017：第三方 Agent 經由獨立、以 API 金鑰授權的 /agent-api/v1 操作平台

Agent 只連伺服器；調試交給指定的錄製端，驗證與執行交給 Worker，業務規則與發布門檻沿用現有服務。新的一層只做認證、權限、稽核與對外契約。

提議中
日期
2026-10-23
影響範圍
rpa-server（新路由、API 用戶端、稽核、遷移）、rpa-runner（調試的 snapshot 命令）、RPA 錄製端 App（讀頁面結構）；第二期另含 rpa-worker
相關
ADR 0011（API 與 OpenAPI）、ADR 0012（Worker API）、ADR 0014（錄製端與互動子程序）、ADR 0015（版本與發布紀錄）；設計：對外 Agent API；Agent 使用指南

背景

使用者要求（2026-10-23）：第三方的 Agent 系統使用 Linux 伺服器的 API 操作錄製端，完成場景腳本與參數的新增、修改、調試運行；再經由伺服器呼叫 Worker 完成驗證與執行，並取得運行過程。

現有的 /api 已有場景、版本、調試、驗證、執行的全部操作，但沒有認證：只開在伺服器本機的 8080，或帶錄製端的裝置權杖從對外埠進來。互動子程序開在「請求經過的那台錄製端」，Agent 不經過錄製端，無法指定。Worker 只回報五個階段，沒有步驟級的進度。

決策

  1. 獨立的對外 API。對外埠新增 /agent-api/v1，有自己的 OpenAPI；路由只轉接服務層，不複製業務規則。/api、Client API、Worker API 不變。
  2. API 用戶端。每個 Agent 系統在管理後台登記為一個用戶端，金鑰只顯示一次、只存雜湊。用戶端設定權限範圍（scenes:read、scenes:write、debug、runs:validate、scenes:publish、runs:execute、runs:read）、可用領域與錄製端、執行位置與 Worker、限額、回傳頁面內容、到期與來源 IP。
  3. Agent 只連伺服器。調試請求帶 recorderId，伺服器以現有的 use_recorder 把子程序交給那台；錄製端要在裝置頁打開「允許 Agent 調試」，可以只允許無頭。場景已有人在調試時回 409，不關掉對方。
  4. 發布要個別授權。Agent 可以發布，但只有勾選 scenes:publish 的用戶端可以，預設不勾（使用者 2026-10-23 決定）。發布門檻不變：發布的版本必須是驗證通過、雜湊相符的版本。
  5. 頁面內容預設不回傳。截圖、頁面結構與錄影受用戶端的「回傳頁面內容」控制，預設關；管理員確認 Agent 的模型可以接收內部頁面後再打開（使用者同意的建議）。Secrets 的值永遠不回傳。
  6. 讀頁面結構在第一期。調試子程序加 snapshot 命令（無障礙樹、表單欄位、iframe 與分頁），值遮罩；錄製端上線時回報支援，舊版回 409 並提示更新（使用者 2026-10-23 要求提前）。
  7. 運行過程。第一期提供狀態、階段、結束後的步驟與產物；第二期由 steps.json 經心跳回報步驟進度，提供事件長輪詢與 Webhook。
  8. 稽核。每個寫入請求記下時間、用戶端、動作、對象與結果，只增不改；版本與運行標出觸發的用戶端。
  9. 不做 MCP 轉接。只提供 HTTP API 與使用指南（使用者 2026-10-23 決定）。

後果

  • 大部分端點是轉接，第一期的工作集中在認證、權限、稽核、指定錄製端與讀頁面結構。
  • 多一個對外的介面：金鑰在 HTTP 下是明文，Agent 不在受信任的區網時要在伺服器前加 HTTPS。
  • 讀頁面結構要出新版錄製端 App；舊版 App 仍可調試，只是不能讀頁面結構。
  • Agent 接外部模型時，打開「回傳頁面內容」等於讓內部頁面離開內網；這要由管理員逐個用戶端決定。
  • M8 加入使用者與專案權限時，API 用戶端要併入同一套權限模型。

沒有選的方案

方案為什麼不選
直接對外開放 /api 並加權杖/api 跟著 Portal 介面改動，不適合當對外契約；權限與稽核要穿插在每個頁面用的路由裡。
Agent 直接連錄製端或 Worker錄製端與 Worker 要開埠、Agent 要知道每台的位置；破壞「所有連線由 App 主動發起」（ADR 0012、0014）。
在伺服器開瀏覽器給 Agent 調試Linux 伺服器沒有畫面也可能沒裝瀏覽器；錄製、調試的瀏覽器開在錄製端（ADR 0014）。
遠端畫面串流ADR 0014 已決定不做；Agent 用截圖與頁面結構即可。
一開始就用 SSE 或 WebSocket 推送事件長輪詢與 Worker、錄製端一致，穿得過代理；推送等第二期再評估。
MCP 轉接使用者 2026-10-23 決定不做。
