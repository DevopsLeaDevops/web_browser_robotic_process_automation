ADR 0002：後端、執行與工具鏈採用 Python 技術棧

除了 Web 前端，所有元件都用 Python，放在同一個 uv workspace。

已接受
日期
2026-10-09
影響範圍
所有 Python 套件、CI、開發環境
相關
技術選型、ADR 0004

背景

團隊的主力語言是 Python。平台需要瀏覽器自動化、資料模型校驗、Web API 與 AI 整合，這些在 Python 都有成熟方案。

決策

  • 瀏覽器：Playwright for Python，執行引擎使用 async API。
  • 模型：Pydantic v2，DSL 與 API 共用同一套模型。
  • API：FastAPI；資料庫：SQLAlchemy 2.0 + Alembic。
  • 工程：uv workspace 單倉多套件；ruff、pyright strict、pytest。
  • 最低版本 Python 3.12。

後果

好處

  • 團隊熟悉，review 與維護成本低。
  • DSL 模型從校驗、API 到 AI 生成一路共用。
  • AI 與資料處理生態完整。

代價

  • 前端無法直接共用 Python 型別，改由 OpenAPI 與 JSON Schema 生成 TypeScript 型別。
  • Playwright 原生語言是 TypeScript，部分新功能可能稍晚出現在 Python 版。

沒有選的方案

方案為什麼不選
TypeScript 全端型別可前後端共用，但團隊主力不是 TypeScript。
Python + Selenium缺少自動等待、語意化定位與 Trace，穩定性較差。
poetry 管理依賴可行，但 uv 更快且原生支援 workspace。
