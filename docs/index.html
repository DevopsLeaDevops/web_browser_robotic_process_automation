一句話說明

以「場景」為核心資產：一段可重複執行的瀏覽器操作流程，用聲明式 DSL 描述。平台負責把場景生成出來（錄製、自然語言、範本），管理起來（版本、參數、權限），執行它（Playwright），再把結果回饋給使用者（截圖、Trace、失敗定位）。

產品定位

要解決什麼問題、核心概念、生成到回饋的閉環。

場景 DSL

聲明式 DSL 與場景契約：入參、出參、獨立斷言，以及每個欄位與動作的規格。

系統架構

元件、資料流與目錄結構，以及每個套件的職責。

技術選型

每一層的選擇、備選方案與理由。

多用戶與內部系統

認證、權限、Secrets、稽核，以及內部系統帶來的限制。

介面風格

介面設計系統 v1.0：兩級 Portal、藍色主色、緊湊資訊密度。

MVP 原型

場景管理、錄製與調試、報告、自由試驗場的離線互動原型，以及真實執行的範例。

建議閱讀順序

第一次接觸本工程
  1. 產品定位：先理解「場景」這個核心概念。
  2. 系統架構：看懂元件之間怎麼協作。
  3. 決策索引：了解幾個關鍵決定的來龍去脈。
  4. 路線圖：知道現在在哪一步、下一步做什麼。
  5. 本機從零運行（一條命令裝好環境）、開發環境與開發規範：開始動手。

倉庫現況

M2 進行中
rpa-core
場景 DSL 與場景契約的模型、YAML 載入與校驗；範例在 scenarios/
rpa-runner
執行引擎：入參校驗、在 Chromium 或 Firefox 中執行步驟、獨立斷言、出參發布、執行報告
rpa-cli
rpa run 執行場景；rpa validate 校驗場景並指出行號、步驟與欄位，rpa schema 輸出 DSL 或單一場景入參、出參的 JSON Schema；--lang 切換繁中、簡中、英文
工具鏈
uv（依賴以 uv.lock 鎖定）、ruff、pyright（strict）、pytest、pre-commit
CI
靜態檢查，Python 3.12 / 3.13 測試，含 Chromium 冒煙測試；一鍵安裝腳本每週在 macOS、Ubuntu、Windows 實際執行
文檔
本站，繁中、簡中、英文三種語言，含連結與翻譯同步的自動檢查
