开发环境

从零到能跑测试，大约五分钟。Windows、macOS、Linux 指令相同。想一条命令装好全部，用本机从零运行的一键脚本；第一次在 Mac 上设置，可照macOS 本机运行一步步做。

第一次设置

git clone https://github.com/DevopsLeaDevops/web_browser_robotic_process_automation.git
cd web_browser_robotic_process_automation

# 创建 .venv，安装全部包与开发工具
uv sync

# 下载 Chromium 与 Firefox（Linux 第一次可加 --with-deps 安装系统依赖）
uv run python tools/install_browsers.py

# 提交前自动检查
uv run pre-commit install

# 确认安装成功
uv run rpa --version

前置需求

Python
3.12 以上。没有的话 uv 会自动下载。
uv
0.11 以上，安装方式见 uv 官方文档。
Git
任一近期版本。
Node.js
M8 开始做前端时才需要。
数据库
不用安装。M7 起开发用 SQLite（Python 内置）；PostgreSQL 只有正式环境需要，见 ADR 0008。

Linux 服务器：分发包（建议）

下载 RPA-Server-版本-linux-x64.tar.gz（aarch64 用 linux-arm64），解压后运行里面的 install.sh。分发包内含 Python 3.13 与照 uv.lock 装好的所有包：服务器不需要 git clone、uv，也不必连到 GitHub 或 PyPI；在能上网的电脑下载一个文件、拷贝到服务器就能安装。适用的系统和从源代码安装相同：RHEL／CentOS 衍生版、x86_64 或 aarch64、glibc 2.28 以上。

# 文件名里的版本换成实际下载的
tar -xzf RPA-Server-0.6.3-linux-x64.tar.gz
bash RPA-Server-0.6.3-linux-x64/install.sh --install-service
sudo systemctl status rpa-server

# 不用 systemd（例如容器）：前景启动
~/rpa-server/bin/rpa-server

# 升级（0.6.0 起，运行环境没变时）：用约 2 MB 的更新档，见部署与操作
~/rpa-server/bin/rpa update RPA-Update-0.6.4.zip

# 升级（要完整的分发包时）：解压新版的分发包，再运行一次；服务正在运行时自动重新启动
tar -xzf RPA-Server-0.6.4-linux-x64.tar.gz
bash RPA-Server-0.6.4-linux-x64/install.sh
取得
GitHub Release 附 x64、arm64 两个分发包与 SHA256SUMS.txt（sha256sum -c SHA256SUMS.txt --ignore-missing），v0.5.0 起每个发布都有；0.6.0 起另附签章的更新档 RPA-Update-版本.zip（用更新档升级服务器）。要试尚未发布的版本时，从 GitHub Actions「服务器分发包」那次运行的产物下载（需要登录 GitHub）。
安装位置
默认 ~/rpa-server（--prefix 或 RPA_SERVER_HOME 可改）。每个版本放在 releases/版本-提交/（我们的程序 app/、bin/rpa），Python 与第三方包放在 runtimes/环境代号/，环境代号相同的版本共用一份（ADR 0018）；current 指向使用中的版本；bin/rpa-server 是启动器（systemd 也用它），bin/rpa 是 rpa 命令。新版本先放好、确认包内的 Python 在这台能运行，才把 current 换过去；保留最近 3 个版本（--keep）。
设置与数据
设置档 ~/rpa-server/rpa-server.env，变量和下方的 .rpa-server.env 相同（RPA_DATA_DIR、RPA_PORT、RPA_WORKER_PORT、RPA_WORKER_HOST、RPA_TESTSITE_HOST）；首次安装时可以用环境变量指定，之后修改文件再重新启动服务。数据默认在 ~/.local/share/rpa-server，安装、升级与重装都不会清除。
从 clone 安装改过来
第一次安装时自动沿用 setup-linux.sh 的设置：先找 systemd 服务启动的那份 .rpa-server.env，再找默认的 clone 位置；也可以用 --import-env 指定。数据目录照旧，不搬动数据。现有服务仍指向 clone 的那份时，安装程序不动它；加上 --install-service 才换成分发包并重新启动。换过去之后，clone 与 .venv-server 可以保留或删除。
系统包
只补装缺少的 libstdc++ 与 git（git 只有领域文件夹的 git 同步要用），所以升级通常不用 sudo 装包；管理员已备妥时加 --skip-system-packages。安装 unit 与重新启动服务需要 sudo。
升级失败时
新版本启动后约 60 秒内管理端口没有回应，安装程序停下并说明怎么退回上一版（current 指回 releases/上一版 后重新启动）。数据库迁移在新版本启动时运行：升级前照下方的方式备份整个数据目录，退回旧版前先还原。

分发包由 CI 建置（tools/build_server.py、「服务器分发包」流程）：只选 manylinux_2_28 以下的包，建好后用包内的 Python 运行；再在同架构的 Rocky Linux 8 容器（glibc 2.28、公司映像的 os-release、一般账号）实际安装、沿用旧设置、冒烟测试、重装与升级。容器没有 systemd：真实的服务启停与公司主机仍需验收。首次管理、SSH 转发与防火墙和下方相同。

Linux 服务器：从源代码安装（yum／dnf）

一般建议用上方的分发包；要在服务器上跑还没发布的代码，或服务器连得到 GitHub 与 PyPI 时，也可以 clone 后安装。无桌面服务器负责 Portal、数据库与调度；远程 Worker 运行浏览器，录制端提供录制、人工登录与有头调试。使用 setup-linux.sh 安装 .venv-server，不下载浏览器、不安装桌面 App、开发工具或 Git hooks。CLI 既有相依仍包含 Playwright 的 Python 包，但不启动其浏览器 driver。

系统辨识
读取 /etc/os-release 的 ID 与 ID_LIKE，接受 rhel、centos、fedora；先用 yum，再用 dnf。公司系统即使 ID=""、名称空白，只要 ID_LIKE="rhel fedora centos " 仍可辨识；不把 VERSION_ID="3" 当作 CentOS 3。
运行环境
x86_64 或 aarch64、glibc 2.28 以上；用 uname -m 和 getconf GNU_LIBC_VERSION 检查。x86_64、glibc 2.32 符合这些前置检查，实际公司包库与主机仍需验收。不替换系统 glibc 或 Python；uv 下载 .python-version 指定的 Python，依 uv.lock 安装。
系统包
git curl ca-certificates tar gzip libstdc++ libgcc。一般账号运行；yum／dnf 与 systemd 操作使用 sudo。管理员已备妥包时可加 --skip-system-packages。
数据
默认 ~/.local/share/rpa-server；首次可用 RPA_DATA_DIR 改位置。若接续既有服务，必须指定原数据目录，否则会创建新的空白环境。
# 已经 clone：在项目根目录（在 scripts 目录时改成 bash setup-linux.sh）
bash scripts/setup-linux.sh
.venv-server/bin/rpa-server

# 或安装为开机自启动服务，不需要在终端保持前景进程
bash scripts/setup-linux.sh --install-service
sudo systemctl status rpa-server
sudo journalctl -u rpa-server -f

# 尚无代码：完整下载成功后再运行（需要先有 curl 与 CA 凭证）
curl -LsSf https://raw.githubusercontent.com/DevopsLeaDevops/web_browser_robotic_process_automation/main/scripts/setup-linux.sh -o /tmp/rpa-setup-linux.sh
bash /tmp/rpa-setup-linux.sh --dir "$HOME/code/web_browser_robotic_process_automation"

第一次产生项目内的 .rpa-server.env（Bash 语法、权限 600、已加入 Git ignore）。默认管理页面只听 127.0.0.1:8080，设备 API 听 0.0.0.0:8081；以 --no-local-worker 启动，默认不启动测试网站。可修改文件中的 RPA_DATA_DIR、RPA_PORT、RPA_WORKER_PORT、RPA_WORKER_HOST、RPA_TESTSITE_HOST（设成 0.0.0.0 时在 8765 启动测试网站并让录制端、Worker 也连得到，见共用服务器的测试网站；较早创建的设置档没有这一行，自己加上），再重启服务；重跑 setup 会保留设置。服务与数据都归运行脚本的账号，不要整份脚本改用 sudo。

首次管理：在自己的电脑运行下面的 SSH 转发，再开 http://127.0.0.1:8080，从「设备」创建邀请。Worker／录制端的邀请地址要是它们可连到的服务器 IP 或 DNS、端口 8081；不要填 SSH 转发的 127.0.0.1。配对后录制端可经其本机闸道使用管理页面。见远程 Worker与桌面端分发。

ssh -N -L 8080:127.0.0.1:8080 admin@SERVER

# 修改设置后
sudo systemctl restart rpa-server

# 升级：先停服务并备份完整数据目录（含 rpa.db、scenes、roles、secrets.json）
sudo systemctl stop rpa-server
# 在此备份 .rpa-server.env 中 RPA_DATA_DIR 指向的完整目录
git pull --ff-only
bash scripts/setup-linux.sh --install-service

脚本只在 --install-service 时启动服务；前景进程请用 Ctrl+C 停止。systemd 服务运行中会拒绝更新环境，前景进程也应先停止。容器没有 systemd 时使用前景命令；产生的 unit 在 .venv-server/rpa-server.service。重装不删数据，但启动服务会应用数据库迁移，回退前需准备整份备份。脚本不会自动 pull 既有 checkout、切换既有分支或改防火墙；只让需要连接的设备访问设备端口。

公司网络：需要可读取代码、uv 安装档、Python 发行档及锁文件列出的包来源。可设置 HTTPS_PROXY、UV_PYTHON_INSTALL_MIRROR；公司 CA 已加入系统信任时可用 UV_NATIVE_TLS=true。Git、curl 也必须信任该 CA，不要关闭 TLS 验证。已有合规安装的 uv 可直接重用；版本太旧时脚本会指出最低版本，由原安装方式升级。

包来源。Python 包依 uv.lock 安装，默认先测速再选来源（--mirror auto）：PyPI 与清华（tuna）、中科大（ustc）、阿里云（aliyun）、腾讯云（tencent）、华为云（huawei）的镜像同时下载锁文件里的同一个文件，只考虑 sha256 和锁文件相符的来源，选最快的那个并列出每个来源的速度；都不行时用 PyPI。可以直接指定：bash scripts/setup-linux.sh --mirror tuna、--mirror pypi，或公司镜像的 simple 网址，例如 --mirror https://nexus.example.com/repository/pypi/simple（也可以设置 RPA_PYPI_MIRROR；没有指定、但有设置 UV_INDEX_URL 或 UV_DEFAULT_INDEX 时就用它，不测速）。

为什么要这样做：uv sync --locked 照锁文件记的网址下载（files.pythonhosted.org），单设 UV_INDEX_URL 不会改变下载的位置，还会让 uv 判定锁文件过期而停止。所以用镜像时，脚本只在这次安装期间把 uv.lock 里的索引与文件网址换成镜像的（版本、文件与 sha256 都不变，uv 下载后照样验证哈希），装完、失败或中断都还原；镜像装到一半失败时自动改用 PyPI 再试一次。公司只允许核准的来源时，用 --mirror pypi（搭配 HTTPS_PROXY）或公司镜像的网址，不要用 auto。不要删锁文件或临时改版本。此 setup 不需要 Playwright 浏览器下载站。

验证：CI 在 Rocky Linux 8（真实 yum、glibc 2.28、一般账号）验证项目内安装、独立脚本 clone、空 ID 的公司标记、重跑保留设置、管理端口与设备端口隔离、设备配对及重启后数据保留。容器只检查 systemd unit 语法；公司映像、aarch64 和真实 systemd 开机自启动仍需主机验收。可用 .venv-server/bin/python tools/linux_server_smoke.py 做隔离数据的 HTTP 冒烟测试。

常见问题

CI 说 uv.lock 需要更新
改了 pyproject.toml 的依赖却没有更新锁文件。运行 uv lock，把 uv.lock 一起提交。
内网连不到 PyPI
设置环境变量 UV_INDEX_URL 指向公司的包镜像。Linux 服务器的安装脚本用 --mirror 指定公司镜像的 simple 网址，见包来源。
浏览器下载失败
一键安装会先测速并选最快的可用来源；也可运行 uv run python tools/install_browsers.py。需要固定来源时，设置 PLAYWRIGHT_DOWNLOAD_HOST 指向内部镜像；浏览器冒烟测试在本机没有浏览器时会自动略过。
测试说简中不是最新
改了繁中文档或消息目录后，运行 uv run python tools/i18n.py sync 并提交产生的文件。
测试说英文翻译需要更新
依繁中的修改更新 docs/en/ 的同一页，再运行测试消息里的 stamp 命令。
pyright 找不到包
确认已运行 uv sync，且编辑器使用的是项目的 .venv。
