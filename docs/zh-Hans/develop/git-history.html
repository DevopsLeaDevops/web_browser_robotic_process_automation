Git 历史图

把提交、分支、标签与 PR 的关系保存成可脱机打开的交互 HTML；后续重新运行同一命令即可更新。

产生与更新

在仓库根目录运行。工具只需要 Python 3.12 以上与 Git，不需要另外安装 Python 包。已有开发环境可用 uv run python；Linux 服务器可用 .venv-server/bin/python；Windows 可用 .venv\Scripts\python.exe 代替下面的 python。

python tools/git_history.py --open
python tools/git_history.py --fetch --github --lang zh-Hans --timezone Asia/Shanghai --open

第一条只读本机已有的全部历史。第二条先截取远程分支、标签与 GitHub 保留的 PR head，并读取所有状态的 PR；需要已安装且登录的 gh（先运行 gh auth login）。移除 --github 仍可用于其他 Git 服务。脱机时移除 --fetch --github。

默认输出到 artifacts/git-history.html（已被 Git 忽略）。无桌面的服务器不要加 --open；把产出的 HTML 拷贝到自己的电脑后用浏览器打开。所有数据、样式与程序都在这个文件中，无需 CDN 或网站服务。

python tools/git_history.py --repo /path/to/repository --output /path/to/history.html --fetch
python tools/git_history.py --help

--lang 支持 zh-Hant（默认）、zh-Hans 与 en，页面上也能切换。--timezone 默认 America/Los_Angeles，画面会标出实际采用的时区。重新产生会取代同一输出档，不会持续在背景监控。

怎么读图

  • 默认显示全部历史，包含 CI 指针等独立分支；选择 origin/main 可只看目前远程主线及其祖先。main 是本机分支，两者可能不同。
  • 圆点代表提交，线沿实际父提交相连，空心圆有多个父提交。顺序由新到旧且遵守父子拓扑，不保证跨分支的日期严格递减。
  • 搜索消息、作者、SHA、分支或 #57，以「上一笔／下一笔」跳转；不隐藏中间节点，因此连接仍然完整。点击提交可看完整消息、引用、PR 与可跳转的父提交。
  • Squash 合并会产生不同 SHA；图中分开保存原 PR head 与 GitHub 记录的合入提交，不能把「PR 已合并」当作两点间的真实 Git 父子连接。PR 若合入功能分支，也不等于已进入 main。
  • 卷动会逐段绘制，没有固定提交数上限；图形仍需把完整 JSON 加载内存，极大型仓库的文件与内存用量会随历史增加。

「全部」的范围与副作用

收集所有本机引用与 HEAD 可达的提交，包含已截取的远程分支、标签与 PR。默认不读 reflog，也不扫描 dangling objects；已删除且没有引用保留的提交无法保证找回。浅层拷贝会显示警告；远程有完整历史时，可先运行 git fetch --unshallow 再产生。

工具不 checkout、merge、rebase 或 push，不改动工作文件与分支。--fetch 会更新远程追踪引用、下载对象与标签；GitHub PR head 存在专用的 refs/git-history/origin/pr/*（使用 --remote 指定其他远程时名称随之改变）。不删除旧引用；因此已删除远程分支的本机缓存也可能出现在图中，不能把所有引用都当作远程仍存在的分支。

输出包含提交消息、作者、分支名称与 PR 标题；分享 HTML 即分享这些仓库历史。工具不输出 Git 认证数据，也不读取 Portal 数据目录。页面是明确标示产生时间的快照，最新状态需重新截取。
