部署与操作

服务器、运行端（RPA Worker）、录制端（RPA 录制端）各放在哪里、怎么启动、平常怎么用、出问题看哪里。第一次配对与安装 App 的逐步说明在远程 worker，这一页只连过去，不重复。设计见 ADR 0012、ADR 0014。

三种角色

角色做什么装什么启动
服务器管理 Portal、数据库、场景版本、运行报告、登录状态与 Secrets 都在这台；也可以自己运行任务（本机 worker）。开发环境（一键脚本），macOS、Linux、Windows 都可以。uv run rpa serve --worker-port 8081
运行端领取并运行场景，有头模式的浏览器窗口开在这台；报告、截图、Trace 传回服务器。Windows：RPA Worker App；其他系统用开发环境。App 登录时自动启动；命令行 uv run rpa worker
录制端通过它操作管理 Portal 时，录制、逐步调试、人工登录的浏览器开在这台；录制稿、截图与登录状态传回服务器。不运行场景。macOS（Apple 芯片）：RPA 录制端 App；其他系统用开发环境。打开 App；命令行 uv run rpa recorder

连接方向只有一种：运行端与录制端主动连到服务器的对外端口（默认 8081），服务器不连它们。三台都要连得到被测试的网站。三种角色可以在同一台电脑，也可以各自一台。

常见的部署方式

一台 Mac 全包
uv run rpa serve，打开 http://127.0.0.1:8080。录制、调试、人工登录、运行都在这台，不需要配对任何设备。
Linux 服务器 ＋ Mac 录制端 ＋ Windows 运行端
服务器放在一直开着的 Linux（没有桌面也可以）；在 Mac 打开 RPA 录制端 App 操作管理 Portal，录制、调试、人工登录的窗口开在 Mac；有头模式的运行交给 Windows 的 RPA Worker。Linux 自己也能运行无头模式的任务；全部交给 Windows 时加 --no-local-worker。
Mac 服务器 ＋ Windows 运行端
在 Mac 的 8080 操作，录制在 Mac；运行交给 Windows，Mac 不再被有头模式的窗口占住。

服务器没有桌面时，从 8080（例如 SSH 通道）打开的页面不能录制、不能逐步调试、不能人工登录：这些按钮是灰的，鼠标移上去会提示改用录制端。要在 Mac 录制、调试或人工登录，一定要通过录制端打开管理 Portal；「粘贴录制稿」与其他管理工作照常可用。

服务器

安装

用一键脚本安装（装 uv、下载代码、安装依赖、下载 Chromium 与 Firefox、跑测试）。Linux 上浏览器缺系统函数库时，脚本会用 sudo 交给 Playwright 安装（只支持 Debian、Ubuntu 自动安装）。之后的命令都在项目文件夹运行。

启动

cd ~/code/web_browser_robotic_process_automation
uv run rpa serve --worker-port 8081                      # 有远程设备时
uv run rpa serve --worker-port 8081 --no-local-worker    # 全部交给远程 worker
uv run rpa serve --worker-port 8081 --data ~/rpa-data    # 数据放在项目以外

启动消息会印出管理 Portal 的网址、文件夹，以及「对外端口：http://区网 IP:8081」。按 Ctrl+C 停止。

选项作用
--worker-port 8081开放对外端口给运行端与录制端。不加就只有本机能用，设备页不能产生邀请。
--worker-host对外端口监听的地址，默认 0.0.0.0（所有网络界面）。只想让某张网卡收连接时指定它的 IP。
--no-local-worker这台不运行任务，全部交给远程 worker。
--data 文件夹数据放哪里，默认项目里的 data（也可以用环境变量 RPA_DATA_DIR）。见管理 Portal › 文件夹。
--port、--host管理页面的端口与地址，默认 127.0.0.1:8080。不要改成 0.0.0.0：管理页面没有登录保护。
--no-testsite不在 127.0.0.1:8765 启动测试网站。
--testsite-host 0.0.0.0测试网站对其他电脑开放（默认只有本机 127.0.0.1）。见下方共用服务器的测试网站。
RPA_LANG环境变量：服务器创建的消息用哪种语言（zh-Hant、zh-Hans、en）。

两个端口

  • 8080，管理页面。没有登录保护，只听 127.0.0.1，只有服务器本机打得开。
  • 8081，对外端口。每个请求都要权杖或一次性的邀请：运行端用 Worker API，录制端用 Client API，并用录制端的权杖打开管理页面。没配对的电脑打开只会看到 401。防火墙只开这个端口，而且只开给区网（或 VPN），例如 Ubuntu：sudo ufw allow from 192.168.1.0/24 to any port 8081 proto tcp。
  • 是 HTTP，不加密。Secrets 与登录状态会经过网络，只在信任的区网或 VPN 使用。服务器在云端或不同网段时，可以用 SSH 通道把对外端口带到设备那台：ssh -N -L 8081:127.0.0.1:8081 用户@服务器，设备配对时服务器填 http://127.0.0.1:8081。

共用服务器的测试网站

默认每台电脑各自在 127.0.0.1:8765 跑一份测试网站，数据与登录不互通：在 Mac 建的记录，Windows 查不到。要让录制端与 Worker 都用服务器上的同一份：

  1. 服务器加 --testsite-host 0.0.0.0 启动。用 Linux 安装脚本时，在 .rpa-server.env 设 export RPA_TESTSITE_HOST=0.0.0.0 再重新启动（较早创建的设置档没有这一行，自己加上）。启动消息会印出「测试网站：http://区网 IP:8765/」，地址是猜的。
  2. 防火墙开 8765，只开给录制端与 Worker 那几台：测试网站没有任何保护，连得到的人都能创建记录、用示范账号登录。例如 RHEL 系：sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=192.168.1.0/24 port port=8765 protocol=tcp accept'，再 sudo firewall-cmd --reload。
  3. 录制的起始网址填 http://服务器:8765/。示例场景要用它时，在 BA-001～BA-005 的场景页把「默认网址」改成 http://服务器:8765；「登录与凭证」把两个测试网站角色的登录网址、检查网址改成 http://服务器:8765/login、http://服务器:8765/account。

改好之后，BA-001 建的记录在任何一台用 BA-002 都查得到，角色的登录状态也对每一台有效。

从别台电脑打开管理 Portal

  • 通过录制端（建议）。在 Mac 配对录制端后，App 的窗口就是管理 Portal；录制、调试、人工登录的浏览器开在 Mac。
  • SSH 通道。ssh -N -L 8080:127.0.0.1:8080 用户@服务器，再打开 http://127.0.0.1:8080。能做所有管理工作，但浏览器开在服务器上（见上方的部署方式）。

Linux：开机自动启动（systemd）

用运行一键脚本的那个账号（浏览器下载在它的家目录）。创建 /etc/systemd/system/rpa-portal.service，把 rpa 换成实际的账号：

[Unit]
Description=RPA management portal
After=network-online.target
Wants=network-online.target

[Service]
User=rpa
WorkingDirectory=/home/rpa/code/web_browser_robotic_process_automation
ExecStart=/home/rpa/.local/bin/uv run rpa serve --worker-port 8081 --data /home/rpa/rpa-data
Restart=on-failure

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now rpa-portal     # 现在启动，之后开机自动启动
sudo systemctl status rpa-portal
journalctl -u rpa-portal -f                # 看启动消息与日志
sudo systemctl restart rpa-portal          # 更新后重新启动

更新版本

  1. 到「运行报告」确认没有运行中的任务，录制端那边也没有进行中的录制或调试。
  2. 停止服务器（Ctrl+C 或 sudo systemctl stop rpa-portal），建议先备份。
  3. git pull，再运行 ./scripts/setup.sh（依赖与浏览器有变动才安装；只想更新依赖用 uv sync）。
  4. 启动服务器。数据库在启动时自动升级，原有的场景与记录都保留。
  5. 把运行端与录制端更新到同一个版本：App 下载同版本的安装档或 DMG，命令行的那台 git pull 后重新启动。

服务器重新启动时，录制端进行中的录制、调试、人工登录会结束；运行端与录制端会自己重新连上，不必重新配对。

备份与搬家

所有数据都在文件夹里（里面有什么见管理 Portal › 文件夹）。停止服务器后拷贝整个文件夹就是备份，例如 tar czf rpa-data-$(date +%Y%m%d).tgz -C ~ rpa-data。搬到新的服务器：在新的那台安装同一个版本，把文件夹放回去，用同样的 --data 启动。设备的权杖也在文件夹里，服务器网址不变时不必重新配对；网址变了（换了 IP）时，在设备页按「重新邀请」，到那台用新的邀请重新配对。文件夹里有 Secrets 的值与登录状态，备份档请一样只有本人能读。

管理设备

管理 Portal › 场景生产 › 设备
  • 添加。「添加设备」选种类（RPA Worker 或 RPA 录制端），产生一次性的邀请（24 小时内有效），贴到那台的 App 或命令行。步骤见远程 worker › 添加设备。
  • 状态。在线、运行中、脱机、已禁用；另外显示操作系统、App 版本与下载过的浏览器。和服务器版本不同时会标出来。
  • 禁用、激活。禁用后那台立刻连不上。命令行的 worker、录制端会停下来，激活后重新运行即可；两个 App 被拒绝时会清掉配对，激活后要用新的邀请再配对。
  • 重新邀请。旧的权杖立刻失效，要用新的邀请在那台重新配对。怀疑权杖外流、换电脑时用。
  • 删除。那台不能再连接；指定给它、还在排队的运行会标为失败，运行记录保留。
  • 默认运行位置。本机、远程 worker、任一。主要用 Windows 运行时改成「远程 worker」，不必每次选。

录制端：平常怎么用

第一次安装与配对见macOS：RPA 录制端 App（命令行见录制端）。

  1. 打开。双击「RPA 录制端」；连上后窗口就是管理 Portal，页眉显示「通过录制端「名称」」。命令行：项目文件夹运行 uv run rpa recorder，会在默认浏览器打开。
  2. 录制。「场景生产 › 自主脚本录制」选新场景或既有场景、起始网址、浏览器与角色，按「开始录制」。浏览器与 Playwright Inspector 开在 Mac；操作完关掉浏览器窗口，草稿自动产生。起始网址填要自动化的网站（例如 Mac 自己的测试网站 http://127.0.0.1:8765/ 或业务系统），不是服务器的 8080、8081：那是管理 Portal 自己，填了会被挡下。
  3. 逐步调试。场景页按「逐步调试」，有头模式的窗口开在 Mac，每一步的截图也显示在页面上。
  4. 人工登录。「场景管理 › 登录与凭证」按角色的「登录」，在 Mac 开的窗口里登录，按「完成登录」或关掉窗口；登录状态存回服务器。
  5. 运行。验证与运行的「运行位置」里，「服务器」是服务器自己，「远程 worker」是运行端。录制端不运行场景。
  6. 结束。关掉 App 窗口或 ⌘Q；有录制、调试、人工登录在进行时会先确认。命令行按 Ctrl+C。
  • 菜单「RPA 录制端 › 状态与设置」：连接状态、版本、进行中的工作、Firefox、浏览器下载镜像、语言、打开日志文件夹、重新配对。
  • 每台电脑同一时间各一段录制；同一个场景的逐步调试只有一个，在另一台开始时，原本那台的会关掉。

运行端：平常怎么用

第一次安装与配对见Windows：RPA Worker App（命令行见worker 机器：启动）。

  1. 开着就好。App 在登录 Windows 时自动启动，缩在通知区接任务；关掉窗口不会停止。命令行：项目文件夹运行 uv run rpa worker，保持终端开着。
  2. 交任务。在管理 Portal 验证、运行或运行串行时，「运行位置」选「远程 worker」或「任一」，或把设备页的默认运行位置改成远程 worker。
  3. 看结果。运行报告在服务器的「运行报告」，标出「在 win-01 运行」。
  4. 暂停。通知区菜单「暂停接任务」：做完目前的任务后不再领取。要长时间不用，在设备页按「禁用」。
  5. 结束。通知区菜单「结束」；有任务在运行时先确认，被取消的任务会回报。命令行按 Ctrl+C。
  • 有头模式的窗口开在登录中的 Windows 桌面上；App 在用户登录后才启动，注销或关机时运行中的任务会被取消并回报。
  • 运行时用到的登录状态由服务器送过去、用完就删；人工登录不在运行端做。

日志在哪里

服务器
启动的终端；systemd 用 journalctl -u rpa-portal。每次运行的日志与报告在文件夹的 runs/<运行编号>/，也可以在「运行报告」打开。
RPA 录制端 App
~/Library/Application Support/rpa/recorder/logs/recorder.log；「状态与设置 › 打开日志文件夹」。
RPA Worker App
%LOCALAPPDATA%\rpa\worker\logs；窗口的「设置 › 打开日志文件夹」。
命令行的 worker、录制端
运行它的终端。

常见问题

状况处理
设备连不上服务器服务器有没有加 --worker-port、IP 与端口号对不对、服务器的防火墙有没有开 8081。检查方法见远程 worker › 常见问题。邀请里的地址是猜的，服务器有多张网卡时常猜错：服务器网址和代码分开填。
录制、逐步调试、人工登录的按钮是灰的，鼠标移上去提示改用录制端页面是从服务器的 8080（例如 SSH 通道）打开的，而服务器没有桌面：改从录制端打开。通过录制端也这样时，是录制端那台没有桌面。
开始录制时说起始网址是管理 Portal 自己的地址起始网址填成了服务器的 8080 或 8081。录制开的是全新的浏览器，没有录制端的权杖，打开这两个端口只会得到 401（recorder_unauthorized）。改填要自动化的网站。
「开始录制」是灰的，上方写著录制中这台已经有一段录制在进行：先把那个浏览器窗口关掉，或按「取消录制」。
录制端说管理 Portal 不再接受这台的权杖设备页重新邀请过、禁用或删除了这台。在设备页产生新的录制端邀请（被禁用时先按「激活」），到「状态与设置」粘贴重新配对。
版本不同的提醒只是程序版本不同时仍可使用，但建议更新到同一个版本；协定版本不同时连不上，一定要更新。见更新版本。
录制、调试突然结束，原因是失联录制端停掉、睡眠或断线超过 30 秒，或服务器重新启动。重新打开后再开始一次。
任务一直排队见远程 worker › 常见问题。
