开发规范

分支、提交、PR、代码与测试的约定。工具能检查的都交给工具，这里只写工具管不到的。

分支与 PR

  • main 受保护。只通过 PR 合并，CI 全绿且至少一人 review。
  • 分支命名。里程碑工作用 m1/dsl-models；其他用 fix/…、docs/…、chore/…。
  • PR 描述三段。做了什么、怎么验证、还没做的部分。
  • 合并方式。Squash merge，PR 标题即为最终提交消息。
  • 依赖变更。添加依赖要在 PR 描述说明理由。

提交消息

Conventional Commits
<类型>(<范围>): <繁体中文摘要>

feat(core): 添加 goto 与 click 动作模型
fix(cli): validate 对空文件回报错误行号
docs(adr): 添加 0008 Secrets 加密方式
类型
feat、fix、docs、refactor、test、ci、chore
范围
包或区域：core、cli、runner、docs、adr…

代码

  • 语言。标识符用英文；注释与文档字符串用繁体中文。
  • 用户看得到的文字。命令行输出、错误与校验消息等一律放进包的 locales/，代码只写消息键；同时写繁中与英文，简中自动产生。见 ADR 0007。
  • 类型。pyright strict；所有函数完整标注类型，避免 Any。
  • 格式。以 ruff 为准，不手动争论格式。
  • 输出。代码中不留 print；CLI 通过 click 输出，函数库用 logging。
  • 数据库。只用 SQLAlchemy 的通用类型与写法，SQLite 与 PostgreSQL 都要能跑；规则见 ADR 0008。
  • 边界。rpa-core 不依赖浏览器或数据库；运行相关的代码放在 rpa-runner。

测试

  • 每个包在自己的 tests/ 下测试；跨包的测试放在根目录 tests/。
  • 需要真实浏览器的测试加上 @pytest.mark.browser。
  • 测试不依赖外部网站；需要网页时用测试网站（M2 起）。
  • 修 bug 先写一个重现问题的测试。
  • 文档页面由 tests/docs 检查结构与链接；三种语言是否同步由 tests/i18n 检查。
不要提交真实账号密码、内部系统网址或包含业务数据的截图。本机机密放在 .env（已被 Git 忽略），范例档用 .env.example。
