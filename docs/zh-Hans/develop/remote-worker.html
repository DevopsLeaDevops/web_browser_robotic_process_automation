远程 worker

把运行交给另一台电脑：管理 Portal、数据库与文件留在你的电脑，浏览器窗口出现在 worker 机器上，你的电脑不再被有头模式占住。以 Windows 当 worker 机器为例；macOS、Linux 的命令也列在旁边。要在另一台电脑录制、调试与人工登录，见录制端；配好之后怎么部署、平常怎么用，见部署与操作。设计见 ADR 0012、ADR 0014。

两台电脑要在同一个区网（或 VPN），而且 worker 机器连得到你的电脑；你的电脑不需要连 worker。两台都要能连到被测试的网站。Secrets 与角色的登录状态会以 HTTP 经过区网，只在信任的网络使用。

1. 你的电脑：开放对外端口

先用 Ctrl+C 停掉原本的 rpa serve，再加上 --worker-port 重新启动：

uv run rpa serve --worker-port 8081

启动消息会多一行 对外端口：http://192.168.1.10:8081（地址是猜的区网 IP）。第一次启动时，macOS 会询问是否允许 Python 接受传入连接，请按「允许」；Windows 的防火墙也会询问。

管理页面仍然在 http://127.0.0.1:8080；8081 这个对外端口上每个请求都要权杖或邀请：Worker API 要 worker 的权杖，管理页面只给录制端的权杖，没配对的电脑打开只会看到 401。

2. 添加设备、取得邀请

  1. 管理 Portal 的「场景生产 › 设备」按「添加设备」。
  2. 代号例如 win-01，名称例如「测试用 Windows 电脑」，按「产生邀请」。
  3. 对话框显示一行邀请（rpa://pair?…，已拷贝到剪贴板）、分开的服务器与代码，以及命令行的用法。邀请只显示这一次、24 小时内有效、只能用一次；遗失或过期时按「重新邀请」（旧的配对立刻失效）。

邀请里的服务器地址是猜的；如果 worker 连不上，改用你的电脑在区网上的 IP（macOS：系统设置 › 网络；Windows：ipconfig），和代码分开填。邀请可以换到权杖，不要分享给别人。

3. worker 机器：安装

和平常的安装一样

用本机从零运行的一键脚本安装（在 PowerShell 运行）：

irm https://raw.githubusercontent.com/DevopsLeaDevops/web_browser_robotic_process_automation/main/scripts/setup.ps1 -OutFile $env:TEMP\rpa-setup.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\rpa-setup.ps1

代码会下载到 %USERPROFILE%\code\web_browser_robotic_process_automation，也会下载 Chromium 与 Firefox。两台电脑要是同一个版本：之后你的电脑 git pull，worker 机器也要 git pull 并重跑脚本。版本不同时设备页会标出来。

4. worker 机器：启动

第一次在项目文件夹用邀请配对并启动（整行邀请加上引号）：

# Windows PowerShell
cd $env:USERPROFILE\code\web_browser_robotic_process_automation
uv run rpa worker --invite "rpa://pair?server=…&app=worker&code=…"

# macOS、Linux（同样在项目文件夹）
uv run rpa worker --invite 'rpa://pair?server=…&app=worker&code=…'

# 服务器地址要改时：代码分开给
uv run rpa worker --server http://192.168.1.10:8081 --invite （代码）

看到「已配对」与「已连上管理 Portal」就好了；设备页的状态变成「在线」。换到的权杖存在工作文件夹的 worker-data\pairing.json（只有你能读写，不要提交到 git），之后只要运行 uv run rpa worker。按 Ctrl+C 停止：运行中的任务会被取消并回报。

以前的方式照样可用：用 API（POST /api/workers/{代号}/token）重新产生权杖后，放在环境变量 RPA_WORKER_TOKEN 或 --token-file token.txt，并加上 --server。Windows 与 macOS（Apple 芯片）上也可以改用 RPA Worker App（Windows、macOS）粘贴邀请，不必安装开发环境。

Windows：RPA Worker App

M10.1：不需要 uv、git、Python
  1. 从 GitHub 仓库的 Releases 下载和管理 Portal 同一个版本的 RPA-Worker-Setup-版本-windows-x64.exe（安装档）。测试还没发布的版本时，改从 PR 或 main 的「桌面端建置」运行记录的 Artifacts 下载 worker-windows-latest（里面有安装档与免安装的 zip）。
  2. 运行安装档。没有代码签章：SmartScreen 出现「Windows 已保护您的电脑」时按「其他信息 › 仍要运行」。选语言（默认繁体中文）后一路「下一步」：只装给目前的用户，不需要管理员，装在 %LOCALAPPDATA%\Programs\RPA Worker，开始功能表有捷径（桌面捷径可以勾选）；装完直接打开 RPA Worker。没有 WebView2 Runtime 时安装档会顺便安装（需要连上网络）。
  3. 窗口打开后，把第 2 步产生的邀请贴在「邀请」栏（只贴代码时另外填管理 Portal 的网址）；需要 Firefox 就勾选，按「配对」。
  4. 第一次会下载 Chromium（解压后约 600 MB），窗口显示进度。状态变成「在线」就好了；设备页显示「在线」与 App 版本。
  • 升级：运行新版的安装档即可。RPA Worker 正在运行时，安装档会先请它结束（运行中的任务被取消并回报给管理 Portal）再换文件；配对、设置与自动启动都保留。窗口提醒「程序版本和管理 Portal 不同」时，旁边的「下载新版」会打开最新的 Release。
  • 卸载：Windows 的「设置 › 应用程序」找到 RPA Worker。确认要卸载后，先问要不要也删除配对、设置与日志：默认「否」（保留），之后重新安装不必再配对；选「是」会一并删除认证管理员里的权杖。接着结束 RPA Worker（运行中的任务被取消并回报）、删除程序、捷径与自动启动。浏览器（%LOCALAPPDATA%\ms-playwright）与 Firefox 模板的缓存（%LOCALAPPDATA%\rpa\cache）别的程序也可能在用，不会删除。用命令行静默卸载（unins000.exe /VERYSILENT）时不问、保留数据，加上 /REMOVEDATA=yes 才删除。
  • 免安装版：Release 也附 RPA-Worker-版本-windows-x64.zip，解压缩到任何文件夹（例如 %USERPROFILE%\RPA Worker）后双击 rpa-worker.exe，用法和安装版相同；升级时先从通知区结束，再解压缩新版覆盖。免安装版和安装版用同一个文件夹的配对，不要同时使用。
  • 关闭窗口不会停止。RPA Worker 缩到通知区继续接任务（第一次会提示）。通知区图标的菜单：打开窗口、暂停接任务、结束；图标右下角的圆点是绿色（在线）、黄色（暂停）或红色（脱机、需要处理）。有任务在运行时按「结束」会先确认，取消后回报给管理 Portal。
  • 登录 Windows 时自动启动：第一次配对成功后默认打开，只出现在通知区；在窗口的「设置」可以关闭。文件夹搬走后开一次 RPA Worker，自动启动就会改成新的位置。
  • 暂停接任务：做完目前的任务后不再领取新的，管理 Portal 约一分钟后显示这台脱机；按「继续接任务」立刻重新上线。
  • 只运行一份：再双击一次会叫出已经在运行的那份窗口。
  • 设置：语言（默认繁体中文）、也下载 Firefox（运行中才勾选的话，下次打开时下载）、下载浏览器的内部镜像（PLAYWRIGHT_DOWNLOAD_HOST）、打开日志文件夹、重新配对。
  • 数据位置：%LOCALAPPDATA%\rpa\worker（配对的服务器与设备 pairing.json、设置 settings.json、日志 logs\、任务的暂存）。权杖存在 Windows 认证管理员（「一般认证」里的 RPA Worker）；认证管理员不能用时退回存在 pairing.json（只有你能读写），窗口的「权杖存放」会标出来。第一步预览版存在文件里的权杖，第一次打开时自动搬进认证管理员。浏览器在 %LOCALAPPDATA%\ms-playwright。日志不记权杖与邀请代码。
  • 需要 Microsoft Edge WebView2：Windows 11 内置，Windows 10 大多已随 Edge 更新装好；安装档在没有时会安装。还是没有时（例如免安装版、安装时没有网络），RPA Worker 会说明怎么安装，在那之前只靠通知区接任务。
  • Windows 注销或关机：运行中的任务立刻被取消并回报；来不及回报时，管理 Portal 约一分钟后判定失联。
  • 排查问题：同文件夹的 rpa-child.exe --worker 是主控台版（和第一步的预览版相同，每一行消息都看得到）；rpa-worker.exe --no-window --invite … --log 文件 不开窗口（自动化用；要它结束时在文件夹放一个 stop.request 文件，运行中的任务会被取消并回报）。两者和窗口版用同一份配对，同一时间只能开一份。

macOS：RPA Worker App

Apple 芯片；功能和 Windows 版相同
  1. 从 Releases 下载和管理 Portal 同一个版本的 RPA-Worker-版本-macos-arm64.dmg（加入 macOS 版之后的第一个发布才有）。测试还没发布的版本时，改从「桌面端建置」运行记录的 Artifacts 下载 worker-macos-14。
  2. 打开 DMG，把「RPA Worker」拖进「应用程序」。没有签章与公证，第一次打开会被挡下：到「系统设置 › 隐私权与安全性」，在下方找到 RPA Worker，选择允许打开并输入密码（和录制端相同）。熟悉终端的人也可以运行 xattr -dr com.apple.quarantine "/Applications/RPA Worker.app"。
  3. 和 Windows 相同：粘贴 Worker 邀请、按「配对」，第一次下载 Chromium，状态变成「在线」就好了。macOS 15 起第一次连到区网时会问是否允许 RPA Worker 连到区网上的设备，请选「允许」。
  • 关闭窗口不会停止。RPA Worker 缩到菜单列（屏幕右上角的图标）继续接任务，Dock 上的图标也收起来；第一次会用通知提示。菜单列图标的菜单与圆点的颜色和 Windows 的通知区相同。要结束：菜单列图标 › 结束，或在窗口按 ⌘Q；有任务在运行时先确认，取消后回报给管理 Portal。
  • 叫出窗口：菜单列图标 › 打开窗口，或在 Finder、Launchpad 再打开一次 RPA Worker。
  • 登录 macOS 时自动启动：第一次配对成功后默认打开，只出现在菜单列；在窗口的「设置」可以关闭。做法是放一个 LaunchAgent（~/Library/LaunchAgents/io.github.devopsleadevops.rpa.worker.plist）：macOS 13 起会通知「已加入背景项目」，也列在「系统设置 › 一般 › 登录项目」；在那里关掉时，系统另外记录禁用，App 的设置不会把它改回来。App 搬到别的位置后开一次，自动启动就会改成新的位置。
  • 升级：先从菜单列结束 RPA Worker（运行中的任务被取消并回报），再把新版的 App 拖进「应用程序」取代。配对、设置与自动启动都保留。窗口的「下载新版」打开最新的 Release。
  • 卸载：先在「设置」关掉自动启动并结束 RPA Worker，再把 App 拖到垃圾桶。要一并删除配对：先运行 "/Applications/RPA Worker.app/Contents/MacOS/rpa-child" --forget-pairing（删除钥匙圈里的权杖），再删除文件夹 ~/Library/Application Support/rpa/worker。浏览器（~/Library/Caches/ms-playwright）录制端也可能在用，不要删。
  • 数据位置：~/Library/Application Support/rpa/worker（pairing.json、settings.json、日志 logs/、任务的暂存）。权杖存在钥匙圈（登录钥匙圈里的 RPA Worker）；钥匙圈不能用时退回存在 pairing.json（只有你能读写），窗口的「权杖存放」会标出来。日志不记权杖与邀请代码。
  • 注销、重新开机或关机：运行中的任务立刻被取消并回报（只等几秒，不挡住注销）；来不及回报时，管理 Portal 约一分钟后判定失联。
  • 同一台 Mac 也装了录制端：两个 App 各自配对（Worker 邀请、录制端邀请），文件夹与钥匙圈项目分开，可以同时运行；下载的浏览器共用。
  • 排查问题："/Applications/RPA Worker.app/Contents/MacOS/rpa-child" --worker 是主控台版；同文件夹的 rpa-worker --no-window --invite … --log 文件 不开窗口。两者都要在登录中的桌面（例如「终端」）运行，有头模式才开得了浏览器；和 App 用同一份配对，同一时间只能开一份。
  • 只支持 Apple 芯片（和录制端相同）。Intel Mac 用开发环境的 rpa worker（启动 worker）。

录制端：浏览器开在另一台电脑

M10.2：录制、逐步调试、人工登录

worker 负责运行场景；录制端让你在另一台电脑（例如 Mac）操作管理 Portal：通过录制端打开的页面，录制、逐步调试、人工登录的浏览器开在那台，录制稿、截图与登录状态传回管理 Portal。场景、数据与运行报告都还在你的电脑，运行场景照旧交给本机或 worker。

  1. 你的电脑照第 1 步开放对外端口。服务器和录制端是同一台时也一样，配对 http://127.0.0.1:8081。
  2. 设备页按「添加设备」，种类选「RPA 录制端」，代号例如 mac-01，按「产生邀请」。
  3. 录制端那台照第 3 步安装（macOS 用一键脚本），在项目文件夹配对并启动：
uv run rpa recorder --invite 'rpa://pair?server=…&app=recorder&code=…'

默认浏览器会打开管理 Portal，页眉多一个「通过录制端「名称」」。权杖存在 recorder-data/pairing.json（只有你能读写，不要提交到 git），之后只要运行 uv run rpa recorder；按 Ctrl+C 停止，进行中的录制、调试、人工登录会结束。

  • 本机闸道。rpa recorder 在 127.0.0.1 的随机端口开一个闸道，加上权杖后转给对外端口。启动消息印出的网址只在这台、这次启动有效（关掉分页后用同一个网址再打开）；权杖不进网页，同一台电脑上的其他程序也用不了闸道。固定端口号用 --port，不自动打开浏览器用 --no-open。
  • 「本机」显示成「服务器」。通过录制端看页面时，运行位置的「本机」指的是服务器那台，所以改称「服务器」，避免误会成录制端这台。
  • 浏览器。录制端上线时回报下载过的浏览器；选了这台没有的浏览器，页面直接说明。没有图形界面的电脑不能录制、逐步调试、人工登录（按钮是灰的）。
  • 失联。录制端停掉或断线超过 30 秒，它进行中的录制、调试、人工登录会结束并记下原因；录制端重新启动、在设备页被禁用、删除或重新邀请时也一样。
  • 测试网站。和 rpa worker 一样，默认在录制端那台启动测试网站（127.0.0.1:8765），录制示例场景时连得到。
  • 同时使用。你的电脑 8080 的页面照旧在你的电脑开浏览器。每台电脑同一时间可以各有一段录制；同一个场景的逐步调试只有一个，在另一台开始时，原本那台的会关掉。

macOS：RPA 录制端 App

M10.2：不需要 uv、git、Python；Apple 芯片
  1. 从 GitHub 仓库的 Releases 下载和管理 Portal 同一个版本的 RPA-Recorder-版本-macos-arm64.dmg（v0.3.0 起）。测试还没发布的版本时，改从 PR 或 main 的「桌面端建置」运行记录的 Artifacts 下载 recorder-macos-14（里面是 DMG）。打开 DMG，把「RPA 录制端」拖进「应用程序」。
  2. 没有签章：第一次打开会被挡下。到「系统设置 › 隐私权与安全性」，在下方找到 RPA 录制端，选择允许打开并输入密码（熟悉终端的人也可以运行 xattr -dr com.apple.quarantine "/Applications/RPA Recorder.app"）。macOS 15 起会询问是否允许连到区网上的设备，请按「允许」。
  3. 窗口打开后，把设备页产生的录制端邀请贴在「邀请」栏（只贴代码时另外填管理 Portal 的网址），需要 Firefox 就勾选，按「配对」。第一次会下载 Chromium，窗口显示进度；连上后自动打开管理 Portal，页眉显示「通过录制端「名称」」。
  • 菜单「RPA 录制端」：「状态与设置」回到 App 自己的页面（服务器、版本、进行中的工作、设置、重新配对、结束），「管理 Portal」回到 Portal，「刷新」。⌘V 可以粘贴邀请。
  • 新窗口与下载。报告、截图、可执行文件案的链接在 App 内开新窗口；连到别的网站（例如角色的登录网址）时用默认浏览器。导出、下载的文件会询问存放位置（默认「下载项目」）。
  • 关掉窗口就结束。有录制、调试或人工登录在进行时先确认（⌘Q 也一样），结束会中断它们，管理 Portal 那边标成结束。再打开一次会叫出已经在运行的那份。
  • 数据位置：~/Library/Application Support/rpa/recorder（配对的服务器与设备 pairing.json、设置、日志 logs/recorder.log、录制与调试的暂存，用完删除）。权杖存在钥匙圈（「RPA Recorder」项目）；钥匙圈不能用时退回存在 pairing.json（只有你能读写），状态页的「权杖存放」会标出来。浏览器在 ~/Library/Caches/ms-playwright，和开发环境共用。
  • 服务器在同一台 Mac：一样用 rpa serve --worker-port 8081 开对外端口，配对 http://127.0.0.1:8081。
  • 升级：先结束 App，打开新版的 DMG，把「RPA 录制端」拖进「应用程序」取代旧的；配对、设置与日志都保留。新版第一次打开可能又要到「隐私权与安全性」允许。状态页提醒「程序版本和管理 Portal 不同」时，旁边的「下载新版」会打开最新的 Release。
  • 卸载：结束 App 后把「RPA 录制端」丢到垃圾桶。配对、设置与日志在上面的文件夹，权杖在钥匙圈的「RPA Recorder」，不要了再删；浏览器的缓存和开发环境共用，不一定要删。
  • 不开 App 的窗口（排查问题、自动化）：在终端运行 "/Applications/RPA Recorder.app/Contents/MacOS/rpa-recorder" --no-window --open，连上后用默认浏览器打开管理 Portal。有头模式照样可以用：录制、逐步调试、人工登录的浏览器窗口照样开在这台，少的只是 App 的窗口，所以要在登录中的桌面运行（不要从 SSH）。消息印在终端，也写进日志。和 App 用同一份配对，同一时间只能开一份（这时双击 App 会用默认浏览器打开管理 Portal）；按 Ctrl+C 结束（或在文件夹放一个 stop.request 文件）。其他选项：--invite、--server、--firefox、--log 文件、--url-file 文件（把经由闸道打开 Portal 的网址写到文件，自动化用）。

5. 把运行交给 worker

  • 运行位置。登记了远程 worker 之后，验证、运行与「运行串行」的表单多一个「运行位置」：本机、远程 worker、任一（谁有空谁运行）。有头模式的浏览器窗口出现在运行的那台电脑。
  • 默认运行位置。在设备页设置；默认是本机（和以前一样）。主要用 worker 时改成「远程 worker」，就不必每次选。
  • 报告。worker 运行完把整个运行目录（报告、截图、Trace、日志）传回来；运行报告标出「在 win-01 运行」，看起来和本机运行一样。
  • 测试网站。rpa worker 也在 worker 机器启动自己的测试网站（127.0.0.1:8765），所以「测试网站自动化」的示例照样能跑；它的数据和你电脑上的测试网站是分开的。其他写成 127.0.0.1 或 localhost 的网址，在 worker 上指的是 worker 自己。
  • 试验场串行整个在同一台 worker：第一个节点由哪台领取，后面的节点就都给它。
  • 登录角色。人工登录在你操作的那台（你的电脑，或通过录制端时在录制端），不在 worker；登录状态在运行时送到 worker，用完就删。worker 自动登录后的新状态会传回来。
  • 只让 worker 运行。rpa serve --worker-port 8081 --no-local-worker：你的电脑完全不运行，全部交给 worker。

开机后自动启动（Windows，选用）

用 RPA Worker App 时不需要这一步：在 App 的「设置」勾选即可（配对后默认打开）。以下是命令行 worker 的做法。

有头模式需要用户已经登录桌面，所以用「登录时」启动，不要做成系统服务。先照第 4 步配对一次，再在项目文件夹创建 start-worker.cmd（不要提交到 git）：

@echo off
cd /d %USERPROFILE%\code\web_browser_robotic_process_automation
uv run rpa worker

然后按 Win+R 输入 shell:startup，在打开的文件夹放一个指向 start-worker.cmd 的捷径。

常见问题

状况处理
「連不上管理 Portal」一直重试确认 Portal 有加 --worker-port、网址的 IP 与端口号正确、你电脑的防火墙允许传入连接。在 worker 机器用浏览器打开 http://IP:8081/worker-api/v1/hello：看到 405 或 Method Not Allowed 代表连得到。
「管理 Portal 拒絕這台 worker」权杖不对、已经重新邀请，或设备被禁用。到设备页按「重新邀请」，用新的邀请重新运行 rpa worker --invite；或按「激活」。
「配對失敗」邀请已经用过、过期（24 小时）、贴错 App，或设备被禁用：看消息的说明，在设备页重新邀请。
运行一直是「排队中」运行页会说明在等哪台 worker。设备页看它是不是「在线」；有头模式的任务只给能显示窗口的 worker；场景要用的浏览器在 worker 机器要下载过（重跑安装脚本）。
运行失败「判定失聯」worker 超过一分钟没有回报（关机、断网、程序被关掉）。那次运行不会自动重跑，因为可能已经在网站上做了部分操作；确认后再重新运行。
设备页标出「版本不同」两台都 git pull 到同一个版本，worker 机器重跑安装脚本后重新启动 rpa worker。
只想暂时不用 worker设备页按「禁用」，或在 worker 机器按 Ctrl+C；默认运行位置改回本机。
