远程 worker

把运行交给另一台电脑：管理 Portal、数据库与文件留在你的电脑，浏览器窗口出现在 worker 机器上，你的电脑不再被有头模式占住。以 Windows 当 worker 机器为例；macOS、Linux 的命令也列在旁边。设计见 ADR 0012。

两台电脑要在同一个区网（或 VPN），而且 worker 机器连得到你的电脑；你的电脑不需要连 worker。两台都要能连到被测试的网站。Secrets 与角色的登录状态会以 HTTP 经过区网，只在信任的网络使用。

1. 你的电脑：开放 Worker API

先用 Ctrl+C 停掉原本的 rpa serve，再加上 --worker-port 重新启动：

uv run rpa serve --worker-port 8081

启动消息会多一行 Worker API：http://192.168.1.10:8081（地址是猜的区网 IP）。第一次启动时，macOS 会询问是否允许 Python 接受传入连接，请按「允许」；Windows 的防火墙也会询问。

管理页面仍然只在 http://127.0.0.1:8080；8081 这个端口只有 Worker API，每个请求都要权杖。

2. 登记 worker、取得权杖

  1. 管理 Portal 的「场景生产 › 远程 Worker」按「添加 worker」。
  2. 代号例如 win-01，名称例如「测试用 Windows 电脑」，按「产生权杖」。
  3. 对话框显示权杖与两组启动命令。权杖只显示这一次，先拷贝下来；遗失时按「重新产生权杖」（旧的立刻失效）。

命令里的网址是猜的；如果 worker 连不上，换成你的电脑在区网上的 IP（macOS：系统设置 › 网络；Windows：ipconfig）。

3. worker 机器：安装

和平常的安装一样

用本机从零运行的一键脚本安装（在 PowerShell 运行）：

irm https://raw.githubusercontent.com/DevopsLeaDevops/web_browser_robotic_process_automation/main/scripts/setup.ps1 -OutFile $env:TEMP\rpa-setup.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\rpa-setup.ps1

代码会下载到 %USERPROFILE%\code\web_browser_robotic_process_automation，也会下载 Chromium 与 Firefox。两台电脑要是同一个版本：之后你的电脑 git pull，worker 机器也要 git pull 并重跑脚本。版本不同时 worker 页会标出来。

4. worker 机器：启动

在项目文件夹，粘贴对话框里的命令：

# Windows PowerShell
cd $env:USERPROFILE\code\web_browser_robotic_process_automation
$env:RPA_WORKER_TOKEN = "（权杖）"
uv run rpa worker --server http://192.168.1.10:8081 --name win-01

# macOS、Linux
export RPA_WORKER_TOKEN='（权杖）'
uv run rpa worker --server http://192.168.1.10:8081 --name win-01

看到「已连上管理 Portal」就好了；worker 页的状态变成「在线」。按 Ctrl+C 停止：运行中的任务会被取消并回报。

权杖也可以放在文件里：--token-file token.txt（不要提交到 git）。

5. 把运行交给 worker

  • 运行位置。登记了远程 worker 之后，验证、运行与「运行串行」的表单多一个「运行位置」：本机、远程 worker、任一（谁有空谁运行）。有头模式的浏览器窗口出现在运行的那台电脑。
  • 默认运行位置。在 worker 页设置；默认是本机（和以前一样）。主要用 worker 时改成「远程 worker」，就不必每次选。
  • 报告。worker 运行完把整个运行目录（报告、截图、Trace、日志）传回来；运行报告标出「在 win-01 运行」，看起来和本机运行一样。
  • 测试网站。rpa worker 也在 worker 机器启动自己的测试网站（127.0.0.1:8765），所以「测试网站自动化」的示例照样能跑；它的数据和你电脑上的测试网站是分开的。其他写成 127.0.0.1 或 localhost 的网址，在 worker 上指的是 worker 自己。
  • 试验场串行整个在同一台 worker：第一个节点由哪台领取，后面的节点就都给它。
  • 登录角色。人工登录仍在你的电脑（要人操作）；登录状态在运行时送到 worker，用完就删。worker 自动登录后的新状态会传回来。
  • 只让 worker 运行。rpa serve --worker-port 8081 --no-local-worker：你的电脑完全不运行，全部交给 worker。

开机后自动启动（Windows，选用）

有头模式需要用户已经登录桌面，所以用「登录时」启动，不要做成系统服务。在项目文件夹创建 start-worker.cmd（不要提交到 git）：

@echo off
cd /d %USERPROFILE%\code\web_browser_robotic_process_automation
set RPA_WORKER_TOKEN=（权杖）
uv run rpa worker --server http://192.168.1.10:8081 --name win-01

然后按 Win+R 输入 shell:startup，在打开的文件夹放一个指向 start-worker.cmd 的捷径。

常见问题

状况处理
「連不上管理 Portal」一直重试确认 Portal 有加 --worker-port、网址的 IP 与端口号正确、你电脑的防火墙允许传入连接。在 worker 机器用浏览器打开 http://IP:8081/worker-api/v1/hello：看到 405 或 Method Not Allowed 代表连得到。
「管理 Portal 拒絕這台 worker」权杖不对、已经重新产生，或 worker 被禁用。到 worker 页重新产生权杖或激活。
运行一直是「排队中」worker 页看它是不是「在线」；有头模式的任务只给能显示窗口的 worker；场景要用的浏览器在 worker 机器要下载过（重跑安装脚本）。
运行失败「判定失聯」worker 超过一分钟没有回报（关机、断网、程序被关掉）。那次运行不会自动重跑，因为可能已经在网站上做了部分操作；确认后再重新运行。
worker 页标出「版本不同」两台都 git pull 到同一个版本，worker 机器重跑安装脚本后重新启动 rpa worker。
只想暂时不用 workerworker 页按「禁用」，或在 worker 机器按 Ctrl+C；默认运行位置改回本机。
