本机从零运行

一条命令，从一台没装过开发工具的电脑，到 CLI、测试与文档站都跑通。macOS、Linux、Windows 都适用；第一次大约十分钟，多半在等下载。

「能运行」指的是：rpa 命令可以运行（目前有 rpa validate、rpa schema、rpa run 与 rpa serve）、全部测试通过、Playwright 能启动 Chromium 与 Firefox、文档站能在浏览器打开。录制场景等功能会在后续里程碑加入，见路线图。

macOS、Linux

在「终端」运行
# 还没下载代码：下载到 ~/code/web_browser_robotic_process_automation 并安装
curl -LsSf https://raw.githubusercontent.com/DevopsLeaDevops/web_browser_robotic_process_automation/main/scripts/setup.sh | bash

# 已经 clone 了：在项目文件夹里运行
./scripts/setup.sh

Windows

在 PowerShell 运行
# 还没下载代码：先下载脚本，再运行；代码会下载到 %USERPROFILE%\code\web_browser_robotic_process_automation
irm https://raw.githubusercontent.com/DevopsLeaDevops/web_browser_robotic_process_automation/main/scripts/setup.ps1 -OutFile $env:TEMP\rpa-setup.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\rpa-setup.ps1

# 已经 clone 了：在项目文件夹里运行
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1

运行前要有什么

macOS
什么都不用先装。没有 Git 时，脚本会叫出「命令行开发者工具」的安装窗口，装完再运行一次同一条命令。
Linux
需要 Git，以及 curl 或 wget。浏览器缺系统函数库时，脚本会用 sudo 自动安装（限 Debian、Ubuntu）。
Windows
Windows 10 以上，内置的 PowerShell 5.1 即可。没有 Git 时，脚本会用 winget 安装。
网络
需要连得到 GitHub、astral.sh（uv）、PyPI 与 Playwright 的浏览器下载站。公司网络见常见问题。
磁盘空间
预留约 1.5 GB，给 Python、包、Chromium 与 Firefox。
不需要
Python、Homebrew、Node.js 都不用自己装。Python 由 uv 下载，不会动到系统的 Python。

运行前想先看脚本

  • 脚本在仓库的 scripts/setup.sh 与 scripts/setup.ps1，开头有完整说明。
  • 习惯先看再跑：把命令里的网址贴到浏览器打开，或先 git clone 再运行项目里的那一份。Windows 的命令本来就是先下载成文件，可以打开看过再运行第二行。
  • 脚本只会在你的家目录安装 uv 与 Python、在项目文件夹创建 .venv、下载 Chromium 与 Firefox；需要系统权限的只有安装 Git（macOS、Windows）与 Linux 的浏览器函数库，都会先询问。
  • 重复运行是安全的：已经完成的步骤会很快跳过，所以失败后修正问题，重跑同一条命令即可。

脚本做了什么

两个平台的步骤相同
步骤做什么已经完成时
1. 检查系统确认操作系统与 CPU 架构。Apple 芯片的 Mac 在 Rosetta 下运行时会提醒。每次都检查
2. 准备代码在项目里运行就用这一份；否则用 git clone 下载到默认位置或 --dir 指定的位置。已经下载过就直接使用，不会自动 git pull
3. 准备 uv没有就用官方安装脚本安装；版本低于 pyproject.toml 的 required-version 时尝试升级。版本够新就跳过
4. 安装 Python 与依赖uv sync：依 .python-version 准备 Python 3.13，创建 .venv，依 uv.lock 的版本安装全部包与开发工具。没有变动时几秒内结束
5. 安装浏览器uv run playwright install chromium firefox，再实际启动一次。Linux 缺系统函数库时运行 playwright install-deps。已下载就跳过下载，只做启动检查
6. 安装提交前检查uv run pre-commit install，之后每次 git commit 前自动跑 ruff、pyright 与文档检查。重新写入同一个 hook，不影响
7. 确认能运行运行 rpa --version，再设置 RPA_REQUIRE_BROWSER=1 跑全部测试：跟 CI 一样，缺浏览器直接失败而不是略过。每次都跑

选项

macOS、LinuxWindows作用
--dir <路径>-Dir <路径>还没有代码时下载到哪里。也可以用环境变量 RPA_DIR。在项目文件夹里运行时没有作用。
--skip-browser-SkipBrowser不下载浏览器，需要浏览器的测试会略过。连不到浏览器下载站时，先用它把其他部分跑通。
--skip-tests-SkipTests只安装，不跑测试。
--no-hooks-NoHooks不安装提交前检查。
--helpGet-Help .\scripts\setup.ps1 -Detailed显示说明。

从零开始的命令也可以带选项：

# macOS、Linux：选项放在 bash -s -- 后面
curl -LsSf https://raw.githubusercontent.com/DevopsLeaDevops/web_browser_robotic_process_automation/main/scripts/setup.sh | bash -s -- --skip-browser

# Windows：选项放在 -File 脚本路径后面
powershell -ExecutionPolicy Bypass -File $env:TEMP\rpa-setup.ps1 -SkipBrowser

成功的样子

最后一步印出版本、全部测试只有 passed，接着是「完成」与接下来可以用的命令：

[7/7] 確認能運行
  ✓ rpa 0.1.0（rpa-core 0.1.0）
  $ env RPA_REQUIRE_BROWSER=1 uv run pytest
…
============================= 46 passed in 2.91s ==============================
  ✓ 全部測試通過

完成！本機環境已經可以運行。

接下來在專案資料夾裡：
  cd /Users/you/code/web_browser_robotic_process_automation
  uv run rpa -h                               # 命令列工具
  uv run rpa serve                            # 管理 Portal（http://127.0.0.1:8080）
  uv run pytest                               # 跑測試
  open docs/index.html                        # 開啟文檔站
  uv run python -m http.server -d docs 8000   # 或用本機伺服器瀏覽文檔
  • 测试数量会随着代码与文档页面增加，重点是没有 failed、也没有 skipped。
  • 中途失败时，脚本会用 ✗（Windows 是 [X]）标出停在哪一步，以及怎么处理。
  • 以 !（Windows 是 [!]）开头的是提醒，不影响运行，但建议看一下。

之后每次使用

cd ~/code/web_browser_robotic_process_automation
git pull              # 取得最新代码
./scripts/setup.sh    # 依赖、浏览器有变动才会安装，最后重跑测试；Windows 用 scripts\setup.ps1

只想更新依赖、不想跑完整流程时，用 uv sync 即可。其他常用命令见开发环境。

常见问题

看到什么怎么处理
Windows：「因为在此系统上禁止运行脚本」用本页带 -ExecutionPolicy Bypass 的命令运行，只对这一次有效，不需要改系统设置。
Windows：用 irm … | iex 运行，出现「is not recognized」或「Unexpected attribute」改用本页「先下载、再用 -File 运行」的两行命令。脚本存成含 BOM 的 UTF-8，Windows PowerShell 5.1 才不会把中文读成乱码；但 BOM 会留在 irm 下载的字符串里，让 iex 解析失败。
macOS：「請在跳出的視窗按『安裝』」安装命令行开发者工具，完成后再运行同一条命令。不需要安装完整的 Xcode。
「已經存在，而且不是空資料夾」默认位置被其他东西占用。用 --dir（Windows 是 -Dir）指定别的位置；如果那就是项目，进到文件夹里运行 scripts/setup.sh。
「安裝依賴失敗」或「下載瀏覽器失敗」多半是公司网络。设置 UV_INDEX_URL 或 PLAYWRIGHT_DOWNLOAD_HOST 后重跑，见开发环境的常见问题；浏览器暂时下载不了，可以先加 --skip-browser。
Linux：「瀏覽器缺少系統函式庫」脚本会用 sudo 运行 playwright install-deps，需要输入密码。不是 Debian、Ubuntu 时，依错误消息手动安装缺少的函数库。
完成后输入 uv 显示找不到命令脚本刚安装 uv，只对新开的终端窗口生效。开一个新窗口；macOS、Linux 也可以运行 source $HOME/.local/bin/env。
「測試沒有通過」往上找 FAILED 的测试名称与错误。在项目文件夹运行 uv run pytest -x 可以停在第一个失败。
想整个重来删除项目里的 .venv，再运行一次脚本。Mac 特有的问题（Rosetta、xcrun: error 等）见 macOS 本机运行的常见问题。
不想用脚本、或想知道每一步的细节：Mac 的逐步说明见 macOS 本机运行，各平台通用的命令见开发环境。
