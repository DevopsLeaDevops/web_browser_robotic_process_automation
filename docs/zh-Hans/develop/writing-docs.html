文档与 ADR

怎么添加一个文档页面、怎么维持三种语言同步，以及怎么记录架构决策。背景见 ADR 0005 与 ADR 0007。

写作原则

  • 先结论，后细节。页面描述一句话讲清楚这页在说什么。
  • 一个面板一个主题。面板标题就是读者会扫的目录。
  • 用对组件。比较用表格，定义用规格清单，要点用重点清单，提醒用提示框。
  • 状态要有文字。不能只靠颜色表达状态。
  • 不重复。同一件事只在一个地方详细说明，其他地方连过去。

添加页面

  1. 先写繁中版：拷贝同一目录下现有的页面，保留 <head> 与 <body> 的属性。
  2. 修改 data-page（页面 id）与 data-root（回到该语言根目录的相对路径，例如 ../）。
  3. 在 docs/assets/nav.js 登记页面，名称同时写 "zh-Hant" 与 "en"。
  4. 在 docs/en/ 相同路径写英文版，见下方三种语言。
  5. 运行 uv run python tools/i18n.py sync 产生简中，再运行 uv run pytest tests/docs tests/i18n。

页面模板

以 docs/design/ 下的页面为例
<!doctype html>
<html lang="zh-Hant">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>页面名称 · 浏览器 RPA 工程文档</title>
<link rel="stylesheet" href="../../design-system/assets/portal.css">
<link rel="stylesheet" href="../../assets/docs.css">
<script defer src="../../assets/nav.js"></script>
<script defer src="../../assets/docs-shell.js"></script>
</head>
<body data-page="頁面-id" data-root="../">
<main id="main">
  <div class="heading"><div><h1>页面名称</h1><p>一句话说明</p></div></div>
  <div class="stack">
    <section class="panel">
      <div class="panel-header"><h2>面板标题</h2></div>
      <div class="panel-body">内容</div>
    </section>
  </div>
</main>
</body>
</html>

可用组件

来自 portal.css 与 docs.css
组件class适合
面板panel、panel-header、panel-body每个主题一个
版面stack、two-col、four-col、grid面板的排列；窄屏幕自动变单栏
规格清单spec-list（dl）名词与定义、设置值
重点清单points（ul）三到六个要点
表格table-scroll 包住 table.wrap多个项目的比较
提示框notice、notice warn、notice success需要特别注意的事
状态标签badge blue | green | amber | red状态，必须含文字
代码区块pre.source命令与示例；HTML 要跳脱 < 与 >

三种语言

繁中、英文由人维护，简中自动产生

目录与规则

  • 繁中在 docs/，英文在 docs/en/，简中在 docs/zh-Hans/；三个目录的文件名、结构与锚点（id）完全相同。
  • 英文页的 lang="en"，共用资源多回一层，例如 ../../assets/docs.css；data-root 仍是回到 docs/en/ 的路径。
  • 页面之间的链接只连同语言的页面；切换语言由页眉处理。
  • docs/zh-Hans/ 与 nav.js 的 "zh-Hans" 是产生的，不要手改；用词不对就加到 tools/zh-Hans-overrides.json。
  • 程序实际印出的繁中消息（例如一键安装脚本的输出），加上 translate="no"，产生简中时保留原文。

修改繁中页面之后

# 1. 依修改内容更新 docs/en/ 的同一页
# 2. 记下英文版对照的是哪个繁中版本
uv run python tools/i18n.py stamp docs/en/develop/setup.html

# 3. 重新产生简中（提交前检查也会自动运行）
uv run python tools/i18n.py sync

# 只检查不写入
uv run python tools/i18n.py check

繁中改了而英文没有重新 stamp，测试会失败并指出是哪一页。只改错字、英文不受影响时，直接 stamp 即可。

添加 ADR

什么时候写

  • 选择会影响多个包或很难反悔。
  • 有两个以上合理的方案，而且需要让后来的人知道为什么选这个。
  • 推翻或修改既有的 ADR。

怎么写

  • 拷贝最近一份 ADR，文件名 NNNN-英文短名.html，编号递增。
  • 固定段落：日期、影响范围、背景、决策、后果（好处与代价）、没有选的方案。
  • 新 ADR 先标「提议中」，在 PR 中讨论，合并时改为「已接受」。
  • 更新 adr/index.html 与 nav.js，并照三种语言的规则提供英文版。
  • 取代旧决策时，旧 ADR 改为「已取代」并连到新的 ADR，内容不删。
