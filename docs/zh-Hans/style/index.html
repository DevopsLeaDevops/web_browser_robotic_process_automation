必守規則

  • 緊湊資訊密度。不用大橫幅、插畫或大量留白；重複的標題只保留一次。
  • 狀態要有文字。不能只用圖示或色點。
  • 鍵盤可操作。焦點框清楚；對話框可用 Esc 關閉。
  • 三種尺寸驗收。1440×900、1280×720、390×844，不得出現整頁水平捲動。
  • 不另造導覽。新頁面一律放進兩級 Portal。

v1.1 補充的規則

2026-10-13 · 範例見設計系統的「編輯與摘要」
  • 卡片網格與卡片連結。卡片每張至少 272px（card-grid），1440 寬一列 4 張；卡片等高，同一列的截圖、連結與按鈕對齊。連結固定一列、11px、分隔線上下貫通，依文字長短分配寬度，真的放不下才以 … 結尾（card-links even）。
  • 第二級選單名稱不換行。太長時以 … 結尾，完整名稱放在 title。
  • 重點突出。面板標題 14px／650，項目數放在標題旁（h2 .count），右側說明 12px 或操作按鈕；連結做的按鈕用主要文字色；摘要用鍵值格（kv-grid，4 欄），重點數字放進結果數字列（result-strip）。
  • 同一份資料兩種檢視。表格內直接編輯（edit-table，一列一筆、補充欄位在下一列）與原文編輯；切換時先校驗，不悄悄丟掉修改。原文編輯器右側是固定寬度的參考欄，點名稱插入（editor-layout、chip-btn）。
  • 不撐開整頁。長內容的表格欄位換行（table.wrap）、程式碼在框內捲動（code-view）。

收錄時發現的缺口
  • 設計變數不完整。tokens.json 沒有成功、警告、錯誤與選取背景色；這些只出現在 portal.css。
  • 選取背景色不一致。設計系統的色彩頁寫 #eaf3ff，portal.css 實際使用 #eaf4ff。
  • 步驟編輯器細節。已有流程畫布與節點樣式，但沒有拖拽、定位器候選切換、校驗錯誤標示的狀態。
  • 執行詳情。逐步日誌、截圖回放與 Trace 連結的版面。
  • YAML 編輯器。已有 code-editor 基礎樣式，需確認語法高亮與錯誤行標示。
  • 圖示。目前只有一個通用圖示，選單與動作需要一套圖示。
  • 深色模式。目前沒有，需確認是否需要。
  • 三種語言的版面。設計包以繁中設計；英文通常較長，原型要用英文與簡中各檢查一次，見 ADR 0007。
