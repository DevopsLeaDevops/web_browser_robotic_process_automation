一句话说明

以「场景」为内核资产：一段可重复运行的浏览器操作流程，用声明式 DSL 描述。平台负责把场景生成出来（录制、自然语言、模板），管理起来（版本、参数、权限），运行它（Playwright），再把结果反馈给用户（截图、Trace、失败定位）。

产品定位

要解决什么问题、内核概念、生成到反馈的闭环。

场景 DSL

声明式 DSL 与场景契约：入参、出参、独立断言，以及每个字段与动作的规格。

管理 Portal

页面与流程、版本与发布门槛、数据模型、API 与背景 worker。

系统架构

组件、数据流与目录结构，以及每个包的职责。

技术选型

每一层的选择、备选方案与理由。

多用户与内部系统

认证、权限、Secrets、审核，以及内部系统带来的限制。

界面风格

界面设计系统 v1.0：两级 Portal、蓝色主色、紧凑信息密度。

MVP 原型

场景管理、录制与调试、报告、自由试验场的脱机交互原型，以及真实运行的示例。

建议阅读顺序

第一次接触本工程
  1. 产品定位：先理解「场景」这个核心概念。
  2. 系统架构：看懂组件之间怎么协作。
  3. 决策索引：了解几个关键决定的来龙去脉。
  4. 路线图：知道现在在哪一步、下一步做什么。
  5. 本机从零运行（一条命令装好环境）、开发环境与开发规范：开始动手。

仓库现况

M3 进行中
rpa-core
场景 DSL 与场景契约的模型、YAML 加载与校验；示例在 scenarios/
rpa-runner
运行引擎：入参校验、在 Chromium 或 Firefox 中运行步骤、独立断言、出参发布、运行报告
rpa-worker
背景 worker：领取任务、以子进程运行、取消；不依赖数据库
rpa-server
管理 Portal：FastAPI 的 API 与 Jinja 页面、SQLite、版本与发布门槛、运行队列
rpa-cli
rpa serve 启动管理 Portal；rpa run 运行场景；rpa validate 校验场景并指出行号、步骤与字段，rpa schema 输出 DSL 或单一场景入参、出参的 JSON Schema；--lang 切换繁中、简中、英文
工具链
uv（依赖以 uv.lock 锁定）、ruff、pyright（strict）、pytest、pre-commit
CI
静态检查，Python 3.12 / 3.13 测试，含 Chromium 冒烟测试；一键安装脚本每周在 macOS、Ubuntu、Windows 实际运行
文档
本站，繁中、简中、英文三种语言，含链接与翻译同步的自动检查
