一句话说明

以「场景」为内核资产：一段可重复运行的浏览器操作流程，用声明式 DSL 描述。平台负责把场景生成出来（录制、自然语言、模板），管理起来（版本、参数、权限），运行它（Playwright），再把结果反馈给用户（报告、截图、录像回看、失败定位）。

产品定位

要解决什么问题、内核概念、生成到反馈的闭环。

场景 DSL

声明式 DSL 与场景契约：入参、出参、独立断言，以及每个字段与动作的规格。

管理 Portal

页面与流程、版本与发布门槛、数据模型、API 与背景 worker。

系统架构

组件、数据流与目录结构，以及每个包的职责。

技术选型

每一层的选择、备选方案与理由。

多用户与内部系统

认证、权限、Secrets、审核，以及内部系统带来的限制。

桌面端分发

服务器、录制端与 Worker 的安装、配对、发布，以及服务器把更新分发给设备。

对外 Agent API

第三方 Agent 系统经由 API 创建、调试、验证与运行场景，并取得运行过程。

界面风格

界面设计系统 v1.1：两级 Portal、蓝色主色、紧凑信息密度。

MVP 原型

场景管理、录制与调试、报告、自由试验场的脱机交互原型，以及真实运行的示例。

建议阅读顺序

第一次接触本工程
  1. 产品定位：先理解「场景」这个核心概念。
  2. 系统架构：看懂组件之间怎么协作。
  3. 决策索引：了解几个关键决定的来龙去脉。
  4. 路线图：知道现在在哪一步、下一步做什么。
  5. 本机从零运行（一条命令装好环境）、开发环境与开发规范：开始动手。

仓库现况

main a26b929（2026-10-28）
rpa-core
场景 DSL 与场景契约的模型、YAML 加载与校验、录制稿转 DSL 草稿；iframe、新分页、上传文件的写法（M7a～M7c）；领域文件夹与组合场景的格式；示例在 scenarios/
rpa-runner
运行引擎：入参校验（含文件入参）、登录检查、在 Chromium 或 Firefox 中运行步骤、独立断言、出参发布、运行报告与录像；录制、人工登录与逐步调试的子进程
rpa-worker
背景 worker：领取任务、以子进程运行、取消；不依赖数据库。也可以在另一台电脑当远程 worker，经由管理 Portal 的 Worker API 领取（M9a）；配对、录制端的本机闸道与交互子进程（M10）
rpa-server
管理 Portal：FastAPI 的 API 与 Jinja 页面、SQLite、版本与发布门槛、运行队列、登录角色与 Secrets、录制、逐步调试、组合场景与项目空间、设备与邀请、领域文件夹与 git 同步、运行回看、上传文件区、对外 Agent API（/agent-api/v1），以及把更新分发给设备
rpa-update
热更新：更新档的清单、Ed25519 签章验证、环境代号、程序层的安装与选层、桌面 App 的启动器；只用标准函数库（ADR 0018）
rpa-desktop
RPA 录制端（macOS）与 RPA Worker（Windows、macOS）两个桌面 App：pywebview 窗口、配对、下载浏览器、通知区或菜单栏、打包后的入口（桌面端分发）
rpa-cli
rpa serve 启动管理 Portal（--worker-port 开放给设备）；rpa worker、rpa recorder 让这台电脑当远程 worker 或录制端；rpa run 运行场景；rpa record 录制并转成场景草稿；rpa validate 校验场景并指出行号、步骤与字段，rpa pack check 校验领域文件夹，rpa schema 输出 DSL 或单一场景入参、出参的 JSON Schema；rpa update 用更新档升级服务器分发包；--lang 切换繁中、简中、英文
工具链
uv（依赖以 uv.lock 锁定）、ruff、pyright（strict）、pytest、pre-commit
CI
PR 与合并时依生产角色分配测试：Linux 测网站、Windows 测 Worker、macOS 测录制端 App；依层建置，同一组输入只验证一次、外壳没变不重新打包；每天凌晨在三个系统跑全部测试，浏览器测试连跑三遍。触发节点、时间、手动触发与耗时记录见 CI 与流水线
