ADR 0003：以 PostgreSQL 作为任务队列

运行任务与调度直接存放在 PostgreSQL，不另外引入 Redis。

已接受
日期
2026-10-09
影响范围
rpa-server、rpa-worker、部署（M7、M9）
相关
系统架构

背景

多用户共用需要多个 worker 并发运行、定时调度、失败重试。平台本来就需要 PostgreSQL 存放场景与运行记录。

RPA 的瓶颈在浏览器本身：一次运行通常是数秒到数分钟，任务量是每分钟数十到数百笔，而不是每秒数千笔。

决策

  • 使用 Procrastinate：以 PostgreSQL 为后端、原生 asyncio 的任务队列，支持定时任务。
  • 创建运行记录与入列任务放在同一个数据库事务里，不会出现有记录没任务的情况。
  • worker 通过一层薄接口调用队列，必要时可替换实现。

后果

好处

  • 部署少一个组件，备份与监控只需顾好 PostgreSQL。
  • 任务与运行记录的一致性由事务保证。
  • 与 Playwright async 运行模型兼容。

代价

  • 吞吐量上限低于专用消息队列；以本工程的规模足够。
  • 依赖单一函数库，因此保留替换接口。

没有选的方案

方案为什么不选
Celery + Redis成熟但多一个组件，asyncio 支持较弱。
arq（Redis）asyncio 原生，但同样需要 Redis。
自行实现 SKIP LOCKED 队列可行，但重试、调度、监控都要自己写。
