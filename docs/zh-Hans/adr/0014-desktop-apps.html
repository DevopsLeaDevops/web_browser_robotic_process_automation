ADR 0014：录制端与 Worker 以桌面 App 分发，壳内沿用现有网页

服务器与数据库部署在一台电脑，录制者与运行机各自安装一个桌面 App 就能用。App 是 pywebview 壳＋服务器现有的 Jinja 页面；录制、逐步调试、人工登录的浏览器改开在操作的那台电脑。

已接受
日期
2026-10-15（提议）；2026-10-16（接受）
影响范围
新包 rpa-desktop；rpa-runner（子进程命令）、rpa-server（设备、邀请、对外端口、交互子进程）、rpa-worker（版本信息）；CI 与发布（M10 起）
相关
延伸 ADR 0012（对外端口与权杖）；ADR 0011（只用 Python、服务器渲染页面）；ADR 0010；桌面端分发。编号 0013 保留未用。

背景

服务器与数据库之后会部署在固定的电脑（先在用户自己的电脑调试，再搬到正式环境）。录制者与运行机目前都要装 uv、git、Python 并跑安装脚本，版本也要手动对齐；用户希望像 Claude Desktop 一样，拿到一个安装档就能用。

更根本的限制是：录制、逐步调试、人工登录的浏览器都开在运行 Portal 的那台电脑（M4 的设计，ADR 0012 也维持）。服务器搬走以后，录制者在自己的电脑上什么都开不了。管理页面又没有登录（M8 才有），不能整个开放给区网。

Claude Desktop 是 Electron 应用：壳里带一个 Chromium，主要界面是网页。我们的界面本来就是服务器渲染的网页，壳只需要一个能加载网址的窗口。

决策

  • 两个 App，同一份代码。「RPA 录制端」与「RPA Worker」都在 apps/desktop（包 rpa-desktop），各自一份建置设置。MVP 交付录制端 macOS（Apple 芯片）与 Worker Windows（x64）；其他组合保留方案。
  • 壳用 pywebview。macOS 用系统的 WKWebView、Windows 用 WebView2，不另带浏览器。录制端的窗口加载服务器现有的 Portal 页面，模板不分两套；App 自己的少数页面（配对、下载浏览器、状态）也用设计系统的 HTML。
  • 邀请配对。Portal 的「设备」页产生一次性邀请（24 小时内有效、只能用一次、限定是哪个 App）；App 用邀请换到设备权杖，存在系统钥匙串或 Windows 认证管理员。
  • 对外端口多两种用途。rpa serve --worker-port 的端口除了 Worker API，也提供 Client API（配对、交互子进程）与 Portal 页面；Portal 页面只接受录制端的设备权杖，没有就拒绝。127.0.0.1:8080 的本机用法不变。
  • 交互子进程在操作的那台运行。服务器多一层子进程主机：请求从录制端进来时，录制、逐步调试、人工登录的子进程交给那台录制端运行，输出与文件传回；从本机浏览器进来时照旧在服务器运行。转换、遮罩、版本与发布门槛仍在服务器。
  • 子进程命令集中。所有 sys.executable -m … 改由 rpa_runner.commands 产生；打包后改走 App 自己的入口。
  • 浏览器第一次启动时下载。用 App 内附的 Playwright driver 下载，版本必定相符；可以设置内部镜像。
  • MVP 不签章。macOS 只有 ad-hoc 签章、Windows 没有代码签章；文档说明第一次打开要怎么允许。之后有账号再加签章与公证。

后果

好处

  • 录制者与运行机不需要 uv、git、Python；粘贴邀请、下载浏览器就能用。
  • 录制的浏览器开在录制者自己的电脑，服务器可以放在任何地方（包括没有屏幕的正式环境）。
  • 界面只有一套：Portal 页面的修改，录制端立即看到；工程仍然只有 Python。
  • Worker 沿用 M9a 的 Worker API 与 runner，没有第二套运行逻辑。
  • 没配对的电脑打开对外端口看不到管理页面，是 M8 之前最小的访问控制。

代价

  • 多一个 CI 构建流程（macOS、Windows），每次发布要附两个安装档；App 与服务器版本要对齐。
  • 没有签章时，第一次打开要手动允许（macOS「隐私权与安全性」、Windows SmartScreen）。
  • 录制、调试要经过网络传输输出与截图；设备权杖、Secrets 与登录状态在 HTTP 下是明文，只适合信任的区网（同 ADR 0012）。
  • 打包后的 Python 脚本场景只能 import 标准函数库与 App 内附的包（2026-10-29 修订：只对兼容模式成立；运行环境模式的 Python 节点用 App 附带的 RPA Python 运行环境，见 ADR 0020）。
  • 系统 WebView 依赖操作系统版本：Windows 要有 WebView2（Windows 11 内置），macOS 依系统的 Safari 内核。

没有选的方案

方案为什么不选
Electron 壳＋Python 子进程（Claude Desktop 的做法）生态完整（自动更新、签章工具），但要多一套 Node／TypeScript 工具链与第二个 Chromium；壳只负责开窗口，换成本小，之后需要时可以替换。
Tauri 壳安装档最小，但要 Rust 工具链；理由同上。
不做壳，用系统浏览器开 Portal，背景跑一个程序看起来不像一个 App；权杖要放进浏览器 Cookie，换浏览器就失效。
一个 App，邀请决定角色建置只有一份，但用户选了两个 App：名称与安装对象清楚，Worker 机器上不会出现录制功能。
安装档内含浏览器脱机可用，但安装档多 150 MB 以上，macOS 之后公证也较麻烦；保留为脱机方案。
整个 Portal 开放给区网没有登录（M8），区网上的人都能操作（ADR 0012 已排除）。
远程画面实时传输（录制时看服务器那台的浏览器）操作延迟高、要另做串流组件，服务器还是要有图形界面。
PyInstaller 单档（onefile）每次启动都要解压上百 MB，也较容易被杀毒误判；改用文件夹（onedir）加安装档。
