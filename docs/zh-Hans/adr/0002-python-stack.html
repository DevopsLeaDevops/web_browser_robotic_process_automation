ADR 0002：后端、运行与工具链采用 Python 技术栈

除了 Web 前端，所有组件都用 Python，放在同一个 uv workspace。

已接受
日期
2026-10-09
影响范围
所有 Python 包、CI、开发环境
相关
技术选型、ADR 0004

背景

团队的主力语言是 Python。平台需要浏览器自动化、数据模型校验、Web API 与 AI 集成，这些在 Python 都有成熟方案。

决策

  • 浏览器：Playwright for Python，运行引擎使用 async API。
  • 模型：Pydantic v2，DSL 与 API 共用同一套模型。
  • API：FastAPI；数据库：SQLAlchemy 2.0 + Alembic。
  • 工程：uv workspace 单仓多包；ruff、pyright strict、pytest。
  • 最低版本 Python 3.12。

后果

好处

  • 团队熟悉，review 与维护成本低。
  • DSL 模型从校验、API 到 AI 生成一路共用。
  • AI 与数据处理生态完整。

代价

  • 前端无法直接共用 Python 类型，改由 OpenAPI 与 JSON Schema 生成 TypeScript 类型。
  • Playwright 原生语言是 TypeScript，部分新功能可能稍晚出现在 Python 版。

没有选的方案

方案为什么不选
TypeScript 全端类型可前后端共用，但团队主力不是 TypeScript。
Python + Selenium缺少自动等待、语意化定位与 Trace，稳定性较差。
poetry 管理依赖可行，但 uv 更快且原生支持 workspace。
