ADR 0016：运行时录像，回看时靠同一个时钟把视频和步骤对上

验证与运行的自动化阶段用 Playwright 录像，存在运行目录；步骤记下开始与结束的实际时间，回看页用它们在视频上定位。缩略图在看视频的浏览器里产生。

已接受
日期
2026-10-20
影响范围
rpa-runner、rpa-worker、rpa-server（M12 起）
相关
ADR 0009（运行目录）、ADR 0012（远程 worker 上传运行目录）；M11 的 D4（运行记录不进 git）；管理 Portal › 运行 › 录像

背景

运行失败时，报告只有最后一张截图、步骤的结果与日志，看不出失败前画面发生了什么；运行多半在另一台 Worker 上跑，无头模式更是什么都看不到。用户要求（2026-10-20）：验证与运行时录像，有头、无头都要；运行结束后在运行记录回看；回看是之后很常用的独立功能，要能暂停、拖曳、用缩略图找到当时的画面，并且和步骤关联，还原运行现场。

Playwright 本身就能录像：浏览器把每一格画面和它出现的实际时间交给 Playwright，用它自带的 ffmpeg 编成 WebM。

决策

  1. 录什么。DSL 场景的自动化阶段，用 BrowserContext 的录像，有头、无头都录；画面跟页面一样大，宽度最多 1280（等比例缩小）。登录检查、逐步调试、录制与 Python 脚本场景不录。
  2. 怎么对上步骤。Playwright 依每一格的实际时间编码，视频的第 t 秒＝录像开始时间＋t；开始时间在 WebM 标头（DateUTC，毫秒）。steps.json 每一步记下 startedAt、endedAt（UTC、毫秒）与步骤后的网址。两边是同一台电脑的同一个时钟，相减就是步骤在视频里的位置。标头没有开始时间时（旧版 Playwright），用开页面的时间。
  3. 怎么收尾。子进程结束前先关 BrowserContext，Playwright 这时把视频写完；父进程把它整理成 video.webm 与 video.json（开始时间、长度、大小、是否修复过）。被终止时（取消、超过总期限）：Linux 与 macOS 上 Playwright 把 ffmpeg 放在自己的进程组，不会被一起结束，自己收尾；Windows 的 taskkill /T 会连 ffmpeg 一起结束，所以录像时先列出子孙，结束 ffmpeg 以外的全部，等 ffmpeg 收尾。还是没有长度与索引的视频，用 Playwright 自带的 ffmpeg 重新封装（不重新编码）。
  4. 存在哪里。运行目录（远程 worker 照旧上传整个目录）；数据库的 runs 记下长度、大小、钉选与删除的时间与原因。视频不进领域文件夹，也不进 git。
  5. 留多久。服务器设置，默认全部录；通过的运行保留 7 天，失败、超时、取消、需要登录的保留 30 天；全部最多 20 GB，超过从最旧的删起；钉选的不删。清理只删视频，运行记录、报告、截图都留着，run.json 记下删除的时间与原因。
  6. 怎么回看。回看页直接播放运行目录的视频（支持 Range、可缓存）。缩略图在看视频的浏览器里产生：另开一个看不见的 video 跳到各时间点、画到 canvas；Linux 服务器上没有浏览器，也没有 ffmpeg。

后果

  • 每分钟约 1～3 MB（1280 宽；画面静止时更小）。保留规则与总量上限控制磁盘用量。
  • Worker 多一个实时编码的 ffmpeg（VP9，Playwright 依画面大小调整线程与比特率）。
  • 视频会留下画面上的一切，包括业务数据与填在一般字段里的值。用户同意保存（2026-10-20，D3）；M8 之前能开管理 Portal 的人都看得到。
  • 录像时取消，要多等几秒让 ffmpeg 收尾（最多 8 秒）。取消时停止操作的时机不变。
  • 浏览器要能播 WebM VP9：Chrome、Edge、Firefox 可以；macOS 的 Safari 与录制端 App（WKWebView）要人工验收。
  • 被强制终止的视频只录到最后一次画面变化，之后的等待没有画面；回看页把超出视频的步骤接在最后一格。

没有选的方案

方案为什么不选
Playwright Trace文件大，要另外开 Trace Viewer；用户要的是视频播放、拖曳与缩略图。
每一步截图多一次浏览器来回，改变步骤的时间；看不到步骤之间发生的事。
Playwright 的 showActions（在视频上标出点击位置）在页面注入标注，而且每个操作前多等 500 ms，改变运行本身。步骤由回看页显示。
服务器端产生缩略图Linux 服务器没有浏览器与 ffmpeg；另加影音包会增加脱机安装的负担。
自己接收每一格画面再编码Playwright 已经依实际时间编码；自己做要重复编码，被终止时也一样要处理。
