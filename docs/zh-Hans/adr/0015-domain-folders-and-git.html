ADR 0015：场景与组合场景放在领域文件夹，经由 git 在服务器之间同步

每个领域一个自给自足的文件夹（说明档＋不可变的版本＋验证与发布记录）；数据库只是索引。领域文件夹可以和 git 仓库里的一个目录同步，让分散录制、多人验证、分散使用的服务器共用同一份定义，而登录状态、Secrets 与运行记录留在各自的服务器。

背景

M10 之前场景版本放在文件夹的 scenes/<场景>/<n>/，版本状态、验证结果、发布与组合场景的定义都只在 SQLite 里。一台服务器没有问题，但营运是分布式的多人协作：分散录制、多人验证后发布、分散使用。两台服务器之间没有办法交换场景，也看不到对方的验证结果；组合场景用到另一个业务领域的场景时，没有地方说明它依赖什么。

用户希望场景与组合场景能像代码一样放进第三方仓库，每个领域可以单独加载，新的服务器只拉自己需要的领域就能录制、调试、运行。

决策

  • 领域文件夹。domains/<领域>/ 有 pack.yaml（名称、说明、依赖的领域与它们的来源）、scenes/、roles/、composites/。场景与组合场景同一套规则：说明档＋不可变的版本目录＋版本说明档（哈希）＋验证记录。格式在 rpa_core.pack，rpa pack check 不开 Portal 也能校验。
  • 数据库是索引。启动、拉取、按「重新加载」时依文件夹重建；只在数据库的是每台自己的设置（网址覆写、排序、数据源、同步状态）。
  • 验证与发布记录进文件夹（D3）。每次验证写一份记录（谁、哪台服务器、哪台 worker、结果、哈希；组合场景另记每个节点跑的场景版本），发布写在 scene.yaml／composite.yaml。发布门槛是「文件夹里有一份哈希相符的通过记录」，不管是哪台服务器验证的。
  • 运行记录不进文件夹（D4）。报告、截图留在服务器的 runs/、workflow-runs/，另写 run.json 给之后的回看。
  • git 同步只在服务器（D5、D6）。每个领域可以设置仓库、分支、目录与认证（公开仓库、HTTPS 权杖、Portal 产生的 SSH 部署密钥）。拉取与推送以文件为单位三方合并（上次同步、本机、远程）；同一个文件两边改成不同内容才是冲突，停下来三选一（取消、推送到新分支、以远程为准并先备份），永远不强推。内容哈希相同的版本视为同一个版本。
  • 代号全域唯一（D8）。DSL、角色与组合场景的引用方式不变；跨领域的依赖记在组合场景版本的 requires（领域、场景、版本、哈希）与 pack.yaml，缺的时候页面提示怎么补（从 git 添加、拉取、重新保存）。
  • 机密不离开服务器（D9）。Secrets 的值、登录状态、网址覆写、git 权杖与私钥只在服务器的文件夹；推送前挡下看起来像机密的文件名与含有 Secret 值的内容。
  • 升级自动迁移（D7）。先备份到 backups/，再把旧的版本目录、数据库里的验证、发布与组合场景搬进领域文件夹。

后果

好处

  • 场景、组合场景与它们的验证、发布历史可以用 git 审阅、回溯，放在公司自己的仓库。
  • 任何一台服务器的通过记录都能当发布依据，「甲验证、乙发布」不必重跑。
  • 新服务器只设置需要的领域就能用；录制端与 worker 不变（任务自带文件）。
  • 在文件夹外面改了已存在的版本，哈希对不上，那个版本不能运行也不能发布。

代价

  • 多了文件夹与数据库两份状态：文件夹是真相，数据库要在加载时对齐；在外面改文件要按「重新加载」（D10，不监看）。
  • 同一个场景同时在两台服务器创建同号版本或同时发布会冲突，要人决定；建议同一个场景同时只在一台编辑。
  • 服务器需要 git 2.25 以上；推送需要仓库的写入权限（权杖或部署密钥）。
  • MVP 的取舍：工作副本取回整个分支的对象，不做只取设置目录的部分拷贝（仓库很大时才有差）；同步进行中，同一个领域的第二个 git 操作直接回「正在同步」，Portal 的保存不排队，改在应用前确认文件夹没被改过、改过就请用户重试。

没有选的方案

方案为什么不选
数据库之间同步（导出入或复写）看不到历史、不能审阅，也不能只取一个领域；SQLite 不适合多台写入。
发布状态只在各自的服务器（不进 git）原本的建议；用户要求发布状态要记录，因为多人验证后发布、分散使用（D3）。
每次保存都提交提交会非常碎，推送也要等网络；改成「本机变更＝文件夹和上次同步的差异」，推送时一次提交。
自动合并同一个文件的内容版本与发布的 YAML 合并错了会让发布门槛失效；版本目录不可变、验证记录一次一个文件，冲突本来就少，交给人决定。
稀疏工作副本＋rebase原本的设计；改成裸仓库＋git 底层命令只换掉设置的目录，不需要工作目录，结果和 rebase 一样，也不会动到仓库的其他目录。
录制端与 worker 也做 git凭证要散到每台电脑；任务本来就带着版本文件过去（M9a、M10），不必改协定。
