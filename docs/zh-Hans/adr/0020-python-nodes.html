ADR 0020：Python 脚本场景演进成 Python 节点，和浏览器场景串在组合场景里

不另开新的场景种类：现有的 script: 加上 runtime，就跑在平台建置的 RPA Python 运行环境、不开浏览器；没写 runtime 的照旧运行。组合场景的节点可以是浏览器场景，也可以是 Python 节点，数据以 array／object 出入参传递，文件经由同一台 Worker 上的共用工作文件夹传递。

背景

浏览器场景做不到的事很多：读写 Excel、合并文件、整理数据、调用 API、建模型。M1.1 起有「Python 脚本场景」（script: { automation, assertion }），但打包后的 App 用自己内附的 Python 运行它，只有标准函数库与 App 带的包，派工也一律当成要开浏览器。

10-24 的第二版设计打算封存它、另开一种 python: 场景。10-29 查证后发现：脚本场景的契约本来就不依赖浏览器（Runner 交 input.json、收 facts.json 与候选出参）；组合场景的节点只记「场景＋固定版本＋入参绑定」，不分种类；同一次组合运行本来就固定在同一台 Worker。缺的是包、派工、结构化入参与文件的传递。

决策

  • 一种节点、两种模式。script.runtime 没写是兼容模式，和以前完全相同（哈希不变、可以自己开浏览器）；写了 "1" 是运行环境模式：用 RPA Python 运行环境 1，不能写 browser、login，断言可以是 assertion.py 或 DSL 的 verify（用 verify 时出参写 from），可以有 file 入参。两种模式都可以写 files（脚本会用到的其他文字档，纳入哈希）与 platforms。
  • RPA Python 运行环境。平台建置、测试的一套 Python 3.13 加固定的包，CI 为每个平台建好，附在 Worker App 与 Linux 分发包；第一次用到时解压到缓存文件夹、自我检查后沿用。运行时以 -E -s 隔开电脑上的 Python 与 PYTHON* 环境变量。模型包不放进基本版，之后另做选用层（D4）。
  • 派工。运行环境模式的任务只交给回报了这个主版本、平台在 platforms 里的设备，不看浏览器与窗口；没有时运行页说明在等什么。旧版 App 由 M7a 的 features（pythonNodes、jsonInputs）挡下。
  • 组合场景里的数据与文件。入参多 array、object，上游的同类型出参可以直接接；同一次组合运行在那台 Worker 上有一个共用工作文件夹，也是 Python 节点的工作目录，组合运行结束就删，只有声明的产出文件上传（D3）。
  • rpa_script。运行环境模式由 python -m rpa_script 启动：照契约自己读写文件的脚本不用改；用 @automation 的脚本有步骤、事实、产出文件与数据预览，写成和 DSL 相同格式的 steps.json。
  • 运行的 runtime 阶段。入参之后、自动化之前准备运行环境，不算进总期限；result.json 多一个 python（模式、版本、平台、沿用或新解压）。

后果

  • 浏览器场景与 Python 节点在同一个组合场景、同一套入参出参、同一个发布门槛；不需要学另一种模型。
  • 既有的脚本场景不用迁移；ADR 0009「脚本场景不写 verify」只对兼容模式成立。ADR 0014「打包后的脚本只能用 App 内附的包」也只对兼容模式成立。
  • Worker App 与 Linux 分发包多带一个运行环境（压缩后约 60～75 MB），第一次用到时多几秒解压。
  • 没有下载浏览器、没有屏幕的电脑也能当 Python 节点的 Worker。
  • Python 节点不是沙箱：等于在 Worker 上以那位用户的身分运行任意程序，只给信任的人编辑，审核时特别标示。
  • 共用工作文件夹里的中间文件不会留下；要看的文件写到产出文件。远程 Worker 错过了结束通知时，一天后在上线时清掉。
  • 之后（P3）：模型包的选用层、脚本工作台、组合场景的扇出（foreach）、Python 节点使用登录角色（待决定）。

没有选的方案

方案为什么不选
封存 script:、另开 python:（第二版）多一套模型、派工与报告，旧场景要迁移；用户 10-29 选择统一。
运行环境模式也能开浏览器用户选择不能：网页操作留在 DSL；运行环境的 Playwright 版本要和 Worker 下载的浏览器绑在一起，容易出错。
用电脑上的 Python、conda 或场景自己锁定包每台结果不同、Worker 要连得到包来源；正是要避免的版本与倚赖问题。
文件经由服务器在节点之间传递同一次组合运行已经在同一台 Worker，走本机路径最快；只有声明的产出文件上传。
组合场景里直接写一段转换程序的节点少了版本、发布门槛与独立断言；Python 节点已经涵盖。
