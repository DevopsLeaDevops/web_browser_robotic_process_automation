ADR 0001：场景以声明式 DSL 为唯一真实来源

场景存成受 schema 约束的数据，而不是代码。

已接受
日期
2026-10-09
影响范围
rpa-core、所有生成方式、Web UI 编辑器、运行引擎
相关
场景 DSL（草案）

背景

场景会由三种方式产生（录制、AI、手动编辑），要在网页上可视化编辑、比较版本，并交给多个 worker 运行。

如果场景直接存成 Playwright 脚本，编辑器很难可靠地解析和改写它，AI 的输出也无法在运行前验证；脚本可以做任何事，审核和安全边界都不清楚。

决策

  • 场景以声明式 DSL 描述：YAML 编写、JSON 存储。
  • DSL 以 Pydantic v2 模型定义，同一份定义导出 JSON Schema，供 AI 生成与前端使用。
  • DSL 带有 schemaVersion，格式变更时提供迁移。
  • 可以导出成 Playwright 代码给开发者参考，但导出结果不能回写成场景。
  • DSL 表达不了的情况使用受控的 script 步骤。

后果

好处

  • 编辑器、版本比较、审核都直接处理结构化数据。
  • AI 的输出能被校验，错误可以精确反馈给模型修正。
  • 运行层可替换，安全边界由 DSL 决定。

代价

  • 表达能力受限，需要逃生门，并在审核时标示。
  • 要自行维护 DSL 规格与版本迁移。

没有选的方案

方案为什么不选
直接存 Playwright 脚本无法可靠地可视化编辑，运行前无法校验，安全边界不清楚。
流程图 JSON（低代码平台常见）本质相同，但难以手写和在 Git 中比较；YAML DSL 兼顾两者。
采购现成 RPA 平台授权成本高，生成与客制化受限。
