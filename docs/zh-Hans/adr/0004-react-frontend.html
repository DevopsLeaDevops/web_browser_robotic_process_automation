ADR 0004：前端采用 React + TypeScript

Python 为主的工程中，Web UI 是唯一的 TypeScript 部分。

已接受
日期
2026-10-09
影响范围
apps/web（M8）
相关
ADR 0002、ADR 0006

背景

管理界面最重要的页面是步骤编辑器：拖拽排序、实时校验、定位器候选切换，以及运行时逐步回放截图。这类交互在纯 Python 的 UI 框架里很难做好。

决策

  • 前端使用 React + TypeScript + Vite，放在 apps/web。
  • 样式沿用界面设计系统 v1.0 的 portal.css 与设计变量，不另选组件库。
  • API 类型由 FastAPI 的 OpenAPI 生成，DSL 类型由 JSON Schema 生成，不手写。

后果

好处

  • 生态成熟，复杂交互有现成方案。
  • 类型由后端生成，前后端不会各说各话。

代价

  • 团队需要维护一份 TypeScript 代码；范围严格限于 UI，业务逻辑都在后端。
  • CI 需要另外的 Node.js 工作流程（M8 加入）。

没有选的方案

方案为什么不选
NiceGUI、Streamlit纯 Python，但复杂交互与多用户下的性能受限。
Jinja2 + HTMX适合表单类页面，不适合步骤编辑器。
Vue同样可行；React 的拖拽与编辑器相关包较多。
