ADR 0005：文档以 HTML 撰写并应用 Portal 样式

除非必要，不使用 Markdown；文档本身就是一个可以直接部署的静态网站。

已接受
日期
2026-10-09
影响范围
docs/ 下所有文档
相关
文档与 ADR 写作方式

背景

项目负责人要求文档易读、易理解、重点突出，并且之后能直接做成文档网站。Markdown 只能表达线性的文字，难以做出并排比较、状态标签、规格清单这类重点突出的版面。

决策

  • 文档以手写 HTML 放在 docs/，应用界面设计系统的 portal.css。
  • 导览集中在 docs/assets/nav.js，由 docs-shell.js 产生；页面只写内容。
  • 不使用静态网站生成器，不需要构建，直接打开文件或用任何静态服务器即可浏览。
  • 只有仓库根目录的 README.md 保留 Markdown，因为 GitHub 首页需要它。
  • CI 检查每个页面的结构、导览登记与链接。

后果

好处

  • 脱机可读，风格与产品一致。
  • docs/ 原样就能部署为文档网站（GitHub Pages 或内部静态服务器）。

代价

  • 手写 HTML 比 Markdown 冗长；以页面模板和自动检查降低出错机会。
  • 在 GitHub 网页上看到的是源代码，需要部署或下载后浏览。

没有选的方案

方案为什么不选
Markdown难以做出重点突出的版面，与要求不符。
Markdown + MkDocs 等生成器写作方便，但需要构建流程，风格难与产品一致。
