系统架构

组件、数据流与目录结构。平台全部部署在内网，worker 直接连到目标系统。

组件总览

M9 完成后的样貌
蓝框为内核组件；灰底为平台外部的系统。M2 之前只有 CLI 与 Runner，直接在本机运行。开发与原型可以用 SQLite 取代 PostgreSQL，这时队列与调度在 API 进程内运行，见 ADR 0008。

包职责

uv workspace，每个包可单独测试
包职责依赖起始
rpa-coreDSL 模型、YAML 加载与校验、表达式引擎、JSON Schema 导出、多语言消息目录。不碰浏览器、不碰数据库。Pydantic、ruamel.yaml、Jinja2M0
rpa-runner运行引擎：步骤处理器注册表、浏览器与上下文管理、产物收集。无状态。rpa-core、PlaywrightM2
rpa-recorder本机录制：注入监听脚本，把用户操作转成 DSL 步骤。rpa-core、PlaywrightM4
rpa-generatorAI 生成与选择器自愈：页面快照 + 自然语言 → DSL，校验失败反馈修正。rpa-core、LLM SDKM5
rpa-clirpa 命令：validate、run、record、generate、push。上述包、clickM0
rpa-serverAPI 服务、数据库模型、权限、调度。rpa-core、FastAPI、SQLAlchemyM7
rpa-worker从队列取任务，调用 rpa-runner 运行，回写结果与产物。rpa-runner、ProcrastinateM9
web管理界面（TypeScript，不属于 Python workspace）。React、ViteM8

一次运行的数据流

  1. 用户在 Web UI 或 CLI 触发运行，或调度器到点创建任务。
  2. API 检查权限，取出指定版本的场景，写入一笔运行记录与一个队列任务。
  3. 空闲的 worker 收到 PostgreSQL 的通知（或定期查询时发现），主动领取并锁住这笔任务，向 API 解出参数与 Secrets（只在内存中）。
  4. Runner 打开独立的浏览器上下文，逐步运行；每一步回报状态。
  5. 截图、Trace、下载文件上传到对象保存；抽取的数据写回运行记录。
  6. 运行结束，结果通知触发者；失败时标出出错的步骤与截图。
