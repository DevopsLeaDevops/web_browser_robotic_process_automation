系统架构

组件、数据流与目录结构。平台全部部署在内网：服务器保存场景与记录，录制端与 Worker 两个桌面 App 主动连到服务器，浏览器在它们那台直接操作目标系统。本页对照 v0.4.0（2026-10-21）。

目前的部署

v0.4.0：一台服务器＋录制端（macOS）＋Worker（Windows）
蓝框为内核组件；灰底为平台外部的系统；虚线为选用。所有连接都由 App 主动发起，服务器不需要连到它们；只有服务器访问数据库与数据目录；服务器可以是 Linux、macOS 或 Windows，不需要屏幕。录制端用设备权杖、Worker 用 worker 权杖，权杖在 HTTP 下是明文，只适合信任的区网。服务器没有浏览器时（例如 Linux 主机），「检查」登录状态改由录制端运行。安装见部署与操作、桌面端分发。

目标样貌

M5、M8、M9 完成后；尚未实现
蓝框为内核组件；灰底为平台外部的系统。原本 worker 直接连 PostgreSQL 的任务队列（ADR 0003）已由 Worker API 取代（ADR 0012）；场景的真相是领域文件夹，数据库只是索引（ADR 0015）。

各部分怎么运作

单一用户（登录与权限在 M8）；一台服务器，设备可以有很多台
管理 Portal

服务器以 Jinja 渲染的页面，沿用 MVP 原型的版面（ADR 0011）。在服务器那台用浏览器开 8080，或在录制端 App 的窗口里经由对外端口开（ADR 0014）。

API 服务

FastAPI：场景、版本与发布门槛、入参出参、运行与取消、报告、调试工作阶段、组合场景、设备与邀请、领域与 git 同步、回看。交互的子进程在「正在操作的那台」运行：从录制端来的请求交给录制端。

运行

本机 worker 是服务器里的线程，远程是 Worker App 或 rpa worker（ADR 0012）。每台一次一个任务；每次运行以子进程跑 Runner，应用总期限与取消。运行位置可选本机、远程或任一；组合场景整个在同一台。

数据与产物

领域文件夹保存场景、角色、组合场景的不可变版本与验证、发布记录，是真相；SQLite 是索引与每台自己的状态（ADR 0015、ADR 0008）。运行目录、录像、登录状态与 Secrets 只在这台服务器。

请求方向：Portal → API → worker。worker 回写运行状态与产物，Portal 以轮询读取进度；长任务不阻塞网页请求。

远程运行（M9a、M10.1）：Worker 主动连到对外端口的 Worker API，长轮询领取任务；任务带着场景版本的文件、入参、用到的 Secrets 与登录状态；每 5 秒心跳（同时得知是否取消），运行完上传整个运行目录并回报结果。60 秒没有心跳就判定失联，运行标为失败、不自动重跑。App 回报看得懂的 DSL 扩充（例如 iframe 的 frame），用到它不懂的写法时服务器不交给它。见远程 worker。

录制端（M10.2）：App 用邀请配对，窗口经由本机闸道加载 Portal 页面；录制、逐步调试、人工登录与登录检查的子进程由服务器经 Client API 交给这台运行，输出与文件传回；转换、遮罩密码、版本与发布门槛仍在服务器。见桌面端分发。

同步（M11）：每个领域可以设置 git 仓库的一个目录；拉取与推送以文件为单位三方合并，冲突时停下来三选一。任何一台服务器写下的、哈希相符的通过记录都能当发布依据。推送前挡下看起来像机密的文件。

数据目录/（RPA_DATA_DIR）

  runs/<运行编号>/       # 运行目录（见下）
  workflow-runs/         # 组合场景的运行记录
  roles/<角色>/          # 登录状态（只限本人读写）
  secrets.json           # Secrets 的值（明文，只限本人；M8 加密）
  recordings/、debug/    # 录制稿、调试工作阶段
  git/、work/、backups/  # git 工作数据、运行中的版本快照、迁移前的备份

runs/<运行编号>/
  input.json          # 校验后的本次入参
  facts.json          # 自动化抽取的页面事实
  output.json         # 只有独立断言与出参校验都通过才产生
  steps.json          # 每一步的结果、开始与结束时间、步骤后的网址
  screenshot.png、diagnostic.json
  video.webm、video.json  # 自动化阶段的录像与说明（M12，ADR 0016）
  automation.log、assertion.log
  scenario/           # 本次使用的场景版本快照（含 Python 脚本）
  result.json、report.html、run.json

包职责

包职责依赖起始
rpa-coreDSL 模型、YAML 加载与校验、表达式引擎、JSON Schema 导出、多语言消息目录；组合场景的定义与检查（rpa_core.workflow，M6）；领域文件夹的格式与校验（rpa_core.pack，M11）；录制稿转 DSL（rpa_core.recording，M4）。不碰浏览器、不碰数据库。Pydantic、PyYAML、Jinja2M0
rpa-runner运行引擎：入参校验、步骤处理器注册表、浏览器与上下文管理（含 iframe，M7a）、登录检查与人工登录、独立断言、出参发布、运行目录与报告、录像（M12）；也运行 Python 脚本场景，并提供录制、逐步调试、人工登录的子进程（子进程命令集中在 rpa_runner.commands，打包后走 App 的入口）。无状态。rpa-core、PlaywrightM2
录制在隔离的浏览器中记录用户操作，保存原始录制稿并转成 DSL 草稿。M4 没有另外做包：录制用 Playwright codegen，转换是 rpa-core 的 rpa_core.recording（不碰浏览器，可以单独测试）。rpa-core、PlaywrightM4
rpa-generatorAI 助手：对话调试、自然语言 → DSL、校验失败反馈修正、选择器自愈；只能修改草稿。尚未创建：要先决定模型与数据去向。rpa-core、LLM SDKM5
rpa-clirpa 命令：validate、schema、run、record、serve、worker、recorder、pack check；generate 在 M5。上述包、clickM0
rpa-serverAPI 与管理页面、数据库模型与迁移、版本与发布门槛、调试工作阶段、组合场景的运行（M6）、Worker API（M9a）、设备、邀请与 Client API（M10）、领域文件夹的加载与 git 同步（M11）、回看与录像保留（M12）；权限（M8）、调度（M9）。rpa-core、FastAPI、Jinja2、SQLAlchemyM3
rpa-worker取出待运行的任务，以子进程调用 rpa-runner，应用总期限与取消，回写结果与产物。M3 在同一台电脑；M9a 起也可以在另一台电脑，经由 Worker API 领取（rpa worker，ADR 0012）。M10 起也包含配对、录制端的本机闸道与交互子进程主机（rpa_worker.pairing、gateway、recorder），两个 App 与 rpa recorder 共用。rpa-runner；标准函数库的 HTTPM3
rpa-desktop（apps/desktop）两个桌面 App：RPA 录制端（pywebview 窗口加载 Portal 页面，在这台运行录制、调试、人工登录的子进程）与 RPA Worker（状态窗口＋远程 worker）；配对、下载浏览器、打包后的入口。M10 起（ADR 0014）。rpa-runner、rpa-worker、pywebviewM10

一次运行的数据流

  1. 用户在管理 Portal、组合场景或 CLI 触发运行（M9 起也可以由调度器创建）。
  2. API 确认版本：一般运行只用已发布的版本，而且领域文件夹里的文件哈希要相符；在启动浏览器前校验入参，写入一笔运行记录（含运行位置）与一个任务。
  3. 本机 worker 或远程 Worker 领取任务，以子进程启动 Runner，传入场景版本的文件、入参、Secrets 与登录状态（只在内存与暂保存中，用完删除），并设置总期限。
  4. Runner 打开独立的浏览器上下文逐步运行，记下页面事实；每一步回报状态与开始、结束的时间。自动化阶段录像（M12，ADR 0016），回看时视频与步骤靠同一个时钟对上。
  5. 独立断言比较页面事实与入参；通过后出参校验，才写出 output.json。
  6. 截图、录像、日志与报告存入运行目录，远程 Worker 上传整个目录（M9 改为对象存储）；失败时标出出错的阶段、步骤与截图。
  7. 验证运行的结果写成领域文件夹里的验证记录；哈希相符的通过记录就是发布的依据，可以经由 git 交给其他服务器。
