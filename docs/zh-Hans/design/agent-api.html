对外 Agent API

第三方 Agent 系统只通过服务器的 /agent-api/v1：写场景与入参出参、指定录制端开浏览器逐步调试、交给 Worker 验证与运行，在项目里组合场景并运行，并取得运行过程。新的一层只做认证、权限与审核，业务规则与发布门槛沿用现有服务。

第一期实现中
决策与没有选的方案见 ADR 0017；给 Agent 的调用方式见 Agent 使用指南。设计 2026-10-23 由用户确认，第一期同日实现（审阅中）；2026-10-24 用户要求把项目与组合场景并入第一期，并给 Agent 写测试方案指南与测试报告指南；端点以服务器的 /agent-api/v1/openapi.json 为准，/agent-api/v1/docs 可以直接试。

架构

Agent 只连服务器
蓝框是添加的一层；灰底为平台外部的系统；虚线的 Webhook 是第二期。录制端与 Worker 的连接方式不变，不必开任何端口，Agent 也不必知道它们在哪里。不直接开放 /api：它没有认证、跟着 Portal 界面改动；独立的 /agent-api/v1 可以保持稳定、单独管版本。

API 用户端、权限与审核

每个 Agent 系统是一个「API 用户端」，在管理后台登记后拿到一把只显示一次的 API 密钥；服务器只存哈希，做法与设备权杖相同。请求带 Authorization: Bearer <API 密钥>。

权限范围
下表的勾选；新用户端默认只有 scenes:read、runs:read 与 projects:read
可用的领域
能读写哪些领域的场景；默认全部
可用的项目
能用哪些项目里的组合场景；默认全部。限定了项目的用户端不能添加项目；不属于任何项目的组合场景不给 Agent

能在哪几台录制端开调试浏览器；默认无。录制端本身也要在设备页打开「允许 Agent 调试」，可以设成「只允许无头」
运行位置

  • 不抢人的工作阶段：场景已有别人（人或其他 Agent）在调试时回 409 debug_in_use，不关掉对方；Agent 只看得到、只能操作自己开的工作阶段（Portal 从另一台开始时仍照旧关掉原本的）。debug_busy 沿用原本的意思：同一个工作阶段上一个命令还没跑完。
  • 审核：每个写入请求记一笔（时间、用户端、动作、对象、结果码），管理后台可以筛选，不能修改或删除。Agent 存的版本说明自动标「由 Agent〈名称〉创建」，运行记录记下触发的用户端。
  • 传输：对外端口是 HTTP，密钥是明文。用户确认（2026-10-23）Agent 系统与服务器在同一个局域网，第一期不要求 HTTPS；日后 Agent 移到局域网外时，在服务器前放反向代理提供 HTTPS，程序本身不做 TLS。

  • 事件：queued、claimed（哪台 Worker）、stage（入参、登录、自动化、断言、出参）、step（第几步开始或结束、结果、耗时）、finished（最终状态、出参、错误摘要）。序号递增，用 after 接续，断线不漏。
  • 步骤进度的来源：Runner 的子进程每跑完一步已经写 steps.json。本机 worker 读档更新数据库；远程 Worker 在心跳附上目前步骤，步骤变化时立刻多送一次。旧版 Worker 不送这些字段也照常运作，只看得到阶段。
  • 先用长轮询：Worker 与录制端已经用同样的方式，穿得过代理，不需要服务器主动连 Agent。Agent 系统与服务器在同一个局域网（用户 2026-10-23 确认），第二期的 Webhook 可以由服务器直接连到 Agent。
  • 调试不需要事件：调试的每个命令跑完才回应，回应里就是那一步的结果。

典型流程

  1. 读 /meta、/dsl/schema、可用的录制端与角色。
  2. 创建场景，存第一版（开网址、需要时声明登录角色）。
  3. 在指定的录制端开调试工作阶段。
  4. 读页面结构、截图、测定位器。
  5. 写下一段步骤，存成新版本。
  6. 换到新版本，运行到最后一步；有步骤失败就回到第 4 步。
  7. 补入参、出参与独立断言，用 /dsl/check 校验。
  8. 交给 Worker 验证；没通过就回到调试。
  9. 发布（有权限的 Agent 自己发布，否则请人在 Portal 发布）。
  10. 正式运行，读状态与出参。运行停在「需要登录」时，请人在录制端人工登录后调用 rerun。
  11. 需要组成流程时，在项目里创建组合场景（节点是发布过的场景版本），检查、验证、发布后运行，用 /composite-runs 读进度与每个节点的运行。拿来做测试时，测试方案与测试报告由 Agent 写给人验收，平台不读取它们。

读页面结构

第一期，录制端 App 要更新
  • 做法：调试子进程 rpa_runner.debug 加 snapshot 命令：目前分页的无障碍树（Playwright 的 ARIA 快照）、表单字段（标签、名称、类型、是否必填）、iframe 阶层与已开的分页。Agent 据此写 role／label／text 定位器。
  • 遮罩：填了 Secret 的字段与密码字段的值一律遮罩，沿用 Runner 的遮罩。
  • 大小：超过上限时截断并标示，Agent 可以用 within 指定只看页面的一部分。
  • 兼容：录制端上线时回报支持 snapshot；旧版 App 没有回报时回 422 recorder_outdated，说明要更新 RPA 录制端（沿用 M7a 的做法与状态码）。

安全与数据外流

  • 页面内容会离开服务器：截图、页面结构、页面事实与出参都回传给 Agent；Agent 接的是外部模型时，这些内容就送到外部。这和 M5 尚待决定的数据去向是同一个问题，所以「回传页面内容」默认关。
  • Secrets：只能引用名称，值永远不回传。
  • 发布门槛不变：Agent 写的场景和人写的一样要经过真实验证，发布的版本必须就是验证通过的版本。
  • 调试有副作用：调试会在目标系统上真的点击与填写；建议专给 Agent 一台录制端，并用测试账号的角色。
  • 失控保护：限额防止排满队列或占住录制端；密钥可以一键禁用。
