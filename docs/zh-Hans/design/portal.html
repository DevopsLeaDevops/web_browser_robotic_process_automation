管理 Portal

在瀏覽器裡建立場景、驗證、發布、執行並查看報告（M3）；錄製、逐步調試、登入角色與入參出參的表單（M4）。單機、單使用者（ADR 0010），FastAPI + Jinja（ADR 0011），SQLite（ADR 0008）；版面沿用 MVP 原型與設計系統 v1.0。

M4
啟動：uv run rpa serve，再打開 http://127.0.0.1:8080。會一起在 127.0.0.1:8765 啟動本機測試網站，「測試網站自動化」的案例直接就能執行。資料放在 data/（或 --data 指定的資料夾）。沒有登入保護，預設只開放本機連線。

領域

場景管理的二級選單
  • 依目標系統或業務劃分場景。例如「測試網站自動化」「谷歌自動化」「微軟自動化」。每個領域是「場景管理」左側的一個選單，最後一項是「領域管理」。
  • 領域頁是場景卡片。每張卡片有名稱與標籤（DSL 場景、Python 腳本、待發布）、最近一次執行的截圖、說明，「自動化腳本、斷言腳本、執行報告、入參設定、出參設定」五個連結（DSL 場景另有「逐步調試」），以及場景編號、最近一次結果、「調試」（驗證最新版本）與「運行」（執行已發布版本）。
  • 領域管理。新增領域（代號用在網址，建立後不能改）、改名稱與說明、刪除沒有場景的領域。場景頁的「執行設定」可以把場景移到其他領域。
  • 測試網站自動化。第一次啟動時自動建立，放進對測試網站執行的真實案例：建立紀錄（BA-001）、查詢紀錄（BA-002，入參是 BA-001 的出參）、查詢不存在的紀錄（BA-003）、Python 腳本版的建立紀錄，以及兩個登入範例（BA-004 一般使用者、BA-005 主管）。它的名稱與說明跟著介面語言顯示，改過之後就照改的內容；場景的名稱與說明是場景檔的內容，不會翻譯。

流程

驗收：在瀏覽器內走完一次
1 建立或匯入2 編輯3 驗證4 發布5 執行6 看報告
  1. 建立或匯入。新增場景會產生第 1 版草稿（只開一個網頁）；也可以一鍵匯入 scenarios/demo 的範例。場景編號就是 DSL 的 id，建立後不能改、也不會重複使用。
  2. 編輯。直接編輯 YAML（腳本場景另有兩支腳本）。存檔前先用 rpa validate 同一套規則校驗，有問題時列出行號、步驟與欄位，不會建立新版本。
  3. 驗證。用真實瀏覽器執行指定版本，入參、瀏覽器、瀏覽器視窗、網址都可以在表單調整。
  4. 發布。只有通過驗證的版本可以發布，而且要使用者在對話框確認。
  5. 執行。一律使用已發布的版本；新的草稿不影響正式執行。
  6. 看報告。依分類、場景、結果與目的篩選：每個條件是一個按鈕，顯示目前的選擇，點開勾選一項或多項，按「套用」或關閉選單就更新；沒勾選代表全部。每次執行都有 M2 的 report.html、截圖與完整的執行目錄。

版本與發布門檻

  • 版本不可變。每次存檔都是新版本（v1、v2…），內容寫進資料目錄後設成唯讀。存檔要帶「從哪一版開始改」，不是最新版就回 409，避免覆蓋別人的修改。
  • 狀態。草稿 → 驗證中 → 驗證通過／驗證失敗；狀態是最近一次驗證的結果。發布後場景指向該版本，舊的發布版本留在歷史中。
  • 驗證的就是發布的。版本記錄內容雜湊，演算法與 rpa-runner 寫在 result.json 的 scenarioHash 相同。發布時要同時符合：最近一次驗證通過、有一次通過的驗證執行跑的雜湊等於版本雜湊、磁碟上的內容重新計算後也還是同一個雜湊。
  • 改內容就重新驗證。新版本一律從草稿開始，舊版本的驗證結果不能拿來發布新內容。

執行

  • 先校驗、再排隊。請求執行時先檢查入參，不合規則直接回 422，不會排進佇列；通過後回 202 與執行編號。
  • 背景 worker。rpa-worker 在伺服器程序內的背景執行緒，依建立時間一次執行一個（SQLite 只允許單一程序）。它呼叫 M2 的 rpa_runner.run.execute，總期限、子程序與程序群組的終止都沿用 M2。
  • 有頭模式與無頭模式。執行表單的「瀏覽器視窗」：顯示（有頭模式，headed）會在執行 Portal 的這台電腦上打開瀏覽器視窗，看得到每個步驟；不顯示（無頭模式，headless）在背景執行。預設有頭模式；這台電腦沒有圖形介面（Windows、macOS 以外，又沒有 DISPLAY 或 WAYLAND_DISPLAY）時只能無頭，API 要求有頭會回 422。執行頁會記下用的是哪一種。rpa run 命令列維持無頭，加 --headed 才顯示。
  • 進度。執行頁每秒查詢一次狀態，階段或狀態改變時重新整理。
  • 取消。排隊中的直接取消；執行中的立即終止子程序與瀏覽器，狀態為「已取消」。已經在目標網站完成的動作不會復原。
  • 不重複送出。表單每次載入產生一個 idempotencyKey，重複送出只會得到同一個執行。
  • 重新執行。結束的執行都可以用同樣的入參與選項再執行一次（驗證用同一個版本，正式執行用目前發布的版本）。
  • 伺服器重啟。啟動時把上次執行到一半的任務標為失敗；排隊中的會繼續執行。

登入與角色

M4：每個角色一份登入狀態，執行前先檢查
  • 場景只寫角色。需要登入的場景寫 login: { role: 角色代號 }（DSL）。怎麼登入、怎麼判斷已登入，在「場景管理 › 登入與憑證」登記：登入網址、確認網址、已登入時看得到的元素（DSL 定位器），以及選用的自動登入步驟。
  • 人工登入為主。按「登入」會在執行 Portal 的這台電腦開瀏覽器視窗到登入網址，由使用者自己登入，所以 SSO、驗證碼、手機或 App 二次驗證都能處理。完成後按「完成登入」或直接關掉視窗；Portal 先用無頭瀏覽器確認真的登入了，才取代原本的登入狀態。這台電腦沒有圖形介面時不能人工登入。
  • 自動登入（選用）。只適合單純帳號密碼的系統：角色附一段 DSL 步驟，密碼用 {{ secrets.名稱 }}。執行前發現沒登入時先自動登入一次。
  • 需要登入（needs_login）。每次執行先在「登入檢查」階段打開確認網址：看得到元素就繼續；沒有（例如被轉到登入頁）而且不能自動登入時，停在「需要登入」，不執行任何步驟，並留下登入檢查的截圖。執行頁有「登入角色」與「重新執行」：登入後用同樣的入參再跑一次。
  • 角色互不干擾。登入狀態（Playwright storageState）每個角色一份，存在資料目錄的 roles/<角色>/state.json，只有本人能讀寫；每次執行開新的瀏覽器 context，只載入場景指定的那個角色。登入狀態不會複製進執行目錄，也不經由網頁或 API 提供。執行的結果也會更新角色的狀態（已登入、需要登入）。
  • Secrets。同一頁可以設定 Secrets 的值：存在資料目錄的 secrets.json（只有本人能讀寫，M8 改為加密），頁面與 API 只顯示名稱與更新時間，永遠不回傳值。執行時把場景與角色用到的值交給執行引擎；沒有設定的再從同名的環境變數找。頁面也列出場景用到、但還沒設定的 Secrets。
  • 測試網站的兩個角色。匯入範例時，BA-004（一般使用者）與 BA-005（主管）用到的角色依 scenarios/demo/roles.json 一起建立；示範帳號寫在測試網站的登入頁。兩個帳號看到的待辦不同，用來確認角色之間沒有混用。

錄製

M4：原始錄製稿 → DSL 草稿
1 錄製草稿2 調試與修改3 驗證4 確認發布
  • 在這台電腦錄製。「場景生產 › 自主腳本錄製」按「開始錄製」，執行 Portal 的電腦會開啟 Playwright codegen 的瀏覽器與 Inspector；照平常的方式操作，完成後關掉瀏覽器視窗。選了登入角色時先載入它的登入狀態。也可以在命令列用 rpa record 網址 --out 錄製稿.py --scenario 草稿.yaml。
  • 貼上錄製稿。在別台電腦錄好的 codegen 原始稿（同步、非同步或 pytest 寫法）可以貼上直接轉換，例如 Portal 跑在沒有圖形介面的電腦時。
  • 轉換規則。goto、click、fill、press、select_option、check 與常見的 expect，以及 get_by_role、label、placeholder、text、test_id、CSS、XPath、first、nth、filter(has_text) 等定位器。第一個網址的來源成為 browser.baseUrl。轉不了的行（hover、上傳、iframe、新分頁…）以註解留在草稿裡並列在錄製詳情。
  • 自動參數化。每個輸入的值變成一個入參，預設值是錄到的值；名稱取自欄位的英數名稱（沒有時叫 field、field_2…），欄位標籤寫在說明，之後在場景頁的表單改名。
  • 密碼不落地。密碼欄位（標籤、提示文字或選擇器含有 password、密碼等字）改成 Secret 引用，原始錄製稿也遮罩成 *** 才保存；錄製中的暫存原始稿轉換後就刪除。
  • 只產生草稿。轉換結果存成新場景的 v1，或既有場景的新版本；錄製稿只當來源，一樣要調試、驗證通過才能發布。

逐步調試

M4：一個瀏覽器、一次一步
  • 開始。場景頁或卡片的「逐步調試」選版本、入參、瀏覽器與視窗模式。有圖形介面時瀏覽器視窗開在這台電腦上；兩種模式都在頁面上顯示每一步之後的截圖、網址與頁面事實。只支援 DSL 場景。
  • 執行。每一步可以「執行這一步」，或「執行到這裡」（只執行還沒執行過的步驟，遇到失敗就停）。有副作用的步驟（點擊、填寫、選擇、勾選、按鍵）執行過一次後，再執行要先確認；不會自動重複任何步驟。「從頭開始」開新的頁面並重新載入登入狀態。
  • 定位器測試。輸入 DSL 定位器（例如 { role: button, name: 登入 }），回報找到幾個元素與前幾個的文字，截圖時以紅框標出。
  • 修改。頁面下方直接編輯 YAML，存成新版本後換到新版本繼續；瀏覽器與頁面事實保留，執行過的步驟依 id 保留狀態。
  • 限制。每個場景同一時間一個工作階段；閒置 15 分鐘自動結束，伺服器關閉時全部結束。調試會真的操作目標網站，請用測試環境。

入參與出參的表單

M4

場景頁的入參、出參表格按「編輯」可以新增、刪除、改名，修改型別、預設值、必填、說明、限制與出參的取值。存檔時只改寫場景檔的 inputs:、outputs: 兩段，其他內容與註解完全不變；入參改名時，步驟裡引用舊名稱的 {{ inputs.舊名稱 }} 一起改。一樣建立新版本、經過校驗與「不是最新版就 409」的檢查，新版本要重新驗證。Python 腳本場景的出參由 assertion.py 產生，改名也不會改到腳本。

API

JSON、camelCase；互動文件在 /api/docs
介面用途
GET、POST /api/domains領域清單；新增領域（id、name、description）
GET、PATCH、DELETE /api/domains/{代號}領域與它的場景卡片（最近一次執行、截圖）；改名稱與說明；刪除沒有場景的領域
GET /api/scenes、POST /api/scenes場景清單（q、category、domain）；建立場景（可帶 domainId）
POST /api/scenes/import匯入範例資料夾的場景，已存在的略過；可帶 domainId，預設放進測試網站自動化
GET、PATCH /api/scenes/{id}場景與版本清單；修改所屬領域、預設網址、封存
GET /api/scenes/{id}/revisions/{n}版本與檔案內容
POST /api/scenes/{id}/revisions存成新版本：baseRevision、files、note；409 不是最新版、422 校驗問題（含行號）
POST /api/scenes/{id}/revisions/{n}/validate驗證；202 回執行
POST /api/scenes/{id}/revisions/{n}/publish發布；不符合發布門檻時 409
POST /api/scenes/{id}/runs以已發布版本執行：inputs、engine、baseUrl、headless（不寫時有圖形介面就用有頭模式）、idempotencyKey；驗證也接受同樣的欄位
GET /api/runs、GET /api/runs/{執行編號}報告清單（scene、category、status、purpose 可重複）；單次狀態、result.json 與檔案清單
POST /api/runs/{執行編號}/cancel取消
POST /api/runs/{執行編號}/rerun同樣的入參與選項再執行一次；202 回新的執行
PUT /api/scenes/{id}/contract入參與出參的表單存檔：baseRevision、inputs、outputs（每項有 name、改名前的 previous…）、note
GET、POST /api/roles；GET、PATCH、DELETE /api/roles/{角色}登入角色：name、loginUrl、checkUrl、check（定位器）、engine、autoLogin；還有場景用到時不能刪除
POST /api/roles/{角色}/login、…/login/finish、…/login/cancel人工登入：開瀏覽器視窗、完成、取消；進度看角色的 activity 與 session
POST /api/roles/{角色}/check、DELETE /api/roles/{角色}/state在背景檢查是否已登入（必要時自動登入）；登出
GET /api/secrets、PUT、DELETE /api/secrets/{名稱}Secrets：只回傳名稱與更新時間；PUT 的內容是 value
GET、POST /api/recordings、POST /api/recordings/import錄製清單；在這台電腦錄製（202）；貼上錄製稿直接轉換（201）。都要 target（新場景或既有場景）、url、engine、選用的 roleId
GET /api/recordings/{錄製編號}、…/cancel錄製狀態、轉不了的行與檔案；取消錄製
POST /api/scenes/{id}/debug開始逐步調試（revision、inputs、engine、headless、baseUrl）；已經有工作階段時回傳它
GET、DELETE /api/debug/{工作階段}；POST …/steps/{n}、…/run-to/{n}、…/locate、…/screenshot、…/reset、…/reload調試狀態與結束；執行一步（有副作用而且執行過時 409 confirm_required，帶 force 再送）、執行到第 n 步、測試定位器、截圖、從頭開始、換到新版本
錯誤一律是 {"error": {"code", "message", …}}：404 找不到、409 狀態衝突、422 內容有問題。

recordings
錄製編號、目標場景與版本、來源（錄製或貼上）、網址、瀏覽器、角色、狀態、轉不了的行

模型用 SQLAlchemy 2，結構變更走 Alembic 遷移（伺服器啟動時自動升級）；測試會比對遷移與模型是否一致。

設定

--host、--port
預設 127.0.0.1:8080；沒有指定埠號而 8080 被其他程式占用時，自動改用下一個空的埠號（到 8089）。占用的如果就是管理 Portal，只顯示它的網址，不再開第二個
RPA_DATA_DIR
資料資料夾，預設 data；也可以用 --data
RPA_DATABASE_URL
預設 SQLite；PostgreSQL 在 M8
RPA_LANG
預設語言，也是執行報告的語言；頁面右上角可以切換
--no-testsite
不要一起啟動測試網站（預設會在 127.0.0.1:8765 啟動；已經在執行就沿用）
RPA_EXAMPLES_DIR
「測試網站自動化」的範例資料夾，預設 scenarios/demo
Secrets
在「登入與憑證」設定；沒有設定的，從伺服器程序的同名環境變數讀取

安全與限制

  • 沒有登入。預設只聽 127.0.0.1；改成其他位址時 rpa serve 會提醒。認證與權限在 M8。
  • 擋掉跨站請求。寫入請求帶了 Origin 標頭時必須同源，避免其他網站在背景呼叫本機的 API。
  • 執行目錄的檔案。只提供執行目錄內的檔案；只有 report.html 當成網頁顯示，並加上只允許內嵌樣式與截圖的內容安全政策。
  • 腳本場景等同執行任意程式。與 M2 相同，Python 腳本場景只給信任的人編輯。
  • 登入狀態與 Secrets 只在這台電腦。兩者都在資料目錄、只有本人能讀寫，不經由網頁或 API 提供，也不寫進執行目錄、報告與日誌；錄製稿裡的密碼遮罩後才保存。M8 加密存放。
