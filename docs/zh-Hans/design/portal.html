管理 Portal

M3：在浏览器里创建场景、验证、发布、运行并查看报告。单机、单用户（ADR 0010），FastAPI + Jinja（ADR 0011），SQLite（ADR 0008）；版面沿用 MVP 原型与设计系统 v1.0。

M3
启动：uv run rpa serve，再打开 http://127.0.0.1:8080。数据放在 data/（或 --data 指定的文件夹）。没有登录保护，默认只开放本机连接。

流程

验收：在浏览器内走完一次
1 创建或导入2 编辑3 验证4 发布5 运行6 看报告
  1. 创建或导入。添加场景会产生第 1 版草稿（只开一个网页）；也可以一键导入 scenarios/demo 的示例。场景编号就是 DSL 的 id，创建后不能改、也不会重复使用。
  2. 编辑。直接编辑 YAML（脚本场景另有两支脚本）。保存前先用 rpa validate 同一套规则校验，有问题时列出行号、步骤与字段，不会创建新版本。
  3. 验证。用真实浏览器运行指定版本，入参、浏览器、网址都可以在表单调整。
  4. 发布。只有通过验证的版本可以发布，而且要用户在对话框确认。
  5. 运行。一律使用已发布的版本；新的草稿不影响正式运行。
  6. 看报告。依分类、场景（多选）、结果与目的筛选；每次运行都有 M2 的 report.html、截图与完整的运行目录。

版本与发布门槛

  • 版本不可变。每次保存都是新版本（v1、v2…），内容写进数据目录后设成唯读。保存要带「从哪一版开始改」，不是最新版就回 409，避免覆盖别人的修改。
  • 状态。草稿 → 验证中 → 验证通过／验证失败；状态是最近一次验证的结果。发布后场景指向该版本，旧的发布版本留在历史中。
  • 验证的就是发布的。版本记录内容哈希，算法与 rpa-runner 写在 result.json 的 scenarioHash 相同。发布时要同时符合：最近一次验证通过、有一次通过的验证运行跑的哈希等于版本哈希、磁盘上的内容重新计算后也还是同一个哈希。
  • 改内容就重新验证。新版本一律从草稿开始，旧版本的验证结果不能拿来发布新内容。

运行

  • 先校验、再排队。请求运行时先检查入参，不合规则直接回 422，不会排进队列；通过后回 202 与运行编号。
  • 背景 worker。rpa-worker 在服务器进程内的背景线程，依创建时间一次运行一个（SQLite 只允许单一进程）。它调用 M2 的 rpa_runner.run.execute，总期限、子进程与进程组的终止都沿用 M2。
  • 进度。运行页每秒查询一次状态，阶段或状态改变时刷新。
  • 取消。排队中的直接取消；运行中的立即终止子进程与浏览器，状态为「已取消」。已经在目标网站完成的动作不会复原。
  • 不重复送出。表单每次加载产生一个 idempotencyKey，重复送出只会得到同一个运行。
  • 服务器重启。启动时把上次运行到一半的任务标为失败；排队中的会继续运行。

页面

顶部第一级、左侧第二级，与 MVP 原型相同
路径内容
/scenes统计、搜索与分类筛选、场景卡片；添加场景、导入示例
/scenes/{id}版本清单与状态、发布、入参与出参、默认网址、最近运行
/scenes/{id}/edit编辑 YAML 与脚本，存成新版本；校验问题列在页面上
/scenes/{id}/run验证或运行的表单：入参（JSON，已带入默认值）、浏览器、网址
/runs运行报告：分类、场景多选，结果、目的筛选
/runs/{运行编号}状态、阶段、独立断言、入参与出参、截图、运行目录的文件；取消、发布
/recording、/playground预留位置：录制在 M4、自由试验场在 M6

API

JSON、camelCase；交互文档在 /api/docs
界面用途
GET /api/scenes、POST /api/scenes场景列表（q、category）；创建场景
POST /api/scenes/import导入示例文件夹的场景，已存在的略过
GET、PATCH /api/scenes/{id}场景与版本清单；修改默认网址、封存
GET /api/scenes/{id}/revisions/{n}版本与文件内容
POST /api/scenes/{id}/revisions存成新版本：baseRevision、files、note；409 不是最新版、422 校验问题（含行号）
POST /api/scenes/{id}/revisions/{n}/validate验证；202 回运行
POST /api/scenes/{id}/revisions/{n}/publish发布；不符合发布门槛时 409
POST /api/scenes/{id}/runs以已发布版本运行：inputs、engine、baseUrl、idempotencyKey
GET /api/runs、GET /api/runs/{运行编号}报告清单（scene、category、status、purpose 可重复）；单次状态、result.json 与文件清单
POST /api/runs/{运行编号}/cancel取消
错误一律是 {"error": {"code", "message", …}}：404 找不到、409 状态冲突、422 内容有问题。

数据

data/
  rpa.db                     SQLite：scenes、revisions、runs
  scenes/<场景 id>/<版本>/   scenario.yaml（脚本场景另有两支脚本）
  runs/<运行编号>/            M2 的运行目录（input.json、report.html…）
scenes
id、名称与分类（取自最新版本）、默认网址、最新与已发布的版本号码、封存
revisions
场景、版本号码（唯一）、内容哈希、种类、状态、说明、发布时间
runs
运行编号、场景与版本、当时的名称与分类、目的、状态与阶段、入参与出参、错误、哈希、时间

模型用 SQLAlchemy 2，结构变更走 Alembic 迁移（服务器启动时自动升级）；测试会比较迁移与模型是否一致。

设置

--host、--port
默认 127.0.0.1:8080；没有指定端口号而 8080 被其他程序占用时，自动改用下一个空的端口号（到 8089）。占用的如果就是管理 Portal，只显示它的网址，不再开第二个
RPA_DATA_DIR
数据文件夹，默认 data；也可以用 --data
RPA_DATABASE_URL
默认 SQLite；PostgreSQL 在 M8
RPA_LANG
默认语言，也是运行报告的语言；页面右上角可以切换
RPA_EXAMPLES_DIR
「导入示例」的文件夹，默认 scenarios/demo
Secrets
与 M2 相同，从服务器进程的同名环境变量读取

安全与限制

  • 没有登录。默认只听 127.0.0.1；改成其他地址时 rpa serve 会提醒。认证与权限在 M8。
  • 挡掉跨站请求。写入请求带了 Origin 标头时必须同源，避免其他网站在背景调用本机的 API。
  • 运行目录的文件。只提供运行目录内的文件；只有 report.html 当成网页显示，并加上只允许内嵌样式与截图的内容安全政策。
  • 脚本场景等同运行任意程序。与 M2 相同，Python 脚本场景只给信任的人编辑。
