产品定位

要解决什么问题，以及整个平台围绕的核心概念。

要解决的问题

  • 重复的人工操作。每天在内部系统登录、填表、查找、导出报表，耗人力又容易出错。
  • 脚本只有开发者能写。自动化脚本散落在个人电脑，难以共用，也没人知道哪个版本是对的。
  • 页面一改就坏。选择器失效后很难看出坏在哪一步、为什么坏。
  • 团队共用缺少治理。没有权限、审核与凭证管理，帐号密码常常直接写在脚本里。

不在范围内

  • 桌面应用程序自动化：只处理浏览器内的操作。
  • 破解验证码或绕过目标系统的安全机制。
  • 大规模网页爬取。
  • 取代测试框架：可以做检查，但定位是业务流程自动化。

生成 → 管理 → 运行 → 回馈

平台的主循环

1　生成

  • 录制用户操作
  • 用自然语言让 AI 产生
  • 由范本或子场景组合

2　管理

  • 版本与差异比较
  • 参数、标签与项目
  • 权限与审核

3　运行

  • 手动、调度或 API 触发
  • 多 worker 并发
  • 重试与逾时控制

4　回馈

  • 每一步的截屏与日志
  • Playwright Trace 回放
  • 失败定位与选择器自愈

内核概念

场景 Scenario
一段可重复运行的浏览器操作流程，以声明式 DSL 描述。平台的核心资产，有版本。
步骤 Step
场景中的一个动作，例如打开网址、点击、填写、抽取数据。每个步骤有稳定的 id。
定位器 Target
描述「要操作页面上的哪个元素」，可以有多个候选，依优先级尝试。
参数 Param
运行时才给定的值，例如查找月份；有类型与默认值。
Secret
帐号密码等机密，场景只引用名称，明文不会出现在场景、日志或截屏说明中。
运行 Run
场景的一次运行，记录触发者、参数、每一步的结果与耗时。
产物 Artifact
运行产生的截屏、Trace、下载档与抽取的数据。
项目 Project
权限隔离的单位。场景、Secrets、运行纪录都属于某个项目。
