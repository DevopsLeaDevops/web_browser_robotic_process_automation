场景 DSL

场景的唯一真实来源。YAML 编写、JSON 存储，以 Pydantic 模型校验；包含入参、出参与独立断言的场景契约。本页是 schemaVersion 1 的规格。

schemaVersion 1 · M1.1
模型在 packages/rpa_core/src/rpa_core/dsl/，示例在 scenarios/，JSON Schema 在 schema/scenario.v1.json。决策背景见 ADR 0001 与 ADR 0009。

示例

节录自 scenarios/demo/ba-001.yaml（MVP 原型的 BA-001）
# yaml-language-server: $schema=../../schema/scenario.v1.json
schemaVersion: 1
id: ba-001
name: 创建示例记录
category: 示例数据
inputs:
  title: { type: string, minLength: 1, maxLength: 60 }
  quantity: { type: integer, minimum: 1, maximum: 30, default: 12 }
outputs:
  recordId:
    pattern: '^DEMO-[A-Z0-9]+$'
    from: '{{ facts.record.recordId }}'
browser: { engine: firefox, baseUrl: http://127.0.0.1:8765 }
deadline: 45000
steps:
  - id: open
    action: goto
    url: /
  - id: fill-title
    action: fill
    target: { label: 标题, exact: true }
    value: '{{ inputs.title }}'
  - id: submit
    action: click
    target: { role: button, name: 创建记录 }
  - id: read-record
    action: extract
    target: { css: '#receipt' }
    as: record
    fields:
      recordId: { target: { css: '#record-id' } }
      status: { target: { css: '#record-status' } }
verify:
  - name: 状态是已创建
    value: '{{ facts.record.status }}'
    equals: 已创建

设计原则

  • 成功要有证据。步骤只操作页面、留下页面事实；由独立断言 verify 判定成功，通过后才发布出参。「脚本没有出错」不等于成功。
  • 入参、出参是契约。入参在启动浏览器前校验；出参可以串到下一个场景的入参。两者都能导出成 JSON Schema。
  • 每个步骤有稳定的 id。运行结果、截图与日志按步骤归档；插入或删除步骤时不会错位。
  • 定位器有优先级。testId → role + name → label → placeholder → text → altText → title → css → xpath。录制时同时记下多个候选放在 fallback，作为自愈的基础。
  • 只用条件等待。不提供固定秒数的 sleep，改用 waitFor；整次运行受 deadline 限制。
  • 写错就挡下来。无法识别的字段、类型不符、YAML 的隐式转型都在校验时报错，并指出文件行号、步骤与字段。
  • Secrets 只引用名称。值在运行时注入，日志与截图说明自动遮罩。
  • Python 节点补足浏览器。DSL 表达不了、或浏览器做不到的事（文件、数据处理、网络）用 Python 节点（script），沿用同一份契约，可以和浏览器场景串在同一个组合场景里；审核时特别标示。

场景顶层

字段名称一律是 camelCase
字段必填说明
schemaVersion是DSL 版本，目前是 1。格式有不兼容的变更时递增，并提供迁移。
id是小写英文字母、数字、- 与 _，以英数开头，最长 64 个字符。会用在文件名与网址，不重复使用。
name是给人看的名称。
description说明。
category分类，场景列表与报告依此筛选。
inputs入参声明，键是名称（英文字母、数字与 _），见下方场景契约。
outputs出参声明；有出参就要有 verify。
secrets机密名称列表，例如 ERP_PASSWORD（大写英文字母、数字与 _）。值不写在场景里。
login需要先登录时写 { role: 角色代号 }（与场景 id 相同的写法）。怎么登录、怎么判断已登录登记在管理 Portal 的角色上，场景只写用哪个角色；运行前先检查这个角色是否已登录（见下方运行顺序）。
browser运行环境模式的 Python 节点不能写。engine（chromium、firefox；webkit 可用但 CI 不测；默认 chromium）、headless（默认 true）、viewport（width、height）、baseUrl、locale（例如 zh-TW）。
defaultstimeout：单一步骤的默认超时。
deadline整次运行的总期限（毫秒），从启动浏览器算到发布出参；每一步只能用剩下的时间。
steps二择一自动化步骤列表，至少一步。
script二择一Python 节点。
verify独立断言列表，见下方场景契约。
网址以 / 开头时接在 browser.baseUrl 后面，同一个场景换环境（测试、正式）只要改 baseUrl。M1 的 params 已改名为 inputs，写旧名会提示新名。

场景契约

入参 → 步骤 → 页面事实 → 独立断言 → 出参
inputs
每个入参有 type（string、number、integer、boolean、array、object、file，默认 string；array、object 是 JSON 的数组与对象，上游节点同类型的出参可以直接接进来，不能写 enum 与长度、数值范围）、default、description，以及限制：enum、minLength、maxLength、pattern（字符串）、minimum、maximum（数字）。没有默认值代表运行时必须提供。默认值也要符合限制；可以是动态值（例如 {{today}}），每次运行时求值。
facts
页面事实：extract 以 as: 名称 存成 facts.名称。步骤只能引用前面步骤产生的事实；verify 与 outputs 可以引用全部。
verify
每一条有 value（必须含 {{ }}）与 equals、contains、matches（正则表达式）、notEmpty: true 其中一种比较；name 会出现在报告。比较时两边都以代入后的文字比较。
outputs
类型多了 array、object，限制同入参；from 指定取值，例如 {{ facts.record.recordId }}。只有一个 {{ }} 时保留原本的类型（例如列表），否则依 type 转换文字。
script
Python 节点：自动化与独立断言写成 Python，契约相同，见下一节。

运行顺序与失败时的处理见 ADR 0009；运行引擎在 M2 实现。rpa schema 场景文件 --part inputs 或 --part outputs 输出单一场景的入参或出参 JSON Schema。

Python 节点 script

ADR 0020：文件、数据处理、网络，和浏览器场景串在组合场景里

一个场景文件加几支 .py。入参、出参、Secrets、总期限、发布门槛和 DSL 场景相同；差别是「自动化」那一段由 automation.py 完成：它读入参、做事、把观察到的事实写进 facts，不判定成功；成功由独立断言判定（verify 或 assertion.py）。

# scenes/merge-branch-sales/revisions/1/scenario.yaml
schemaVersion: 1
id: merge-branch-sales
name: 合并分店销售报表
inputs:
  reports: { type: file, multiple: true, accept: [.xlsx] }   # 上游下载或上传的文件
  options: { type: object, default: { sheet: 销售 } }
outputs:
  total:    { type: number, from: '{{ facts.total }}' }
  byBranch: { type: object, from: '{{ facts.byBranch }}' }
deadline: 600000
script:
  runtime: "1"                       # RPA Python 运行环境 1；没写是兼容模式
  automation: automation.py
  files: [helpers.py, query.sql]     # 脚本会用到的其他文字档
  platforms: [windows, macos, linux] # 选用
verify:
  - name: 至少合并一份报表
    value: '{{ facts.fileCount }}'
    matches: '^[1-9][0-9]*$'
兼容模式（没写 runtime）运行环境模式（runtime: "1"）
解释器运行那台的 Python（打包后是 App 内的 Python，只有标准函数库与 App 内附的包）RPA Python 运行环境：固定的 Python 3.13 与包（Excel、pandas、Word、PDF、requests…），随 Worker App 与 Linux 分发包附带，第一次用到时解压、之后沿用
浏览器脚本可以自己用 Playwright 开（例如 scenarios/demo/ba-001-script/）不开；不能写 browser、login；交给没有浏览器、不能显示窗口的 Worker 也能运行
独立断言assertion 必要，不能写 verifyassertion 或 verify 二择一（没有出参时都可以不写）
出参由 assertion.py 写出，不写 from用 assertion.py 时同左；用 verify 时每个出参写 from，取自事实
文件入参不能用可以：脚本从 RPA_INPUT_FILES（或 run.input_files）拿到实际路径
派工同 DSL：要有场景的浏览器要有这个主版本的运行环境、平台在 platforms 里
automation、assertion
Python 文件的相对路径（相对于场景文件所在的文件夹，以 .py 结尾，不能用 ..）。automation.py 接受 --input --facts --screenshot --target-url，assertion.py 接受 --input --facts --output（沿用 MVP 原型的命令行契约；运行环境模式的 --target-url 是空字符串）。assertion.py 结束码不是 0 就是断言失败。
files
脚本会用到的其他文字档（例如 helpers.py、SQL、JSON 模板），最多 16 个，路径规则同上、任何扩展名；跟着版本存放、纳入场景哈希，脚本可以 import 同文件夹的 .py。二进位档（Excel 模板）放场景附件 files/，不列在这里。管理 Portal 的「完整场景文件」可以添加与移除这些文件。
platforms
windows、macos、linux 的子集，只派给这些系统的 Worker；没写是不限。
环境变量
两种模式都有 RPA_DEADLINE_SECONDS（剩下的总期限）、RPA_LANG（界面语言）与场景声明的 Secrets（同名）。运行环境模式另有 RPA_WORKSPACE（共用工作文件夹，也是工作目录）、RPA_OUTPUT_DIR（产出文件，运行目录的 outputs/，跟着上传）、RPA_INPUT_FILES（file 入参的路径，JSON 文件）、RPA_STEPS、RPA_RUNTIME、RPA_PLATFORM；不会有电脑上的 PYTHONPATH、VIRTUAL_ENV 之类的变量。兼容模式的浏览器相关变量见下方 rpa run。
共用工作文件夹
同一次组合运行的节点固定在同一台 Worker，共用一个工作文件夹：上一个节点下载、写出的文件，下一个节点用路径就读得到（路径入参也允许指到这里）。组合运行结束就删除；单独运行时是暂存文件夹，结束就删。要留下来给人看的文件写进 RPA_OUTPUT_DIR。
不是沙箱
Python 节点等于在 Worker 上以那位用户的身分运行任意程序；只给信任的人编辑，审核时特别标示，建议 Worker 用专用账号运行。

rpa_script（选用）

运行环境模式由 python -m rpa_script automation.py … 启动：照契约自己读写文件的脚本不用改；用 @automation 的脚本拿到一个 Run，报告会有步骤、数据预览与产出文件。兼容模式的脚本也可以 import 它（用 rpa_script.current()）。

from pathlib import Path

import pandas as pd

from rpa_script import Run, StepError, automation


@automation
def main(run: Run) -> None:
    with run.step("read", "读取分店报表"):            # 步骤：时间、结果、错误、源代码行号
        paths = run.input_files["reports"]
        if not paths:
            raise StepError("没有收到报表")           # 报告只显示消息
        frames = [pd.read_excel(path).assign(分店=Path(path).stem) for path in paths]
    with run.step("merge", "合并并计算总额"):
        merged = pd.concat(frames, ignore_index=True)
        run.preview("合并结果", merged)               # 数据预览：前 50 列、30 栏
        merged.to_excel(run.output_dir / "merged.xlsx", index=False)
        run.facts.update(fileCount=len(paths), total=float(merged["金额"].sum()),
                         byBranch=merged.groupby("分店")["金额"].sum().to_dict())

run.inputs（运行态入参）、run.input_files、run.secrets、run.facts、with run.step(id, 名称)（循环里同一个 id 记成第 n 次）、run.output_dir、run.workspace、run.preview(名称, 值)、run.log(消息)、StepError、run.remaining_seconds、run.platform、run.runtime、run.lang。主控台输出与错误里的 Secrets 值自动遮罩。

入参的动态值

每次运行开始时换成当下的日期、随机数

入参的值里可以写 {{ … }} 动态值：场景的 default、管理 Portal 运行表单的入参 JSON 与 API、rpa run -i／--input、试验场节点的固定值、逐步调试的入参都可以。{{ }} 里可以有空白，名称不分大小写；可以夹在文字中，例如 CG-001 创建于 {{today}}。

写法结果（以 2026-10-21 07:30:05 运行为例）
{{today}}2026-10-21
{{today+1}}、{{today-7}}2026-10-22、2026-10-14（往后、往前几天）
{{today:YYYY/MM/DD}}、{{today+1:yyyyMMdd}}、{{today:yyyy年MM月dd日}}2026/10/21、20261022、2026年10月21日
{{now}}、{{now:HH:mm}}、{{now:yyyyMMddHHmmss}}2026-10-21 07:30:05、07:30、20261021073005
{{random:10:30}}10 到 30 之间（含两端）的随机整数，每个 random 各自抽
{{"{{"}}引号里的文字原样保留，用来写出 {{ 本身
格式
yyyy／YYYY 年、MM 月、dd／DD 日、HH 时、mm 分、ss 秒（都补零），其他字符照写。today 只有日期，格式里写了时、分、秒会报错（最常见的是把月份写成小写 mm）。
求值的时间
每次运行开始时（入参阶段，启动浏览器之前），用运行那台电脑的本地时区；同一次运行的所有入参用同一个「现在」，所以 {{today}} 在每个入参都是同一天。运行记录保存原本的写法，重新运行会重新求值；input.json 与报告是实际用到的值。脚本、后续步骤、断言与报告共用这份运行态入参，每次引用不会重新抽样。
类型
求值的结果是数字的文字时（例如整个值是 {{random:10:30}}），integer、number 入参得到数字；其他都是文字，再照入参的 type 与限制校验。
校验
值里任何 {{ … }} 都当成动态值，看不懂（例如 {{tody}}、{{random:30:10}}）就报错。保存与排入队列时保留配置态写法：动态值只检查语法，不读取日期、不抽样、不枚举可能结果；普通值仍检查类型与限制。实际运行开始时才展开一次，针对这份运行态入参检查 type、enum、pattern、长度及数值范围。不符合时本次运行在启动浏览器前失败，不会重新抽到合格为止。例如 maximum: 20 配 {{random:10:30}} 可以保存，当次抽到 26 就回报超过上限；抽到 18 则继续运行。
录制的文字
录制稿中的填写内容照原样保留；即使文字含有 {{today}} 或其他大括号，也会自动跳脱。需要动态值时再编辑入参的默认值。
上游的出参
试验场把上游节点的出参交给下游时永远照原样，出参的文字里刚好有 {{ 也不会被求值。
步骤里
步骤的 {{ }} 是表达式，不能直接写 today、now、random；请在 inputs 加一个入参、默认值写动态值，步骤再引用 {{ inputs.名称 }}。
远程运行
动态值在运行的那台设备上求值，包含逐步调试与接著录制。调试重载保留已求值的入参，只对添加默认值求值；Portal 显示录制端实际用到的值。用到动态值的运行只交给回报看得懂 dynamicValues 的 Worker／录制端 App；旧的 App 会看到要更新的说明（同 M7a 的做法）。
inputs:
  arrivalDate: { default: "{{today}}" }
  expiryDate: { default: "{{today+1}}" }
  purchaseQuantity: { type: integer, minimum: 10, maximum: 30, default: "{{random:10:30}}" }
  remark: { default: "CG-001脚本创建{{today}}日期" }

YAML 里以 { 开头的值要加引号。也可以在管理 Portal 场景页的「入参」按「编辑」，把默认值改成 {{today}}，保存时会自动加引号。

上传文件

M7c：入参的 type: file 与 upload 步骤

要上传的文件一律是入参：场景里只写「这一步上传哪个入参」，每次运行再决定是哪个文件。网页看到的是文件原本的名称（或入参指定的 name），不会看到运行那台电脑上的暂存路径。

inputs:
  orderFile:
    type: file
    accept: [.xlsx, .xls, .csv]
    maxSize: 20MB
    default: { attachment: files/orders.csv, name: 订单导入.csv }
  photos: { type: file, multiple: true, accept: [image/*], default: [files/product.png] }
steps:
  - { id: open, action: goto, url: /upload }
  - id: choose-orders
    action: upload
    target: { label: 导入文件 }            # 上传框本身，隐藏的也可以
    files: '{{ inputs.orderFile }}'
  - id: attach
    action: upload
    trigger: { role: button, name: 选择附件 }   # 点了才开出选择文件窗口的按钮
    files: '{{ inputs.orderFile }}'
  - id: drop
    action: upload
    dropzone: { text: 把文件拖到这里 }      # 只有拖放区、没有上传框
    files: '{{ inputs.photos }}'
type: file
可以写 accept（清单；.扩展名 或 MIME，例如 image/*）、maxSize（例如 20MB、500KB）、multiple（一次多个文件，默认 false）、description 与 default；不能写 enum、pattern、长度与数值范围。出参没有 file 类型（之后随下载步骤加入）。
值的写法
三种来源：上传到管理 Portal 的文件 {"file": "代号", "name": "十月订单.xlsx"}（代号由上传回传，大小与 sha256 以服务器的为准）；这个版本的场景附件 files/文件名 或 {"attachment": "files/文件名", "name": "网页看到的名称"}；运行那台电脑上的路径 {"path": "D:/报表/{{today}}.xlsx"}（路径可以有动态值）。multiple: true 时写成列表，同一个入参不能混用上传档与路径。默认值不能是上传档（上传档会过期）。
场景附件
放在版本文件夹的 files/ 底下，跟着版本存放、git 同步，并纳入场景哈希（没有附件的场景哈希不变），验证的文件就是发布的文件。文件名只能用英文字母、数字、_、.、-；网页要看到中文文件名时在值里写 name。每个附件最多 20 MB、一个版本合计最多 50 MB。在管理 Portal 场景页的「场景附件」上传与删除，rpa pack check 也检查。
那台电脑上的路径
只能读允许的文件夹：RPA Worker App 的设置「文件入参可以读的文件夹」，或 Worker 与服务器本机的环境变量 RPA_INPUT_FOLDERS（多个用路径分隔符号隔开）；都没有设置时不能用 path。rpa run 在自己的电脑运行，不受限制。
upload
files 是 '{{ inputs.名称 }}' 或这种引用的清单（只能引用 file 入参）；写 [] 代表清空上传框，只能配 target。target 指向 input type=file（隐藏的、在 iframe 里的都可以；within 指向外层的按钮也行）；trigger 点击后等选择文件窗口再交出文件；dropzone 在页面里模拟拖放，文件要先送进页面，合计最多 20 MB。上传框一次只能选一个文件时给它多个会失败并说明。
等上传完成
upload 在文件交给网页时就算完成；网页之后送到服务器要多久不一定，用后面的 waitFor／expect 等画面上的结果，不加固定秒数。
运行时
入参阶段（启动浏览器之前）找出每个文件、检查 accept、maxSize 与合计上限，以网页要看到的名称放进暂存文件夹，运行完删除。input.json、报告与 {{ inputs.名称 }} 看到的是 {name, size, sha256}（清单时是清单），没有本机路径；verify 可以拿 {{ inputs.orderFile.sha256 }} 和网页收到的比较。
选择文件窗口
每一页都会拦下选择文件的窗口：不是 upload 开出来的（例如录制时点了上传按钮，录制稿只有 click）会自动关掉，步骤照常继续，记一条提醒「把这一步改成 upload，用 trigger 指定这个元素」。
录制稿转换
set_input_files 转成 upload 加一个 file 入参（名称取自元素，accept 取自录到的扩展名，多个文件时 multiple: true），前一个点同一个元素的 click 会拿掉；录制稿只有文件名，要在入参放文件（例如加成场景附件）。
上限与保留
上传档单一文件默认最多 50 MB、一次运行合计 200 MB（RPA_UPLOAD_MAX_FILE_MB、RPA_UPLOAD_MAX_RUN_MB）。上传后 24 小时没被用到就删；用过的保留到最后一次使用后 90 天（RPA_UPLOAD_KEEP_DAYS）；全部超过 10 GB（RPA_UPLOAD_MAX_TOTAL_GB）时从最久没用的开始删；组合场景节点的固定文件不删。只删内容，运行记录仍看得到当时的文件名与 sha256。
命令行
rpa run 场景 -i orderFile=data/十月订单.xlsx -i photos=files/a.png -i photos=b.png：值是 files/… 时是场景附件，其他是这台电脑上的路径；同一个 multiple 入参重复写就是多个文件。
远程运行
上传档由 Worker 与录制端另外下载并比较大小与 sha256；场景附件跟着版本的文件送过去。用到 upload 或文件入参的场景只交给回报看得懂 upload、fileInputs 的 App，旧的 App 看到要更新的说明。Python 节点只有运行环境模式能用文件入参。

步骤共同字段

id
必填，场景内唯一。格式同场景 id。
action
必填，动作名称，见下方动作表。
name
给人看的步骤说明。
timeout
这一步的超时，毫秒整数，大于 0、最多 3,600,000（一小时）。没写就用 defaults.timeout；不会超过总期限剩下的时间。
page
在哪个分页运行（M7b）：前面某一步用 popup 开出来的分页名称；没写是一开始的分页。名称要在「之前」的步骤开过，不然校验时指出这一步。
popup
只有 click、fill、select、check、press 可以写（M7b）：这一步会开出新分页（弹出窗口，例如链接的 target="_blank" 或 window.open），运行时等它开好并取这个名称，之后的步骤用 page 指定它；同一个名称只能开一次。没有开出新分页时这一步超时失败。例如 { action: click, target: { role: link, name: 打开商品明细 }, popup: items }，之后 { action: fill, page: items, target: { placeholder: 请选择 }, value: … }。

retry 与 onError 在 M7 加入；重试只用于没有副作用的步骤，送出表单之类的动作不会自动重试。

字符串匹配

expect 的 text、value、url、title 与 waitFor 的 url 用 match 指定匹配方式：

contains
默认。包含这段文字即可，例如 text: 欢迎 对得到「欢迎回来，王小明」。
equals
完全相等。
regex
Python re 语法的正则表达式；校验时会先编译，写错会报错。

定位器 target

恰好指定一种主要方式
主要方式对应 Playwright适合
testIdget_by_test_id系统有测试用属性时最稳定
role（搭配 name）get_by_role按钮、链接、输入框等；role 是 ARIA 角色，例如 button、textbox、link、row
labelget_by_label有标签的表单字段
placeholderget_by_placeholder没有标签、只有提示文字的输入框
textget_by_text依画面上的文字
altTextget_by_alt_text图片
titleget_by_title有 title 属性的元素
csslocator("css=…")其他方式都不行时；避免自动产生的 id 或 class
xpathlocator("xpath=…")最后手段
name
role 的无障碍名称，例如按钮上的文字。只能搭配 role。
exact
文字要完全相符（默认为包含且不分大小写）。用于 role + name、label、placeholder、text、altText、title。
nth
符合多个元素时取第几个：0 是第一个，-1 是最后一个。
hasText
只保留内含这段文字的元素，例如找出含有某个订单编号的那一列。
within
另一个定位器：先找到外层元素（表格、对话框），再在里面找。
frame
元素在 iframe 里时，指出那个 iframe 的定位器：先找到 iframe，再在它加载的页面里找（within 也在那个页面里找）。iframe 里还有 iframe 时，在 frame 里再写 frame（外层的 iframe），例如 { label: 我已确认, frame: { css: "#note-frame", frame: { css: "#form-frame" } } }。没写 frame 只在最外层的页面找。（M7a）
anyFrame
true：在页面与所有 iframe（含嵌套）里找，不必写出是哪个 iframe，但要刚好只在一个 iframe 里找到。codegen 对两层以上的 iframe 会录成不带参数的 frame_locator()，转换后就是 anyFrame，例如 { role: checkbox, name: 我已确认, anyFrame: true }。只能写在最外层（有 frame 时写在最深的那个 frame 上），不能写在 within 里。（M7a）
fallback
备用定位器列表，主要方式失败时依序尝试（M2 运行、M5 自愈时使用）。备用定位器不能再有 fallback；没写 frame 时沿用主要定位器的 frame。

存成页面事实 facts.名称；同一个场景内不能重复。
extract 的 get
text（默认）、value、html、attribute（要用 attribute 指定属性名称）、table（把 <table> 依表头转成记录列表）。

抽取所有符合的元素，得到列表；默认只取第一个。
extract 的 fields
每个元素抽成一笔记录，键是字段名称，值可写 target（相对于该元素）、get、attribute。有 fields 时不写外层的 get。
expect 是步骤内的防护，verify 才决定是否发布出参。download、条件与循环等在 M7 加入；upload 提前到 M7c（上传文件）；iframe 用定位器的 frame（M7a），新分页用步骤的 popup 与 page（M7b）。

YAML 编写规则

  • 只用 YAML 1.2 core 规则。yes、no、on 是字符串，不是布尔；2026-09-01 是字符串，不是日期；12:30 是字符串，不是六十进位数字。
  • 不自动转型。字符串字段写了数字或 true/false 会报错，请加引号，例如 value: "0123"。
  • 以 {{ 开头的值要加引号。例如 value: "{{ inputs.title }}"、default: "{{today}}"；没加引号时 YAML 会读成对象，校验会提示加引号。
  • 键不能重复。同一层出现两次的键会报错并指出第一次出现的行号。
  • 无法识别的字段会报错。名称相近时提示正确写法，例如 fullpage → fullPage。
  • 只接受一般的标签。!!python/…、!!binary 与自订标签一律拒绝；锚点与别名可以用，不支持 << 合并。
  • 编码是 UTF-8。可以有 BOM。

表达式 {{ }}

Jinja2；M2 在沙箱内求值
  • 可用的变量只有 inputs、secrets、facts、env；可以用 Jinja2 的过滤器，例如 {{ inputs.title | upper }}。
  • 校验时就会检查语法、未知的变量与过滤器、没有声明的 inputs 与 secrets、没有 extract 产生或还没产生的 facts。
  • facts 不能用在 browser 设置，因为那时还没开始操作页面。
  • today、now、random 是入参值的动态值，不是这里的变量；写在步骤里时校验会提示改写在入参。
  • 场景、步骤与断言的 name、description 是给人看的文字，不检查也不代入。

$ rpa run scenarios/demo/ba-002.yaml --input runs/ba-001-…/output.json   # 无法识别的入参会报错，可改用 -i recordId=…
顺序
入参校验（有问题就不启动浏览器）→ 登录检查（只有写了 login 的场景：打开角色的确认网址，看不到已登录的元素时先自动登录，不能自动登录就停在「需要登录」needs_login，不运行任何步骤）→ 在子进程中运行步骤或 automation.py → 独立断言（verify 或 assertion.py）→ 出参转型与校验 → 写出 output.json。任何一步失败都没有成功出参。
总期限
以单调时钟计算；每一步只能用剩下的时间。子进程超过期限就终止整个进程组，结果是「超时」。
选项
-i 名称=值（依类型转换，可重复；array、object 写 JSON）、--input 文件.json、--base-url、--browser chromium|firefox、--headed、--video（录像成运行目录的 video.webm，M12；只有 DSL 场景）、--deadline 毫秒、--out 文件夹（默认 runs/）、--format json、--storage-state 登录状态.json（场景有 login 时加载这个 storageState，只加载不检查；检查与人工登录在管理 Portal）。退出码：0 通过、1 未通过。
运行目录
input.json、facts.json、steps.json、output.json（只有通过时）、screenshot.png 与 screenshot 步骤的截图、automation.log（自动化日志：开头写这次的浏览器、窗口模式、起始网址与开始时间，接着每一步一行（时间、第几步、名称与动作、通过或失败、耗时；打开网页与出错时加上网址），失败时写出错的步骤、略过的步骤、证据在哪里与完整的错误原文；时间是运行那台电脑的当地时间，网址与错误遮罩 Secrets，不写入参的值）、diagnostic.json（失败时）、scenario/（本次的场景快照）、result.json、report.html；有登录检查时另有 login.json、login.log 与 login.png。登录状态本身不拷贝进来。
Secrets
命令行从同名的环境变量读取（例如 ERP_PASSWORD）；管理 Portal 先用「登录与凭证」设置的值，没有才找环境变量。只传给子进程，日志与报告中会遮罩；M8 改为加密存放。
Python 节点
运行环境模式在入参之后多一个「运行环境」阶段（准备运行环境，不算进总期限），见 Python 节点。兼容模式：剩下的总期限在环境变量 RPA_DEADLINE_SECONDS，浏览器在 RPA_BROWSER，目前的语言在 RPA_LANG（脚本要写给人看的消息时可以参考），要不要显示浏览器窗口在 RPA_HEADLESS（0 有头模式、1 无头模式），场景有 login 时登录状态档的路径在 RPA_STORAGE_STATE（给 browser.new_context(storage_state=…)）；示例见 scenarios/demo/ba-001-script/。脚本自己启动浏览器，不使用下面的预热设置档。
Firefox 设置档
Firefox 每次用全新的设置档启动时，会先初始化设置档而停止回应几秒（Windows 上机器忙时可能超过步骤的超时）。所以每台电脑、每个 Firefox 版本会保留一份预先初始化过的空白设置档，每次运行拷贝一份来用，结束后删除，每次运行仍然是干净的。第一次用 Firefox 运行时创建，约多花 7～10 秒。放在缓存文件夹 RPA_CACHE_DIR，默认是 Windows 的 %LOCALAPPDATA%\rpa\cache、macOS 的 ~/Library/Caches/rpa、Linux 的 ~/.cache/rpa；删掉也没关系，下次会重建。

参数
文件或文件夹，可以多个；文件夹会找出底下所有 .yaml 与 .yml（略过隐藏文件夹）。脚本场景会检查脚本文件是否存在。

rpa pack check
校验领域文件夹（M11）：说明档的格式、版本内容与版本说明档的哈希、验证记录、发布门槛、角色定义，以及不能放进文件夹的登录状态、Secrets 与私钥；规则和管理 Portal 加载时相同。--id 要求 pack.yaml 的代号；--format json 给程序使用。有错误时退出码 1（警告不算），可以放在数据仓库的 CI。
rpa schema
输出 DSL 的 JSON Schema。仓库中的 schema/scenario.v1.json 由它产生；场景文件第一行加上 # yaml-language-server: $schema=…，VS Code 的 YAML 插件就能自动补全与实时检查。指定场景文件时输出该场景的入参或出参 Schema。
Python
rpa_core.dsl.validate_file()、validate_text()、validate_data() 回传场景模型与所有问题；inputs_json_schema()、outputs_json_schema() 产生单一场景的契约。管理界面与 API 也用同一套。
