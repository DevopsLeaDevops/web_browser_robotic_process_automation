场景 DSL

场景的唯一真实来源。YAML 编写、JSON 存储，以 Pydantic 模型校验；本页是 schemaVersion 1 的规格。

schemaVersion 1 · M1 定稿
模型在 packages/rpa_core/src/rpa_core/dsl/，完整示例在 examples/，JSON Schema 在 schema/scenario.v1.json。决策背景见 ADR 0001。

示例

节录自 examples/erp-login.yaml
# yaml-language-server: $schema=../schema/scenario.v1.json
schemaVersion: 1
id: erp-login
name: 登录 ERP
params:
  user: { type: string, description: 登录账号 }
secrets: [ERP_PASSWORD]
browser:
  baseUrl: https://erp.example.internal
  viewport: { width: 1280, height: 800 }
defaults:
  timeout: 10000
steps:
  - id: open
    action: goto
    url: /login
  - id: fill-user
    action: fill
    target: { role: textbox, name: 账号 }
    value: "{{ params.user }}"
  - id: fill-password
    action: fill
    target: { label: 密码 }
    value: "{{ secrets.ERP_PASSWORD }}"
  - id: submit
    action: click
    target:
      role: button
      name: 登录
      fallback: [{ testId: login-submit }]
  - id: check-welcome
    action: expect
    target: { text: 欢迎回来 }
    state: visible

设计原则

  • 每个步骤有稳定的 id。运行结果、截图与日志按步骤归档；插入或删除步骤时不会错位。
  • 定位器有优先级。testId → role + name → label → placeholder → text → altText → title → css → xpath。录制时同时记下多个候选放在 fallback，作为自愈的基础。
  • 只用条件等待。不提供固定秒数的 sleep，改用 waitFor 等待元素、网址或加载状态。
  • 写错就挡下来。无法识别的字段、类型不符、YAML 的隐式转型都在校验时报错，并指出文件行号、步骤与字段。
  • Secrets 只引用名称。值在运行时注入，日志与截图说明自动遮罩。
  • 表达式在沙箱内求值。{{ }} 以 Jinja2 沙箱环境处理（M3），只能读取 params、env、secrets 与先前步骤的输出。
  • 保留逃生门。DSL 表达不了的情况使用受控的 script 步骤（M3 之后），并在审核时特别标示。

场景顶层

字段名称一律是 camelCase
字段必填说明
schemaVersion是DSL 版本，目前是 1。格式有不兼容的变更时递增，并提供迁移。
id是小写英文字母、数字、- 与 _，以英数开头，最长 64 个字符。会用在文件名与网址。
name是给人看的名称。
description说明。
params参数声明，键是参数名称（英文字母、数字与 _）。每个参数有 type（string、number、integer、boolean，默认 string）、default、description；没有默认值代表运行时必须提供。
secrets机密名称列表，例如 ERP_PASSWORD（大写英文字母、数字与 _）。值不写在场景里。
browserengine（chromium、firefox、webkit，默认 chromium）、headless（默认 true）、viewport（width、height）、baseUrl、locale（例如 zh-TW）。
defaultstimeout：步骤默认超时。
steps是步骤列表，至少一步。
网址以 / 开头时接在 browser.baseUrl 后面，同一个场景换环境（测试、正式）只要改 baseUrl。

步骤共同字段

id
必填，场景内唯一。格式同场景 id。
action
必填，动作名称，见下方动作表。
name
给人看的步骤说明。
timeout
这一步的超时，毫秒整数，大于 0、最多 3,600,000（一小时）。没写就用 defaults.timeout。

retry 与 onError（继续、失败、跳到某一步）在 M3 加入。

字符串匹配

expect 的 text、value、url、title 与 waitFor 的 url 用 match 指定匹配方式：

contains
默认。包含这段文字即可，例如 text: 欢迎 对得到「欢迎回来，王小明」。
equals
完全相等。
regex
Python re 语法的正则表达式；校验时会先编译，写错会报错。

定位器 target

恰好指定一种主要方式
主要方式对应 Playwright适合
testIdget_by_test_id系统有测试用属性时最稳定
role（搭配 name）get_by_role按钮、链接、输入框等；role 是 ARIA 角色，例如 button、textbox、link、row
labelget_by_label有标签的表单字段
placeholderget_by_placeholder没有标签、只有提示文字的输入框
textget_by_text依画面上的文字
altTextget_by_alt_text图片
titleget_by_title有 title 属性的元素
csslocator("css=…")其他方式都不行时；避免自动产生的 id 或 class
xpathlocator("xpath=…")最后手段
name
role 的无障碍名称，例如按钮上的文字。只能搭配 role。
exact
文字要完全相符（默认为包含且不分大小写）。用于 role + name、label、placeholder、text、altText、title。
nth
符合多个元素时取第几个：0 是第一个，-1 是最后一个。
hasText
只保留内含这段文字的元素，例如找出含有某个订单编号的那一列。
within
另一个定位器：先找到外层元素（表格、对话框），再在里面找。
fallback
备用定位器列表，主要方式失败时依序尝试（M2 运行、M5 自愈时使用）。备用定位器不能再有 fallback。

动作

粗体为必填
动作用途字段规则
goto打开网址url、waitUntil（load、domcontentloaded、networkidle、commit；默认 load）url 是 http(s) 网址、about:blank，或以 / 开头并设置 baseUrl
click点击元素target、button（left、right、middle）、clickCount（1–3）、modifiers（Alt、Control、ControlOrMeta、Meta、Shift）
fill清空输入框后填入target、valuevalue 是字符串；空字符串代表清空，数字要加引号
select选择下拉选项target、optionoption 是选项的值或显示文字；写成列表代表多选
press按键或组合键key（Enter、Tab、Control+A…）、target没有 target 时送给目前聚焦的元素
waitFor等待条件成立target + state（visible、hidden、attached、detached）、url + match、loadState三种条件恰好选一种
expect断言，不成立即判定失败target + state、text、value、count 其一；或不给 target，检查 url、title 其一；matchstate 可用 visible、hidden、enabled、disabled、checked、unchecked、editable
extract从页面抽取数据target、as、get、attribute、multiple、fields见下方说明
screenshot截图存为产物file、target、fullPagefile 是不含扩展名的文件名，没写就用步骤 id；fullPage 不能搭配 target
extract 的 get
text（默认）、value、html、attribute（要用 attribute 指定属性名称）、table（把 <table> 依表头转成记录列表）。
extract 的 multiple
抽取所有符合的元素，得到列表；默认只取第一个。
extract 的 fields
每个元素抽成一笔记录，键是字段名称，值可写 target（相对于该元素）、get、attribute。有 fields 时不写外层的 get。
extract 的 as
存成的变量名称，之后的步骤可以引用（M3）。
download、upload、iframe、多标签页、条件与循环等在 M3 加入。

YAML 编写规则

  • 只用 YAML 1.2 core 规则。yes、no、on 是字符串，不是布尔；2026-09-01 是字符串，不是日期；12:30 是字符串，不是六十进位数字。
  • 不自动转型。字符串字段写了数字或 true/false 会报错，请加引号，例如 value: "0123"。
  • 键不能重复。同一层出现两次的键会报错并指出第一次出现的行号。
  • 无法识别的字段会报错。名称相近时提示正确写法，例如 fullpage → fullPage。
  • 只接受一般的标签。!!python/…、!!binary 与自订标签一律拒绝；锚点与别名可以用，不支持 << 合并。
  • 编码是 UTF-8。可以有 BOM。

表达式 {{ }}

M1 只做静态检查
  • 字符串字段可以写 {{ params.名称 }}、{{ secrets.名称 }}、{{ env.名称 }}，求值在 M3 加入。
  • 校验时检查 {{ 有没有对应的 }}、内容是否空白，以及引用的 params、secrets 有没有声明。
  • 场景与步骤的 name、description 是给人看的文字，不检查也不代入。

校验：rpa validate

$ rpa validate examples/ scenarios/login.yaml
scenarios/login.yaml:14:9: 步骤 3（login-pass） › target.css：只能指定一种定位方式，目前有：label, css；其他写法可以放在 fallback
scenarios/login.yaml:20:5: 步骤 4（shot） › fullpage：无法识别的字段 fullpage，是不是 fullPage？
检查 3 个文件，1 个未通过，共 2 个问题。
位置
文件:行:列，与编译器相同的格式，编辑器与 CI 可以直接跳到错误位置。行与列从 1 开始。
参数
文件或文件夹，可以多个；文件夹会找出底下所有 .yaml 与 .yml（略过隐藏文件夹）。
--format json
每个问题含 line、column、step、stepId、field、path、code、message，给程序与 AI 自动修正（M5）使用。
退出码
0 全部通过；1 有文件未通过，或文件夹里没有 YAML；2 参数错误。
rpa schema
输出 JSON Schema。仓库中的 schema/scenario.v1.json 由它产生；场景文件第一行加上 # yaml-language-server: $schema=…，VS Code 的 YAML 插件就能自动补全与实时检查。
Python
rpa_core.dsl.validate_file()、validate_text()、validate_data() 回传场景模型与所有问题；Web UI 与 API 也用同一套。
