场景 DSL

场景的唯一真实来源。YAML 编写、JSON 存储，以 Pydantic 模型校验；包含入参、出参与独立断言的场景契约。本页是 schemaVersion 1 的规格。

schemaVersion 1 · M1.1
模型在 packages/rpa_core/src/rpa_core/dsl/，示例在 scenarios/，JSON Schema 在 schema/scenario.v1.json。决策背景见 ADR 0001 与 ADR 0009。

示例

节录自 scenarios/demo/ba-001.yaml（MVP 原型的 BA-001）
# yaml-language-server: $schema=../../schema/scenario.v1.json
schemaVersion: 1
id: ba-001
name: 创建示例记录
category: 示例数据
inputs:
  title: { type: string, minLength: 1, maxLength: 60 }
  quantity: { type: integer, minimum: 1, maximum: 30, default: 12 }
outputs:
  recordId:
    pattern: '^DEMO-[A-Z0-9]+$'
    from: '{{ facts.record.recordId }}'
browser: { engine: firefox, baseUrl: http://127.0.0.1:8765 }
deadline: 45000
steps:
  - id: open
    action: goto
    url: /
  - id: fill-title
    action: fill
    target: { label: 标题, exact: true }
    value: '{{ inputs.title }}'
  - id: submit
    action: click
    target: { role: button, name: 创建记录 }
  - id: read-record
    action: extract
    target: { css: '#receipt' }
    as: record
    fields:
      recordId: { target: { css: '#record-id' } }
      status: { target: { css: '#record-status' } }
verify:
  - name: 状态是已创建
    value: '{{ facts.record.status }}'
    equals: 已创建

设计原则

  • 成功要有证据。步骤只操作页面、留下页面事实；由独立断言 verify 判定成功，通过后才发布出参。「脚本没有出错」不等于成功。
  • 入参、出参是契约。入参在启动浏览器前校验；出参可以串到下一个场景的入参。两者都能导出成 JSON Schema。
  • 每个步骤有稳定的 id。运行结果、截图与日志按步骤归档；插入或删除步骤时不会错位。
  • 定位器有优先级。testId → role + name → label → placeholder → text → altText → title → css → xpath。录制时同时记下多个候选放在 fallback，作为自愈的基础。
  • 只用条件等待。不提供固定秒数的 sleep，改用 waitFor；整次运行受 deadline 限制。
  • 写错就挡下来。无法识别的字段、类型不符、YAML 的隐式转型都在校验时报错，并指出文件行号、步骤与字段。
  • Secrets 只引用名称。值在运行时注入，日志与截图说明自动遮罩。
  • 保留逃生门。DSL 表达不了的场景可以改用 Python 脚本（script），沿用同一份契约，审核时特别标示。

场景顶层

字段名称一律是 camelCase
字段必填说明
schemaVersion是DSL 版本，目前是 1。格式有不兼容的变更时递增，并提供迁移。
id是小写英文字母、数字、- 与 _，以英数开头，最长 64 个字符。会用在文件名与网址，不重复使用。
name是给人看的名称。
description说明。
category分类，场景列表与报告依此筛选。
inputs入参声明，键是名称（英文字母、数字与 _），见下方场景契约。
outputs出参声明；有出参就要有 verify。
secrets机密名称列表，例如 ERP_PASSWORD（大写英文字母、数字与 _）。值不写在场景里。
browserengine（chromium、firefox；webkit 可用但 CI 不测；默认 chromium）、headless（默认 true）、viewport（width、height）、baseUrl、locale（例如 zh-TW）。
defaultstimeout：单一步骤的默认超时。
deadline整次运行的总期限（毫秒），从启动浏览器算到发布出参；每一步只能用剩下的时间。
steps二择一自动化步骤列表，至少一步。
script二择一Python 脚本逃生门，见下方场景契约。
verify独立断言列表，见下方场景契约。
网址以 / 开头时接在 browser.baseUrl 后面，同一个场景换环境（测试、正式）只要改 baseUrl。M1 的 params 已改名为 inputs，写旧名会提示新名。

场景契约

入参 → 步骤 → 页面事实 → 独立断言 → 出参
inputs
每个入参有 type（string、number、integer、boolean，默认 string）、default、description，以及限制：enum、minLength、maxLength、pattern（字符串）、minimum、maximum（数字）。没有默认值代表运行时必须提供。默认值也要符合限制。
facts
页面事实：extract 以 as: 名称 存成 facts.名称。步骤只能引用前面步骤产生的事实；verify 与 outputs 可以引用全部。
verify
每一条有 value（必须含 {{ }}）与 equals、contains、matches（正则表达式）、notEmpty: true 其中一种比较；name 会出现在报告。比较时两边都以代入后的文字比较。
outputs
类型多了 array、object，限制同入参；from 指定取值，例如 {{ facts.record.recordId }}。只有一个 {{ }} 时保留原本的类型（例如列表），否则依 type 转换文字。
script
automation 与 assertion 两个 Python 文件，路径相对于场景文件所在的文件夹、不能用 ..。automation.py 接受 --input --facts --screenshot --target-url，assertion.py 接受 --input --facts --output（沿用 MVP 原型的命令行契约）。脚本场景不写 verify，出参也不写 from。

运行顺序与失败时的处理见 ADR 0009；运行引擎在 M2 实现。rpa schema 场景文件 --part inputs 或 --part outputs 输出单一场景的入参或出参 JSON Schema。

步骤共同字段

id
必填，场景内唯一。格式同场景 id。
action
必填，动作名称，见下方动作表。
name
给人看的步骤说明。
timeout
这一步的超时，毫秒整数，大于 0、最多 3,600,000（一小时）。没写就用 defaults.timeout；不会超过总期限剩下的时间。

retry 与 onError 在 M7 加入；重试只用于没有副作用的步骤，送出表单之类的动作不会自动重试。

字符串匹配

expect 的 text、value、url、title 与 waitFor 的 url 用 match 指定匹配方式：

contains
默认。包含这段文字即可，例如 text: 欢迎 对得到「欢迎回来，王小明」。
equals
完全相等。
regex
Python re 语法的正则表达式；校验时会先编译，写错会报错。

定位器 target

恰好指定一种主要方式
主要方式对应 Playwright适合
testIdget_by_test_id系统有测试用属性时最稳定
role（搭配 name）get_by_role按钮、链接、输入框等；role 是 ARIA 角色，例如 button、textbox、link、row
labelget_by_label有标签的表单字段
placeholderget_by_placeholder没有标签、只有提示文字的输入框
textget_by_text依画面上的文字
altTextget_by_alt_text图片
titleget_by_title有 title 属性的元素
csslocator("css=…")其他方式都不行时；避免自动产生的 id 或 class
xpathlocator("xpath=…")最后手段
name
role 的无障碍名称，例如按钮上的文字。只能搭配 role。
exact
文字要完全相符（默认为包含且不分大小写）。用于 role + name、label、placeholder、text、altText、title。
nth
符合多个元素时取第几个：0 是第一个，-1 是最后一个。
hasText
只保留内含这段文字的元素，例如找出含有某个订单编号的那一列。
within
另一个定位器：先找到外层元素（表格、对话框），再在里面找。
fallback
备用定位器列表，主要方式失败时依序尝试（M2 运行、M5 自愈时使用）。备用定位器不能再有 fallback。

动作

粗体为必填
动作用途字段规则
goto打开网址url、waitUntil（load、domcontentloaded、networkidle、commit；默认 load）url 是 http(s) 网址、about:blank，或以 / 开头并设置 baseUrl
click点击元素target、button（left、right、middle）、clickCount（1–3）、modifiers（Alt、Control、ControlOrMeta、Meta、Shift）
fill清空输入框后填入target、valuevalue 是字符串；空字符串代表清空，数字要加引号
select选择下拉选项target、optionoption 是选项的值或显示文字；写成列表代表多选
press按键或组合键key（Enter、Tab、Control+A…）、target没有 target 时送给目前聚焦的元素
waitFor等待条件成立target + state（visible、hidden、attached、detached）、url + match、loadState三种条件恰好选一种
expect步骤内的检查，不成立即判定失败target + state、text、value、count 其一；或不给 target，检查 url、title 其一；matchstate 可用 visible、hidden、enabled、disabled、checked、unchecked、editable
extract抽取页面事实target、as、get、attribute、multiple、fields见下方说明
screenshot截图存为产物file、target、fullPagefile 是不含扩展名的文件名，没写就用步骤 id；fullPage 不能搭配 target
extract 的 as
存成页面事实 facts.名称；同一个场景内不能重复。
extract 的 get
text（默认）、value、html、attribute（要用 attribute 指定属性名称）、table（把 <table> 依表头转成记录列表）。
extract 的 multiple
抽取所有符合的元素，得到列表；默认只取第一个。
extract 的 fields
每个元素抽成一笔记录，键是字段名称，值可写 target（相对于该元素）、get、attribute。有 fields 时不写外层的 get。
expect 是步骤内的防护，verify 才决定是否发布出参。download、upload、iframe、多标签页、条件与循环等在 M7 加入。

YAML 编写规则

  • 只用 YAML 1.2 core 规则。yes、no、on 是字符串，不是布尔；2026-09-01 是字符串，不是日期；12:30 是字符串，不是六十进位数字。
  • 不自动转型。字符串字段写了数字或 true/false 会报错，请加引号，例如 value: "0123"。
  • 键不能重复。同一层出现两次的键会报错并指出第一次出现的行号。
  • 无法识别的字段会报错。名称相近时提示正确写法，例如 fullpage → fullPage。
  • 只接受一般的标签。!!python/…、!!binary 与自订标签一律拒绝；锚点与别名可以用，不支持 << 合并。
  • 编码是 UTF-8。可以有 BOM。

表达式 {{ }}

Jinja2；M2 在沙箱内求值
  • 可用的变量只有 inputs、secrets、facts、env；可以用 Jinja2 的过滤器，例如 {{ inputs.title | upper }}。
  • 校验时就会检查语法、未知的变量与过滤器、没有声明的 inputs 与 secrets、没有 extract 产生或还没产生的 facts。
  • facts 不能用在 browser 设置，因为那时还没开始操作页面。
  • 场景、步骤与断言的 name、description 是给人看的文字，不检查也不代入。

运行：rpa run

M2
$ uv run python -m testsite --port 8765          # 另开一个终端：本机测试网站
$ rpa run scenarios/demo/ba-001.yaml -i title=测试 -i quantity=3
ba-001 创建示例记录：通过（1.4 秒）
出参：runs/ba-001-20261010-123405-164e7e/output.json
报告：runs/ba-001-20261010-123405-164e7e/report.html
$ rpa run scenarios/demo/ba-002.yaml --input runs/ba-001-…/output.json   # 无法识别的入参会报错，可改用 -i recordId=…
顺序
入参校验（有问题就不启动浏览器）→ 在子进程中运行步骤或 automation.py → 独立断言（verify 或 assertion.py）→ 出参转型与校验 → 写出 output.json。任何一步失败都没有成功出参。
总期限
以单调时钟计算；每一步只能用剩下的时间。子进程超过期限就终止整个进程组，结果是「超时」。
选项
-i 名称=值（依类型转换，可重复）、--input 档.json、--base-url、--browser chromium|firefox、--headed、--deadline 毫秒、--out 文件夹（默认 runs/）、--format json。退出码：0 通过、1 未通过。
运行目录
input.json、facts.json、steps.json、output.json（只有通过时）、screenshot.png 与 screenshot 步骤的截图、automation.log、diagnostic.json（失败时）、scenario/（本次的场景快照）、result.json、report.html。
Secrets
M2 从同名的环境变量读取（例如 ERP_PASSWORD），只传给子进程，日志与报告中会遮罩；M8 改为加密存放。
Python 脚本场景
剩下的总期限在环境变量 RPA_DEADLINE_SECONDS，浏览器在 RPA_BROWSER；示例见 scenarios/demo/ba-001-script/。

校验：rpa validate

$ rpa validate scenarios/
scenarios/login.yaml:14:9: 步骤 3（login-pass） › target.css：只能指定一种定位方式，目前有：label, css；其他写法可以放在 fallback
scenarios/login.yaml:31:15: 步骤 5（read） › value：facts.total 要等后面的 extract 步骤才会产生
检查 5 个文件，1 个未通过，共 2 个问题。
位置
文件:行:列，与编译器相同的格式，编辑器与 CI 可以直接跳到错误位置。行与列从 1 开始。
参数
文件或文件夹，可以多个；文件夹会找出底下所有 .yaml 与 .yml（略过隐藏文件夹）。脚本场景会检查脚本文件是否存在。
--format json
每个问题含 line、column、step、stepId、field、path、code、message，给程序与 AI 自动修正（M5）使用。
退出码
0 全部通过；1 有文件未通过，或文件夹里没有 YAML；2 参数错误。
rpa schema
输出 DSL 的 JSON Schema。仓库中的 schema/scenario.v1.json 由它产生；场景文件第一行加上 # yaml-language-server: $schema=…，VS Code 的 YAML 插件就能自动补全与实时检查。指定场景文件时输出该场景的入参或出参 Schema。
Python
rpa_core.dsl.validate_file()、validate_text()、validate_data() 回传场景模型与所有问题；inputs_json_schema()、outputs_json_schema() 产生单一场景的契约。管理界面与 API 也用同一套。
