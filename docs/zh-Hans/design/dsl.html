范例

示意；download 在 M3 加入
id: erp-export-report
name: 登录 ERP 并导出月报
params:
  month: { type: string, default: "2026-09" }
secrets: [ERP_PASSWORD]
browser: { engine: chromium, headless: true }
steps:
  - id: open
    action: goto
    url: https://erp.example.internal/login
  - id: login-user
    action: fill
    target: { role: textbox, name: 账号 }
    value: "{{ env.ERP_USER }}"
  - id: login-pass
    action: fill
    target: { label: 密码 }
    value: "{{ secrets.ERP_PASSWORD }}"
  - id: submit
    action: click
    target:
      role: button
      name: 登录
      fallback: [{ css: "#login-btn" }]
  - id: check
    action: expect
    target: { text: 欢迎回来 }
    state: visible
  - id: export
    action: download
    trigger:
      action: click
      target: { role: button, name: 导出 }
    saveAs: "report-{{ params.month }}.xlsx"

设计原则

  • 每个步骤有稳定的 id。运行结果、截图与日志按步骤归档；界面编辑时不会错位。
  • 定位器有优先级。testId → role + name → label → text → css / xpath。录制时同时记下多个候选，作为自愈的基础。
  • 只用条件等待。不允许固定秒数的 sleep，改用 waitFor 等待元素、网址或网络状态。
  • 步骤级错误处理。每一步可设置 retry、timeout 与 onError（继续、失败、跳到某一步）。
  • Secrets 只引用名称。值在运行时注入，日志与截图说明自动遮罩。
  • 表达式在沙箱内求值。{{ }} 以 Jinja2 沙箱环境处理，只能读取 params、env、secrets 与先前步骤的输出。
  • 保留逃生门。DSL 表达不了的情况使用受控的 script 步骤，并在审核时特别标示。

M1 预计支持的动作

动作用途主要字段
goto打开网址url、waitUntil
click点击元素target、button、clickCount
fill填写输入框target、value
select选择下拉选项target、option
press按键或组合键target、key
waitFor等待条件成立target、state、url、timeout
expect断言，不成立即判定失败target、state、text
extract从页面抽取数据（文字、属性、表格）target、as、fields
screenshot截图存为产物target、fullPage、name
download、upload、iframe、多标签页、条件与循环等在 M3 加入。
