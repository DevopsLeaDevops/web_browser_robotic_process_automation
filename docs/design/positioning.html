產品定位

要解決什麼問題，以及整個平台圍繞的核心概念。

要解決的問題

  • 重複的人工操作。每天在內部系統登入、填表、查詢、匯出報表，耗人力又容易出錯。
  • 腳本只有開發者能寫。自動化腳本散落在個人電腦，難以共用，也沒人知道哪個版本是對的。
  • 頁面一改就壞。選擇器失效後很難看出壞在哪一步、為什麼壞。
  • 團隊共用缺少治理。沒有權限、稽核與憑證管理，帳號密碼常常直接寫在腳本裡。

不在範圍內

  • 桌面應用程式自動化：只處理瀏覽器內的操作。
  • 破解驗證碼或繞過目標系統的安全機制。
  • 大規模網頁爬取。
  • 取代測試框架：可以做檢查，但定位是業務流程自動化。

生成 → 管理 → 執行 → 回饋

平台的主循環

1　生成

  • 錄製使用者操作
  • 用自然語言讓 AI 產生
  • 由範本或子場景組合

2　管理

  • 版本與差異比較
  • 參數、標籤與專案
  • 權限與稽核

3　執行

  • 手動、排程或 API 觸發
  • 多 worker 併發
  • 重試與逾時控制

4　回饋

  • 每一步的截圖與日誌
  • Playwright Trace 回放
  • 失敗定位與選擇器自癒

核心概念

場景 Scenario
一段可重複執行的瀏覽器操作流程，以聲明式 DSL 描述。平台的核心資產，有版本。
步驟 Step
場景中的一個動作，例如開啟網址、點擊、填寫、抽取資料。每個步驟有穩定的 id。
定位器 Target
描述「要操作頁面上的哪個元素」，可以有多個候選，依優先順序嘗試。
參數 Param
執行時才給定的值，例如查詢月份；有型別與預設值。
Secret
帳號密碼等機密，場景只引用名稱，明文不會出現在場景、日誌或截圖說明中。
執行 Run
場景的一次執行，記錄觸發者、參數、每一步的結果與耗時。
產物 Artifact
執行產生的截圖、Trace、下載檔與抽取的資料。
專案 Project
權限隔離的單位。場景、Secrets、執行紀錄都屬於某個專案。
