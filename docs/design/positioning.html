產品定位

要解決什麼問題，以及整個平台圍繞的核心概念。

要解決的問題

  • 重複的人工操作。每天在內部系統登入、填表、查詢、匯出報表，耗人力又容易出錯。
  • 腳本只有開發者能寫。自動化腳本散落在個人電腦，難以共用，也沒人知道哪個版本是對的。
  • 頁面一改就壞。選擇器失效後很難看出壞在哪一步、為什麼壞。
  • 團隊共用缺少治理。沒有權限、稽核與憑證管理，帳號密碼常常直接寫在腳本裡。

不在範圍內

  • 桌面應用程式自動化：只處理瀏覽器內的操作。
  • 破解驗證碼或繞過目標系統的安全機制。
  • 大規模網頁爬取。
  • 取代測試框架：可以做檢查，但定位是業務流程自動化。

生成 → 管理 → 執行 → 回饋

平台的主循環

1　生成

  • 錄製使用者操作
  • 用自然語言讓 AI 產生
  • 由範本或子場景組合

2　管理

  • 版本與發布門檻
  • 入參、出參與分類
  • 權限與稽核

3　執行

  • 手動、排程或 API 觸發
  • 多 worker 併發
  • 重試與逾時控制

4　回饋

  • 每一步的截圖與日誌
  • Playwright Trace 回放
  • 失敗定位與選擇器自癒

核心概念

場景 Scenario
一段可重複執行的瀏覽器操作流程，以聲明式 DSL 描述（少數情況用 Python 腳本，見 ADR 0009）。平台的核心資產，有穩定的 id 與分類。
版本 Revision
場景的一個不可變版本：草稿 → 驗證中 → 通過或失敗 → 已發布。修改後要重新驗證，發布的版本必須就是驗證通過的版本。
步驟 Step
場景中的一個動作，例如開啟網址、點擊、填寫、抽取資料。每個步驟有穩定的 id。
定位器 Target
描述「要操作頁面上的哪個元素」，可以有多個候選，依優先順序嘗試。
入參 Input
執行時才給定的值，例如查詢月份；有型別、限制與預設值，啟動瀏覽器前校驗。
頁面事實 Fact
執行中從頁面抽取的值，只描述看到了什麼，不代表成功。
獨立斷言 Verify
自動化結束後，比對頁面事實與入參的規則。「腳本沒有出錯」不等於成功。
出參 Output
獨立斷言通過後才發布的結果，可以串到下一個場景的入參。
Secret
帳號密碼等機密，場景只引用名稱，明文不會出現在場景、日誌或截圖說明中。
執行 Run
某個版本的一次執行，記錄觸發者、入參、每一步的結果與耗時；狀態為排隊、執行中、通過、失敗、逾時、已取消或需要登入。
產物 Artifact
執行產生的截圖、Trace、下載檔與抽取的資料。
編排 Workflow
把已發布的場景排成序列，上游的出參綁到下游的入參，失敗就停止（M6）。
調試工作階段 Debug session
錄製稿或草稿在隔離的瀏覽器中調試；AI 助手只能修改草稿，發布要使用者確認（M4、M5）。
專案 Project
權限隔離的單位。場景、Secrets、執行紀錄都屬於某個專案（M8；MVP 是單使用者）。
