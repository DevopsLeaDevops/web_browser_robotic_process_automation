場景 DSL

場景的唯一真實來源。YAML 編寫、JSON 存儲，以 Pydantic 模型校驗；本頁是 schemaVersion 1 的規格。

schemaVersion 1 · M1 定稿
模型在 packages/rpa_core/src/rpa_core/dsl/，完整範例在 examples/，JSON Schema 在 schema/scenario.v1.json。決策背景見 ADR 0001。

範例

節錄自 examples/erp-login.yaml
# yaml-language-server: $schema=../schema/scenario.v1.json
schemaVersion: 1
id: erp-login
name: 登入 ERP
params:
  user: { type: string, description: 登入帳號 }
secrets: [ERP_PASSWORD]
browser:
  baseUrl: https://erp.example.internal
  viewport: { width: 1280, height: 800 }
defaults:
  timeout: 10000
steps:
  - id: open
    action: goto
    url: /login
  - id: fill-user
    action: fill
    target: { role: textbox, name: 帳號 }
    value: "{{ params.user }}"
  - id: fill-password
    action: fill
    target: { label: 密碼 }
    value: "{{ secrets.ERP_PASSWORD }}"
  - id: submit
    action: click
    target:
      role: button
      name: 登入
      fallback: [{ testId: login-submit }]
  - id: check-welcome
    action: expect
    target: { text: 歡迎回來 }
    state: visible

設計原則

  • 每個步驟有穩定的 id。執行結果、截圖與日誌按步驟歸檔；插入或刪除步驟時不會錯位。
  • 定位器有優先順序。testId → role + name → label → placeholder → text → altText → title → css → xpath。錄製時同時記下多個候選放在 fallback，作為自癒的基礎。
  • 只用條件等待。不提供固定秒數的 sleep，改用 waitFor 等待元素、網址或載入狀態。
  • 寫錯就擋下來。不認得的欄位、型別不符、YAML 的隱式轉型都在校驗時報錯，並指出檔案行號、步驟與欄位。
  • Secrets 只引用名稱。值在執行時注入，日誌與截圖說明自動遮罩。
  • 表達式在沙箱內求值。{{ }} 以 Jinja2 沙箱環境處理（M3），只能讀取 params、env、secrets 與先前步驟的輸出。
  • 保留逃生門。DSL 表達不了的情況使用受控的 script 步驟（M3 之後），並在審核時特別標示。

場景頂層

欄位名稱一律是 camelCase
欄位必填說明
schemaVersion是DSL 版本，目前是 1。格式有不相容的變更時遞增，並提供遷移。
id是小寫英文字母、數字、- 與 _，以英數開頭，最長 64 個字元。會用在檔名與網址。
name是給人看的名稱。
description說明。
params參數宣告，鍵是參數名稱（英文字母、數字與 _）。每個參數有 type（string、number、integer、boolean，預設 string）、default、description；沒有預設值代表執行時必須提供。
secrets機密名稱清單，例如 ERP_PASSWORD（大寫英文字母、數字與 _）。值不寫在場景裡。
browserengine（chromium、firefox、webkit，預設 chromium）、headless（預設 true）、viewport（width、height）、baseUrl、locale（例如 zh-TW）。
defaultstimeout：步驟預設逾時。
steps是步驟清單，至少一步。
網址以 / 開頭時接在 browser.baseUrl 後面，同一個場景換環境（測試、正式）只要改 baseUrl。

步驟共同欄位

id
必填，場景內唯一。格式同場景 id。
action
必填，動作名稱，見下方動作表。
name
給人看的步驟說明。
timeout
這一步的逾時，毫秒整數，大於 0、最多 3,600,000（一小時）。沒寫就用 defaults.timeout。

retry 與 onError（繼續、失敗、跳到某一步）在 M3 加入。

字串比對

expect 的 text、value、url、title 與 waitFor 的 url 用 match 指定比對方式：

contains
預設。包含這段文字即可，例如 text: 歡迎 對得到「歡迎回來，王小明」。
equals
完全相等。
regex
Python re 語法的正規表示式；校驗時會先編譯，寫錯會報錯。

定位器 target

恰好指定一種主要方式
主要方式對應 Playwright適合
testIdget_by_test_id系統有測試用屬性時最穩定
role（搭配 name）get_by_role按鈕、連結、輸入框等；role 是 ARIA 角色，例如 button、textbox、link、row
labelget_by_label有標籤的表單欄位
placeholderget_by_placeholder沒有標籤、只有提示文字的輸入框
textget_by_text依畫面上的文字
altTextget_by_alt_text圖片
titleget_by_title有 title 屬性的元素
csslocator("css=…")其他方式都不行時；避免自動產生的 id 或 class
xpathlocator("xpath=…")最後手段
name
role 的無障礙名稱，例如按鈕上的文字。只能搭配 role。
exact
文字要完全相符（預設為包含且不分大小寫）。用於 role + name、label、placeholder、text、altText、title。
nth
符合多個元素時取第幾個：0 是第一個，-1 是最後一個。
hasText
只保留內含這段文字的元素，例如找出含有某個訂單編號的那一列。
within
另一個定位器：先找到外層元素（表格、對話框），再在裡面找。
fallback
備用定位器清單，主要方式失敗時依序嘗試（M2 執行、M5 自癒時使用）。備用定位器不能再有 fallback。

動作

粗體為必填
動作用途欄位規則
goto開啟網址url、waitUntil（load、domcontentloaded、networkidle、commit；預設 load）url 是 http(s) 網址、about:blank，或以 / 開頭並設定 baseUrl
click點擊元素target、button（left、right、middle）、clickCount（1–3）、modifiers（Alt、Control、ControlOrMeta、Meta、Shift）
fill清空輸入框後填入target、valuevalue 是字串；空字串代表清空，數字要加引號
select選擇下拉選項target、optionoption 是選項的值或顯示文字；寫成清單代表多選
press按鍵或組合鍵key（Enter、Tab、Control+A…）、target沒有 target 時送給目前聚焦的元素
waitFor等待條件成立target + state（visible、hidden、attached、detached）、url + match、loadState三種條件恰好選一種
expect斷言，不成立即判定失敗target + state、text、value、count 其一；或不給 target，檢查 url、title 其一；matchstate 可用 visible、hidden、enabled、disabled、checked、unchecked、editable
extract從頁面抽取資料target、as、get、attribute、multiple、fields見下方說明
screenshot截圖存為產物file、target、fullPagefile 是不含副檔名的檔名，沒寫就用步驟 id；fullPage 不能搭配 target
extract 的 get
text（預設）、value、html、attribute（要用 attribute 指定屬性名稱）、table（把 <table> 依表頭轉成記錄清單）。
extract 的 multiple
抽取所有符合的元素，得到清單；預設只取第一個。
extract 的 fields
每個元素抽成一筆記錄，鍵是欄位名稱，值可寫 target（相對於該元素）、get、attribute。有 fields 時不寫外層的 get。
extract 的 as
存成的變數名稱，之後的步驟可以引用（M3）。
download、upload、iframe、多分頁、條件與迴圈等在 M3 加入。

YAML 撰寫規則

  • 只用 YAML 1.2 core 規則。yes、no、on 是字串，不是布林；2026-09-01 是字串，不是日期；12:30 是字串，不是六十進位數字。
  • 不自動轉型。字串欄位寫了數字或 true/false 會報錯，請加引號，例如 value: "0123"。
  • 鍵不能重複。同一層出現兩次的鍵會報錯並指出第一次出現的行號。
  • 不認得的欄位會報錯。名稱相近時提示正確寫法，例如 fullpage → fullPage。
  • 只接受一般的標籤。!!python/…、!!binary 與自訂標籤一律拒絕；錨點與別名可以用，不支援 << 合併。
  • 編碼是 UTF-8。可以有 BOM。

表達式 {{ }}

M1 只做靜態檢查
  • 字串欄位可以寫 {{ params.名稱 }}、{{ secrets.名稱 }}、{{ env.名稱 }}，求值在 M3 加入。
  • 校驗時檢查 {{ 有沒有對應的 }}、內容是否空白，以及引用的 params、secrets 有沒有宣告。
  • 場景與步驟的 name、description 是給人看的文字，不檢查也不代入。

校驗：rpa validate

$ rpa validate examples/ scenarios/login.yaml
scenarios/login.yaml:14:9: 步驟 3（login-pass） › target.css：只能指定一種定位方式，目前有：label, css；其他寫法可以放在 fallback
scenarios/login.yaml:20:5: 步驟 4（shot） › fullpage：不認得的欄位 fullpage，是不是 fullPage？
檢查 3 個檔案，1 個未通過，共 2 個問題。
位置
檔案:行:列，與編譯器相同的格式，編輯器與 CI 可以直接跳到錯誤位置。行與列從 1 開始。
參數
檔案或資料夾，可以多個；資料夾會找出底下所有 .yaml 與 .yml（略過隱藏資料夾）。
--format json
每個問題含 line、column、step、stepId、field、path、code、message，給程式與 AI 自動修正（M5）使用。
退出碼
0 全部通過；1 有檔案未通過，或資料夾裡沒有 YAML；2 參數錯誤。
rpa schema
輸出 JSON Schema。倉庫中的 schema/scenario.v1.json 由它產生；場景檔第一行加上 # yaml-language-server: $schema=…，VS Code 的 YAML 外掛就能自動補全與即時檢查。
Python
rpa_core.dsl.validate_file()、validate_text()、validate_data() 回傳場景模型與所有問題；Web UI 與 API 也用同一套。
