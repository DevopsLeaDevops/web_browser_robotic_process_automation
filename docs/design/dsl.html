場景 DSL

場景的唯一真實來源。YAML 編寫、JSON 存儲，以 Pydantic 模型校驗；包含入參、出參與獨立斷言的場景契約。本頁是 schemaVersion 1 的規格。

schemaVersion 1 · M1.1
模型在 packages/rpa_core/src/rpa_core/dsl/，範例在 scenarios/，JSON Schema 在 schema/scenario.v1.json。決策背景見 ADR 0001 與 ADR 0009。

範例

節錄自 scenarios/demo/ba-001.yaml（MVP 原型的 BA-001）
# yaml-language-server: $schema=../../schema/scenario.v1.json
schemaVersion: 1
id: ba-001
name: 建立範例紀錄
category: 範例資料
inputs:
  title: { type: string, minLength: 1, maxLength: 60 }
  quantity: { type: integer, minimum: 1, maximum: 30, default: 12 }
outputs:
  recordId:
    pattern: '^DEMO-[A-Z0-9]+$'
    from: '{{ facts.record.recordId }}'
browser: { engine: firefox, baseUrl: http://127.0.0.1:8765 }
deadline: 45000
steps:
  - id: open
    action: goto
    url: /
  - id: fill-title
    action: fill
    target: { label: 標題, exact: true }
    value: '{{ inputs.title }}'
  - id: submit
    action: click
    target: { role: button, name: 建立紀錄 }
  - id: read-record
    action: extract
    target: { css: '#receipt' }
    as: record
    fields:
      recordId: { target: { css: '#record-id' } }
      status: { target: { css: '#record-status' } }
verify:
  - name: 狀態是已建立
    value: '{{ facts.record.status }}'
    equals: 已建立

設計原則

  • 成功要有證據。步驟只操作頁面、留下頁面事實；由獨立斷言 verify 判定成功，通過後才發布出參。「腳本沒有出錯」不等於成功。
  • 入參、出參是契約。入參在啟動瀏覽器前校驗；出參可以串到下一個場景的入參。兩者都能匯出成 JSON Schema。
  • 每個步驟有穩定的 id。執行結果、截圖與日誌按步驟歸檔；插入或刪除步驟時不會錯位。
  • 定位器有優先順序。testId → role + name → label → placeholder → text → altText → title → css → xpath。錄製時同時記下多個候選放在 fallback，作為自癒的基礎。
  • 只用條件等待。不提供固定秒數的 sleep，改用 waitFor；整次執行受 deadline 限制。
  • 寫錯就擋下來。不認得的欄位、型別不符、YAML 的隱式轉型都在校驗時報錯，並指出檔案行號、步驟與欄位。
  • Secrets 只引用名稱。值在執行時注入，日誌與截圖說明自動遮罩。
  • 保留逃生門。DSL 表達不了的場景可以改用 Python 腳本（script），沿用同一份契約，審核時特別標示。

場景頂層

欄位名稱一律是 camelCase
欄位必填說明

name是給人看的名稱。
description說明。
category分類，場景清單與報告依此篩選。
inputs入參宣告，鍵是名稱（英文字母、數字與 _），見下方場景契約。
outputs出參宣告；有出參就要有 verify。
secrets機密名稱清單，例如 ERP_PASSWORD（大寫英文字母、數字與 _）。值不寫在場景裡。
login需要先登入時寫 { role: 角色代號 }（與場景 id 相同的寫法）。怎麼登入、怎麼判斷已登入登記在管理 Portal 的角色上，場景只寫用哪個角色；執行前先檢查這個角色是否已登入（見下方執行順序）。
browserengine（chromium、firefox；webkit 可用但 CI 不測；預設 chromium）、headless（預設 true）、viewport（width、height）、baseUrl、locale（例如 zh-TW）。

網址以 / 開頭時接在 browser.baseUrl 後面，同一個場景換環境（測試、正式）只要改 baseUrl。M1 的 params 已改名為 inputs，寫舊名會提示新名。

場景契約

入參 → 步驟 → 頁面事實 → 獨立斷言 → 出參
inputs
每個入參有 type（string、number、integer、boolean，預設 string）、default、description，以及限制：enum、minLength、maxLength、pattern（字串）、minimum、maximum（數字）。沒有預設值代表執行時必須提供。預設值也要符合限制；可以是動態值（例如 {{today}}），每次執行時求值。
facts
頁面事實：extract 以 as: 名稱 存成 facts.名稱。步驟只能引用前面步驟產生的事實；verify 與 outputs 可以引用全部。
verify
每一條有 value（必須含 {{ }}）與 equals、contains、matches（正規表示式）、notEmpty: true 其中一種比較；name 會出現在報告。比較時兩邊都以代入後的文字比對。
outputs
型別多了 array、object，限制同入參；from 指定取值，例如 {{ facts.record.recordId }}。只有一個 {{ }} 時保留原本的型別（例如清單），否則依 type 轉換文字。
script
automation 與 assertion 兩個 Python 檔，路徑相對於場景檔所在的資料夾、不能用 ..。automation.py 接受 --input --facts --screenshot --target-url，assertion.py 接受 --input --facts --output（沿用 MVP 原型的命令列契約）。腳本場景不寫 verify，出參也不寫 from。

執行順序與失敗時的處理見 ADR 0009；執行引擎在 M2 實作。rpa schema 場景檔 --part inputs 或 --part outputs 輸出單一場景的入參或出參 JSON Schema。

入參的動態值

每次執行開始時換成當下的日期、隨機數

入參的值裡可以寫 {{ … }} 動態值：場景的 default、管理 Portal 執行表單的入參 JSON 與 API、rpa run -i／--input、試驗場節點的固定值、逐步調試的入參都可以。{{ }} 裡可以有空白，名稱不分大小寫；可以夾在文字中，例如 CG-001 建立於 {{today}}。

寫法結果（以 2026-10-21 07:30:05 執行為例）
{{today}}2026-10-21
{{today+1}}、{{today-7}}2026-10-22、2026-10-14（往後、往前幾天）
{{today:YYYY/MM/DD}}、{{today+1:yyyyMMdd}}、{{today:yyyy年MM月dd日}}2026/10/21、20261022、2026年10月21日
{{now}}、{{now:HH:mm}}、{{now:yyyyMMddHHmmss}}2026-10-21 07:30:05、07:30、20261021073005
{{random:10:30}}10 到 30 之間（含兩端）的隨機整數，每個 random 各自抽
{{"{{"}}引號裡的文字原樣保留，用來寫出 {{ 本身
格式
yyyy／YYYY 年、MM 月、dd／DD 日、HH 時、mm 分、ss 秒（都補零），其他字元照寫。today 只有日期，格式裡寫了時、分、秒會報錯（最常見的是把月份寫成小寫 mm）。
求值的時間
每次執行開始時（入參階段，啟動瀏覽器之前），用執行那台電腦的本地時區；同一次執行的所有入參用同一個「現在」，所以 {{today}} 在每個入參都是同一天。執行紀錄保存原本的寫法，重新執行會重新求值；input.json 與報告是實際用到的值。腳本、後續步驟、斷言與報告共用這份運行態入參，每次引用不會重新抽樣。
型別
求值的結果是數字的文字時（例如整個值是 {{random:10:30}}），integer、number 入參得到數字；其他都是文字，再照入參的 type 與限制校驗。
校驗
值裡任何 {{ … }} 都當成動態值，看不懂（例如 {{tody}}、{{random:30:10}}）就報錯。保存與排入佇列時保留配置態寫法：動態值只檢查語法，不讀取日期、不抽樣、不枚舉可能結果；普通值仍檢查型別與限制。實際執行開始時才展開一次，針對這份運行態入參檢查 type、enum、pattern、長度及數值範圍。不符合時本次執行在啟動瀏覽器前失敗，不會重新抽到合格為止。例如 maximum: 20 配 {{random:10:30}} 可以保存，當次抽到 26 就回報超過上限；抽到 18 則繼續執行。
錄製的文字
錄製稿中的填寫內容照原樣保留；即使文字含有 {{today}} 或其他大括號，也會自動跳脫。需要動態值時再編輯入參的預設值。
上游的出參
試驗場把上游節點的出參交給下游時永遠照原樣，出參的文字裡剛好有 {{ 也不會被求值。
步驟裡
步驟的 {{ }} 是表達式，不能直接寫 today、now、random；請在 inputs 加一個入參、預設值寫動態值，步驟再引用 {{ inputs.名稱 }}。
遠端執行
動態值在執行的那台裝置上求值，包含逐步調試與接著錄製。調試重載保留已求值的入參，只對新增預設值求值；Portal 顯示錄製端實際用到的值。用到動態值的執行只交給回報看得懂 dynamicValues 的 Worker／錄製端 App；舊的 App 會看到要更新的說明（同 M7a 的做法）。
inputs:
  arrivalDate: { default: "{{today}}" }
  expiryDate: { default: "{{today+1}}" }
  purchaseQuantity: { type: integer, minimum: 10, maximum: 30, default: "{{random:10:30}}" }
  remark: { default: "CG-001脚本创建{{today}}日期" }

YAML 裡以 { 開頭的值要加引號。也可以在管理 Portal 場景頁的「入參」按「編輯」，把預設值改成 {{today}}，存檔時會自動加引號。

步驟共同欄位

id
必填，場景內唯一。格式同場景 id。
action
必填，動作名稱，見下方動作表。
name
給人看的步驟說明。
timeout
這一步的逾時，毫秒整數，大於 0、最多 3,600,000（一小時）。沒寫就用 defaults.timeout；不會超過總期限剩下的時間。
page
在哪個分頁執行（M7b）：前面某一步用 popup 開出來的分頁名稱；沒寫是一開始的分頁。名稱要在「之前」的步驟開過，不然校驗時指出這一步。
popup
只有 click、fill、select、check、press 可以寫（M7b）：這一步會開出新分頁（彈出視窗，例如連結的 target="_blank" 或 window.open），執行時等它開好並取這個名稱，之後的步驟用 page 指定它；同一個名稱只能開一次。沒有開出新分頁時這一步逾時失敗。例如 { action: click, target: { role: link, name: 開啟商品明細 }, popup: items }，之後 { action: fill, page: items, target: { placeholder: 請選擇 }, value: … }。

retry 與 onError 在 M7 加入；重試只用於沒有副作用的步驟，送出表單之類的動作不會自動重試。

字串比對

expect 的 text、value、url、title 與 waitFor 的 url 用 match 指定比對方式：

contains
預設。包含這段文字即可，例如 text: 歡迎 對得到「歡迎回來，王小明」。
equals
完全相等。
regex
Python re 語法的正規表示式；校驗時會先編譯，寫錯會報錯。

定位器 target

恰好指定一種主要方式
主要方式對應 Playwright適合
testIdget_by_test_id系統有測試用屬性時最穩定
role（搭配 name）get_by_role按鈕、連結、輸入框等；role 是 ARIA 角色，例如 button、textbox、link、row
labelget_by_label有標籤的表單欄位
placeholderget_by_placeholder沒有標籤、只有提示文字的輸入框
textget_by_text依畫面上的文字
altTextget_by_alt_text圖片
titleget_by_title有 title 屬性的元素
csslocator("css=…")其他方式都不行時；避免自動產生的 id 或 class
xpathlocator("xpath=…")最後手段
name
role 的無障礙名稱，例如按鈕上的文字。只能搭配 role。
exact
文字要完全相符（預設為包含且不分大小寫）。用於 role + name、label、placeholder、text、altText、title。
nth
符合多個元素時取第幾個：0 是第一個，-1 是最後一個。
hasText
只保留內含這段文字的元素，例如找出含有某個訂單編號的那一列。
within
另一個定位器：先找到外層元素（表格、對話框），再在裡面找。
frame
元素在 iframe 裡時，指出那個 iframe 的定位器：先找到 iframe，再在它載入的頁面裡找（within 也在那個頁面裡找）。iframe 裡還有 iframe 時，在 frame 裡再寫 frame（外層的 iframe），例如 { label: 我已確認, frame: { css: "#note-frame", frame: { css: "#form-frame" } } }。沒寫 frame 只在最外層的頁面找。（M7a）
anyFrame
true：在頁面與所有 iframe（含巢狀）裡找，不必寫出是哪個 iframe，但要剛好只在一個 iframe 裡找到。codegen 對兩層以上的 iframe 會錄成不帶引數的 frame_locator()，轉換後就是 anyFrame，例如 { role: checkbox, name: 我已確認, anyFrame: true }。只能寫在最外層（有 frame 時寫在最深的那個 frame 上），不能寫在 within 裡。（M7a）
fallback
備用定位器清單，主要方式失敗時依序嘗試（M2 執行、M5 自癒時使用）。備用定位器不能再有 fallback；沒寫 frame 時沿用主要定位器的 frame。

存成頁面事實 facts.名稱；同一個場景內不能重複。
extract 的 get
text（預設）、value、html、attribute（要用 attribute 指定屬性名稱）、table（把 <table> 依表頭轉成記錄清單）。

抽取所有符合的元素，得到清單；預設只取第一個。
extract 的 fields
每個元素抽成一筆記錄，鍵是欄位名稱，值可寫 target（相對於該元素）、get、attribute。有 fields 時不寫外層的 get。
expect 是步驟內的防護，verify 才決定是否發布出參。download、upload、條件與迴圈等在 M7 加入；iframe 用定位器的 frame（M7a），新分頁用步驟的 popup 與 page（M7b）。

YAML 撰寫規則

  • 只用 YAML 1.2 core 規則。yes、no、on 是字串，不是布林；2026-09-01 是字串，不是日期；12:30 是字串，不是六十進位數字。
  • 不自動轉型。字串欄位寫了數字或 true/false 會報錯，請加引號，例如 value: "0123"。
  • 以 {{ 開頭的值要加引號。例如 value: "{{ inputs.title }}"、default: "{{today}}"；沒加引號時 YAML 會讀成物件，校驗會提示加引號。
  • 鍵不能重複。同一層出現兩次的鍵會報錯並指出第一次出現的行號。
  • 不認得的欄位會報錯。名稱相近時提示正確寫法，例如 fullpage → fullPage。
  • 只接受一般的標籤。!!python/…、!!binary 與自訂標籤一律拒絕；錨點與別名可以用，不支援 << 合併。
  • 編碼是 UTF-8。可以有 BOM。

表達式 {{ }}

Jinja2；M2 在沙箱內求值
  • 可用的變數只有 inputs、secrets、facts、env；可以用 Jinja2 的過濾器，例如 {{ inputs.title | upper }}。
  • 校驗時就會檢查語法、未知的變數與過濾器、沒有宣告的 inputs 與 secrets、沒有 extract 產生或還沒產生的 facts。
  • facts 不能用在 browser 設定，因為那時還沒開始操作頁面。
  • today、now、random 是入參值的動態值，不是這裡的變數；寫在步驟裡時校驗會提示改寫在入參。
  • 場景、步驟與斷言的 name、description 是給人看的文字，不檢查也不代入。

順序
入參校驗（有問題就不啟動瀏覽器）→ 登入檢查（只有寫了 login 的場景：打開角色的確認網址，看不到已登入的元素時先自動登入，不能自動登入就停在「需要登入」needs_login，不執行任何步驟）→ 在子程序中執行步驟或 automation.py → 獨立斷言（verify 或 assertion.py）→ 出參轉型與校驗 → 寫出 output.json。任何一步失敗都沒有成功出參。
總期限
以單調時鐘計算；每一步只能用剩下的時間。子程序超過期限就終止整個程序群組，結果是「逾時」。
選項
-i 名稱=值（依型別轉換，可重複）、--input 檔.json、--base-url、--browser chromium|firefox、--headed、--video（錄影成執行目錄的 video.webm，M12；只有 DSL 場景）、--deadline 毫秒、--out 資料夾（預設 runs/）、--format json、--storage-state 登入狀態.json（場景有 login 時載入這個 storageState，只載入不檢查；檢查與人工登入在管理 Portal）。退出碼：0 通過、1 未通過。
執行目錄
input.json、facts.json、steps.json、output.json（只有通過時）、screenshot.png 與 screenshot 步驟的截圖、automation.log（自動化日誌：開頭寫這次的瀏覽器、視窗模式、起始網址與開始時間，接著每一步一行（時間、第幾步、名稱與動作、通過或失敗、耗時；打開網頁與出錯時加上網址），失敗時寫出錯的步驟、略過的步驟、證據在哪裡與完整的錯誤原文；時間是執行那台電腦的當地時間，網址與錯誤遮罩 Secrets，不寫入參的值）、diagnostic.json（失敗時）、scenario/（本次的場景快照）、result.json、report.html；有登入檢查時另有 login.json、login.log 與 login.png。登入狀態本身不複製進來。
Secrets
命令列從同名的環境變數讀取（例如 ERP_PASSWORD）；管理 Portal 先用「登入與憑證」設定的值，沒有才找環境變數。只傳給子程序，日誌與報告中會遮罩；M8 改為加密存放。
Python 腳本場景
剩下的總期限在環境變數 RPA_DEADLINE_SECONDS，瀏覽器在 RPA_BROWSER，目前的語言在 RPA_LANG（腳本要寫給人看的訊息時可以參考），要不要顯示瀏覽器視窗在 RPA_HEADLESS（0 有頭模式、1 無頭模式），場景有 login 時登入狀態檔的路徑在 RPA_STORAGE_STATE（給 browser.new_context(storage_state=…)）；範例見 scenarios/demo/ba-001-script/。腳本自己啟動瀏覽器，不使用下面的預熱設定檔。
Firefox 設定檔
Firefox 每次用全新的設定檔啟動時，會先初始化設定檔而停止回應幾秒（Windows 上機器忙時可能超過步驟的逾時）。所以每台電腦、每個 Firefox 版本會保留一份預先初始化過的空白設定檔，每次執行複製一份來用，結束後刪除，每次執行仍然是乾淨的。第一次用 Firefox 執行時建立，約多花 7～10 秒。放在快取資料夾 RPA_CACHE_DIR，預設是 Windows 的 %LOCALAPPDATA%\rpa\cache、macOS 的 ~/Library/Caches/rpa、Linux 的 ~/.cache/rpa；刪掉也沒關係，下次會重建。

錄製：rpa record

M4
$ rpa record https://erp.example.com/login --out erp-login.py --scenario erp-login.yaml
$ rpa record --from 別台電腦錄的.py --out erp-login.py --scenario erp-login.yaml   # 只轉換，不錄製
錄製
用 Playwright codegen：瀏覽器視窗與 Inspector 開在這台電腦上，操作完關掉視窗即結束；需要圖形介面。--browser chromium|firefox，--load-storage state.json 先載入登入狀態。
輸出
--out 是密碼遮罩成 *** 的錄製稿（含密碼的暫存原始稿轉換後刪除）；--scenario 是 DSL 草稿，--id、--name 指定場景 id 與名稱。
轉換
goto、click、fill、press、select_option、check 與常見的 expect；Inspector 的「Assert text」「Assert value」變成 extract 步驟＋出參＋verify 檢查（錄到的值等於某個輸入時檢查等於該入參，否則檢查有內容）；輸入的值變成入參（預設值是錄到的值），密碼欄位變成 Secret（名稱是場景 id 加上 _PASSWORD），轉不了的行以註解保留並列出行號。管理 Portal 的錄製用同一套轉換。

校驗：rpa validate

$ rpa validate scenarios/
scenarios/login.yaml:14:9: 步驟 3（login-pass） › target.css：只能指定一種定位方式，目前有：label, css；其他寫法可以放在 fallback
scenarios/login.yaml:31:15: 步驟 5（read） › value：facts.total 要等後面的 extract 步驟才會產生
檢查 5 個檔案，1 個未通過，共 2 個問題。
位置
檔案:行:列，與編譯器相同的格式，編輯器與 CI 可以直接跳到錯誤位置。行與列從 1 開始。
參數
檔案或資料夾，可以多個；資料夾會找出底下所有 .yaml 與 .yml（略過隱藏資料夾）。腳本場景會檢查腳本檔是否存在。
--format json
每個問題含 line、column、step、stepId、field、path、code、message，給程式與 AI 自動修正（M5）使用。
退出碼
0 全部通過；1 有檔案未通過，或資料夾裡沒有 YAML；2 參數錯誤。
rpa pack check
校驗領域資料夾（M11）：說明檔的格式、版本內容與版本說明檔的雜湊、驗證紀錄、發布門檻、角色定義，以及不能放進資料夾的登入狀態、Secrets 與私鑰；規則和管理 Portal 載入時相同。--id 要求 pack.yaml 的代號；--format json 給程式使用。有錯誤時退出碼 1（警告不算），可以放在資料倉庫的 CI。
rpa schema
輸出 DSL 的 JSON Schema。倉庫中的 schema/scenario.v1.json 由它產生；場景檔第一行加上 # yaml-language-server: $schema=…，VS Code 的 YAML 外掛就能自動補全與即時檢查。指定場景檔時輸出該場景的入參或出參 Schema。
Python
rpa_core.dsl.validate_file()、validate_text()、validate_data() 回傳場景模型與所有問題；inputs_json_schema()、outputs_json_schema() 產生單一場景的契約。管理介面與 API 也用同一套。
