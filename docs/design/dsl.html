草案 · M1 定稿
本頁是方向草案，欄位名稱與動作清單在 M1 討論後定稿。決策背景見 ADR 0001。

範例

示意；download 在 M3 加入
id: erp-export-report
name: 登入 ERP 並匯出月報
params:
  month: { type: string, default: "2026-09" }
secrets: [ERP_PASSWORD]
browser: { engine: chromium, headless: true }
steps:
  - id: open
    action: goto
    url: https://erp.example.internal/login
  - id: login-user
    action: fill
    target: { role: textbox, name: 帳號 }
    value: "{{ env.ERP_USER }}"
  - id: login-pass
    action: fill
    target: { label: 密碼 }
    value: "{{ secrets.ERP_PASSWORD }}"
  - id: submit
    action: click
    target:
      role: button
      name: 登入
      fallback: [{ css: "#login-btn" }]
  - id: check
    action: expect
    target: { text: 歡迎回來 }
    state: visible
  - id: export
    action: download
    trigger:
      action: click
      target: { role: button, name: 匯出 }
    saveAs: "report-{{ params.month }}.xlsx"

設計原則

  • 每個步驟有穩定的 id。執行結果、截圖與日誌按步驟歸檔；介面編輯時不會錯位。
  • 定位器有優先順序。testId → role + name → label → text → css / xpath。錄製時同時記下多個候選，作為自癒的基礎。
  • 只用條件等待。不允許固定秒數的 sleep，改用 waitFor 等待元素、網址或網路狀態。
  • 步驟級錯誤處理。每一步可設定 retry、timeout 與 onError（繼續、失敗、跳到某一步）。
  • Secrets 只引用名稱。值在執行時注入，日誌與截圖說明自動遮罩。
  • 表達式在沙箱內求值。{{ }} 以 Jinja2 沙箱環境處理，只能讀取 params、env、secrets 與先前步驟的輸出。
  • 保留逃生門。DSL 表達不了的情況使用受控的 script 步驟，並在審核時特別標示。

M1 預計支援的動作

動作用途主要欄位
goto開啟網址url、waitUntil
click點擊元素target、button、clickCount
fill填寫輸入框target、value
select選擇下拉選項target、option
press按鍵或組合鍵target、key
waitFor等待條件成立target、state、url、timeout
expect斷言，不成立即判定失敗target、state、text
extract從頁面抽取資料（文字、屬性、表格）target、as、fields
screenshot截圖存為產物target、fullPage、name
download、upload、iframe、多分頁、條件與迴圈等在 M3 加入。
