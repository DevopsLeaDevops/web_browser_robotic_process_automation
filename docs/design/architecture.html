系統架構

元件、資料流與目錄結構。平台全部部署在內網：伺服器保存場景與紀錄，錄製端與 Worker 兩個桌面 App 主動連到伺服器，瀏覽器在它們那台直接操作目標系統。本頁對照 v0.4.0（2026-10-21）。

目前的部署

v0.4.0：一台伺服器＋錄製端（macOS）＋Worker（Windows）
藍框為核心元件；灰底為平台外部的系統；虛線為選用。所有連線都由 App 主動發起，伺服器不需要連到它們；只有伺服器存取資料庫與資料目錄；伺服器可以是 Linux、macOS 或 Windows，不需要螢幕。錄製端用裝置權杖、Worker 用 worker 權杖，權杖在 HTTP 下是明文，只適合信任的區網。伺服器沒有瀏覽器時（例如 Linux 主機），「檢查」登入狀態改由錄製端執行。安裝見部署與操作、桌面端分發。

各部分怎麼運作

單一使用者（登入與權限在 M8）；一台伺服器，裝置可以有很多台
管理 Portal

伺服器以 Jinja 渲染的頁面，沿用 MVP 原型的版面（ADR 0011）。在伺服器那台用瀏覽器開 8080，或在錄製端 App 的視窗裡經由對外埠開（ADR 0014）。

API 服務

FastAPI：場景、版本與發布門檻、入參出參、執行與取消、報告、調試工作階段、組合場景、裝置與邀請、領域與 git 同步、回看。互動的子程序在「正在操作的那台」執行：從錄製端來的請求交給錄製端。

執行

本機 worker 是伺服器裡的執行緒，遠端是 Worker App 或 rpa worker（ADR 0012）。每台一次一個任務；每次執行以子程序跑 Runner，套用總期限與取消。執行位置可選本機、遠端或任一；組合場景整個在同一台。

資料與產物

領域資料夾保存場景、角色、組合場景的不可變版本與驗證、發布紀錄，是真相；SQLite 是索引與每台自己的狀態（ADR 0015、ADR 0008）。執行目錄、錄影、登入狀態與 Secrets 只在這台伺服器。

請求方向：Portal → API → worker。worker 回寫執行狀態與產物，Portal 以輪詢讀取進度；長任務不阻塞網頁請求。

遠端執行（M9a、M10.1）：Worker 主動連到對外埠的 Worker API，長輪詢領取任務；任務帶著場景版本的檔案、入參、用到的 Secrets 與登入狀態；每 5 秒心跳（同時得知是否取消），執行完上傳整個執行目錄並回報結果。60 秒沒有心跳就判定失聯，執行標為失敗、不自動重跑。App 回報看得懂的 DSL 擴充（例如 iframe 的 frame），用到它不懂的寫法時伺服器不交給它。見遠端 worker。

錄製端（M10.2）：App 用邀請配對，視窗經由本機閘道載入 Portal 頁面；錄製、逐步調試、人工登入與登入檢查的子程序由伺服器經 Client API 交給這台執行，輸出與檔案傳回；轉換、遮罩密碼、版本與發布門檻仍在伺服器。見桌面端分發。

同步（M11）：每個領域可以設定 git 倉庫的一個目錄；拉取與推送以檔案為單位三方合併，衝突時停下來三選一。任何一台伺服器寫下的、雜湊相符的通過紀錄都能當發布依據。推送前擋下看起來像機密的檔案。

套件職責

套件職責依賴起始
rpa-coreDSL 模型、YAML 載入與校驗、表達式引擎、JSON Schema 導出、多語言訊息目錄；組合場景的定義與檢查（rpa_core.workflow，M6）；領域資料夾的格式與校驗（rpa_core.pack，M11）；錄製稿轉 DSL（rpa_core.recording，M4）。不碰瀏覽器、不碰資料庫。Pydantic、PyYAML、Jinja2M0
rpa-runner執行引擎：入參校驗、步驟處理器註冊表、瀏覽器與上下文管理（含 iframe，M7a）、登入檢查與人工登入、獨立斷言、出參發布、執行目錄與報告、錄影（M12）；也執行 Python 腳本場景，並提供錄製、逐步調試、人工登入的子程序（子程序命令集中在 rpa_runner.commands，打包後走 App 的入口）。無狀態。rpa-core、PlaywrightM2
錄製在隔離的瀏覽器中記錄使用者操作，保存原始錄製稿並轉成 DSL 草稿。M4 沒有另外做套件：錄製用 Playwright codegen，轉換是 rpa-core 的 rpa_core.recording（不碰瀏覽器，可以單獨測試）。rpa-core、PlaywrightM4
rpa-generatorAI 助手：對話調試、自然語言 → DSL、校驗失敗回饋修正、選擇器自癒；只能修改草稿。尚未建立：要先決定模型與資料去向。rpa-core、LLM SDKM5
rpa-clirpa 命令：validate、schema、run、record、serve、worker、recorder、pack check；generate 在 M5。上述套件、clickM0
rpa-serverAPI 與管理頁面、資料庫模型與遷移、版本與發布門檻、調試工作階段、組合場景的執行（M6）、Worker API（M9a）、裝置、邀請與 Client API（M10）、領域資料夾的載入與 git 同步（M11）、回看與錄影保留（M12）；權限（M8）、排程（M9）。rpa-core、FastAPI、Jinja2、SQLAlchemyM3
rpa-worker取出待執行的任務，以子程序呼叫 rpa-runner，套用總期限與取消，回寫結果與產物。M3 在同一台電腦；M9a 起也可以在另一台電腦，經由 Worker API 領取（rpa worker，ADR 0012）。M10 起也包含配對、錄製端的本機閘道與互動子程序主機（rpa_worker.pairing、gateway、recorder），兩個 App 與 rpa recorder 共用。rpa-runner；標準函式庫的 HTTPM3
rpa-desktop（apps/desktop）兩個桌面 App：RPA 錄製端（pywebview 視窗載入 Portal 頁面，在這台執行錄製、調試、人工登入的子程序）與 RPA Worker（狀態視窗＋遠端 worker）；配對、下載瀏覽器、打包後的入口。M10 起（ADR 0014）。rpa-runner、rpa-worker、pywebviewM10

一次執行的資料流

  1. 使用者在管理 Portal、組合場景或 CLI 觸發執行（M9 起也可以由排程器建立）。
  2. API 確認版本：一般執行只用已發布的版本，而且領域資料夾裡的檔案雜湊要相符；在啟動瀏覽器前校驗入參，寫入一筆執行紀錄（含執行位置）與一個任務。
  3. 本機 worker 或遠端 Worker 領取任務，以子程序啟動 Runner，傳入場景版本的檔案、入參、Secrets 與登入狀態（只在記憶體與暫存檔中，用完刪除），並設定總期限。
  4. Runner 開啟獨立的瀏覽器上下文逐步執行，記下頁面事實；每一步回報狀態與開始、結束的時間。自動化階段錄影（M12，ADR 0016），回看時影片與步驟靠同一個時鐘對上。
  5. 獨立斷言比對頁面事實與入參；通過後出參校驗，才寫出 output.json。
  6. 截圖、錄影、日誌與報告存入執行目錄，遠端 Worker 上傳整個目錄（M9 改為物件儲存）；失敗時標出出錯的階段、步驟與截圖。
  7. 驗證執行的結果寫成領域資料夾裡的驗證紀錄；雜湊相符的通過紀錄就是發布的依據，可以經由 git 交給其他伺服器。
