系統架構

元件、資料流與目錄結構。平台全部部署在內網，worker 直接連到目標系統。

元件總覽

M9 完成後的樣貌
藍框為核心元件；灰底為平台外部的系統。M2 之前只有 CLI 與 Runner，直接在本機執行。

套件職責

uv workspace，每個套件可單獨測試
套件職責依賴起始
rpa-coreDSL 模型、YAML 載入與校驗、表達式引擎、JSON Schema 導出、多語言訊息目錄。不碰瀏覽器、不碰資料庫。Pydantic、ruamel.yaml、Jinja2M0
rpa-runner執行引擎：步驟處理器註冊表、瀏覽器與上下文管理、產物收集。無狀態。rpa-core、PlaywrightM2
rpa-recorder本機錄製：注入監聽腳本，把使用者操作轉成 DSL 步驟。rpa-core、PlaywrightM4
rpa-generatorAI 生成與選擇器自癒：頁面快照 + 自然語言 → DSL，校驗失敗回饋修正。rpa-core、LLM SDKM5
rpa-clirpa 命令：validate、run、record、generate、push。上述套件、clickM0
rpa-serverAPI 服務、資料庫模型、權限、排程。rpa-core、FastAPI、SQLAlchemyM7
rpa-worker從佇列取任務，呼叫 rpa-runner 執行，回寫結果與產物。rpa-runner、ProcrastinateM9
web管理介面（TypeScript，不屬於 Python workspace）。React、ViteM8

一次執行的資料流

  1. 使用者在 Web UI 或 CLI 觸發執行，或排程器到點建立任務。
  2. API 檢查權限，取出指定版本的場景，寫入一筆執行紀錄與一個佇列任務。
  3. 某個 worker 取到任務，向 API 解出參數與 Secrets（只在記憶體中）。
  4. Runner 開啟獨立的瀏覽器上下文，逐步執行；每一步回報狀態。
  5. 截圖、Trace、下載檔上傳到 MinIO；抽取的資料寫回執行紀錄。
  6. 執行結束，結果通知觸發者；失敗時標出出錯的步驟與截圖。
