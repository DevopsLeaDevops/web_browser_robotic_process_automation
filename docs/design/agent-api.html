對外 Agent API

第三方 Agent 系統只透過伺服器的 /agent-api/v1：寫場景與入參出參、指定錄製端開瀏覽器逐步調試、交給 Worker 驗證與執行，並取得運行過程。新的一層只做認證、權限與稽核，業務規則與發布門檻沿用現有服務。

第一期實作中
決策與沒有選的方案見 ADR 0017；給 Agent 的呼叫方式見 Agent 使用指南。設計 2026-10-23 由使用者確認，第一期同日實作（審閱中）；端點以伺服器的 /agent-api/v1/openapi.json 為準，/agent-api/v1/docs 可以直接試。

架構

Agent 只連伺服器
藍框是新增的一層；灰底為平台外部的系統；虛線的 Webhook 是第二期。錄製端與 Worker 的連線方式不變，不必開任何埠，Agent 也不必知道它們在哪裡。不直接開放 /api：它沒有認證、跟著 Portal 介面改動；獨立的 /agent-api/v1 可以保持穩定、單獨管版本。

API 用戶端、權限與稽核

每個 Agent 系統是一個「API 用戶端」，在管理後台登記後拿到一把只顯示一次的 API 金鑰；伺服器只存雜湊，做法與裝置權杖相同。請求帶 Authorization: Bearer <API 金鑰>。

權限範圍
下表的勾選；新用戶端預設只有 scenes:read 與 runs:read
可用的領域
能讀寫哪些領域的場景；預設全部
可用的錄製端
能在哪幾台錄製端開調試瀏覽器；預設無。錄製端本身也要在裝置頁打開「允許 Agent 調試」，可以設成「只允許無頭」
執行位置
local、remote、any，以及可以指定（workerId）的 Worker；預設跟隨伺服器的預設執行位置、任一台
限額
同時進行的調試工作階段、排隊中的執行；建議預設 2 個、20 個，超過回 429
回傳頁面內容
截圖、頁面結構、錄影能不能給這個用戶端；預設關，管理員確認 Agent 的模型可以接收內部頁面後再打開；關閉時這些端點回 403
到期、啟用、來源 IP
到期、停用或不在允許清單時金鑰立即失效；預設不到期、啟用、不限
權限範圍允許的操作
scenes:read讀領域、場景、版本、角色的登入狀態、Secrets 的名稱
scenes:write建立場景、存新版本、改入參出參、匯入 Playwright 腳本
debug在允許的錄製端開調試工作階段
runs:validate驗證任一版本
scenes:publish發布驗證通過、雜湊相符的版本；預設不給
runs:execute正式執行已發布版本、取消、重跑
runs:read讀運行狀態與產物
  • 不搶人的工作階段：場景已有別人（人或其他 Agent）在調試時回 409 debug_in_use，不關掉對方；Agent 只看得到、只能操作自己開的工作階段（Portal 從另一台開始時仍照舊關掉原本的）。debug_busy 沿用原本的意思：同一個工作階段上一個命令還沒跑完。
  • 稽核：每個寫入請求記一筆（時間、用戶端、動作、對象、結果碼），管理後台可以篩選，不能修改或刪除。Agent 存的版本說明自動標「由 Agent〈名稱〉建立」，運行紀錄記下觸發的用戶端。
  • 傳輸：對外埠是 HTTP，金鑰是明文。使用者確認（2026-10-23）Agent 系統與伺服器在同一個局域網，第一期不要求 HTTPS；日後 Agent 移到局域網外時，在伺服器前放反向代理提供 HTTPS，程式本身不做 TLS。

運行過程

第一期可查詢，第二期即時
端點內容期
GET /runs/{id}狀態（排隊、執行中、通過、失敗、逾時、已取消、需要登入）、目前階段、哪台 Worker、入參、出參（只有通過才有）、錯誤、開始與結束時間一
GET /runs?scene=&status=&purpose=&mine=這個用戶端看得到的運行（可用領域裡的場景）；mine 只列自己觸發的一
GET /runs/{id}/steps每一步的狀態、開始與結束時間、錯誤、步驟後的網址；第二期起執行中也即時更新一、二
GET /runs/{id}/files/{path}截圖、report.html、result.json、錄影等產物（受「回傳頁面內容」控制）一
GET /runs/{id}/events?after=&wait=事件長輪詢：有新事件立刻回，沒有就最多等 wait 秒二
Webhook運行結束時 POST 到用戶端登記的網址，帶 HMAC 簽章，失敗會重試二
  • 事件：queued、claimed（哪台 Worker）、stage（入參、登入、自動化、斷言、出參）、step（第幾步開始或結束、結果、耗時）、finished（最終狀態、出參、錯誤摘要）。序號遞增，用 after 接續，斷線不漏。
  • 步驟進度的來源：Runner 的子程序每跑完一步已經寫 steps.json。本機 worker 讀檔更新資料庫；遠端 Worker 在心跳附上目前步驟，步驟變化時立刻多送一次。舊版 Worker 不送這些欄位也照常運作，只看得到階段。
  • 先用長輪詢：Worker 與錄製端已經用同樣的方式，穿得過代理，不需要伺服器主動連 Agent。Agent 系統與伺服器在同一個局域網（使用者 2026-10-23 確認），第二期的 Webhook 可以由伺服器直接連到 Agent。
  • 調試不需要事件：調試的每個命令跑完才回應，回應裡就是那一步的結果。

典型流程

  1. 讀 /meta、/dsl/schema、可用的錄製端與角色。
  2. 建立場景，存第一版（開網址、需要時宣告登入角色）。
  3. 在指定的錄製端開調試工作階段。
  4. 讀頁面結構、截圖、測定位器。
  5. 寫下一段步驟，存成新版本。
  6. 換到新版本，執行到最後一步；有步驟失敗就回到第 4 步。
  7. 補入參、出參與獨立斷言，用 /dsl/check 校驗。
  8. 交給 Worker 驗證；沒通過就回到調試。
  9. 發布（有權限的 Agent 自己發布，否則請人在 Portal 發布）。
  10. 正式執行，讀狀態與出參。執行停在「需要登入」時，請人在錄製端人工登入後呼叫 rerun。

讀頁面結構

第一期，錄製端 App 要更新
  • 做法：調試子程序 rpa_runner.debug 加 snapshot 命令：目前分頁的無障礙樹（Playwright 的 ARIA 快照）、表單欄位（標籤、名稱、型別、是否必填）、iframe 階層與已開的分頁。Agent 據此寫 role／label／text 定位器。
  • 遮罩：填了 Secret 的欄位與密碼欄位的值一律遮罩，沿用 Runner 的遮罩。
  • 大小：超過上限時截斷並標示，Agent 可以用 within 指定只看頁面的一部分。
  • 相容：錄製端上線時回報支援 snapshot；舊版 App 沒有回報時回 422 recorder_outdated，說明要更新 RPA 錄製端（沿用 M7a 的做法與狀態碼）。

安全與資料外流

  • 頁面內容會離開伺服器：截圖、頁面結構、頁面事實與出參都回傳給 Agent；Agent 接的是外部模型時，這些內容就送到外部。這和 M5 尚待決定的資料去向是同一個問題，所以「回傳頁面內容」預設關。
  • Secrets：只能引用名稱，值永遠不回傳。
  • 發布門檻不變：Agent 寫的場景和人寫的一樣要經過真實驗證，發布的版本必須就是驗證通過的版本。
  • 調試有副作用：調試會在目標系統上真的點擊與填寫；建議專給 Agent 一台錄製端，並用測試帳號的角色。
  • 失控保護：限額防止排滿佇列或占住錄製端；金鑰可以一鍵停用。

資料庫與相容性

第一期的遷移是 0015_agent_api（專案空間的遷移先合併時改接在它後面），只用 SQLite 與 PostgreSQL 都能跑的通用型別（ADR 0008）。現有 /api、Client API、Worker API 不變；舊版 App 照常可用。

測試與驗收

  • 自動測試：金鑰與權限（缺權限 403、停用或到期 401、超過限額 429）、每個端點的轉接、不搶人的調試工作階段、冪等鍵、稽核；錄製端與 Worker 用現有的測試輔助模擬。
  • 瀏覽器測試：測試網站上的完整流程（建立 → 讀頁面結構 → 調試 → 驗證 → 發布 → 執行 → 讀結果），登記到 tools/ci_roles.py。
  • 人工驗收：Linux 伺服器＋macOS 錄製端＋Windows Worker，從另一台電腦用腳本走完整流程；關掉「允許 Agent 調試」後請求被拒。
