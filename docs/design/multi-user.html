多用戶與內部系統

團隊共用與內部系統這兩個前提，對設計提出的具體要求。

多用戶

主要在 M7 實作
認證
先做本地帳號；預留 OIDC 與 LDAP 接口，方便接公司的 AD 或 SSO。
權限
以「專案」為單位隔離場景、Secrets 與執行紀錄。
Secrets
加密存放。使用者可以在場景中引用，但無法讀出明文。
稽核
誰在什麼時間修改、執行了哪個場景，全部留紀錄，不可刪改。
版本
場景每次儲存產生不可變的新版本；執行紀錄指向確切版本。
資料庫
正式環境用 PostgreSQL，支援多個 worker 與併發寫入；SQLite 只用於開發與原型（單機、單一程序），見 ADR 0008。
Runner 無狀態
從 M2 起只接收場景、參數與 Secrets，輸出結果與產物；放進 worker 時不用改。

內部系統帶來的要求

情況對策落在
目標系統只能從內網存取平台與 worker 都部署在內網；worker 必須能直連目標系統M9
每次執行都要登入保存並重用登入狀態（Playwright storage state），減少登入次數，也降低觸發帳號鎖定的風險M3
老系統缺少語意化標籤定位器更依賴 css、xpath 與文字；錄製器避開自動生成的 id，產出穩定的選擇器M1、M4
iframe、彈出視窗、多分頁DSL 提供切換 frame 與分頁的步驟，定位器可指定所在 frameM3
檔案上傳與下載upload、download 動作；下載檔作為產物保存M3
表格資料抽取extract 支援表格轉成結構化資料M1
自簽憑證場景層級可設定忽略 HTTPS 錯誤，預設關閉並在審核時標示M2
頁面內容可能敏感AI 生成可切換到自架模型；截圖與 Trace 依專案權限存取M5、M7
錄製在使用者自己的電腦上進行：CLI 開一個有畫面的瀏覽器，錄好後上傳到伺服器。之後可考慮改成瀏覽器擴充功能。測試網站（M2）會模擬一個典型內部系統：登入、選單、iframe、表格與檔案下載。
