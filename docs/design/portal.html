管理 Portal

在瀏覽器裡建立場景、驗證、發布、執行並查看報告（M3）；錄製、逐步調試、登入角色與入參出參的表單（M4）；自由試驗場的 DAG 組合場景（M6）。單機、單使用者（ADR 0010），FastAPI + Jinja（ADR 0011），SQLite（ADR 0008）；版面沿用 MVP 原型與設計系統 v1.1。

M6
啟動：uv run rpa serve，再打開 http://127.0.0.1:8080。會一起在 127.0.0.1:8765 啟動本機測試網站，「測試網站自動化」的案例直接就能執行。資料放在 data/（或 --data 指定的資料夾，見資料夾）。沒有登入保護，預設只開放本機連線。

資料夾

管理 Portal 的所有資料都在一個資料夾裡
  • 是什麼。領域、場景與每個版本的檔案、執行紀錄與報告、登入角色的登入狀態、Secrets、錄製稿，全部存在同一個資料夾（裡面有什麼見下方資料）。換一個資料夾，就是一份全新、互不相干的管理 Portal。
  • 預設與指定。預設是執行命令時所在資料夾裡的 data（在專案資料夾執行就是專案裡的 data）。用 uv run rpa serve --data 資料夾 或環境變數 RPA_DATA_DIR 換成別的，例如 --data data-m4；相對路徑以執行命令時所在的資料夾為準，資料夾不存在時自動建立。
  • 每次用同一個。要看到同一份內容，每次啟動都要指定同一個資料夾；不加 --data 就回到 data。
  • 全新的資料夾。第一次啟動（還沒有任何領域）時，自動建立「測試網站自動化」，放進 scenarios/demo 的範例與登入角色。適合驗收新版本，又不動到平常用的資料。
  • 舊的資料夾。新版本第一次打開時自動升級資料庫，原有的場景與紀錄都保留；新版本新增的範例要到「測試網站自動化」按「匯入範例」。
  • 領域資料夾（M11）。場景、版本、角色與驗證、發布紀錄放在 domains/<領域>/，一個領域一個資料夾，可以單獨校驗（rpa pack check）。M11 之前的資料夾第一次打開時自動把舊的 scenes/ 搬進去，搬之前先把資料庫與 scenes/ 備份到 backups/<時間>-before-domains/；沒有領域的場景與沒有場景用到的角色放進「未分類」。資料庫裡的組合場景（M11 PR 2）搬進「組合場景」領域，代號是 wf-<原編號>、現在的定義成為第 1 版；搬之前先把資料庫備份到 backups/<時間>-before-composites/。
  • git 同步（M11 PR 3）。領域可以和 git 倉庫裡的一個目錄同步：「領域管理 › 同步」設定倉庫網址、分支、目錄與認證方式（公開倉庫免認證只能拉取；HTTPS 用使用者名稱＋存取權杖；SSH 用 Portal 產生的部署金鑰），也可以「從 git 新增」領域。只有伺服器做拉取與推送，錄製端與 worker 照舊由伺服器送來需要的檔案。本機變更＝資料夾和上次同步的提交的差異，存檔不必每次提交；拉取與推送都以檔案為單位合併，同一個檔案兩邊改成不同內容就停下來三選一（版本說明檔的內容雜湊相同時視為同一個版本、用遠端的那份，所以各自自動匯入範例的兩台第一次拉取不會衝突）（取消、推送到新分支 rpa/<領域>-<時間>、以遠端為準並先備份到 backups/），永遠不強推。推送前擋下登入狀態、Secrets、私鑰之類的檔名、非定義檔、超過 1 MB 的檔案，以及內容含有已保存的 Secret 值的檔案；組合場景依賴的其他領域的版本還沒推送時提醒。伺服器啟動時在背景拉取設定了「自動拉取」的領域，連不上時用本機上一次的資料。
  • 從頭開始與備份。先停止管理 Portal（終端機按 Ctrl+C）：刪掉資料夾就是從頭開始，複製整個資料夾就是備份。
  • 不要提交或分享。裡面有登入狀態與 Secrets 的值（只有本人能讀寫）。Git 已經忽略專案裡的 data/ 與 data-*/；用其他名稱或放在別處時請自己留意。

領域

場景管理的二級選單
  • 依目標系統或業務劃分場景。例如「測試網站自動化」「谷歌自動化」「微軟自動化」。每個領域是「場景管理」左側的一個選單，最後一項是「領域管理」。
  • 領域頁是場景卡片。1440 寬一列 4 張（每張至少 272px）。每張卡片有名稱與分類（沒有分類時顯示 DSL 場景或 Python 腳本）、最近一次執行的截圖、說明，「自動化腳本、斷言腳本、執行報告、入參設定、出參設定」五個連結，以及場景編號、最近一次結果、「調試」（DSL 場景打開逐步調試，在那裡可以接著驗證；Python 腳本場景直接驗證最新版本）與「運行」（執行已發布版本；還沒發布時顯示「待發布」）。
  • 領域管理。新增領域（代號用在網址，建立後不能改）、改名稱與說明、刪除沒有場景的領域。場景頁的「執行設定」可以把場景移到其他領域。
  • 測試網站自動化。第一次啟動時自動建立，放進對測試網站執行的真實案例：建立紀錄（BA-001）、查詢紀錄（BA-002，入參是 BA-001 的出參）、查詢不存在的紀錄（BA-003）、Python 腳本版的建立紀錄，以及兩個登入範例（BA-004 一般使用者、BA-005 主管）。它的名稱與說明跟著介面語言顯示，改過之後就照改的內容；場景的名稱與說明是場景檔的內容，不會翻譯。

流程

驗收：在瀏覽器內走完一次
1 建立或匯入2 編輯3 驗證4 發布5 執行6 看報告
  1. 建立或匯入。新增場景會產生第 1 版草稿（只開一個網頁）；也可以一鍵匯入 scenarios/demo 的範例。場景編號就是 DSL 的 id，建立後不能改、也不會重複使用。
  2. 編輯。直接編輯 YAML（腳本場景另有兩支腳本）。存檔前先用 rpa validate 同一套規則校驗，有問題時列出行號、步驟與欄位，不會建立新版本。
  3. 驗證。用真實瀏覽器執行指定版本，入參、瀏覽器、瀏覽器視窗、網址都可以在表單調整。
  4. 發布。只有通過驗證的版本可以發布，而且要使用者在對話框確認。
  5. 執行。一律使用已發布的版本；新的草稿不影響正式執行。
  6. 看報告。依分類、場景、結果與目的篩選：每個條件是一個按鈕，顯示目前的選擇，點開勾選一項或多項，按「套用」或關閉選單就更新；沒勾選代表全部。每次執行都有 M2 的 report.html、截圖與完整的執行目錄。

版本與發布門檻

  • 版本不可變。每次存檔都是新版本（v1、v2…），內容寫進資料目錄後設成唯讀。存檔要帶「從哪一版開始改」，不是最新版就回 409，避免覆蓋別人的修改。
  • 狀態。草稿 → 驗證中 → 驗證通過／驗證失敗；狀態是最近一次驗證紀錄的結果。發布後場景指向該版本，舊的發布版本留在歷史中。
  • 驗證的就是發布的。版本記錄內容雜湊，演算法與 rpa-runner 寫在 result.json 的 scenarioHash 相同。發布時要同時符合：磁碟上的內容重新計算後是同一個雜湊、版本說明檔記的也是它，而且領域資料夾裡有一份雜湊相符的通過驗證紀錄。
  • 紀錄跟著領域資料夾（M11）。每次驗證寫一份驗證紀錄（通過、失敗都寫：誰、哪台伺服器、哪台 worker、結果、雜湊），發布寫進 scene.yaml。紀錄跟著領域資料夾同步，任何一台伺服器的通過紀錄都能當發布的依據；場景頁列出全部驗證紀錄。
  • 改內容就重新驗證。新版本一律從草稿開始，舊版本的驗證結果不能拿來發布新內容。

執行

  • 先校驗、再排隊。請求執行時先檢查入參，不合規則直接回 422，不會排進佇列；通過後回 202 與執行編號。
  • 背景 worker。rpa-worker 在伺服器程序內的背景執行緒，依建立時間一次執行一個（SQLite 只允許單一程序）。它呼叫 M2 的 rpa_runner.run.execute，總期限、子程序與程序群組的終止都沿用 M2。
  • 有頭模式與無頭模式。執行表單的「瀏覽器視窗」：顯示（有頭模式，headed）會在執行 Portal 的這台電腦上打開瀏覽器視窗，看得到每個步驟；不顯示（無頭模式，headless）在背景執行。預設有頭模式；這台電腦沒有圖形介面（Windows、macOS 以外，又沒有 DISPLAY 或 WAYLAND_DISPLAY）時只能無頭，API 要求有頭會回 422。執行頁會記下用的是哪一種。rpa run 命令列維持無頭，加 --headed 才顯示。
  • 進度。執行頁每秒查詢一次狀態，階段或狀態改變時重新整理。
  • 取消。排隊中的直接取消；執行中的立即終止子程序與瀏覽器，狀態為「已取消」。已經在目標網站完成的動作不會復原。
  • 不重複送出。表單每次載入產生一個 idempotencyKey，重複送出只會得到同一個執行。
  • 重新執行。結束的執行都可以用同樣的入參與選項再執行一次（驗證用同一個版本，正式執行用目前發布的版本）。
  • 伺服器重啟。啟動時把上次執行到一半的任務標為失敗；排隊中的會繼續執行。
  • 錄影（M12）。DSL 場景的自動化階段錄影，有頭、無頭都錄，存成執行目錄的 video.webm 與 video.json；steps.json 記下每一步的開始、結束時間與步驟後的網址，回看時和影片對上。畫面跟頁面一樣大，寬度最多 1280。取消、逾時、失敗的運行也有完整的影片（Windows 上取消時先只結束瀏覽器，讓 Playwright 把影片寫完；寫壞的影片用 Playwright 自帶的 ffmpeg 重新封裝）。登入檢查、逐步調試、錄製與 Python 腳本場景不錄。預設全部錄；通過的運行保留 7 天，失敗、逾時、取消、需要登入的保留 30 天，全部最多 20 GB（超過時從最舊的刪起），釘選的不刪。清理只刪影片，運行紀錄、報告、截圖都留著。見 ADR 0016。

登入與角色

M4：每個角色一份登入狀態，執行前先檢查
  • 場景只寫角色。需要登入的場景寫 login: { role: 角色代號 }（DSL）。怎麼登入、怎麼判斷已登入，在「場景管理 › 登入與憑證」登記：登入網址、確認網址、已登入時看得到的元素（DSL 定位器），以及選用的自動登入步驟。
  • 人工登入為主。按「登入」會在操作的那台電腦開瀏覽器視窗到登入網址（直接打開管理 Portal 時是執行 Portal 的這台，透過錄製端時是錄製端那台），由使用者自己登入，所以 SSO、驗證碼、手機或 App 二次驗證都能處理。完成後按「完成登入」或直接關掉視窗；開視窗的那台先用剛取得的登入狀態開一個無頭瀏覽器打開確認網址，看得到已登入時的元素，才把登入狀態傳回伺服器、取代原本的，所以伺服器不需要瀏覽器。還沒登入就按「完成登入」時，頁面說明確認網址停在哪裡，視窗不關，登入後再按一次；關掉視窗時還沒登入就結束，原本的登入狀態不變。操作的那台沒有圖形介面時不能人工登入。舊版的錄製端不會自己確認，改由伺服器確認（伺服器沒有瀏覽器時會說明要更新錄製端）。
  • 自動登入（選用）。只適合單純帳號密碼的系統：角色附一段 DSL 步驟，密碼用 {{ secrets.名稱 }}。執行前發現沒登入時先自動登入一次。
  • 檢查。角色的「檢查」用無頭瀏覽器確認登入狀態是否仍然有效（有自動登入步驟時，沒登入就自動登入）。伺服器有下載角色用的瀏覽器時在伺服器檢查；沒有時（例如 Linux 安裝腳本裝的伺服器），透過錄製端打開管理 Portal 就在錄製端檢查，直接打開時按鈕是灰的。檢查用登入狀態的複本，通過後才取代原本的；檢查期間人工登入或執行更新了登入狀態時，保留較新的那份。不先檢查也可以：每次執行都會先在執行的那台檢查。
  • 需要登入（needs_login）。每次執行先在「登入檢查」階段打開確認網址：看得到元素就繼續；沒有（例如被轉到登入頁）而且不能自動登入時，停在「需要登入」，不執行任何步驟，並留下登入檢查的截圖。執行頁有「登入角色」與「重新執行」：登入後用同樣的入參再跑一次。
  • 角色互不干擾。登入狀態（Playwright storageState）每個角色一份，存在資料目錄的 roles/<角色>/state.json，只有本人能讀寫；每次執行開新的瀏覽器 context，只載入場景指定的那個角色。登入狀態不會複製進執行目錄，也不經由網頁或 API 提供。執行的結果也會更新角色的狀態（已登入、需要登入）。
  • Secrets。同一頁可以設定 Secrets 的值：存在資料目錄的 secrets.json（只有本人能讀寫，M8 改為加密），頁面與 API 只顯示名稱與更新時間，永遠不回傳值。執行時把場景與角色用到的值交給執行引擎；沒有設定的再從同名的環境變數找。頁面也列出場景用到、但還沒設定的 Secrets。
  • 測試網站的兩個角色。匯入範例時，BA-004（一般使用者）與 BA-005（主管）用到的角色依 scenarios/demo/roles.json 一起建立；示範帳號寫在測試網站的登入頁。兩個帳號看到的待辦不同，用來確認角色之間沒有混用。

錄製

M4：原始錄製稿 → DSL 草稿
1 錄製草稿2 調試與修改3 驗證4 確認發布
  • 在這台電腦錄製。「場景生產 › 自主腳本錄製」按「開始錄製」，執行 Portal 的電腦會開啟 Playwright codegen 的瀏覽器與 Inspector；照平常的方式操作，完成後關掉瀏覽器視窗。選了登入角色時先載入它的登入狀態。也可以在命令列用 rpa record 網址 --out 錄製稿.py --scenario 草稿.yaml。
  • 三種目標。新場景（存成 v1）；既有場景「接著現有步驟錄製」：先在錄製的瀏覽器裡用入參預設值執行最新版本的步驟，停在最後一步的頁面，再開始錄製，錄到的步驟、出參與斷言接在原有內容後面（原有的內容與註解不變；既有步驟執行失敗時錄製停止，不會存檔）；既有場景「整份換成錄製的內容」：從起始網址重新錄，存成新版本。選既有場景時，起始網址、瀏覽器、登入角色自動帶入它的設定。
  • Inspector 的程式碼不能直接改。Inspector 右側的程式碼是 Playwright 依操作即時產生的，只能看、複製（Playwright 本身的設計，不是本工程限制）；Locator 分頁可以輸入並測試定位器。要修改請在轉換後到場景的「自動化腳本」「斷言腳本」編輯。
  • 貼上錄製稿。在別台電腦錄好的 codegen 原始稿（同步、非同步或 pytest 寫法）可以貼上直接轉換，例如 Portal 跑在沒有圖形介面的電腦時。
  • 斷言變成出參。Inspector 的「Assert text」「Assert value」（expect(…).to_contain_text、to_have_value、to_have_text）不當成步驟裡的檢查，而是：自動化腳本多一個 extract 讀取那個元素（先等它出現），出參多一項取自這個頁面事實，斷言腳本（verify:）多一條檢查——錄到的值等於某個輸入的值時檢查「等於該入參」，否則檢查「有取得內容」。出參名稱取自元素的英數名稱，之後可以改。
  • 轉換規則。goto、click、fill、press、select_option、check 與其他常見的 expect，以及 get_by_role、label、placeholder、text、test_id、CSS、XPath、first、nth、filter(has_text) 等定位器。第一個網址的來源成為 browser.baseUrl。轉不了的行（hover、上傳、iframe、新分頁…）以註解留在草稿裡並列在錄製詳情。
  • 自動參數化。每個輸入的值變成一個入參，預設值是錄到的值；名稱取自欄位的英數名稱（沒有時叫 field、field_2…），欄位標籤寫在說明，之後在場景頁的表單改名。
  • 密碼不落地。密碼欄位（標籤、提示文字或選擇器含有 password、密碼等字）改成 Secret 引用，原始錄製稿也遮罩成 *** 才保存；錄製中的暫存原始稿轉換後就刪除。
  • 只產生草稿。轉換結果存成新場景的 v1，或既有場景的新版本；錄製稿只當來源，一樣要調試、驗證通過才能發布。錄製詳情列出步驟、入參、出參、斷言與轉不了的行的數量。

逐步調試

M4：一個瀏覽器、一次一步
  • 開始。場景頁的「逐步調試」或卡片的「調試」選版本、入參、瀏覽器與視窗模式。有圖形介面時瀏覽器視窗開在這台電腦上；兩種模式都在頁面上顯示每一步之後的截圖、網址與頁面事實。只支援 DSL 場景。
  • 執行。每一步可以「執行這一步」，或「執行到這裡」（只執行還沒執行過的步驟，遇到失敗就停）。有副作用的步驟（點擊、填寫、選擇、勾選、按鍵）執行過一次後，再執行要先確認；不會自動重複任何步驟。「從頭開始」開新的頁面並重新載入登入狀態。
  • 定位器測試。輸入 DSL 定位器（例如 { role: button, name: 登入 }），回報找到幾個元素與前幾個的文字，截圖時以紅框標出。
  • 修改。頁面下方直接編輯 YAML，存成新版本後換到新版本繼續；瀏覽器與頁面事實保留，執行過的步驟依 id 保留狀態。
  • 限制。每個場景同一時間一個工作階段；閒置 15 分鐘自動結束，伺服器關閉時全部結束。調試會真的操作目標網站，請用測試環境。

分段編輯：自動化腳本、斷言腳本、入參、出參

M4
  • 自動化腳本與斷言腳本分開。DSL 場景的卡片與場景頁有「自動化腳本」（steps:）與「斷言腳本」（verify:）兩個入口，各自只顯示、只改寫場景檔的那一段；執行時先跑自動化步驟，再用斷言腳本檢查取得的頁面事實，全部通過才發布出參。斷言腳本右側可以一鍵插入 notEmpty、equals、contains、matches 的檢查，點一下頁面事實或入參的名稱就插入到游標位置。存檔前校驗，問題標出段落裡的行號。
  • 入參與出參左右編輯。場景頁優先呈現契約工作台，預設左右兩欄 YAML 原文；表格仍可新增、排序、改名與設定限制。切換檢視保留兩欄草稿，統一「儲存入參與出參」會一起校驗並建立一個版本，任一欄有錯不會部分保存。錯誤標示欄位及段落行號；版本衝突回 409，保留草稿。
  • 三個唯讀預覽。在左右編輯器下方依序平鋪「預設入參」「出參樣例」「出參提取映射」，桌面三欄同時可見，窄屏縱向排列，無需切換頁籤。預設入參與提取映射隨草稿自動刷新；草稿無效時清除舊預覽並提示不可用。預設入參由目前草稿產生，沒有預設值的必填項另列，不偽造值。出參樣例只取該已儲存版本最近一次成功執行的真實出參，標明版本與執行編號；沒有結果時明確顯示空狀態，草稿已修改時提示尚未驗證。提取映射來自草稿的 outputs.from；Python 場景明示由 assertion.py 產生。三個預覽不接受編輯保存。
  • 修改與驗證動線。契約、完整檔案與腳本分段保存後留在原頁，更新版本並顯示「驗證這個版本」。發布後留在報告，顯示已發布版本與執行入口。離開有修改的編輯器會提示。契約保存只替換 inputs／outputs，其他段落與註解保留；表格改名同步更新 DSL 引用，YAML 改名需自行調整引用。新版本仍需重新驗證、發布；不修改 Python 腳本。

自由試驗場與組合場景

DAG：可分叉、可匯合，成功出參傳給下游，失敗即停
  • 管理與生產。「場景管理 › 組合場景自動化」沿用測試網站自動化的卡片風格，以真實節點座標和依賴產生 DAG 縮圖，管理名稱、節點、問題與最近執行；卡片的「執行組合場景」可直接選引擎、執行位置與視窗模式；「場景生產 › 自由試驗場」建立、開啟與編輯畫布。場景生產選單依序為自主腳本錄製、自由試驗場、運行報告、裝置（M10.1 前叫「遠端 Worker」）。
  • 依賴畫布。場景庫可點選加入或拖入畫布。拖動節點或用方向鍵微調位置；點上游右側圓點，再點下游左側圓點建立連線。點連線設定下游入參，也可以從右側加入上游。縮放與適應只改視角，不改座標。節點座標隨組合場景保存；畫布位置和節點陣列順序不代表執行順序。頂部名稱與操作合併成一列，說明收在「說明」，執行歷史預設折疊。畫布下方的全寬參數區獨立捲動，並列上游出參、下游入參、匹配方式、取值／來源；點選 DAG 連線會切到該組上游與下游。多上游可切換來源節點。
  • 四種入參來源。同名匹配僅搜尋直接連線的上游，唯一同名且型別相容時取其出參，沒有命中則用場景預設，多個命中必須指定來源；場景預設強制忽略上游同名值；人工指定只覆蓋此節點；指定上游出參可以跨欄位綁定。選擇出參會建立依賴；一個出參可供多個下游，一個入參只有一個來源。整數可以傳給數字，其他型別必須相同。
  • 參數連線。拖動出參圓點到入參，或依次用滑鼠／鍵盤選取兩端，建立顯式綁定；型別不符不修改原值。四種模式以按鈕同列呈現，仍可用出參選單精確選擇。唯一同名匹配與顯式來源畫出對應連線；歧義、預設值及人工值不畫假連線。契約按鈕原地顯示該固定版本的唯讀原文；編輯場景明示另開分頁，並提示驗證、發布後回畫布選新版本。
  • 執行與返回。從畫布啟動後原地顯示快照版本、進度與各節點狀態，點節點可看本次入參、成功出參或錯誤；可原地取消。完整報告與節點報告由使用者主動打開，回畫布恢復選取節點、上游與縮放／捲動位置。卡片快捷執行仍直接進入報告。編輯畫布不改變已開始執行的快照。
  • 直接依賴與清理。顯式連線及出參引用都形成依賴。移除連線清理對應的出參引用並重新檢查來源；移除節點同時清理它的連線與下游引用。重設入參會恢復同名匹配。循環、自我依賴、重複邊或不存在的端點不可執行。
  • 代號、領域與版本（M11 PR 2）。組合場景有英數代號（沒填就是 wf-<數字>，所有領域不能重複），放在某個領域資料夾的 composites/<代號>/，沒選領域就放「組合場景」領域。改定義的每次存檔都是新版本（revisions/<版本>/workflow.json，唯讀），版本說明檔釘住每個節點用到的場景版本（領域、場景、版本、雜湊）；改名稱與說明只改 composite.yaml，不分版本。用到其他領域時寫進 pack.yaml 的 requires。
  • 驗證、發布與執行（M11 PR 2）。執行時選目的：「驗證」跑某個版本（預設最新），結束時寫驗證紀錄（每個節點的場景、版本、雜湊、狀態與執行編號）；「執行」只跑發布的版本，不寫驗證紀錄。發布要有雜湊相符的通過驗證紀錄，而且每個節點跑的都是釘住的場景版本、那些場景版本現在還在且雜湊相同；發布寫進 composite.yaml。每次執行在 workflow-runs/<執行編號>/run.json 記下定義快照、版本、目的與每個節點的狀態。
  • 依賴檢查（M11 PR 2）。組合場景頁列出最新版本與發布版本的依賴問題並給補全方式：沒有那個領域（新增領域）、場景或版本不在、版本不能執行（重新載入領域）、雜湊不符或沒釘住（重新存檔）是錯誤，不能執行與發布；角色沒登入、缺少 Secrets 是提醒。卡片顯示「依賴不完整」或「依賴有提醒」。有組合場景的領域不能刪除。rpa pack check 一次給多個資料夾時也檢查它們之間的依賴。
  • 補全依賴與管理（M11 收尾）。領域接上 git 後，依賴它的領域的 pack.yaml 在 requires 記下 source（倉庫、目錄、分支，不含帳密）；別人缺這個領域時，依賴提示的「從 git 新增」帶著它預填；領域有資料來源但缺場景或版本時提示「拉取」。領域管理頁列出每個領域被哪些組合場景依賴。組合場景頁可以改代號、搬到其他領域（資料夾連同版本與驗證紀錄改名或搬走）、封存（不能執行），也可以驗證指定的舊版本。
  • 保存與預檢。草稿可帶待修正的問題保存；保存攜帶 baseVersion，版本衝突回 409，頁面保留草稿供匯出。執行前檢查全圖、已發布固定版本、欄位、型別、必填值及固定值規則；有問題時第一個節點也不排入佇列。問題清單與執行阻擋對話框顯示節點、場景、入參及具體原因，點選可定位到畫布節點或入參欄位；欄位同步標紅。「執行前檢查」可手動檢查，卡片執行也重新取得最新問題。新增場景時不自動建立與前一節點的連線。
  • 分叉與匯合。拓撲排序保證所有上游都通過才執行下游；就緒節點以定義中的順序穩定選取，逐個排入既有佇列。每個節點有自己的真實執行、入參、成功出參與報告。下游執行前再檢查實際值，不符合規則就停止，不回退到預設值。
  • 快照與恢復。開始時固定編排、場景版本及同名匹配的具體來源，後續編輯不影響已開始的執行。失敗、逾時、取消、需要登入或 worker 失聯皆停止全圖；續跑沿用拓撲順序中已通過的結果，不重複已成功的外部操作。所有節點沿用同一台 worker；取消不回滾外部動作。
  • 格式與相容。新定義使用 version: 2、mode: "dag"、onFailure: "stop"、nodes 及 edges: [{"source":"n1","target":"n2"}]。節點可帶 position: {"x":40,"y":60}；inputs 的值可為 {"auto":true}、{"value":7} 或 {"node":"n1","output":"quantity"}，省略代表場景預設。舊版 serial 定義與歷史快照繼續可用；舊序列開啟畫布後，下次保存轉成相同順序的依賴邊，不更動已有歷史執行。JSON 匯出、匯入保留座標與綁定。
  • 本次範圍。最多 50 節點，支援一般分叉與匯合，不做條件路由或同時執行。沿用現有 DSL 的字串、整數、數字、布林入參；原型裡的重複次數、日期／隨機占位符與複合型別入參未納入本次五項需求。原型 JSON 是參考契約，不直接當成 Portal 的匯入格式。

遠端 worker

M9a：執行交給另一台電腦，這台電腦不再被瀏覽器視窗占住（ADR 0012）
  • 兩個埠。rpa serve --worker-port 8081 另外開一個對外埠（M10 起的稱呼），只有 Worker API（/worker-api/v1）與桌面 App 的 Client API（/client-api/v1，M10.1 只有配對），預設聽所有網路介面；管理頁面與 /api 仍然只在 --host（預設 127.0.0.1）。兩邊的路徑互相擋掉：從對外埠看不到管理頁面，從管理頁面的埠也呼叫不到 Worker API 與 Client API。
  • 裝置與邀請（M10.1）。「場景生產 › 裝置」（原「遠端 Worker」頁，舊網址 /workers 轉到 /devices）新增裝置（代號、名稱；目前種類只有 Worker），產生一份邀請：一行 rpa://pair?server=…&app=worker&code=…，代碼一次性、24 小時內有效、限定 App 種類，資料庫只存雜湊；也分開顯示伺服器與代碼。在那台電腦的 RPA Worker（或 rpa worker --invite）貼上，經由 Client API 的 /pair 換到權杖。「重新邀請」讓舊權杖與之前的邀請立刻失效。邀請要先開對外埠；沒開時「新增裝置」不能按。可以停用、刪除（執行中不能刪；指定給它而還在排隊的執行標為失敗）。頁面列出每台的狀態（線上、執行中、離線、停用）、最後回報、作業系統、瀏覽器、能不能有頭模式、App 版本，以及程式版本是否和 Portal 相同。
  • 領取。worker 執行 rpa worker --server …，上線時回報協定版本（不同就拒絕）、程式指紋（不同只提醒）、瀏覽器與能不能顯示視窗；之後長輪詢（最多 25 秒）領取任務。只給它能跑的：執行位置是遠端或任一、瀏覽器有下載、有頭模式要能顯示視窗、指定給它的。依建立順序先進先出。
  • 任務的內容。場景版本的檔案（照位元組傳送，雜湊和 Portal 一致）、入參、瀏覽器、網址、視窗模式、語言；場景有登入角色時加上登入設定與目前的登入狀態，以及用到的 Secrets 的值。worker 只放在記憶體與執行期間的暫存檔，執行完刪除。
  • 心跳、取消、失聯。執行中每 5 秒心跳，同時回報階段；在 Portal 取消時，下一次心跳就終止瀏覽器。領取時給 60 秒租約、心跳延長；過期就把執行標為失敗「worker 失聯」，不自動重跑（可能已經有副作用），之後 worker 才回報的結果一律拒絕。Portal 重新啟動時，遠端執行中的任務給一次租約的時間重新報到；本機的照舊標為中斷。
  • 結果。worker 把整個執行目錄打包上傳（只接受安全的相對路徑，有檔案數與大小上限），再回報 result.json 的內容；寫回的規則和本機相同，包括驗證時的雜湊比對。自動登入後的新登入狀態傳回角色。
  • 執行位置。登記了遠端 worker 之後，驗證、執行與「執行序列」的表單多一個「執行位置」：本機、遠端 worker、任一；預設在裝置頁設定（沒設定是本機）。有頭模式能不能選，跟著所選的位置。場景的網址指向本機（127.0.0.1、localhost、::1，測試網站的 8765 除外）而位置不是本機時，表單提醒那指的是 worker 自己。執行報告與執行頁顯示由哪台執行；執行報告可以依「執行位置」篩選（本機與各台 worker）。排隊中而沒有線上的遠端 worker 可以接時（包括序列固定的那台離線），執行頁與序列執行頁說明正在等待並連到裝置頁。
  • 試驗場序列。整個序列用同一個執行位置，而且第一個節點由哪台 worker 領取，後面的節點都固定給它（測試網站的資料、登入狀態一致）；那台離線時後面的節點等著，可以取消。「從停下的節點繼續」也固定給原本那台。
  • 只讓 worker 執行。--no-local-worker：這台電腦不執行，執行位置不能選本機，預設改成任一。
  • 仍在這台電腦的。錄製、逐步調試、人工登入要有人操作，還是在執行 Portal 的電腦。

手動驗收

M4、M6、M9a：錄製、人工登入、試驗場與遠端 worker 要有人操作；自動測試用預先錄好的錄製稿

在有圖形介面的電腦（macOS、Windows，或有桌面的 Linux）上，用一個全新的資料夾走一次，大約二十分鐘：

  1. 啟動。uv run rpa serve --data data-check，打開 http://127.0.0.1:8080；「測試網站自動化」已經有 BA-001～BA-005。
  2. 錄製新場景。「場景生產 › 自主腳本錄製」選「新場景」，起始網址 http://127.0.0.1:8765/，按「開始錄製」。在測試頁填標題與數量、按「建立紀錄」，在 Inspector 用「Assert text」點一下紀錄編號，關掉瀏覽器。錄製詳情應該有 goto、兩個 fill、click、一個 extract，入參 2 個、出參 1 個、斷言 1 條。
  3. 調試、驗證、發布、運行。在新場景按「調試」，逐步執行到最後一步並看截圖；回到場景頁驗證 v1，通過後發布，再從卡片按「運行」，報告是「通過」，出參有紀錄編號。
  4. 接著現有步驟錄製。選「既有場景的新版本」與剛才的場景，再選「接著現有步驟錄製」：瀏覽器先自動跑完原有步驟，停在建立結果的頁面，再錄一個動作；新版本的步驟接在原有內容後面，原本的註解不變。
  5. 兩個角色。「場景管理 › 登入與憑證」對 testsite-user 按「登入」，在跳出的視窗用 user / user-pass 登入後按「完成登入」；testsite-manager 用 manager / manager-pass。再分別運行 BA-004、BA-005：兩份報告看到的待辦不同。
  6. 需要登入與重新執行。對 testsite-user 按「登出」，再運行 BA-004：停在「需要登入」，沒有執行任何步驟；點執行頁的登入角色回到「登入與憑證」再登入一次，回到執行頁按「重新執行」，結果是「通過」。
  7. 自由試驗場。先驗證並發布 BA-001、BA-002。建立組合場景，加入一個 BA-001、兩個 BA-002 及另一個 BA-001 作為匯合節點；連接「建立 → 兩次查詢 → 匯合」，讓兩個查詢的 recordId 同名匹配上游，匯合的 title 與 quantity 分別取自兩個查詢。拖動節點、儲存並重載，確認位置保留。執行後四個節點都通過且實際入參相符；反向連線應被拒絕。從場景管理的組合場景卡片打開最近執行，確認報告可追溯。
  8. 遠端 worker（兩台電腦，M9a）。Portal 改用 uv run rpa serve --data data-check --worker-port 8081 啟動；「場景生產 › 裝置」新增 win-01，在另一台電腦用對話框裡的邀請啟動 rpa worker --invite …（M10.1 的 RPA Worker App 交付後改在 App 貼上；步驟見遠端 worker），裝置頁變成「線上」。用「遠端 worker」、有頭模式執行 BA-001：瀏覽器視窗出現在 worker 機器，這台電腦沒有跳出視窗；報告是「通過」，執行頁顯示「執行的電腦：win-01」，截圖看得到。再用「遠端 worker」執行第 7 步的組合場景，四個節點都在 win-01。執行中在 worker 機器按 Ctrl+C：Portal 上那次執行變成「已取消」。
  9. 運行回看（M12）。運行報告的「回看」欄有 ▶ 與影片長度；打開第 3 步的驗證：影片可以播放、暫停、拖曳，滑過時間軸有預覽，步驟清單跟著影片走，點一步跳到那一步。執行 BA-002 查詢不存在的編號（失敗）：打開回看就停在失敗步驟之前，結束時有「回到失敗的步驟」。在 win-01 用有頭、無頭各執行一次，執行中取消一次：三段影片都能播放與拖曳。在 Mac 錄製端 App 裡打開同一頁也能播放。

結束後停止管理 Portal，刪掉 data-check 資料夾即可；worker 機器上的 worker-data 資料夾也可以刪掉。

代號、名稱、說明、排列順序；最近一次載入領域資料夾的時間與載入問題；git 資料來源（不含權杖）與同步狀態（上次同步的提交、上次看到的遠端提交、分支、錯誤、衝突的檔案）
scenes
id、名稱與分類（取自最新版本）、所屬領域、預設網址、最新與已發布的版本號碼、封存、來源缺失
revisions
場景、版本號碼（唯一）、內容雜湊、種類、狀態、說明、發布時間；來源缺失、不能執行的問題、有沒有雜湊相符的通過驗證紀錄
runs
執行編號、場景與版本、當時的名稱與分類、目的、狀態與階段、有頭或無頭模式、入參與出參、錯誤、雜湊、時間；試驗場節點的序列執行與節點代號；執行位置、指定的 worker、實際執行的 worker 與租約；錄影的長度與大小、釘選、刪除的時間與原因（M12）
roles
代號、名稱、登入網址、確認網址與判斷元素、瀏覽器、自動登入步驟、最近的狀態與檢查時間；所在領域、來源缺失
recordings
錄製編號、目標場景與版本、方式（新場景、接著現有步驟、整份換掉）與接續的版本、來源（錄製或貼上）、網址、瀏覽器、角色、狀態、轉不了的行
workflows
組合場景：代號、所在領域、名稱、說明、最新版本的定義（JSON）與版本號碼、發布的版本、封存、來源缺失
workflow_revisions
組合場景的版本（資料夾的索引）：版本號碼、雜湊、狀態、有沒有雜湊相符的通過驗證紀錄、不能執行的問題、說明、發布時間
workflow_runs
序列的執行：序列與當時的名稱、代號、版本與目的、定義的快照、狀態、停在哪個節點與原因、沿用的節點（從停下的節點繼續時）、瀏覽器與視窗模式、時間；執行位置與固定的 worker
workers
遠端 worker：代號、名稱、權杖的雜湊、停用、上線時回報的資訊（M10.1 加上 App 版本）、目前的執行、最後回報時間
device_invites
裝置邀請（M10.1）：代碼的雜湊、App 種類、裝置代號、產生時間、期限、使用時間
settings
設定（預設執行位置、伺服器代號與名稱、資料夾的格式、錄影）

模型用 SQLAlchemy 2，結構變更走 Alembic 遷移（伺服器啟動時自動升級）；測試會比對遷移與模型是否一致。

設定

--host、--port
預設 127.0.0.1:8080；沒有指定埠號而 8080 被其他程式占用時，自動改用下一個空的埠號（到 8089）。占用的如果就是管理 Portal，只顯示它的網址，不再開第二個
RPA_DATA_DIR
資料夾，預設 data；也可以用 --data（見資料夾）
RPA_DATABASE_URL
預設 SQLite；PostgreSQL 在 M8
RPA_LANG
預設語言，也是執行報告的語言；頁面右上角可以切換
--no-testsite
不要一起啟動測試網站（預設會在 127.0.0.1:8765 啟動；已經在執行就沿用）
RPA_EXAMPLES_DIR
「測試網站自動化」的範例資料夾，預設 scenarios/demo
Secrets
在「登入與憑證」設定；沒有設定的，從伺服器程序的同名環境變數讀取（遠端 worker 執行時，從 worker 程序的環境變數讀取）
--worker-port、--worker-host
開放對外埠給裝置（M9a；M10 起稱「對外埠」）：另一個埠，預設聽 0.0.0.0；只有 /worker-api（要權杖）與 /client-api（配對用邀請代碼）。邀請裡的伺服器網址：聽所有介面時猜這台的區網位址，聽特定位址時就用那個位址
--no-local-worker
這台電腦不執行，全部交給遠端 worker

安全與限制

  • 沒有登入。預設只聽 127.0.0.1；改成其他位址時 rpa serve 會提醒。認證與權限在 M8。
  • 擋掉跨站請求。寫入請求帶了 Origin 標頭時必須同源，避免其他網站在背景呼叫本機的 API。
  • 執行目錄的檔案。只提供執行目錄內的檔案；只有 report.html 當成網頁顯示，並加上只允許內嵌樣式與截圖的內容安全政策。
  • 腳本場景等同執行任意程式。與 M2 相同，Python 腳本場景只給信任的人編輯。
  • 登入狀態與 Secrets 存在這台電腦。兩者都在資料目錄、只有本人能讀寫，不經由網頁或 /api 提供，也不寫進執行目錄、報告與日誌；錄製稿裡的密碼遮罩後才保存。M8 加密存放。
  • 遠端 worker 拿得到執行要用的 Secrets 與登入狀態。只在領取任務的回應裡，worker 放在記憶體與執行期間只有本人能讀寫的暫存檔，執行完刪除。Worker API 用 HTTP 時在區網上是明文：只在信任的網路使用；權杖只存雜湊，可以隨時停用或重新產生。
