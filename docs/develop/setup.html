開發環境

從零到能跑測試，大約五分鐘。Windows、macOS、Linux 指令相同。想一條命令裝好全部，用本機從零運行的一鍵腳本；第一次在 Mac 上設定，可照macOS 本機運行一步步做。

第一次設定

git clone https://github.com/DevopsLeaDevops/web_browser_robotic_process_automation.git
cd web_browser_robotic_process_automation

# 建立 .venv，安裝全部套件與開發工具
uv sync

# 下載 Chromium 與 Firefox（Linux 第一次可加 --with-deps 安裝系統依賴）
uv run python tools/install_browsers.py

# 提交前自動檢查
uv run pre-commit install

# 確認安裝成功
uv run rpa --version

uv
0.11 以上，安裝方式見 uv 官方文件。
Git
任一近期版本。
Node.js
M8 開始做前端時才需要。

不用安裝。M7 起開發用 SQLite（Python 內建）；PostgreSQL 只有正式環境需要，見 ADR 0008。

Linux 伺服器：分發包（建議）

下載 RPA-Server-版本-linux-x64.tar.gz（aarch64 用 linux-arm64），解壓後執行裡面的 install.sh。分發包內含 Python 3.13 與照 uv.lock 裝好的所有套件：伺服器不需要 git clone、uv，也不必連到 GitHub 或 PyPI；在能上網的電腦下載一個檔案、複製到伺服器就能安裝。適用的系統和從原始碼安裝相同：RHEL／CentOS 衍生版、x86_64 或 aarch64、glibc 2.28 以上。

# 檔名裡的版本換成實際下載的
tar -xzf RPA-Server-0.4.1-linux-x64.tar.gz
bash RPA-Server-0.4.1-linux-x64/install.sh --install-service
sudo systemctl status rpa-server

# 不用 systemd（例如容器）：前景啟動
~/rpa-server/bin/rpa-server

# 升級：解壓新版的分發包，再執行一次；服務正在執行時自動重新啟動
tar -xzf RPA-Server-0.4.2-linux-x64.tar.gz
bash RPA-Server-0.4.2-linux-x64/install.sh
取得
GitHub Release 附 x64、arm64 兩個分發包與 SHA256SUMS.txt（sha256sum -c SHA256SUMS.txt --ignore-missing）；加入分發包之後的第一個發布才有。在那之前，或要試尚未發布的版本，從 GitHub Actions「伺服器分發包」那次運行的產物下載（需要登入 GitHub）。
安裝位置
預設 ~/rpa-server（--prefix 或 RPA_SERVER_HOME 可改）。每個版本放在 releases/版本-提交/，current 指向使用中的版本；bin/rpa-server 是啟動器（systemd 也用它），bin/rpa 是 rpa 命令。新版本先放好、確認包內的 Python 在這台能執行，才把 current 換過去；保留最近 3 個版本（--keep）。
設定與資料
設定檔 ~/rpa-server/rpa-server.env，變數和下方的 .rpa-server.env 相同（RPA_DATA_DIR、RPA_PORT、RPA_WORKER_PORT、RPA_WORKER_HOST、RPA_TESTSITE_HOST）；首次安裝時可以用環境變數指定，之後修改檔案再重新啟動服務。資料預設在 ~/.local/share/rpa-server，安裝、升級與重裝都不會清除。
從 clone 安裝改過來
第一次安裝時自動沿用 setup-linux.sh 的設定：先找 systemd 服務啟動的那份 .rpa-server.env，再找預設的 clone 位置；也可以用 --import-env 指定。資料目錄照舊，不搬動資料。現有服務仍指向 clone 的那份時，安裝程式不動它；加上 --install-service 才換成分發包並重新啟動。換過去之後，clone 與 .venv-server 可以保留或刪除。
系統套件
只補裝缺少的 libstdc++ 與 git（git 只有領域資料夾的 git 同步要用），所以升級通常不用 sudo 裝套件；管理員已備妥時加 --skip-system-packages。安裝 unit 與重新啟動服務需要 sudo。
升級失敗時
新版本啟動後約 60 秒內管理埠沒有回應，安裝程式停下並說明怎麼退回上一版（current 指回 releases/上一版 後重新啟動）。資料庫遷移在新版本啟動時執行：升級前照下方的方式備份整個資料目錄，退回舊版前先還原。

分發包由 CI 建置（tools/build_server.py、「伺服器分發包」流程）：只選 manylinux_2_28 以下的套件，建好後用包內的 Python 執行；再在同架構的 Rocky Linux 8 容器（glibc 2.28、公司映像的 os-release、一般帳號）實際安裝、沿用舊設定、冒煙測試、重裝與升級。容器沒有 systemd：真實的服務啟停與公司主機仍需驗收。首次管理、SSH 轉發與防火牆和下方相同。

Linux 伺服器：從原始碼安裝（yum／dnf）

一般建議用上方的分發包；要在伺服器上跑還沒發布的程式碼，或伺服器連得到 GitHub 與 PyPI 時，也可以 clone 後安裝。無桌面伺服器負責 Portal、資料庫與調度；遠端 Worker 執行瀏覽器，錄製端提供錄製、人工登入與有頭調試。使用 setup-linux.sh 安裝 .venv-server，不下載瀏覽器、不安裝桌面 App、開發工具或 Git hooks。CLI 既有相依仍包含 Playwright 的 Python 套件，但不啟動其瀏覽器 driver。

系統辨識
讀取 /etc/os-release 的 ID 與 ID_LIKE，接受 rhel、centos、fedora；先用 yum，再用 dnf。公司系統即使 ID=""、名稱空白，只要 ID_LIKE="rhel fedora centos " 仍可辨識；不把 VERSION_ID="3" 當作 CentOS 3。
執行環境
x86_64 或 aarch64、glibc 2.28 以上；用 uname -m 和 getconf GNU_LIBC_VERSION 檢查。x86_64、glibc 2.32 符合這些前置檢查，實際公司套件庫與主機仍需驗收。不替換系統 glibc 或 Python；uv 下載 .python-version 指定的 Python，依 uv.lock 安裝。
系統套件
git curl ca-certificates tar gzip libstdc++ libgcc。一般帳號執行；yum／dnf 與 systemd 操作使用 sudo。管理員已備妥套件時可加 --skip-system-packages。
資料
預設 ~/.local/share/rpa-server；首次可用 RPA_DATA_DIR 改位置。若接續既有服務，必須指定原資料目錄，否則會建立新的空白環境。
# 已經 clone：在專案根目錄（在 scripts 目錄時改成 bash setup-linux.sh）
bash scripts/setup-linux.sh
.venv-server/bin/rpa-server

# 或安裝為開機自啟動服務，不需要在終端機保持前景程序
bash scripts/setup-linux.sh --install-service
sudo systemctl status rpa-server
sudo journalctl -u rpa-server -f

# 尚無程式碼：完整下載成功後再執行（需要先有 curl 與 CA 憑證）
curl -LsSf https://raw.githubusercontent.com/DevopsLeaDevops/web_browser_robotic_process_automation/main/scripts/setup-linux.sh -o /tmp/rpa-setup-linux.sh
bash /tmp/rpa-setup-linux.sh --dir "$HOME/code/web_browser_robotic_process_automation"

第一次產生專案內的 .rpa-server.env（Bash 語法、權限 600、已加入 Git ignore）。預設管理頁面只聽 127.0.0.1:8080，裝置 API 聽 0.0.0.0:8081；以 --no-local-worker 啟動，預設不啟動測試網站。可修改檔案中的 RPA_DATA_DIR、RPA_PORT、RPA_WORKER_PORT、RPA_WORKER_HOST、RPA_TESTSITE_HOST（設成 0.0.0.0 時在 8765 啟動測試網站並讓錄製端、Worker 也連得到，見共用伺服器的測試網站；較早建立的設定檔沒有這一行，自己加上），再重啟服務；重跑 setup 會保留設定。服務與資料都歸執行腳本的帳號，不要整份腳本改用 sudo。

首次管理：在自己的電腦執行下面的 SSH 轉發，再開 http://127.0.0.1:8080，從「裝置」建立邀請。Worker／錄製端的邀請位址要是它們可連到的伺服器 IP 或 DNS、埠 8081；不要填 SSH 轉發的 127.0.0.1。配對後錄製端可經其本機閘道使用管理頁面。見遠端 Worker與桌面端分發。

ssh -N -L 8080:127.0.0.1:8080 admin@SERVER

# 修改設定後
sudo systemctl restart rpa-server

# 升級：先停服務並備份完整資料目錄（含 rpa.db、scenes、roles、secrets.json）
sudo systemctl stop rpa-server
# 在此備份 .rpa-server.env 中 RPA_DATA_DIR 指向的完整目錄
git pull --ff-only
bash scripts/setup-linux.sh --install-service

腳本只在 --install-service 時啟動服務；前景程序請用 Ctrl+C 停止。systemd 服務執行中會拒絕更新環境，前景程序也應先停止。容器沒有 systemd 時使用前景命令；產生的 unit 在 .venv-server/rpa-server.service。重裝不刪資料，但啟動服務會套用資料庫遷移，回退前需準備整份備份。腳本不會自動 pull 既有 checkout、切換既有分支或改防火牆；只讓需要連線的裝置存取裝置埠。

公司網路：需要可讀取程式碼、uv 安裝檔、Python 發行檔及鎖檔列出的套件來源。可設定 HTTPS_PROXY、UV_PYTHON_INSTALL_MIRROR；公司 CA 已加入系統信任時可用 UV_NATIVE_TLS=true。Git、curl 也必須信任該 CA，不要關閉 TLS 驗證。已有合規安裝的 uv 可直接重用；版本太舊時腳本會指出最低版本，由原安裝方式升級。

套件來源。Python 套件依 uv.lock 安裝，預設先測速再選來源（--mirror auto）：PyPI 與清華（tuna）、中科大（ustc）、阿里雲（aliyun）、騰訊雲（tencent）、華為雲（huawei）的鏡像同時下載鎖檔裡的同一個檔案，只考慮 sha256 和鎖檔相符的來源，選最快的那個並列出每個來源的速度；都不行時用 PyPI。可以直接指定：bash scripts/setup-linux.sh --mirror tuna、--mirror pypi，或公司鏡像的 simple 網址，例如 --mirror https://nexus.example.com/repository/pypi/simple（也可以設定 RPA_PYPI_MIRROR；沒有指定、但有設定 UV_INDEX_URL 或 UV_DEFAULT_INDEX 時就用它，不測速）。

為什麼要這樣做：uv sync --locked 照鎖檔記的網址下載（files.pythonhosted.org），單設 UV_INDEX_URL 不會改變下載的位置，還會讓 uv 判定鎖檔過期而停止。所以用鏡像時，腳本只在這次安裝期間把 uv.lock 裡的索引與檔案網址換成鏡像的（版本、檔案與 sha256 都不變，uv 下載後照樣驗證雜湊），裝完、失敗或中斷都還原；鏡像裝到一半失敗時自動改用 PyPI 再試一次。公司只允許核准的來源時，用 --mirror pypi（搭配 HTTPS_PROXY）或公司鏡像的網址，不要用 auto。不要刪鎖檔或臨時改版本。此 setup 不需要 Playwright 瀏覽器下載站。

驗證：CI 在 Rocky Linux 8（真實 yum、glibc 2.28、一般帳號）驗證專案內安裝、獨立腳本 clone、空 ID 的公司標記、重跑保留設定、管理埠與裝置埠隔離、裝置配對及重啟後資料保留。容器只檢查 systemd unit 語法；公司映像、aarch64 和真實 systemd 開機自啟動仍需主機驗收。可用 .venv-server/bin/python tools/linux_server_smoke.py 做隔離資料的 HTTP 冒煙測試。

常見問題

CI 說 uv.lock 需要更新
改了 pyproject.toml 的依賴卻沒有更新鎖檔。執行 uv lock，把 uv.lock 一起提交。
內網連不到 PyPI
設定環境變數 UV_INDEX_URL 指向公司的套件鏡像。Linux 伺服器的安裝腳本用 --mirror 指定公司鏡像的 simple 網址，見套件來源。
瀏覽器下載失敗
一鍵安裝會先測速並選最快的可用來源；也可執行 uv run python tools/install_browsers.py。需要固定來源時，設定 PLAYWRIGHT_DOWNLOAD_HOST 指向內部鏡像；瀏覽器冒煙測試在本機沒有瀏覽器時會自動略過。
測試說簡中不是最新
改了繁中文檔或訊息目錄後，執行 uv run python tools/i18n.py sync 並提交產生的檔案。
測試說英文翻譯需要更新
依繁中的修改更新 docs/en/ 的同一頁，再執行測試訊息裡的 stamp 命令。
pyright 找不到套件
確認已執行 uv sync，且編輯器使用的是專案的 .venv。
