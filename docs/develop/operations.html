部署與操作

伺服器、運行端（RPA Worker）、錄製端（RPA 錄製端）各放在哪裡、怎麼啟動、平常怎麼用、出問題看哪裡。第一次配對與安裝 App 的逐步說明在遠端 worker，這一頁只連過去，不重複。設計見 ADR 0012、ADR 0014。

三種角色

角色做什麼裝什麼啟動
伺服器管理 Portal、資料庫、場景版本、執行報告、登入狀態與 Secrets 都在這台；也可以自己執行任務（本機 worker）。開發環境（一鍵腳本），macOS、Linux、Windows 都可以。uv run rpa serve --worker-port 8081
運行端領取並執行場景，有頭模式的瀏覽器視窗開在這台；報告、截圖、Trace 傳回伺服器。Windows：RPA Worker App；其他系統用開發環境。App 登入時自動啟動；命令列 uv run rpa worker
錄製端透過它操作管理 Portal 時，錄製、逐步調試、人工登入的瀏覽器開在這台；錄製稿、截圖與登入狀態傳回伺服器。不執行場景。macOS（Apple 晶片）：RPA 錄製端 App；其他系統用開發環境。打開 App；命令列 uv run rpa recorder

連線方向只有一種：運行端與錄製端主動連到伺服器的對外埠（預設 8081），伺服器不連它們。三台都要連得到被測試的網站。三種角色可以在同一台電腦，也可以各自一台。

常見的部署方式

一台 Mac 全包
uv run rpa serve，打開 http://127.0.0.1:8080。錄製、調試、人工登入、執行都在這台，不需要配對任何裝置。
Linux 伺服器 ＋ Mac 錄製端 ＋ Windows 運行端
伺服器放在一直開著的 Linux（沒有桌面也可以）；在 Mac 打開 RPA 錄製端 App 操作管理 Portal，錄製、調試、人工登入的視窗開在 Mac；有頭模式的執行交給 Windows 的 RPA Worker。Linux 自己也能執行無頭模式的任務；全部交給 Windows 時加 --no-local-worker。
Mac 伺服器 ＋ Windows 運行端
在 Mac 的 8080 操作，錄製在 Mac；執行交給 Windows，Mac 不再被有頭模式的視窗占住。

伺服器沒有桌面時，從 8080（例如 SSH 通道）打開的頁面不能錄製、不能逐步調試、不能人工登入：這些按鈕是灰的，滑鼠移上去會提示改用錄製端。要在 Mac 錄製、調試或人工登入，一定要透過錄製端打開管理 Portal；「貼上錄製稿」與其他管理工作照常可用。

伺服器

安裝

用一鍵腳本安裝（裝 uv、下載程式碼、安裝依賴、下載 Chromium 與 Firefox、跑測試）。Linux 上瀏覽器缺系統函式庫時，腳本會用 sudo 交給 Playwright 安裝（只支援 Debian、Ubuntu 自動安裝）。之後的命令都在專案資料夾執行。

啟動

cd ~/code/web_browser_robotic_process_automation
uv run rpa serve --worker-port 8081                      # 有遠端裝置時
uv run rpa serve --worker-port 8081 --no-local-worker    # 全部交給遠端 worker
uv run rpa serve --worker-port 8081 --data ~/rpa-data    # 資料放在專案以外

啟動訊息會印出管理 Portal 的網址、資料夾，以及「對外埠：http://區網 IP:8081」。按 Ctrl+C 停止。

選項作用
--worker-port 8081開放對外埠給運行端與錄製端。不加就只有本機能用，裝置頁不能產生邀請。
--worker-host對外埠監聽的位址，預設 0.0.0.0（所有網路介面）。只想讓某張網卡收連線時指定它的 IP。
--no-local-worker這台不執行任務，全部交給遠端 worker。
--data 資料夾資料放哪裡，預設專案裡的 data（也可以用環境變數 RPA_DATA_DIR）。見管理 Portal › 資料夾。
--port、--host管理頁面的埠與位址，預設 127.0.0.1:8080。不要改成 0.0.0.0：管理頁面沒有登入保護。
--no-testsite不在 127.0.0.1:8765 啟動測試網站。
--testsite-host 0.0.0.0測試網站對其他電腦開放（預設只有本機 127.0.0.1）。見下方共用伺服器的測試網站。
RPA_LANG環境變數：伺服器建立的訊息用哪種語言（zh-Hant、zh-Hans、en）。

兩個埠

  • 8080，管理頁面。沒有登入保護，只聽 127.0.0.1，只有伺服器本機打得開。
  • 8081，對外埠。每個請求都要權杖或一次性的邀請：運行端用 Worker API，錄製端用 Client API，並用錄製端的權杖打開管理頁面。沒配對的電腦打開只會看到 401。防火牆只開這個埠，而且只開給區網（或 VPN），例如 Ubuntu：sudo ufw allow from 192.168.1.0/24 to any port 8081 proto tcp。
  • 是 HTTP，不加密。Secrets 與登入狀態會經過網路，只在信任的區網或 VPN 使用。伺服器在雲端或不同網段時，可以用 SSH 通道把對外埠帶到裝置那台：ssh -N -L 8081:127.0.0.1:8081 使用者@伺服器，裝置配對時伺服器填 http://127.0.0.1:8081。

共用伺服器的測試網站

預設每台電腦各自在 127.0.0.1:8765 跑一份測試網站，資料與登入不互通：在 Mac 建的紀錄，Windows 查不到。要讓錄製端與 Worker 都用伺服器上的同一份：

  1. 伺服器加 --testsite-host 0.0.0.0 啟動。用 Linux 安裝腳本時，在 .rpa-server.env 設 export RPA_TESTSITE_HOST=0.0.0.0 再重新啟動（較早建立的設定檔沒有這一行，自己加上）。啟動訊息會印出「測試網站：http://區網 IP:8765/」，位址是猜的。
  2. 防火牆開 8765，只開給錄製端與 Worker 那幾台：測試網站沒有任何保護，連得到的人都能建立紀錄、用示範帳號登入。例如 RHEL 系：sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=192.168.1.0/24 port port=8765 protocol=tcp accept'，再 sudo firewall-cmd --reload。
  3. 錄製的起始網址填 http://伺服器:8765/。範例場景要用它時，在 BA-001～BA-005 的場景頁把「預設網址」改成 http://伺服器:8765；「登入與憑證」把兩個測試網站角色的登入網址、檢查網址改成 http://伺服器:8765/login、http://伺服器:8765/account。

改好之後，BA-001 建的紀錄在任何一台用 BA-002 都查得到，角色的登入狀態也對每一台有效。

從別台電腦打開管理 Portal

  • 透過錄製端（建議）。在 Mac 配對錄製端後，App 的視窗就是管理 Portal；錄製、調試、人工登入的瀏覽器開在 Mac。
  • SSH 通道。ssh -N -L 8080:127.0.0.1:8080 使用者@伺服器，再打開 http://127.0.0.1:8080。能做所有管理工作，但瀏覽器開在伺服器上（見上方的部署方式）。

Linux：開機自動啟動（systemd）

用執行一鍵腳本的那個帳號（瀏覽器下載在它的家目錄）。建立 /etc/systemd/system/rpa-portal.service，把 rpa 換成實際的帳號：

[Unit]
Description=RPA management portal
After=network-online.target
Wants=network-online.target

[Service]
User=rpa
WorkingDirectory=/home/rpa/code/web_browser_robotic_process_automation
ExecStart=/home/rpa/.local/bin/uv run rpa serve --worker-port 8081 --data /home/rpa/rpa-data
Restart=on-failure

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now rpa-portal     # 現在啟動，之後開機自動啟動
sudo systemctl status rpa-portal
journalctl -u rpa-portal -f                # 看啟動訊息與日誌
sudo systemctl restart rpa-portal          # 更新後重新啟動

更新版本

  1. 到「運行報告」確認沒有執行中的任務，錄製端那邊也沒有進行中的錄製或調試。
  2. 停止伺服器（Ctrl+C 或 sudo systemctl stop rpa-portal），建議先備份。
  3. git pull，再執行 ./scripts/setup.sh（依賴與瀏覽器有變動才安裝；只想更新依賴用 uv sync）。
  4. 啟動伺服器。資料庫在啟動時自動升級，原有的場景與紀錄都保留。
  5. 把運行端與錄製端更新到同一個版本：App 下載同版本的安裝檔或 DMG，命令列的那台 git pull 後重新啟動。

伺服器重新啟動時，錄製端進行中的錄製、調試、人工登入會結束；運行端與錄製端會自己重新連上，不必重新配對。

備份與搬家

所有資料都在資料夾裡（裡面有什麼見管理 Portal › 資料夾）。停止伺服器後複製整個資料夾就是備份，例如 tar czf rpa-data-$(date +%Y%m%d).tgz -C ~ rpa-data。搬到新的伺服器：在新的那台安裝同一個版本，把資料夾放回去，用同樣的 --data 啟動。裝置的權杖也在資料夾裡，伺服器網址不變時不必重新配對；網址變了（換了 IP）時，在裝置頁按「重新邀請」，到那台用新的邀請重新配對。資料夾裡有 Secrets 的值與登入狀態，備份檔請一樣只有本人能讀。

管理裝置

管理 Portal › 場景生產 › 裝置
  • 新增。「新增裝置」選種類（RPA Worker 或 RPA 錄製端），產生一次性的邀請（24 小時內有效），貼到那台的 App 或命令列。步驟見遠端 worker › 新增裝置。
  • 狀態。線上、執行中、離線、已停用；另外顯示作業系統、App 版本與下載過的瀏覽器。和伺服器版本不同時會標出來。
  • 停用、啟用。停用後那台立刻連不上。命令列的 worker、錄製端會停下來，啟用後重新執行即可；兩個 App 被拒絕時會清掉配對，啟用後要用新的邀請再配對。
  • 重新邀請。舊的權杖立刻失效，要用新的邀請在那台重新配對。懷疑權杖外流、換電腦時用。
  • 刪除。那台不能再連線；指定給它、還在排隊的執行會標為失敗，執行紀錄保留。
  • 預設執行位置。本機、遠端 worker、任一。主要用 Windows 執行時改成「遠端 worker」，不必每次選。

錄製端：平常怎麼用

第一次安裝與配對見macOS：RPA 錄製端 App（命令列見錄製端）。

  1. 打開。雙擊「RPA 錄製端」；連上後視窗就是管理 Portal，頁首顯示「透過錄製端「名稱」」。命令列：專案資料夾執行 uv run rpa recorder，會在預設瀏覽器打開。
  2. 錄製。「場景生產 › 自主腳本錄製」選新場景或既有場景、起始網址、瀏覽器與角色，按「開始錄製」。瀏覽器與 Playwright Inspector 開在 Mac；操作完關掉瀏覽器視窗，草稿自動產生。起始網址填要自動化的網站（例如 Mac 自己的測試網站 http://127.0.0.1:8765/ 或業務系統），不是伺服器的 8080、8081：那是管理 Portal 自己，填了會被擋下。
  3. 逐步調試。場景頁按「逐步調試」，有頭模式的視窗開在 Mac，每一步的截圖也顯示在頁面上。
  4. 人工登入。「場景管理 › 登入與憑證」按角色的「登入」，在 Mac 開的視窗裡登入，按「完成登入」或關掉視窗；登入狀態存回伺服器。
  5. 執行。驗證與執行的「執行位置」裡，「伺服器」是伺服器自己，「遠端 worker」是運行端。錄製端不執行場景。
  6. 結束。關掉 App 視窗或 ⌘Q；有錄製、調試、人工登入在進行時會先確認。命令列按 Ctrl+C。
  • 選單「RPA 錄製端 › 狀態與設定」：連線狀態、版本、進行中的工作、Firefox、瀏覽器下載鏡像、語言、開啟日誌資料夾、重新配對。
  • 每台電腦同一時間各一段錄製；同一個場景的逐步調試只有一個，在另一台開始時，原本那台的會關掉。

運行端：平常怎麼用

第一次安裝與配對見Windows：RPA Worker App（命令列見worker 機器：啟動）。

  1. 開著就好。App 在登入 Windows 時自動啟動，縮在通知區接任務；關掉視窗不會停止。命令列：專案資料夾執行 uv run rpa worker，保持終端機開著。
  2. 交任務。在管理 Portal 驗證、執行或執行序列時，「執行位置」選「遠端 worker」或「任一」，或把裝置頁的預設執行位置改成遠端 worker。
  3. 看結果。執行報告在伺服器的「運行報告」，標出「在 win-01 執行」。
  4. 暫停。通知區選單「暫停接任務」：做完目前的任務後不再領取。要長時間不用，在裝置頁按「停用」。
  5. 結束。通知區選單「結束」；有任務在執行時先確認，被取消的任務會回報。命令列按 Ctrl+C。
  • 有頭模式的視窗開在登入中的 Windows 桌面上；App 在使用者登入後才啟動，登出或關機時執行中的任務會被取消並回報。
  • 執行時用到的登入狀態由伺服器送過去、用完就刪；人工登入不在運行端做。

日誌在哪裡

伺服器
啟動的終端機；systemd 用 journalctl -u rpa-portal。每次執行的日誌與報告在資料夾的 runs/<執行編號>/，也可以在「運行報告」打開。
RPA 錄製端 App
~/Library/Application Support/rpa/recorder/logs/recorder.log；「狀態與設定 › 開啟日誌資料夾」。
RPA Worker App
%LOCALAPPDATA%\rpa\worker\logs；視窗的「設定 › 開啟日誌資料夾」。
命令列的 worker、錄製端
執行它的終端機。

常見問題

狀況處理
裝置連不上伺服器伺服器有沒有加 --worker-port、IP 與埠號對不對、伺服器的防火牆有沒有開 8081。檢查方法見遠端 worker › 常見問題。邀請裡的位址是猜的，伺服器有多張網卡時常猜錯：伺服器網址和代碼分開填。
錄製、逐步調試、人工登入的按鈕是灰的，滑鼠移上去提示改用錄製端頁面是從伺服器的 8080（例如 SSH 通道）打開的，而伺服器沒有桌面：改從錄製端打開。透過錄製端也這樣時，是錄製端那台沒有桌面。
開始錄製時說起始網址是管理 Portal 自己的位址起始網址填成了伺服器的 8080 或 8081。錄製開的是全新的瀏覽器，沒有錄製端的權杖，打開這兩個埠只會得到 401（recorder_unauthorized）。改填要自動化的網站。
「開始錄製」是灰的，上方寫著錄製中這台已經有一段錄製在進行：先把那個瀏覽器視窗關掉，或按「取消錄製」。
錄製端說管理 Portal 不再接受這台的權杖裝置頁重新邀請過、停用或刪除了這台。在裝置頁產生新的錄製端邀請（被停用時先按「啟用」），到「狀態與設定」貼上重新配對。
版本不同的提醒只是程式版本不同時仍可使用，但建議更新到同一個版本；協定版本不同時連不上，一定要更新。見更新版本。
錄製、調試突然結束，原因是失聯錄製端停掉、睡眠或斷線超過 30 秒，或伺服器重新啟動。重新打開後再開始一次。
任務一直排隊見遠端 worker › 常見問題。
