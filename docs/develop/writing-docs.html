文檔與 ADR

怎麼新增一個文檔頁面、怎麼維持三種語言同步，以及怎麼記錄架構決策。背景見 ADR 0005 與 ADR 0007。

寫作原則

  • 先結論，後細節。頁面描述一句話講清楚這頁在說什麼。
  • 一個面板一個主題。面板標題就是讀者會掃的目錄。
  • 用對元件。比較用表格，定義用規格清單，要點用重點清單，提醒用提示框。
  • 狀態要有文字。不能只靠顏色表達狀態。
  • 不重複。同一件事只在一個地方詳細說明，其他地方連過去。

新增頁面

  1. 先寫繁中版：複製同一目錄下現有的頁面，保留 <head> 與 <body> 的屬性。
  2. 修改 data-page（頁面 id）與 data-root（回到該語言根目錄的相對路徑，例如 ../）。
  3. 在 docs/assets/nav.js 登記頁面，名稱同時寫 "zh-Hant" 與 "en"。
  4. 在 docs/en/ 相同路徑寫英文版，見下方三種語言。
  5. 執行 uv run python tools/i18n.py sync 產生簡中，再執行 uv run pytest tests/docs tests/i18n。

頁面範本

以 docs/design/ 下的頁面為例
<!doctype html>
<html lang="zh-Hant">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>頁面名稱 · 瀏覽器 RPA 工程文檔</title>
<link rel="stylesheet" href="../design-system/assets/portal.css">
<link rel="stylesheet" href="../assets/docs.css">
<script defer src="../assets/nav.js"></script>
<script defer src="../assets/docs-shell.js"></script>
</head>
<body data-page="頁面-id" data-root="../">
<main id="main">
  <div class="heading"><div><h1>頁面名稱</h1><p>一句話說明</p></div></div>
  <div class="stack">
    <section class="panel">
      <div class="panel-header"><h2>面板標題</h2></div>
      <div class="panel-body">內容</div>
    </section>
  </div>
</main>
</body>
</html>

可用元件

來自 portal.css 與 docs.css
元件class適合
面板panel、panel-header、panel-body每個主題一個
版面stack、two-col、four-col、grid面板的排列；窄螢幕自動變單欄
規格清單spec-list（dl）名詞與定義、設定值
重點清單points（ul）三到六個要點
表格table-scroll 包住 table.wrap多個項目的比較
提示框notice、notice warn、notice success需要特別注意的事
狀態標籤badge blue | green | amber | red狀態，必須含文字
程式碼區塊pre.source命令與範例；HTML 要跳脫 < 與 >

三種語言

繁中、英文由人維護，簡中自動產生

目錄與規則

  • 繁中在 docs/，英文在 docs/en/，簡中在 docs/zh-Hans/；三個目錄的檔名、結構與錨點（id）完全相同。
  • 英文頁的 lang="en"，共用資源多回一層，例如 ../../assets/docs.css；data-root 仍是回到 docs/en/ 的路徑。
  • 頁面之間的連結只連同語言的頁面；切換語言由頁首處理。
  • docs/zh-Hans/ 與 nav.js 的 "zh-Hans" 是產生的，不要手改；用詞不對就加到 tools/zh-Hans-overrides.json。
  • 程式實際印出的繁中訊息（例如一鍵安裝腳本的輸出），加上 translate="no"，產生簡中時保留原文。

修改繁中頁面之後

# 1. 依修改內容更新 docs/en/ 的同一頁
# 2. 記下英文版對照的是哪個繁中版本
uv run python tools/i18n.py stamp docs/en/develop/setup.html

# 3. 重新產生簡中（提交前檢查也會自動執行）
uv run python tools/i18n.py sync

# 只檢查不寫入
uv run python tools/i18n.py check

繁中改了而英文沒有重新 stamp，測試會失敗並指出是哪一頁。只改錯字、英文不受影響時，直接 stamp 即可。

新增 ADR

什麼時候寫

  • 選擇會影響多個套件或很難反悔。
  • 有兩個以上合理的方案，而且需要讓後來的人知道為什麼選這個。
  • 推翻或修改既有的 ADR。

怎麼寫

  • 複製最近一份 ADR，檔名 NNNN-英文短名.html，編號遞增。
  • 固定段落：日期、影響範圍、背景、決策、後果（好處與代價）、沒有選的方案。
  • 新 ADR 先標「提議中」，在 PR 中討論，合併時改為「已接受」。
  • 更新 adr/index.html 與 nav.js，並照三種語言的規則提供英文版。
  • 取代舊決策時，舊 ADR 改為「已取代」並連到新的 ADR，內容不刪。
