開發規範

分支、提交、PR、程式碼與測試的約定。工具能檢查的都交給工具，這裡只寫工具管不到的。

分支與 PR

  • main 受保護。只透過 PR 合併，CI 全綠且至少一人 review。
  • 分支命名。里程碑工作用 m1/dsl-models；其他用 fix/…、docs/…、chore/…。
  • PR 描述三段。做了什麼、怎麼驗證、還沒做的部分。
  • 合併方式。Squash merge，PR 標題即為最終提交訊息。
  • 依賴變更。新增依賴要在 PR 描述說明理由。

提交訊息

Conventional Commits
<類型>(<範圍>): <繁體中文摘要>

feat(core): 新增 goto 與 click 動作模型
fix(cli): validate 對空檔案回報錯誤行號
docs(adr): 新增 0008 Secrets 加密方式
類型
feat、fix、docs、refactor、test、ci、chore
範圍
套件或區域：core、cli、runner、docs、adr…

程式碼

  • 語言。識別字用英文；註解與文件字串用繁體中文。
  • 使用者看得到的文字。命令列輸出、錯誤與校驗訊息等一律放進套件的 locales/，程式碼只寫訊息鍵；同時寫繁中與英文，簡中自動產生。見 ADR 0007。
  • 型別。pyright strict；所有函式完整標註型別，避免 Any。
  • 格式。以 ruff 為準，不手動爭論格式。
  • 輸出。程式碼中不留 print；CLI 透過 click 輸出，函式庫用 logging。
  • 邊界。rpa-core 不依賴瀏覽器或資料庫；執行相關的程式碼放在 rpa-runner。

測試

  • 每個套件在自己的 tests/ 下測試；跨套件的測試放在根目錄 tests/。
  • 需要真實瀏覽器的測試加上 @pytest.mark.browser。
  • 測試不依賴外部網站；需要網頁時用測試網站（M2 起）。
  • 修 bug 先寫一個重現問題的測試。
  • 文檔頁面由 tests/docs 檢查結構與連結；三種語言是否同步由 tests/i18n 檢查。
不要提交真實帳號密碼、內部系統網址或包含業務資料的截圖。本機機密放在 .env（已被 Git 忽略），範例檔用 .env.example。
