遠端 worker

把執行交給另一台電腦：管理 Portal、資料庫與檔案留在你的電腦，瀏覽器視窗出現在 worker 機器上，你的電腦不再被有頭模式占住。以 Windows 當 worker 機器為例；macOS、Linux 的命令也列在旁邊。設計見 ADR 0012。

兩台電腦要在同一個區網（或 VPN），而且 worker 機器連得到你的電腦；你的電腦不需要連 worker。兩台都要能連到被測試的網站。Secrets 與角色的登入狀態會以 HTTP 經過區網，只在信任的網路使用。

1. 你的電腦：開放 Worker API

先用 Ctrl+C 停掉原本的 rpa serve，再加上 --worker-port 重新啟動：

uv run rpa serve --worker-port 8081

啟動訊息會多一行 Worker API：http://192.168.1.10:8081（位址是猜的區網 IP）。第一次啟動時，macOS 會詢問是否允許 Python 接受傳入連線，請按「允許」；Windows 的防火牆也會詢問。

管理頁面仍然只在 http://127.0.0.1:8080；8081 這個埠只有 Worker API，每個請求都要權杖。

2. 登記 worker、取得權杖

  1. 管理 Portal 的「場景生產 › 遠端 Worker」按「新增 worker」。
  2. 代號例如 win-01，名稱例如「測試用 Windows 電腦」，按「產生權杖」。
  3. 對話框顯示權杖與兩組啟動命令。權杖只顯示這一次，先複製下來；遺失時按「重新產生權杖」（舊的立刻失效）。

命令裡的網址是猜的；如果 worker 連不上，換成你的電腦在區網上的 IP（macOS：系統設定 › 網路；Windows：ipconfig）。

3. worker 機器：安裝

和平常的安裝一樣

用本機從零運行的一鍵腳本安裝（在 PowerShell 執行）：

irm https://raw.githubusercontent.com/DevopsLeaDevops/web_browser_robotic_process_automation/main/scripts/setup.ps1 -OutFile $env:TEMP\rpa-setup.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\rpa-setup.ps1

程式碼會下載到 %USERPROFILE%\code\web_browser_robotic_process_automation，也會下載 Chromium 與 Firefox。兩台電腦要是同一個版本：之後你的電腦 git pull，worker 機器也要 git pull 並重跑腳本。版本不同時 worker 頁會標出來。

4. worker 機器：啟動

在專案資料夾，貼上對話框裡的命令：

# Windows PowerShell
cd $env:USERPROFILE\code\web_browser_robotic_process_automation
$env:RPA_WORKER_TOKEN = "（權杖）"
uv run rpa worker --server http://192.168.1.10:8081 --name win-01

# macOS、Linux
export RPA_WORKER_TOKEN='（權杖）'
uv run rpa worker --server http://192.168.1.10:8081 --name win-01

看到「已連上管理 Portal」就好了；worker 頁的狀態變成「線上」。按 Ctrl+C 停止：執行中的任務會被取消並回報。

權杖也可以放在檔案裡：--token-file token.txt（不要提交到 git）。

5. 把執行交給 worker

  • 執行位置。登記了遠端 worker 之後，驗證、執行與「執行序列」的表單多一個「執行位置」：本機、遠端 worker、任一（誰有空誰執行）。有頭模式的瀏覽器視窗出現在執行的那台電腦。
  • 預設執行位置。在 worker 頁設定；預設是本機（和以前一樣）。主要用 worker 時改成「遠端 worker」，就不必每次選。
  • 報告。worker 執行完把整個執行目錄（報告、截圖、Trace、日誌）傳回來；執行報告標出「在 win-01 執行」，看起來和本機執行一樣。
  • 測試網站。rpa worker 也在 worker 機器啟動自己的測試網站（127.0.0.1:8765），所以「測試網站自動化」的範例照樣能跑；它的資料和你電腦上的測試網站是分開的。其他寫成 127.0.0.1 或 localhost 的網址，在 worker 上指的是 worker 自己。
  • 試驗場序列整個在同一台 worker：第一個節點由哪台領取，後面的節點就都給它。
  • 登入角色。人工登入仍在你的電腦（要人操作）；登入狀態在執行時送到 worker，用完就刪。worker 自動登入後的新狀態會傳回來。
  • 只讓 worker 執行。rpa serve --worker-port 8081 --no-local-worker：你的電腦完全不執行，全部交給 worker。

開機後自動啟動（Windows，選用）

有頭模式需要使用者已經登入桌面，所以用「登入時」啟動，不要做成系統服務。在專案資料夾建立 start-worker.cmd（不要提交到 git）：

@echo off
cd /d %USERPROFILE%\code\web_browser_robotic_process_automation
set RPA_WORKER_TOKEN=（權杖）
uv run rpa worker --server http://192.168.1.10:8081 --name win-01

然後按 Win+R 輸入 shell:startup，在開啟的資料夾放一個指向 start-worker.cmd 的捷徑。

常見問題

狀況處理
「連不上管理 Portal」一直重試確認 Portal 有加 --worker-port、網址的 IP 與埠號正確、你電腦的防火牆允許傳入連線。在 worker 機器用瀏覽器打開 http://IP:8081/worker-api/v1/hello：看到 405 或 Method Not Allowed 代表連得到。
「管理 Portal 拒絕這台 worker」權杖不對、已經重新產生，或 worker 被停用。到 worker 頁重新產生權杖或啟用。
執行一直是「排隊中」worker 頁看它是不是「線上」；有頭模式的任務只給能顯示視窗的 worker；場景要用的瀏覽器在 worker 機器要下載過（重跑安裝腳本）。
執行失敗「判定失聯」worker 超過一分鐘沒有回報（關機、斷網、程式被關掉）。那次執行不會自動重跑，因為可能已經在網站上做了部分操作；確認後再重新執行。
worker 頁標出「版本不同」兩台都 git pull 到同一個版本，worker 機器重跑安裝腳本後重新啟動 rpa worker。
只想暫時不用 workerworker 頁按「停用」，或在 worker 機器按 Ctrl+C；預設執行位置改回本機。
