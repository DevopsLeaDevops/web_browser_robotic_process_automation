遠端 worker

把執行交給另一台電腦：管理 Portal、資料庫與檔案留在你的電腦，瀏覽器視窗出現在 worker 機器上，你的電腦不再被有頭模式占住。以 Windows 當 worker 機器為例；macOS、Linux 的命令也列在旁邊。要在另一台電腦錄製、調試與人工登入，見錄製端；配好之後怎麼部署、平常怎麼用，見部署與操作。設計見 ADR 0012、ADR 0014。

兩台電腦要在同一個區網（或 VPN），而且 worker 機器連得到你的電腦；你的電腦不需要連 worker。兩台都要能連到被測試的網站。Secrets 與角色的登入狀態會以 HTTP 經過區網，只在信任的網路使用。

1. 你的電腦：開放對外埠

先用 Ctrl+C 停掉原本的 rpa serve，再加上 --worker-port 重新啟動：

uv run rpa serve --worker-port 8081

啟動訊息會多一行 對外埠：http://192.168.1.10:8081（位址是猜的區網 IP）。第一次啟動時，macOS 會詢問是否允許 Python 接受傳入連線，請按「允許」；Windows 的防火牆也會詢問。

管理頁面仍然在 http://127.0.0.1:8080；8081 這個對外埠上每個請求都要權杖或邀請：Worker API 要 worker 的權杖，管理頁面只給錄製端的權杖，沒配對的電腦打開只會看到 401。

2. 新增裝置、取得邀請

  1. 管理 Portal 的「叢集管理 › 裝置」按「新增裝置」。
  2. 代號例如 win-01，名稱例如「測試用 Windows 電腦」，按「產生邀請」。
  3. 對話框顯示一行邀請（rpa://pair?…，已複製到剪貼簿）、分開的伺服器與代碼，以及命令列的用法。邀請只顯示這一次、24 小時內有效、只能用一次；遺失或過期時按「重新邀請」（舊的配對立刻失效）。

邀請裡的伺服器位址是猜的；如果 worker 連不上，改用你的電腦在區網上的 IP（macOS：系統設定 › 網路；Windows：ipconfig），和代碼分開填。邀請可以換到權杖，不要分享給別人。

3. worker 機器：安裝

和平常的安裝一樣

用本機從零運行的一鍵腳本安裝（在 PowerShell 執行）：

irm https://raw.githubusercontent.com/DevopsLeaDevops/web_browser_robotic_process_automation/main/scripts/setup.ps1 -OutFile $env:TEMP\rpa-setup.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\rpa-setup.ps1

程式碼會下載到 %USERPROFILE%\code\web_browser_robotic_process_automation，也會下載 Chromium 與 Firefox。兩台電腦要是同一個版本：之後你的電腦 git pull，worker 機器也要 git pull 並重跑腳本。版本不同時裝置頁會標出來。

4. worker 機器：啟動

第一次在專案資料夾用邀請配對並啟動（整行邀請加上引號）：

# Windows PowerShell
cd $env:USERPROFILE\code\web_browser_robotic_process_automation
uv run rpa worker --invite "rpa://pair?server=…&app=worker&code=…"

# macOS、Linux（同樣在專案資料夾）
uv run rpa worker --invite 'rpa://pair?server=…&app=worker&code=…'

# 伺服器位址要改時：代碼分開給
uv run rpa worker --server http://192.168.1.10:8081 --invite （代碼）

看到「已配對」與「已連上管理 Portal」就好了；裝置頁的狀態變成「線上」。換到的權杖存在工作資料夾的 worker-data\pairing.json（只有你能讀寫，不要提交到 git），之後只要執行 uv run rpa worker。按 Ctrl+C 停止：執行中的任務會被取消並回報。

以前的方式照樣可用：用 API（POST /api/workers/{代號}/token）重新產生權杖後，放在環境變數 RPA_WORKER_TOKEN 或 --token-file token.txt，並加上 --server。Windows 與 macOS（Apple 晶片）上也可以改用 RPA Worker App（Windows、macOS）貼上邀請，不必安裝開發環境。

Windows：RPA Worker App

M10.1：不需要 uv、git、Python
  1. 從 GitHub 倉庫的 Releases 下載和管理 Portal 同一個版本的 RPA-Worker-Setup-版本-windows-x64.exe（安裝檔）。測試還沒發布的版本時，改從 PR 或 main 的「桌面端建置」執行紀錄的 Artifacts 下載 worker-windows-latest（裡面有安裝檔與免安裝的 zip）。
  2. 執行安裝檔。沒有程式碼簽章：SmartScreen 出現「Windows 已保護您的電腦」時按「其他資訊 › 仍要執行」。選語言（預設繁體中文）後一路「下一步」：只裝給目前的使用者，不需要管理員，裝在 %LOCALAPPDATA%\Programs\RPA Worker，開始功能表有捷徑（桌面捷徑可以勾選）；裝完直接開啟 RPA Worker。沒有 WebView2 Runtime 時安裝檔會順便安裝（需要連上網路）。
  3. 視窗打開後，把第 2 步產生的邀請貼在「邀請」欄（只貼代碼時另外填管理 Portal 的網址）；需要 Firefox 就勾選，按「配對」。
  4. 第一次會下載 Chromium（解壓後約 600 MB），視窗顯示進度。狀態變成「線上」就好了；裝置頁顯示「線上」與 App 版本。
  • 升級：執行新版的安裝檔即可。RPA Worker 正在執行時，安裝檔會先請它結束（執行中的任務被取消並回報給管理 Portal）再換檔案；配對、設定與自動啟動都保留。視窗提醒「程式版本和管理 Portal 不同」時，旁邊的「下載新版」會打開最新的 Release。
  • 解除安裝：Windows 的「設定 › 應用程式」找到 RPA Worker。確認要解除安裝後，先問要不要也刪除配對、設定與日誌：預設「否」（保留），之後重新安裝不必再配對；選「是」會一併刪除認證管理員裡的權杖。接著結束 RPA Worker（執行中的任務被取消並回報）、刪除程式、捷徑與自動啟動。瀏覽器（%LOCALAPPDATA%\ms-playwright）與 Firefox 範本的快取（%LOCALAPPDATA%\rpa\cache）別的程式也可能在用，不會刪除。用命令列靜默解除安裝（unins000.exe /VERYSILENT）時不問、保留資料，加上 /REMOVEDATA=yes 才刪除。
  • 免安裝版：Release 也附 RPA-Worker-版本-windows-x64.zip，解壓縮到任何資料夾（例如 %USERPROFILE%\RPA Worker）後雙擊 rpa-worker.exe，用法和安裝版相同；升級時先從通知區結束，再解壓縮新版覆蓋。免安裝版和安裝版用同一個資料夾的配對，不要同時使用。
  • 關閉視窗不會停止。RPA Worker 縮到通知區繼續接任務（第一次會提示）。通知區圖示的選單：開啟視窗、暫停接任務、結束；圖示右下角的圓點是綠色（線上）、黃色（暫停）或紅色（離線、需要處理）。有任務在執行時按「結束」會先確認，取消後回報給管理 Portal。
  • 登入 Windows 時自動啟動：第一次配對成功後預設開啟，只出現在通知區；在視窗的「設定」可以關閉。資料夾搬走後開一次 RPA Worker，自動啟動就會改成新的位置。
  • 暫停接任務：做完目前的任務後不再領取新的，管理 Portal 約一分鐘後顯示這台離線；按「繼續接任務」立刻重新上線。
  • 只執行一份：再雙擊一次會叫出已經在執行的那份視窗。
  • 設定：語言（預設繁體中文）、也下載 Firefox（執行中才勾選的話，下次開啟時下載）、下載瀏覽器的內部鏡像（PLAYWRIGHT_DOWNLOAD_HOST）、開啟日誌資料夾、重新配對。
  • 資料位置：%LOCALAPPDATA%\rpa\worker（配對的伺服器與裝置 pairing.json、設定 settings.json、日誌 logs\、任務的暫存）。權杖存在 Windows 認證管理員（「一般認證」裡的 RPA Worker）；認證管理員不能用時退回存在 pairing.json（只有你能讀寫），視窗的「權杖存放」會標出來。第一步預覽版存在檔案裡的權杖，第一次開啟時自動搬進認證管理員。瀏覽器在 %LOCALAPPDATA%\ms-playwright。日誌不記權杖與邀請代碼。
  • 需要 Microsoft Edge WebView2：Windows 11 內建，Windows 10 大多已隨 Edge 更新裝好；安裝檔在沒有時會安裝。還是沒有時（例如免安裝版、安裝時沒有網路），RPA Worker 會說明怎麼安裝，在那之前只靠通知區接任務。
  • Windows 登出或關機：執行中的任務立刻被取消並回報；來不及回報時，管理 Portal 約一分鐘後判定失聯。
  • 排查問題：同資料夾的 rpa-child.exe --worker 是主控台版（和第一步的預覽版相同，每一行訊息都看得到）；rpa-worker.exe --no-window --invite … --log 檔案 不開視窗（自動化用；要它結束時在資料夾放一個 stop.request 檔案，執行中的任務會被取消並回報）。兩者和視窗版用同一份配對，同一時間只能開一份。

macOS：RPA Worker App

Apple 晶片；功能和 Windows 版相同
  1. 從 Releases 下載和管理 Portal 同一個版本的 RPA-Worker-版本-macos-arm64.dmg（加入 macOS 版之後的第一個發布才有）。測試還沒發布的版本時，改從「桌面端建置」執行紀錄的 Artifacts 下載 worker-macos-15。
  2. 打開 DMG，把「RPA Worker」拖進「應用程式」。沒有簽章與公證，第一次打開會被擋下：到「系統設定 › 隱私權與安全性」，在下方找到 RPA Worker，選擇允許打開並輸入密碼（和錄製端相同）。熟悉終端機的人也可以執行 xattr -dr com.apple.quarantine "/Applications/RPA Worker.app"。
  3. 和 Windows 相同：貼上 Worker 邀請、按「配對」，第一次下載 Chromium，狀態變成「線上」就好了。macOS 15 起第一次連到區網時會問是否允許 RPA Worker 連到區網上的裝置，請選「允許」。
  • 關閉視窗不會停止。RPA Worker 縮到選單列（螢幕右上角的圖示）繼續接任務，Dock 上的圖示也收起來；第一次會用通知提示。選單列圖示的選單與圓點的顏色和 Windows 的通知區相同。要結束：選單列圖示 › 結束，或在視窗按 ⌘Q；有任務在執行時先確認，取消後回報給管理 Portal。
  • 叫出視窗：選單列圖示 › 開啟視窗，或在 Finder、Launchpad 再打開一次 RPA Worker。
  • 登入 macOS 時自動啟動：第一次配對成功後預設開啟，只出現在選單列；在視窗的「設定」可以關閉。做法是放一個 LaunchAgent（~/Library/LaunchAgents/io.github.devopsleadevops.rpa.worker.plist）：macOS 13 起會通知「已加入背景項目」，也列在「系統設定 › 一般 › 登入項目」；在那裡關掉時，系統另外記錄停用，App 的設定不會把它改回來。App 搬到別的位置後開一次，自動啟動就會改成新的位置。
  • 升級：先從選單列結束 RPA Worker（執行中的任務被取消並回報），再把新版的 App 拖進「應用程式」取代。配對、設定與自動啟動都保留。視窗的「下載新版」打開最新的 Release。
  • 解除安裝：先在「設定」關掉自動啟動並結束 RPA Worker，再把 App 拖到垃圾桶。要一併刪除配對：先執行 "/Applications/RPA Worker.app/Contents/MacOS/rpa-child" --forget-pairing（刪除鑰匙圈裡的權杖），再刪除資料夾 ~/Library/Application Support/rpa/worker。瀏覽器（~/Library/Caches/ms-playwright）錄製端也可能在用，不要刪。
  • 資料位置：~/Library/Application Support/rpa/worker（pairing.json、settings.json、日誌 logs/、任務的暫存）。權杖存在鑰匙圈（登入鑰匙圈裡的 RPA Worker）；鑰匙圈不能用時退回存在 pairing.json（只有你能讀寫），視窗的「權杖存放」會標出來。日誌不記權杖與邀請代碼。
  • 登出、重新開機或關機：執行中的任務立刻被取消並回報（只等幾秒，不擋住登出）；來不及回報時，管理 Portal 約一分鐘後判定失聯。
  • 同一台 Mac 也裝了錄製端：兩個 App 各自配對（Worker 邀請、錄製端邀請），資料夾與鑰匙圈項目分開，可以同時執行；下載的瀏覽器共用。
  • 排查問題："/Applications/RPA Worker.app/Contents/MacOS/rpa-child" --worker 是主控台版；同資料夾的 rpa-worker --no-window --invite … --log 檔案 不開視窗。兩者都要在登入中的桌面（例如「終端機」）執行，有頭模式才開得了瀏覽器；和 App 用同一份配對，同一時間只能開一份。
  • 只支援 Apple 晶片（和錄製端相同）。Intel Mac 用開發環境的 rpa worker（啟動 worker）。

錄製端：瀏覽器開在另一台電腦

M10.2：錄製、逐步調試、人工登入

worker 負責執行場景；錄製端讓你在另一台電腦（例如 Mac）操作管理 Portal：透過錄製端打開的頁面，錄製、逐步調試、人工登入的瀏覽器開在那台，錄製稿、截圖與登入狀態傳回管理 Portal。場景、資料與執行報告都還在你的電腦，執行場景照舊交給本機或 worker。

  1. 你的電腦照第 1 步開放對外埠。伺服器和錄製端是同一台時也一樣，配對 http://127.0.0.1:8081。
  2. 裝置頁按「新增裝置」，種類選「RPA 錄製端」，代號例如 mac-01，按「產生邀請」。
  3. 錄製端那台照第 3 步安裝（macOS 用一鍵腳本），在專案資料夾配對並啟動：
uv run rpa recorder --invite 'rpa://pair?server=…&app=recorder&code=…'

預設瀏覽器會打開管理 Portal，頁首多一個「透過錄製端「名稱」」。權杖存在 recorder-data/pairing.json（只有你能讀寫，不要提交到 git），之後只要執行 uv run rpa recorder；按 Ctrl+C 停止，進行中的錄製、調試、人工登入會結束。

  • 本機閘道。rpa recorder 在 127.0.0.1 的隨機埠開一個閘道，加上權杖後轉給對外埠。啟動訊息印出的網址只在這台、這次啟動有效（關掉分頁後用同一個網址再打開）；權杖不進網頁，同一台電腦上的其他程式也用不了閘道。固定埠號用 --port，不自動打開瀏覽器用 --no-open。
  • 「本機」顯示成「伺服器」。透過錄製端看頁面時，執行位置的「本機」指的是伺服器那台，所以改稱「伺服器」，避免誤會成錄製端這台。
  • 瀏覽器。錄製端上線時回報下載過的瀏覽器；選了這台沒有的瀏覽器，頁面直接說明。沒有圖形介面的電腦不能錄製、逐步調試、人工登入（按鈕是灰的）。
  • 失聯。錄製端停掉或斷線超過 30 秒，它進行中的錄製、調試、人工登入會結束並記下原因；錄製端重新啟動、在裝置頁被停用、刪除或重新邀請時也一樣。
  • 測試網站。和 rpa worker 一樣，預設在錄製端那台啟動測試網站（127.0.0.1:8765），錄製範例場景時連得到。
  • 同時使用。你的電腦 8080 的頁面照舊在你的電腦開瀏覽器。每台電腦同一時間可以各有一段錄製；同一個場景的逐步調試只有一個，在另一台開始時，原本那台的會關掉。

macOS：RPA 錄製端 App

M10.2：不需要 uv、git、Python；Apple 晶片
  1. 從 GitHub 倉庫的 Releases 下載和管理 Portal 同一個版本的 RPA-Recorder-版本-macos-arm64.dmg（v0.3.0 起）。測試還沒發布的版本時，改從 PR 或 main 的「桌面端建置」執行紀錄的 Artifacts 下載 recorder-macos-15（裡面是 DMG）。打開 DMG，把「RPA 錄製端」拖進「應用程式」。
  2. 沒有簽章：第一次打開會被擋下。到「系統設定 › 隱私權與安全性」，在下方找到 RPA 錄製端，選擇允許打開並輸入密碼（熟悉終端機的人也可以執行 xattr -dr com.apple.quarantine "/Applications/RPA Recorder.app"）。macOS 15 起會詢問是否允許連到區網上的裝置，請按「允許」。
  3. 視窗打開後，把裝置頁產生的錄製端邀請貼在「邀請」欄（只貼代碼時另外填管理 Portal 的網址），需要 Firefox 就勾選，按「配對」。第一次會下載 Chromium，視窗顯示進度；連上後自動打開管理 Portal，頁首顯示「透過錄製端「名稱」」。
  • 選單「RPA 錄製端」：「狀態與設定」回到 App 自己的頁面（伺服器、版本、進行中的工作、設定、重新配對、結束），「管理 Portal」回到 Portal，「重新整理」。⌘V 可以貼上邀請。
  • 新視窗與下載。報告、截圖、執行檔案的連結在 App 內開新視窗；連到別的網站（例如角色的登入網址）時用預設瀏覽器。匯出、下載的檔案會詢問存放位置（預設「下載項目」）。
  • 關掉視窗就結束。有錄製、調試或人工登入在進行時先確認（⌘Q 也一樣），結束會中斷它們，管理 Portal 那邊標成結束。再打開一次會叫出已經在執行的那份。
  • 資料位置：~/Library/Application Support/rpa/recorder（配對的伺服器與裝置 pairing.json、設定、日誌 logs/recorder.log、錄製與調試的暫存，用完刪除）。權杖存在鑰匙圈（「RPA Recorder」項目）；鑰匙圈不能用時退回存在 pairing.json（只有你能讀寫），狀態頁的「權杖存放」會標出來。瀏覽器在 ~/Library/Caches/ms-playwright，和開發環境共用。
  • 伺服器在同一台 Mac：一樣用 rpa serve --worker-port 8081 開對外埠，配對 http://127.0.0.1:8081。
  • 升級：先結束 App，打開新版的 DMG，把「RPA 錄製端」拖進「應用程式」取代舊的；配對、設定與日誌都保留。新版第一次打開可能又要到「隱私權與安全性」允許。狀態頁提醒「程式版本和管理 Portal 不同」時，旁邊的「下載新版」會打開最新的 Release。
  • 解除安裝：結束 App 後把「RPA 錄製端」丟到垃圾桶。配對、設定與日誌在上面的資料夾，權杖在鑰匙圈的「RPA Recorder」，不要了再刪；瀏覽器的快取和開發環境共用，不一定要刪。
  • 不開 App 的視窗（排查問題、自動化）：在終端機執行 "/Applications/RPA Recorder.app/Contents/MacOS/rpa-recorder" --no-window --open，連上後用預設瀏覽器打開管理 Portal。有頭模式照樣可以用：錄製、逐步調試、人工登入的瀏覽器視窗照樣開在這台，少的只是 App 的視窗，所以要在登入中的桌面執行（不要從 SSH）。訊息印在終端機，也寫進日誌。和 App 用同一份配對，同一時間只能開一份（這時雙擊 App 會用預設瀏覽器打開管理 Portal）；按 Ctrl+C 結束（或在資料夾放一個 stop.request 檔案）。其他選項：--invite、--server、--firefox、--log 檔案、--url-file 檔案（把經由閘道打開 Portal 的網址寫到檔案，自動化用）。

5. 把執行交給 worker

  • 執行位置。登記了遠端 worker 之後，驗證、執行與「執行序列」的表單多一個「執行位置」：本機、遠端 worker、任一（誰有空誰執行）。有頭模式的瀏覽器視窗出現在執行的那台電腦。
  • 預設執行位置。在裝置頁設定；預設是本機（和以前一樣）。主要用 worker 時改成「遠端 worker」，就不必每次選。
  • 報告。worker 執行完把整個執行目錄（報告、截圖、Trace、日誌）傳回來；執行報告標出「在 win-01 執行」，看起來和本機執行一樣。
  • 測試網站。rpa worker 也在 worker 機器啟動自己的測試網站（127.0.0.1:8765），所以「測試網站自動化」的範例照樣能跑；它的資料和你電腦上的測試網站是分開的。其他寫成 127.0.0.1 或 localhost 的網址，在 worker 上指的是 worker 自己。
  • 試驗場序列整個在同一台 worker：第一個節點由哪台領取，後面的節點就都給它。
  • 登入角色。人工登入在你操作的那台（你的電腦，或透過錄製端時在錄製端），不在 worker；登入狀態在執行時送到 worker，用完就刪。worker 自動登入後的新狀態會傳回來。
  • 只讓 worker 執行。rpa serve --worker-port 8081 --no-local-worker：你的電腦完全不執行，全部交給 worker。

開機後自動啟動（Windows，選用）

用 RPA Worker App 時不需要這一步：在 App 的「設定」勾選即可（配對後預設開啟）。以下是命令列 worker 的做法。

有頭模式需要使用者已經登入桌面，所以用「登入時」啟動，不要做成系統服務。先照第 4 步配對一次，再在專案資料夾建立 start-worker.cmd（不要提交到 git）：

@echo off
cd /d %USERPROFILE%\code\web_browser_robotic_process_automation
uv run rpa worker

然後按 Win+R 輸入 shell:startup，在開啟的資料夾放一個指向 start-worker.cmd 的捷徑。

常見問題

狀況處理
「連不上管理 Portal」一直重試確認 Portal 有加 --worker-port、網址的 IP 與埠號正確、你電腦的防火牆允許傳入連線。在 worker 機器用瀏覽器打開 http://IP:8081/worker-api/v1/hello：看到 405 或 Method Not Allowed 代表連得到。
「管理 Portal 拒絕這台 worker」權杖不對、已經重新邀請，或裝置被停用。到裝置頁按「重新邀請」，用新的邀請重新執行 rpa worker --invite；或按「啟用」。
「配對失敗」邀請已經用過、過期（24 小時）、貼錯 App，或裝置被停用：看訊息的說明，在裝置頁重新邀請。
執行一直是「排隊中」執行頁會說明在等哪台 worker。裝置頁看它是不是「線上」；有頭模式的任務只給能顯示視窗的 worker；場景要用的瀏覽器在 worker 機器要下載過（重跑安裝腳本）。
執行失敗「判定失聯」worker 超過一分鐘沒有回報（關機、斷網、程式被關掉）。那次執行不會自動重跑，因為可能已經在網站上做了部分操作；確認後再重新執行。
裝置頁標出「版本不同」兩台都 git pull 到同一個版本，worker 機器重跑安裝腳本後重新啟動 rpa worker。
只想暫時不用 worker裝置頁按「停用」，或在 worker 機器按 Ctrl+C；預設執行位置改回本機。
