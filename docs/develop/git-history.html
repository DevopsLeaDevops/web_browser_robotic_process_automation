Git 歷史圖

把提交、分支、標籤與 PR 的關係保存成可離線開啟的互動 HTML；後續重新執行同一命令即可更新。

產生與更新

在倉庫根目錄執行。工具只需要 Python 3.12 以上與 Git，不需要另外安裝 Python 套件。已有開發環境可用 uv run python；Linux 伺服器可用 .venv-server/bin/python；Windows 可用 .venv\Scripts\python.exe 代替下面的 python。

python tools/git_history.py --open
python tools/git_history.py --fetch --github --lang zh-Hans --timezone Asia/Shanghai --open

第一條只讀本機已有的全部歷史。第二條先擷取遠端分支、標籤與 GitHub 保留的 PR head，並讀取所有狀態的 PR；需要已安裝且登入的 gh（先執行 gh auth login）。移除 --github 仍可用於其他 Git 服務。離線時移除 --fetch --github。

預設輸出到 artifacts/git-history.html（已被 Git 忽略）。無桌面的伺服器不要加 --open；把產出的 HTML 複製到自己的電腦後用瀏覽器開啟。所有資料、樣式與程式都在這個檔案中，無需 CDN 或網站服務。

python tools/git_history.py --repo /path/to/repository --output /path/to/history.html --fetch
python tools/git_history.py --help

--lang 支援 zh-Hant（預設）、zh-Hans 與 en，頁面上也能切換。--timezone 預設 America/Los_Angeles，畫面會標出實際採用的時區。重新產生會取代同一輸出檔，不會持續在背景監控。

怎麼讀圖

  • 預設顯示全部歷史，包含 CI 指標等獨立分支；選擇 origin/main 可只看目前遠端主線及其祖先。main 是本機分支，兩者可能不同。
  • 圓點代表提交，線沿實際父提交相連，空心圓有多個父提交。順序由新到舊且遵守父子拓撲，不保證跨分支的日期嚴格遞減。
  • 搜尋訊息、作者、SHA、分支或 #57，以「上一筆／下一筆」跳轉；不隱藏中間節點，因此連線仍然完整。點選提交可看完整訊息、引用、PR 與可跳轉的父提交。
  • Squash 合併會產生不同 SHA；圖中分開保存原 PR head 與 GitHub 記錄的合入提交，不能把「PR 已合併」當作兩點間的真實 Git 父子連線。PR 若合入功能分支，也不等於已進入 main。
  • 捲動會逐段繪製，沒有固定提交數上限；圖形仍需把完整 JSON 載入記憶體，極大型倉庫的檔案與記憶體用量會隨歷史增加。

「全部」的範圍與副作用

收集所有本機引用與 HEAD 可達的提交，包含已擷取的遠端分支、標籤與 PR。預設不讀 reflog，也不掃描 dangling objects；已刪除且沒有引用保留的提交無法保證找回。淺層複製會顯示警告；遠端有完整歷史時，可先執行 git fetch --unshallow 再產生。

工具不 checkout、merge、rebase 或 push，不改動工作檔案與分支。--fetch 會更新遠端追蹤引用、下載物件與標籤；GitHub PR head 存在專用的 refs/git-history/origin/pr/*（使用 --remote 指定其他遠端時名稱隨之改變）。不刪除舊引用；因此已刪除遠端分支的本機快取也可能出現在圖中，不能把所有引用都當作遠端仍存在的分支。

輸出包含提交訊息、作者、分支名稱與 PR 標題；分享 HTML 即分享這些倉庫歷史。工具不輸出 Git 認證資料，也不讀取 Portal 資料目錄。頁面是明確標示產生時間的快照，最新狀態需重新擷取。
