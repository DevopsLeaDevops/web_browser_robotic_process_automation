In one sentence

The core asset is the scenario: a repeatable sequence of browser actions described in a declarative DSL. The platform generates scenarios (recording, natural language, templates), manages them (versions, parameters, permissions), runs them (Playwright), and reports results back to users (reports, screenshots, video replay, failure location).

Repository status

main a26b929 (2026-10-28)
rpa-core
Models of the scenario DSL and the scenario contract, YAML loading and validation, converting recordings into DSL drafts; iframes, new tabs and file uploads (M7a to M7c); the format of domain folders and composite scenarios; examples in scenarios/
rpa-runner
Execution engine: input validation (including file inputs), login checks, running the steps in Chromium or Firefox, independent assertions, output publishing, run reports and video; subprocesses for recording, manual login and step debugging
rpa-worker
Background worker: claims jobs, runs them in a subprocess, cancels them; no database dependency. It can also run on another computer as a remote worker, claiming jobs through the portal's Worker API (M9a); pairing, and the recorder's local gateway and interactive subprocesses (M10)
rpa-server
Management portal: FastAPI API and Jinja pages, SQLite, revisions and the publishing gate, the run queue, login roles and secrets, recording, step debugging, composite scenarios and the project workspace, devices and invitations, domain folders and git sync, run replay, the uploaded-file area, the Agent API (/agent-api/v1), and distributing updates to devices
rpa-update
Hot updates: the update manifest, Ed25519 signature checks, runtime IDs, installing and choosing code layers, and the desktop apps' launcher; standard library only (ADR 0018)
rpa-desktop
The two desktop apps, RPA Recorder (macOS) and RPA Worker (Windows, macOS): pywebview window, pairing, browser download, tray or menu bar, the packaged entry point (Desktop distribution)
rpa-cli
rpa serve starts the management portal (--worker-port opens it to devices); rpa worker and rpa recorder make this computer a remote worker or a recorder; rpa run runs a scenario; rpa record records actions and turns them into a scenario draft; rpa validate checks scenarios and points to the line, step and field, rpa pack check checks domain folders, rpa schema prints the JSON Schema of the DSL or of one scenario's inputs and outputs; rpa update upgrades a server package with an update file; --lang switches between Traditional Chinese, Simplified Chinese and English
Toolchain
uv (dependencies locked in uv.lock), ruff, pyright (strict), pytest, pre-commit
CI
PRs and merges test each system in its production role: the website on Linux, the worker on Windows, the recorder app on macOS; builds are layered, so the same inputs are verified once and apps are not repackaged when their shell has not changed; early every morning all tests run on the three systems, with the browser tests repeated three times. Triggers, durations, manual runs and duration records are in CI & pipelines
