Data flow of a run

  1. A user triggers a run in the web UI or the CLI, or the scheduler creates a task when it is due.
  2. The API checks permissions, fetches the requested version of the scenario, and writes a run record and a queue task.
  3. A worker picks up the task and gets the parameters and secrets from the API (kept in memory only).
  4. The runner opens an isolated browser context and executes step by step, reporting the status of each step.
  5. Screenshots, traces and downloads are uploaded to MinIO; extracted data is written back to the run record.
  6. When the run ends, the person who triggered it is notified; on failure, the failing step and its screenshot are highlighted.
