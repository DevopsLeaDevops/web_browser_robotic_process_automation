Multi-user and internal systems

What the two premises, shared team use and internal target systems, concretely require from the design.

Multi-user

Mostly implemented in M8; the MVP has a single user
Authentication
Local accounts first, with hooks for OIDC and LDAP so the company's AD or SSO can be connected.
Permissions
Scenarios, secrets and runs are isolated per project.
Secrets
Stored encrypted. Users can reference them in scenarios but cannot read the plain value. Until M8 they are a plain-text, owner-only file on the server, sent only to the worker or Recorder that needs them.
Auditing
Who changed or ran which scenario and when is all recorded and cannot be altered or deleted.
Versions
Every save of a scenario creates a new immutable version; each run points to its exact version. Revisions and validation and publishing records live in the domain folders and can be reviewed through git (M11).
Database
Production uses PostgreSQL, which supports several workers and concurrent writes; SQLite is only for development and prototypes (single machine, single process). See ADR 0008.
Stateless runner
From M2 on it only takes scenarios, inputs and secrets and outputs results and artifacts, so it moves into the M3 background worker, the M9a remote workers and the M10 Worker app unchanged.
