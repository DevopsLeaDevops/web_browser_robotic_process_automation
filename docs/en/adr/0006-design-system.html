ADR 0006: Interface design system v1.0 as the visual contract

The design package delivered by a colleague is included as is and shared by the docs site and the future web UI.

Accepted
Date
2026-10-09
Affects
docs/, M6 page prototypes, M8 web UI
Related
Style overview, ADR 0004

Context

M6 on the roadmap is the site design. A colleague has already delivered interface design system v1.0: design tokens, shared styles, a two-level menu shell and a starter layout, verified at three screen sizes.

Decision

  • The design package is included as is in docs/design-system/ and never edited directly; tests check the sha256 values in MANIFEST.json.
  • The docs site uses its portal.css from M0.
  • M6 builds this project's page prototypes from starter.html.
  • From M3 the management interface's Jinja pages use portal.css and tokens.json directly (the original plan to port them to React in M8 was changed by ADR 0011).
  • When the design package is updated, it is replaced as a whole and the version is recorded on this page.

Consequences

Benefits

  • Docs and product share one style; M6 shrinks from "design a style" to "design pages".
  • The design package already includes styles for flow editing (flow canvas, nodes, component library) that the step editor can use directly.

Costs

  • Whatever this project needs but the package does not yet cover must be confirmed with the designer in M6; see the Style overview.
  • The design package cannot be edited directly; this project's additional styles live in its own files.

Options not chosen

OptionWhy not
Redesign from scratchDuplicated work, when verified results already exist.
Adopt an off-the-shelf component libraryWould need extra work to match the team's style and overlaps with the design package.
