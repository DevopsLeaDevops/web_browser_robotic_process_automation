ADR 0005: Docs are written in HTML with the portal style

No Markdown unless necessary; the docs themselves are a static site that can be deployed as is.

Accepted
Date
2026-10-09
Affects
All docs under docs/
Related
How to write docs and ADRs

Context

The project lead wants docs that are easy to read and understand, with the key points standing out, and that can later become a docs website directly. Markdown can only express linear text and makes layouts such as side-by-side comparisons, status badges and spec lists hard to build.

Decision

  • Docs are hand-written HTML in docs/, styled with the design system's portal.css.
  • Navigation is defined once in docs/assets/nav.js and rendered by docs-shell.js; pages contain only their content.
  • No static site generator and no build step: open the files directly or use any static server.
  • Only README.md at the repository root stays in Markdown, because the GitHub front page needs it.
  • CI checks every page's structure, navigation registration and links.

Consequences

Benefits

  • Readable offline, and the style matches the product.
  • docs/ can be deployed as a docs website as is (GitHub Pages or an internal static server).

Costs

  • Hand-written HTML is more verbose than Markdown; page templates and automatic checks reduce mistakes.
  • GitHub shows the source, so the docs must be deployed or downloaded to read.

Options not chosen

OptionWhy not
MarkdownHard to build layouts where the key points stand out, which does not meet the requirement.
Markdown + a generator such as MkDocsEasy to write, but needs a build process and is hard to match to the product's style.
