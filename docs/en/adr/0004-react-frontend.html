ADR 0004: React + TypeScript for the frontend

In a mostly Python project, the web UI is the only TypeScript part.

Superseded
This decision is superseded by ADR 0011: the MVP management interface is rendered on the server with FastAPI + Jinja. The content below is kept for the record.
Date
2026-10-09
Affects
apps/web (M8)
Related
ADR 0002, ADR 0006

Context

The most important page of the management UI is the step editor: drag-and-drop reordering, live validation, switching between locator candidates, and replaying screenshots step by step during a run. This kind of interaction is hard to do well in pure-Python UI frameworks.

Decision

  • The frontend uses React + TypeScript + Vite and lives in apps/web.
  • Styling reuses portal.css and the design tokens of interface design system v1.0; no separate component library.
  • API types are generated from FastAPI's OpenAPI and DSL types from the JSON Schema, not written by hand.

Consequences

Benefits

  • A mature ecosystem with ready-made solutions for complex interaction.
  • Types are generated from the backend, so frontend and backend never disagree.

Costs

  • The team maintains a TypeScript codebase; its scope is strictly the UI, and business logic stays in the backend.
  • CI needs a separate Node.js workflow (added in M8).

Options not chosen

OptionWhy not
NiceGUI, StreamlitPure Python, but limited for complex interaction and performance with many users.
Jinja2 + HTMXGood for form-style pages, not for the step editor.
VueEqually workable; React has more drag-and-drop and editor packages.
