ADR 0002: Python for the backend, execution and tooling

Every component except the web frontend is written in Python and lives in one uv workspace.

Accepted
Date
2026-10-09
Affects
All Python packages, CI, the development environment
Related
Tech stack, ADR 0004

Context

The team's main language is Python. The platform needs browser automation, data model validation, a web API and AI integration, all of which have mature solutions in Python.

Decision

  • Browser: Playwright for Python; the execution engine uses the async API.
  • Models: Pydantic v2, shared by the DSL and the API.
  • API: FastAPI; database: SQLAlchemy 2.0 + Alembic.
  • Project: one repository with multiple packages in a uv workspace; ruff, pyright strict, pytest.
  • Minimum version Python 3.12.

Consequences

Benefits

  • Familiar to the team, so review and maintenance are cheap.
  • The DSL models are shared all the way from validation and the API to AI generation.
  • A complete ecosystem for AI and data processing.

Costs

  • The frontend cannot share Python types directly; TypeScript types are generated from OpenAPI and JSON Schema instead.
  • Playwright's native language is TypeScript, so some new features may reach the Python version a little later.

Full-stack TypeScriptTypes could be shared between frontend and backend, but TypeScript is not the team's main language.
