ADR 0007: The product and docs support English, Traditional Chinese and Simplified Chinese

Build the multilingual mechanism from M0, instead of hunting down hard-coded text after many features exist.

Accepted
Date
2026-10-10
Affects
All user-facing text in every package, the rpa command, the M8 web UI, docs/
Related
Conventions, Docs & ADRs, ADR 0005

Context

The platform's users and the readers of its docs include colleagues who use English, Traditional Chinese and Simplified Chinese.

If Traditional Chinese is hard-coded first, rewriting later means finding text one piece at a time across the command line, validation messages, run reports and the UI, and that cost grows with the code. M0 has very little text, so this is when adoption is cheapest.

Decision

  • Three languages. Traditional Chinese zh-Hant (default), Simplified Chinese zh-Hans, English en. URLs, file names and options all use these codes.
  • Always Traditional Chinese by default, not following the operating system or browser language; users switch manually: --lang or the RPA_LANG environment variable on the command line, a user setting in the web UI, the page header on the docs site.
  • Product text lives in message catalogs. Each package has locales/<language>.json, and code refers to message keys (rpa_core.i18n.Catalog) instead of hard-coding user-facing text. click's built-in "Usage", "Options" and error messages are translated too.
  • Simplified Chinese is generated. Traditional Chinese and English are maintained by hand; Simplified Chinese is generated with OpenCC's tw2sp (converts to Simplified and switches to Mainland terms) and committed, with fixes for unidiomatic terms in tools/zh-Hans-overrides.json. The OpenCC version is pinned.
  • Three docs directories. Traditional Chinese in docs/ (URLs unchanged), English in docs/en/, Simplified Chinese in docs/zh-Hans/; the directory layout and anchors are identical.
  • Checks keep them in sync. Tests ensure all three languages have the same message keys and placeholders, that Simplified Chinese is freshly generated, and that each English page matches the current Traditional Chinese version.

What gets translated

ContentHandling
Command-line output, error and validation messages, run reportsThree languages, in message catalogs
Web UI and API error messages (M7, M8)Three languages; the frontend uses the same codes and default language
Engineering docs docs/Three languages, one directory each
User-written content: scenario names, step descriptions, page text in locatorsNot translated; stored and shown as written
DSL field and action names, code identifiersStay in English, not translated
Code comments and docstrings, README, output of the setup scriptsStay in Traditional Chinese

Consequences

Benefits

  • New features have three languages from their first line, with nothing to backfill.
  • Only two languages are maintained by hand, and Simplified Chinese terminology stays consistent.
  • Missing or outdated translations fail CI instead of quietly producing mixed-language screens.

Costs

  • Changing user-facing text or docs means updating the English too, so PRs get bigger.
  • Because the default is always Traditional Chinese, English users need --lang en every time, or set RPA_LANG.
  • Automatically converted Simplified Chinese occasionally has unidiomatic terms that need entries in the override table.
  • Interface design system v1.0 was designed in Traditional Chinese; English is usually longer, so the M6 page prototypes must check English layouts.

Options not chosen

OptionWhy not
gettext and Babel (.po files)Widely used, but keyed by the English source text and needs a compile step; this project's main language is Traditional Chinese and the web UI must read the same translations, so JSON is more direct.
Maintain all three languages by handThe most precise Simplified Chinese wording, but every change is written three times and drifts out of sync most easily.
Follow the system or browser languageThe same command would print different languages on different computers, making it hard to match docs examples and bug reports; instead the default is always Traditional Chinese with manual switching.
Convert docs to Simplified Chinese in the browserNo generated files, but it ships several megabytes of dictionaries and complicates link checks and offline reading.
