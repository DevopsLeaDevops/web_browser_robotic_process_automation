ADR 0001: A declarative DSL is the single source of truth for scenarios

Scenarios are stored as schema-constrained data, not as code.

Accepted
Date
2026-10-09
Affects
rpa-core, every generation method, the web UI editor, the execution engine
Related
Scenario DSL; for the scenario contract and the Python script escape hatch see ADR 0009

Context

Scenarios come from three sources (recording, AI, manual editing). They must be edited visually on the web, compared across versions, and handed to many workers to run.

If scenarios were stored as Playwright scripts, the editor could not reliably parse and rewrite them, and AI output could not be validated before running. A script can do anything, so review and security boundaries would be unclear.

Decision

  • Scenarios are described in a declarative DSL: written in YAML, stored as JSON.
  • The DSL is defined with Pydantic v2 models, and the same definition exports a JSON Schema for AI generation and the frontend.
  • The DSL carries a schemaVersion, with migrations when the format changes.
  • Scenarios can be exported as Playwright code for developers' reference, but the export cannot be written back as a scenario.
  • When the DSL cannot express something, a controlled script step is used.

Consequences

Benefits

  • The editor, version comparison and review all work directly with structured data.
  • AI output can be validated, and errors can be fed back precisely to the model for correction.
  • The execution layer is replaceable, and the DSL defines the security boundary.

Costs

  • Expressiveness is limited, so an escape hatch is needed and flagged during review.
  • We maintain the DSL specification and version migrations ourselves.

Options not chosen

OptionWhy not
Store Playwright scripts directlyCannot be edited visually in a reliable way, cannot be validated before running, and the security boundary is unclear.
Flowchart JSON (common in low-code platforms)The same idea in essence, but hard to write by hand and to compare in Git; a YAML DSL covers both.
Buy an off-the-shelf RPA platformHigh license costs and limited generation and customization.
