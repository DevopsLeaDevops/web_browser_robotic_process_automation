ADR 0011: Server-rendered management interface with FastAPI + Jinja

FastAPI serves both the API and the pages of the MVP management portal; pages are Jinja templates with the design system's CSS and a little JavaScript. Supersedes React from ADR 0004.

Accepted
Date
2026-10-10
Scope
rpa-server (from M3), every page of the management interface, CI
Related
Supersedes ADR 0004; ADR 0002, ADR 0006, ADR 0010

Context

ADR 0004 chose React mainly because a visual step editor needs drag-and-drop and rich interaction. The pages of the MVP prototype are cards, forms, filters, draft editing and serial workflows, all built with design system v1.0's portal.css, shell.js and one JavaScript file, without a framework.

The prototype's brief suggests Flask + Jinja. The backend already defines the DSL with Pydantic (ADR 0002), and the API returns the same models.

Decision

  • FastAPI serves the API and the pages. The REST API uses rpa-core's Pydantic models directly and generates OpenAPI; the same service renders pages with Jinja2 templates.
  • Only the design system and a little JavaScript on the frontend. Keep portal.css, shell.js and the design tokens; interaction uses small JavaScript modules that need no build, with no framework and no Node.js build.
  • Long tasks never block requests. Runs go to a background worker; pages read progress by polling or server-sent events.
  • Multilingual. Template text lives in the message catalogs, using the same mechanism as the command line (ADR 0007).
  • Room to adjust. If a later step editor truly needs a framework, it is introduced on that page only, with its own ADR.

Consequences

Benefits

  • The whole project is Python, with no TypeScript or frontend build to maintain.
  • Pages match the prototype: the same CSS, layout and components.
  • The API and the pages share models and validation, so error messages are consistent.

Costs

  • Complex drag-and-drop editing needs hand-written JavaScript; past a certain size it must be reconsidered.
  • Server-rendered pages must separately ensure keyboard access and narrow-screen layouts.

Alternatives not chosen

OptionWhy not
Flask + Jinja (the prototype's brief)Equally simple, but request validation and API docs need extra pieces; FastAPI uses Pydantic models directly and generates OpenAPI.
FastAPI + React (ADR 0004)Richest interaction, but the MVP pages do not need it, while it adds a TypeScript codebase and build to maintain.
NiceGUI, StreamlitPure Python, but they cannot reuse the design system's layout and components.
