Git history graph

Save commits, branches, tags and PR associations as an interactive, offline HTML file. Run the same command again to refresh it.

Generate and refresh

Run from the repository root. Only Python 3.12+ and Git are required; no additional Python packages. In a development environment use uv run python; on a Linux server use .venv-server/bin/python; on Windows use .venv\Scripts\python.exe in place of python.

python tools/git_history.py --open
python tools/git_history.py --fetch --github --lang zh-Hans --timezone Asia/Shanghai --open

The first command reads all locally available history. The second fetches remote branches, tags and PR heads retained by GitHub, and reads PRs in every state. It requires an installed, authenticated gh CLI (run gh auth login first). Omit --github for other Git hosts. For offline use, omit --fetch --github.

The default output is artifacts/git-history.html, which Git ignores. On a headless server omit --open, copy the resulting HTML to your computer, and open it in a browser. Data, styles and scripts are embedded; no CDN or web server is required.

python tools/git_history.py --repo /path/to/repository --output /path/to/history.html --fetch
python tools/git_history.py --help

--lang supports zh-Hant (default), zh-Hans and en; the page also has a language selector. --timezone defaults to America/Los_Angeles. The page labels the timezone actually used. Generating again replaces the output file; there is no background monitoring.

Read the graph

  • The default includes all history, including independent branches such as CI metrics. Select origin/main to see the remote main branch and its ancestors. Local main may point elsewhere.
  • Dots represent commits; lines follow actual parents. Hollow dots have multiple parents. Newest-first topological order preserves ancestry, so dates across branches need not strictly decrease.
  • Search messages, authors, SHAs, branch names or #57, then use Previous/Next. Intermediate nodes stay visible, preserving complete paths. Select a commit for its full message, refs, related PRs and clickable parents.
  • A squash merge creates a different SHA. The graph preserves the original PR head and GitHub's recorded integration commit separately. A merged PR does not create a Git parent edge between these nodes. A PR merged into a feature branch is not necessarily in main.
  • Rendering is virtualized while scrolling, with no fixed commit limit. The complete JSON still loads into memory, so large repositories require correspondingly larger files and memory.

Coverage and effects

Includes all commits reachable from local refs and HEAD, including fetched remote branches, tags and PRs. It does not read reflogs or scan dangling objects; deleted commits without surviving refs cannot be guaranteed recoverable. Shallow clones display a warning. If the remote has full history, run git fetch --unshallow before generating again.

The tool does not checkout, merge, rebase or push, or change working files and branches. --fetch updates remote-tracking refs and downloads objects and tags. GitHub PR heads go into dedicated refs/git-history/origin/pr/* refs (the name follows --remote). Old refs are not pruned; cached refs for deleted remote branches may remain visible and do not prove those branches still exist remotely.

The output contains commit messages, authors, branch names and PR titles; sharing the HTML shares this repository history. It does not export Git credentials or read Portal data directories. The page is a dated snapshot; fetch again to obtain current state.
