Docs & ADRs

How to add a docs page, how to keep the three languages in sync, and how to record architecture decisions. For the background see ADR 0005 and ADR 0007.

Writing principles

  • Conclusion first, details after. The page description says in one sentence what the page is about.
  • One topic per panel. Panel titles are the table of contents readers scan.
  • Use the right component. Tables for comparisons, spec lists for definitions, point lists for key points, notices for warnings.
  • States need words. Never rely on color alone to show a state.
  • No repetition. Explain each thing in detail in one place and link to it from elsewhere.

Adding a page

  1. Write the Traditional Chinese version first: copy an existing page in the same directory and keep the <head> and <body> attributes.
  2. Change data-page (the page id) and data-root (the relative path back to that language's root, for example ../).
  3. Register the page in docs/assets/nav.js, with names in both "zh-Hant" and "en".
  4. Write the English version at the same path under docs/en/; see Three languages below.
  5. Run uv run python tools/i18n.py sync to generate Simplified Chinese, then uv run pytest tests/docs tests/i18n.

Page template

An English page under docs/en/design/ as the example
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">

<link rel="stylesheet" href="../../assets/docs.css">

<script defer src="../../assets/docs-shell.js"></script>
</head>
<body data-page="page-id" data-root="../">
<main id="main">
  <div class="heading"><div><h1>Page name</h1><p>One-sentence summary</p></div></div>
  <div class="stack">
    <section class="panel">
      <div class="panel-header"><h2>Panel title</h2></div>
      <div class="panel-body">Content</div>
    </section>
  </div>
</main>
</body>
</html>

Three languages

Traditional Chinese and English by hand, Simplified Chinese generated

Layout and rules

  • Traditional Chinese is in docs/, English in docs/en/, Simplified Chinese in docs/zh-Hans/; the three directories have exactly the same file names, structure and anchors (id).
  • English pages use lang="en" and go up one more level for shared resources, for example ../../assets/docs.css; data-root is still the path back to docs/en/.
  • Links between pages only point to pages in the same language; the page header handles switching languages.
  • docs/zh-Hans/ and the "zh-Hans" entries in nav.js are generated, so never edit them by hand; add wrong terms to tools/zh-Hans-overrides.json.
  • Mark Traditional Chinese text that programs actually print (such as the setup scripts' output) with translate="no" so it stays unchanged in the Simplified Chinese version.

After changing a Traditional Chinese page

# 1. Update the same page under docs/en/ to match the change
# 2. Record which Traditional Chinese version the English page follows
uv run python tools/i18n.py stamp docs/en/develop/setup.html

# 3. Regenerate Simplified Chinese (the pre-commit check also does this)
uv run python tools/i18n.py sync

# Check only, without writing
uv run python tools/i18n.py check

If the Traditional Chinese page changes and the English page is not stamped again, the tests fail and name the page. For a typo fix that does not affect the English, just stamp it.

Adding an ADR

When to write one

  • The choice affects several packages or is hard to reverse.
  • There are two or more reasonable options, and people who come later need to know why this one was chosen.
  • An existing ADR is overturned or changed.

How to write one

  • Copy the most recent ADR; name the file NNNN-short-english-name.html with the next number.
  • Fixed sections: date, scope, context, decision, consequences (benefits and costs), options not chosen.
  • A new ADR starts as "Proposed", is discussed in the PR, and becomes "Accepted" when merged.
  • Update adr/index.html and nav.js, and provide an English version following Three languages.
  • When superseding a decision, mark the old ADR "Superseded" and link it to the new one, without deleting its content.
