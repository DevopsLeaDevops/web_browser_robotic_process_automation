Conventions

Agreements on branches, commits, PRs, code and tests. Whatever tools can check is left to the tools; this page covers only what they cannot.

Branches and PRs

  • main is protected. Merge only through PRs, with CI all green and at least one review.
  • Branch names. Milestone work uses m1/dsl-models; everything else uses fix/…, docs/…, chore/….
  • Three-part PR descriptions. What was done, how it was verified, what is not done yet.
  • Merging. Squash merge; the PR title becomes the final commit message.
  • Dependency changes. Explain the reason for any new dependency in the PR description.

Code

  • Language. Identifiers in English; comments and docstrings in Traditional Chinese.
  • User-facing text. Command-line output, error and validation messages and the like always go into the package's locales/, and code refers to message keys only; write Traditional Chinese and English together, and Simplified Chinese is generated. See ADR 0007.
  • Types. pyright strict; every function fully annotated, avoiding Any.
  • Formatting. ruff decides; no manual arguments about formatting.
  • Output. No leftover print in code; the CLI prints through click and libraries use logging.
  • Boundaries. rpa-core does not depend on a browser or a database; execution code goes into rpa-runner.

Tests

  • Each package tests under its own tests/; cross-package tests go in the root tests/.
  • Tests that need a real browser are marked @pytest.mark.browser.
  • Tests do not depend on external websites; when a web page is needed, use the test site (from M2).
  • When fixing a bug, first write a test that reproduces it.
  • tests/docs checks the structure and links of docs pages; tests/i18n checks that the three languages are in sync.
Never commit real credentials, internal system URLs or screenshots containing business data. Keep local secrets in .env (ignored by Git) and use .env.example for the example file.
