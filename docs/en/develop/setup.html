Dev environment

From nothing to running tests in about five minutes. The commands are the same on Windows, macOS and Linux. To set up everything with one command, use the setup script in Run locally from scratch; for a first setup on a Mac, follow Run on macOS step by step.

First-time setup

git clone https://github.com/DevopsLeaDevops/web_browser_robotic_process_automation.git
cd web_browser_robotic_process_automation

# Create .venv and install all packages and dev tools
uv sync

# Download Chromium and Firefox (on Linux, add --with-deps the first time to install system dependencies)
uv run python tools/install_browsers.py

# Automatic checks before each commit
uv run pre-commit install

# Confirm the installation
uv run rpa --version

Linux server setup (yum/dnf)

The headless server hosts the Portal, database and scheduler. Remote Workers run browsers; the Recorder handles recording, manual login and headed debugging. setup-linux.sh installs .venv-server without browser downloads, desktop apps, development tools or Git hooks. Existing CLI dependencies still include the Playwright Python package, but its browser driver is not started.

Distribution detection
Reads ID and ID_LIKE from /etc/os-release, accepting rhel, centos or fedora; prefers yum, then dnf. Blank names and ID="" work with ID_LIKE="rhel fedora centos ". A corporate VERSION_ID="3" is not interpreted as CentOS 3.
Runtime
x86_64 or aarch64 with glibc 2.28 or newer; check with uname -m and getconf GNU_LIBC_VERSION. x86_64 with glibc 2.32 meets these prerequisites; the actual corporate repositories and host still need acceptance testing. System glibc and Python are not replaced: uv downloads the Python specified by .python-version and installs from uv.lock.
System packages
git curl ca-certificates tar gzip libstdc++ libgcc. Run as a regular user; yum/dnf and systemd operations use sudo. Use --skip-system-packages when an administrator has already installed them.
Data
Defaults to ~/.local/share/rpa-server; set RPA_DATA_DIR before the first installation to change it. To continue an existing service, specify its original data directory or a new empty environment will be created.

The first installation creates .rpa-server.env in the repository (Bash syntax, mode 600, Git ignored). The admin interface listens on 127.0.0.1:8080 and device APIs on 0.0.0.0:8081, with --no-local-worker and, by default, no test site. Edit RPA_DATA_DIR, RPA_PORT, RPA_WORKER_PORT, RPA_WORKER_HOST or RPA_TESTSITE_HOST in this file, then restart. Setting RPA_TESTSITE_HOST to 0.0.0.0 starts the test site on 8765 and lets recorders and workers reach it (see Sharing the server’s test site; settings files created earlier lack this line, so add it yourself). Rerunning setup preserves it. The service and data belong to the user running the script; do not run the whole script with sudo.

Initial administration: run the SSH forwarding command below on your computer, open http://127.0.0.1:8080, and create invitations on the Devices page. Invitations must use the server IP or DNS reachable by the Worker/Recorder on port 8081, not the SSH tunnel's 127.0.0.1. Once paired, the Recorder accesses the Portal through its local gateway. See Remote Workers and Desktop distribution.

ssh -N -L 8080:127.0.0.1:8080 admin@SERVER

# After editing configuration
sudo systemctl restart rpa-server

# Upgrade: stop the service and back up all data (rpa.db, scenes, roles, secrets.json)
sudo systemctl stop rpa-server
# Back up the entire RPA_DATA_DIR specified in .rpa-server.env here
git pull --ff-only
bash scripts/setup-linux.sh --install-service

Setup starts the service only with --install-service; stop foreground processes with Ctrl+C. An active systemd service blocks setup; stop foreground processes before upgrading as well. Use the foreground command in containers without systemd; the generated unit is .venv-server/rpa-server.service. Reinstallation preserves data, but starting the server applies database migrations, so keep a full backup for rollback. The script does not pull or switch branches in existing checkouts or alter firewall rules; allow only the devices that need access to the device port.

Corporate networks must provide access to the code, uv installer, Python distributions and locked package sources. Set HTTPS_PROXY or UV_PYTHON_INSTALL_MIRROR as needed; use UV_NATIVE_TLS=true when the corporate CA is in the system trust store. Git and curl also need to trust that CA; do not disable TLS verification. An existing approved uv installation is reused; an outdated version produces an actionable error and should be upgraded through its original installation method.

Package source. Python packages are installed from uv.lock, and by default the script measures first (--mirror auto): PyPI and the Tsinghua (tuna), USTC (ustc), Alibaba Cloud (aliyun), Tencent Cloud (tencent) and Huawei Cloud (huawei) mirrors all download the same file from the lock file at once; only sources whose sha256 matches the lock file count, the fastest one is used, and every source’s speed is listed. If none works, PyPI is used. You can choose directly: bash scripts/setup-linux.sh --mirror tuna, --mirror pypi, or your company mirror’s simple URL such as --mirror https://nexus.example.com/repository/pypi/simple (or set RPA_PYPI_MIRROR; without either, a set UV_INDEX_URL or UV_DEFAULT_INDEX is used without measuring).

Why it works this way: uv sync --locked downloads from the URLs recorded in the lock file (files.pythonhosted.org); setting UV_INDEX_URL alone does not change where files come from and makes uv stop because the lock file looks outdated. So with a mirror the script rewrites the index and file URLs in uv.lock for this install only (versions, files and sha256 stay the same, and uv still verifies every hash) and restores it afterwards, on failure, or when interrupted; if the mirror fails midway it retries once from PyPI. Where only approved sources are allowed, use --mirror pypi (with HTTPS_PROXY) or the company mirror’s URL instead of auto. Do not delete the lock file or change versions ad hoc. This setup does not require browser download hosts.

Validation: CI uses Rocky Linux 8 (real yum, glibc 2.28, a regular user) for in-repository and standalone-clone installations, blank corporate distribution identifiers, configuration preservation, port isolation, device pairing and data persistence after restart. Containers only check systemd unit syntax; the corporate image, aarch64 and actual systemd boot behavior require host acceptance testing. Run .venv-server/bin/python tools/linux_server_smoke.py for an HTTP smoke test with isolated temporary data.

FAQ

CI says uv.lock needs updating
A dependency in pyproject.toml changed without updating the lock file. Run uv lock and commit uv.lock together with the change.
PyPI unreachable from the intranet
Set the UV_INDEX_URL environment variable to the company's package mirror. For the Linux server installer, pass the mirror's simple URL with --mirror; see Package source.
Browser download fails
Setup first tests and selects the fastest available source; you can also run uv run python tools/install_browsers.py. To use a fixed source, set PLAYWRIGHT_DOWNLOAD_HOST to an internal mirror; the browser smoke test is skipped automatically when no browser is installed locally.
Tests say Simplified Chinese is not up to date
After changing Traditional Chinese docs or message catalogs, run uv run python tools/i18n.py sync and commit the generated files.
Tests say the English translation needs updating
Update the same page under docs/en/ to match the Traditional Chinese change, then run the stamp command shown in the test message.
pyright cannot find packages
Make sure you have run uv sync and your editor uses the project's .venv.
