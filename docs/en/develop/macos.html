Run on macOS

A step-by-step guide for a Mac with no development tools, from downloading the code to a working CLI, tests and docs site. The first time takes about ten minutes, mostly downloading. To do all of the steps below with one command, use the setup script in Run locally from scratch.

This is M0 (project skeleton). "Working" means: the rpa command runs, all tests pass, Playwright can start Chromium, and the docs site opens in a browser. Subcommands for validating, running and recording scenarios arrive in later milestones; see the Roadmap.

Prerequisites

Computer
Any Mac with Apple silicon (M series) or Intel. A macOS version that still receives updates is recommended.
Terminal
The built-in Terminal app (Applications › Utilities). The default shell is zsh, and every command on this page runs in zsh.
Network
Access to GitHub, PyPI and Playwright's browser downloads. On a company network, read the FAQ first.
Disk space
About 1 GB for Python, packages and Chromium.
Not needed
You do not install Python, Homebrew or Node.js yourself. uv downloads Python; Node.js is only needed when frontend work starts in M8.

1. Install Git

First check whether Git is already there:

git --version

If it prints a version number, go to the next step. If a window asks you to install the "command line developer tools", or you see xcrun: error, run the command below, click "Install" in the pop-up window and wait until it finishes. You do not need the full Xcode.

xcode-select --install

2. Install uv

uv downloads Python, creates virtual environments and installs packages; the project requires 0.11 or later. Choose one:

Official installer (recommended)

curl -LsSf https://astral.sh/uv/install.sh | sh

Installs to ~/.local/bin; upgrade later with uv self update.

Already using Homebrew

brew install uv

Upgrade later with brew upgrade uv.

When it is done, close Terminal and open a new window so the PATH takes effect, then check the version:

uv --version    # for example uv 0.11.x; 0.11 or later is required

3. Download the code

Put it in a folder of your choice; this example uses code in your home folder:

mkdir -p ~/code && cd ~/code
git clone https://github.com/DevopsLeaDevops/web_browser_robotic_process_automation.git
cd web_browser_robotic_process_automation
  • All later commands run inside this folder.
  • Avoid the Desktop and Documents folders when iCloud syncs them: the many small files in .venv would be synced over and over.
  • Downloading a ZIP is not recommended: without Git history you cannot update with git pull or install the pre-commit checks.

4. Install dependencies and the browser

# Prepare Python 3.13 per .python-version (downloaded if missing), create .venv, install all packages and dev tools
uv sync

# Download the Chromium used by Playwright
uv run playwright install chromium
.venv/
The project's own virtual environment, inside the project folder. No need to activate it: uv run uses it automatically.
Python
Python downloaded by uv lives in ~/.local/share/uv/python and leaves the system Python alone.
Chromium
Lives in ~/Library/Caches/ms-playwright. macOS does not need --with-deps; that installs system libraries on Linux.
uv.lock
The repository's lock file, recording the exact version of every package; uv sync installs from it, so everyone gets the same versions.

5. Confirm it works

CommandExpected result
uv run rpa --versionrpa 0.1.0（rpa-core 0.1.0）; with --lang en: rpa 0.1.0 (rpa-core 0.1.0)
uv run rpa -hShows the usage and the description; in English (--lang en): "Generate, manage and run browser automation scenarios." M0 has no subcommands yet.
uv run pytestThe last line shows only passed: no failed and no skipped.
RPA_REQUIRE_BROWSER=1 uv run pytest -m browser1 passed (the other tests show as deselected). This is the browser smoke test; like CI, a missing browser fails instead of being skipped.
If uv run pytest shows 1 skipped with the reason "Chromium 未安裝" (Chromium not installed), the browser from step 4 did not install correctly; run uv run playwright install chromium again.

rpa prints Traditional Chinese by default; for Simplified Chinese or English, add --lang zh-Hans or --lang en, or set the RPA_LANG environment variable (for example, add export RPA_LANG=en to ~/.zshrc).

To avoid typing uv run every time, activate the virtual environment first with source .venv/bin/activate, then type rpa --version or pytest directly; leave with deactivate.

6. Open the docs site

# Open the English docs directly in your default browser
open docs/en/index.html

# Or start a local server and browse http://localhost:8000/en/ (Control-C to stop)
uv run python -m http.server -d docs 8000

The top-right corner of the header switches between 繁體中文, 简体中文 and English.

macOS has no python command. Replace the python -m http.server in the README with uv run python as above, or the system python3.

7. Get ready to develop

Optional
# Run ruff, pyright and the docs checks automatically before every git commit
uv run pre-commit install
  • The first pyright run (including the one at commit time) downloads the Node.js runtime it needs, so it takes a little longer.
  • Point your editor's Python interpreter at .venv/bin/python in the project so type checking can find the packages.
  • Common commands are in Dev environment; branch and commit rules are in Conventions.

Every time after that

cd ~/code/web_browser_robotic_process_automation
git pull        # get the latest code
uv sync         # installs only when dependencies changed; otherwise done in seconds
uv run pytest

FAQ

What you seeWhat to do
xcrun: errorCommon after a major macOS upgrade; reinstall the command line developer tools: xcode-select --install.
command not found: uvOpen a new Terminal window. If that does not help, run source $HOME/.local/bin/env, or check with echo $PATH that it contains ~/.local/bin.
command not found: pythonmacOS has no such command by default. Use uv run python (the project's Python 3.13) or python3.
uv is too oldWhen uv sync asks for 0.11 or later: if you used the installer, run uv self update; with Homebrew, run brew upgrade uv.
An M-series Mac reports x86_64uname -m should print arm64. x86_64 means Terminal was opened through Rosetta: in Finder, choose Get Info on Terminal, uncheck the Rosetta option, reopen Terminal and run rm -rf .venv && uv sync.
Address already in usePort 8000 is taken; use another port, for example uv run python -m http.server -d docs 8001.
git pull says uv.lock would be overwrittenThe lock file has been committed to main. Delete your locally generated copy and pull again: rm uv.lock && git pull && uv sync.
Company network, proxy or mirrorsSee the Dev environment FAQ (UV_INDEX_URL, PLAYWRIGHT_DOWNLOAD_HOST).
Start over completelyRebuild the environment: rm -rf .venv && uv sync. Reinstall the browser: rm -rf ~/Library/Caches/ms-playwright, then uv run playwright install chromium.
