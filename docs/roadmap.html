路線圖

十個里程碑，每個都能獨立驗收。每一步：先說明設計 → 確認 → 寫程式與測試 → 開 PR → review 後合併。

為什麼是這個順序

  • CLI 先於 UI。每個能力都能在沒有介面的情況下驗證，Web UI 只是在上面加一層。
  • 生成先於管理後端。生成是本工程的核心差異；M6 之前場景以 YAML 檔放在倉庫，Git 就是版本控制。
  • 原型先於後端。M6 的頁面原型決定 M7 的 API 需要提供哪些資料。
  • Runner 從一開始就無狀態。只吃場景、參數與 Secrets，輸出結果與產物，到 M9 直接放進 worker。
