二、Claude 雲端環境的限制

2026-10-13～14 的 session；之後的環境可能不同
  • 每個 session 是全新、暫時的容器：要先用 add_repo 取得倉庫權限再 git clone；session 結束後工作目錄就不在了（所以筆記都要寫回 Claude 專案或倉庫）。
  • 連不到 PyPI（DNS 被擋）：不能 uv sync。容器裡只有部分套件（pydantic、starlette、uvicorn、jinja2、playwright），沒有 fastapi、sqlalchemy、alembic、httpx，瀏覽器只有 Chromium。所以伺服器的測試、Firefox 的測試只能靠 CI。
  • 可以用的檢查：ruff、pyright（另外從 GitHub 下載 fastapi 等的原始碼，只給 pyright 做型別檢查，不執行）、沒有伺服器相依的 pytest（rpa_core、rpa_runner、rpa_worker、rpa_cli、文檔、多語言目錄）。
  • uv.lock 與簡中產生不了（沒有 PyPI、沒有 OpenCC）→ 由 GitHub Actions 的 bootstrap 代做（見第四節）。
  • 推送要你同意：自動模式會攔下沒被要求的提交或推送（10-13 第一次推 #22 就被攔，你同意後才推）。
  • 碰不到你的電腦：不能在你的 Windows 或 Portal 那台執行任何東西；人工驗收只能靠你回報。
  • 讀不到 Claude 專案的記憶與過去的對話，只讀得到專案文件。
  • GitHub Actions 的日誌本體下載不了（被網路政策擋），annotations 可以讀。
  • Claude 有每週用量上限：快用完時先交接（10-13 剩 12% 時交接）。

四、bootstrap、rebase、衝突、CI 失敗

bootstrap 回寫後怎麼同步

  1. 提交訊息裡寫 [bootstrap] 再推送 → .github/workflows/bootstrap.yml 執行 uv lock、產生簡中與 JSON Schema、跑檢查，不論檢查是否通過都把產生的檔案提交回分支（作者 github-actions[bot]，訊息「chore: 產生 uv.lock 與簡體中文版」）。
  2. 本地一定要 git pull 再繼續改，否則下一次推送會被拒絕。
  3. bootstrap 的「檢查」失敗時沒有 annotations：直接開 PR 讓 CI 跑，從 CI 的 annotations 看錯誤。

CI 失敗

  1. 先分清楚 failure 與 cancelled：同一個 workflow 有新的推送時舊的會被取消（例如 main 上的 151a935），不是失敗。
  2. 讀 annotations（tools/ci_annotations.py 把 pytest 與 pyright 的錯誤轉成 annotations，標在 PR 的檔案行上）。
  3. 本地能重現的先本地修；伺服器測試只能讀錯誤訊息後修正、推送、等 CI。

base 分支被 squash 合併後的 rebase

  1. PR 疊在另一個 PR 上時（#23 疊在 #22 上），base 被 squash 合併後，用 git rebase --onto origin/main <舊 base 的最後一個提交> <分支> 只搬自己的提交。
  2. 用 git diff <rebase 前> <rebase 後> 確認內容完全相同。
  3. git push --force-with-lease，再用 gh api -X PATCH …/pulls/{n} -f base=main 改 PR 的 base，更新 PR 說明。
  4. 到目前為止沒有遇過衝突。遇到時：解衝突 → 本地跑 ruff、pyright、能跑的 pytest → 推送 → 看 CI。

PR 合併到錯的分支

#21 的 base 是 #20 的分支，而 #20 先合併了，所以 M6 沒進 main。處理：從 main 開 m6/main，git cherry-pick #21 的 squash 提交，確認和那個分支內容相同（git diff 為空），開 #22 到 main。預防：疊在別的 PR 上的 PR，合併前先確認 base 是 main。

六、修改時的規則（CI 會檢查）

你自己改程式時照這個做

每次提交前，在專案資料夾執行：

uv run ruff check . && uv run ruff format --check .
uv run pyright                      # strict 模式
uv run pytest -m "not browser"      # 快；要跑真實瀏覽器的就拿掉 -m
uv run python tools/i18n.py check   # 簡中是否同步、英文是否跟上繁中
  • 改資料庫模型就要新增遷移：下一個是 0008，down_revision = "0007"；test_migrations.py 會比對模型與遷移，資料表清單要依字母排序。
  • 介面文字不能寫死：放在 locales/zh-Hant.json、en.json（三種語言的鍵與 {佔位符} 相同）；zh-Hans.json 用 uv run python tools/i18n.py sync 產生。test_render.py 會檢查英文頁面沒有殘留中文。給 JavaScript 用的訊息（js. 開頭）要加到 render.js_messages()，佔位符寫 {{name}}。新增很多訊息時可以用 materials/tools/addmsg.py。
  • 文檔是 HTML：新頁面登記在 docs/assets/nav.js；英文頁放 docs/en/ 同路徑，翻譯完 uv run python tools/i18n.py stamp docs/en/路徑.html；最後 uv run python tools/i18n.py sync 產生簡中。handoff/ 不屬於文檔站，不需要翻譯。
  • 不要改 apps/server/src/rpa_server/static/portal.css、shell.js（設計系統的複製品），自己的樣式放 portal-app.css。
  • 提交與 PR：feat(m9a): …、fix(…): …、docs: …；開分支、開 PR，CI 綠了再合併；PR 的 base 一定是 main（除非刻意疊在別的 PR 上，合併前再確認）。
