2. M9a 遠端 worker 做了什麼

設計：ADR 0012；操作：遠端 worker；管理 Portal 的說明：管理 Portal › 遠端 worker（手動驗收第 8 步是兩台電腦的流程）。

  • rpa serve --worker-port 8081 另開一個埠，只有 Worker API（/worker-api/v1，每個請求都要權杖）；管理頁面仍然只在 127.0.0.1。
  • 「場景生產 › 遠端 Worker」頁：登記 worker、產生權杖（只顯示一次）、停用、重新產生權杖、刪除、預設執行位置。
  • worker 機器：uv run rpa worker --server http://你的IP:8081 --name win-01（權杖放在環境變數 RPA_WORKER_TOKEN）。
  • 執行、驗證、序列的表單多了「執行位置」：本機／遠端 worker／任一。預設本機，所以沒有登記 worker 時和以前一樣。
  • 60 秒沒有心跳就判定 worker 失聯，那次執行標為失敗，不自動重跑。試驗場序列整個固定在第一個節點的 worker。

3. 接下來要做的事

建議依這個順序

3.1 合併 #23，做兩台電腦的驗收（必做，約 20 分鐘）

先合併 #23，兩台電腦都要更新：在專案資料夾 git pull，再重跑安裝腳本（macOS／Linux：./scripts/setup.sh；Windows：powershell -ExecutionPolicy Bypass -File scripts\setup.ps1）。沒有更新就會出現「沒有 worker 這個命令」或不認得 --worker-port。不想先合併的話，兩台都 git fetch origin、git checkout m9a/remote-worker、uv sync。
  1. 你的電腦：uv run rpa serve --data data-check --worker-port 8081，允許防火牆的連入詢問。
  2. Portal「場景生產 › 遠端 Worker」新增 win-01，複製權杖與 PowerShell 命令。
  3. Windows 機器：用 scripts\setup.ps1 安裝，再貼上命令啟動 rpa worker；worker 頁要變成「線上」。
  4. 選「遠端 worker」＋有頭模式執行 BA-001：視窗出現在 Windows 那台，你的電腦不跳視窗；報告「通過」、截圖看得到、執行頁顯示「執行的電腦：win-01」。
  5. 用「遠端 worker」跑 BA-001 → BA-002 的序列：兩個節點都在 win-01。
  6. 執行中在 Windows 按 Ctrl+C：Portal 上那次變成「已取消」。拔掉 Windows 的網路：約一分鐘後變成失敗「worker 失聯」。
有問題請記在第 6 節：哪一步、看到的訊息、rpa worker 終端機的輸出。Windows 上最可能出問題的是防火牆、路徑與換行；雜湊不符（驗證通過卻被標失敗）也請特別記下來。

3.2 M9a 還沒做的小項目（選做，你可以自己寫）

  1. 執行報告的篩選加「執行位置」：render.run_filters 加一個選單，Services.list_runs 加篩選條件（Run.target 或 Run.worker_id），pages.runs 傳參數。
  2. 網址是 localhost／127.0.0.1 時提醒：選「遠端」而場景網址是本機位址時，在 run_form.html 顯示提醒（測試網站 8765 除外，worker 有自己的）。
  3. 排隊中等待 worker 的提示：執行頁狀態是「排隊中」、位置是遠端、而沒有線上的 worker 能接時，顯示「等待可以執行的 worker」（看 WorkerHub.list_workers() 的狀態）。
  4. HTTPS（選用）：rpa serve 產生自簽憑證、worker 第一次連線時確認指紋。只有網路不受信任時才需要。

3.3 M5 AI 助手：需要你決定

設計提案在 Claude 專案的 claude/m5-design-proposal.md（摘要見專案脈絡與對話備忘）。開工前要決定：

  • 用哪個 AI 模型：Claude API、公司內部模型，還是本機模型？推薦「兩種都支援，由設定選擇」。
  • 資料去向：公司內部頁面的內容（網址、可存取性樹、選擇器、校驗錯誤）能不能送到外部 API？不能的話，請給自架端點的網址與模型名稱。
  • 另外兩點有推薦預設：不送截圖、輸入框的值遮罩；金鑰放在「登入與憑證」的 Secrets。

決定後寫在第 6 節，下週直接開工。

4. 修改時的規則（CI 會檢查）

詳細見 開發規範、文檔與 ADR

每次提交前，在專案資料夾執行：

uv run ruff check . && uv run ruff format --check .
uv run pyright                      # strict 模式
uv run pytest -m "not browser"      # 快；要跑真實瀏覽器的就拿掉 -m
uv run python tools/i18n.py check   # 簡中是否同步、英文是否跟上繁中
  • 改資料庫模型就要新增遷移：下一個是 0008，down_revision = "0007"；test_migrations.py 會比對模型與遷移，也要更新資料表清單（依字母排序）。
  • 介面文字不能寫死在程式或樣板裡：放在 locales/zh-Hant.json、en.json（三種語言的鍵與 {佔位符} 要相同）；zh-Hans.json 由 uv run python tools/i18n.py sync 從繁中產生，不要手改。test_render.py 會檢查英文頁面沒有殘留中文。給 JavaScript 用的訊息（js. 開頭）要加到 render.js_messages()，佔位符寫成 {{name}}。
  • 文檔是 HTML：新頁面登記在 docs/assets/nav.js；英文頁放在 docs/en/ 的同一路徑，翻譯完執行 uv run python tools/i18n.py stamp docs/en/路徑.html；最後 uv run python tools/i18n.py sync 產生簡中。
  • 不要改 apps/server/src/rpa_server/static/portal.css、shell.js：它們是設計系統的複製品，要改請先改 docs/design-system/。自己的樣式放 portal-app.css。
  • 提交訊息：feat(m9a): …、fix(…): …、docs: …；開分支、開 PR，CI 綠了再合併。
  • CI 失敗：錯誤會標在 PR「Files changed」的對應行上（tools/ci_annotations.py）。
  • 小技巧：提交訊息裡寫 [bootstrap] 再推上去，GitHub Actions 會自動產生 uv.lock 與簡中並提交回分支（記得之後 git pull）。
