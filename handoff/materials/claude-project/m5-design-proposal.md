# M5 AI 助手：設計提案（2026-10-13，待確認）

依據：路線圖 v2 的 M5（對話調試、受限的工具、自然語言生成 DSL、校驗失敗自動修正、選擇器自癒；驗收：助手只改草稿、發布要使用者確認；一句話描述生成可通過驗證的場景）、MVP 原型的助手限制（讀取本場景檔案、觀察本工作階段、編輯草稿、執行候選版、查看本次證據；禁止任意 Shell、讀取其他工作階段、自動發布）。順序已改成 M6 之後；M6 在 PR #21。

**開工前一定要你決定第 1 點**（資料去向是公司規定的問題，不能由我代決定）。其他我推薦第一個選項。

## 開工前需要你決定

1. **模型與資料去向**（必須）：助手會把頁面內容（網址、可存取性樹或 DOM 摘要、選擇器、校驗錯誤，可能還有截圖）送給模型。
   - A. **兩種都支援、由設定選擇**（推薦）：程式只依賴「模型供應者」介面；`anthropic`（Claude API，雲端）與 `openai-compatible`（自架，例如 vLLM、Ollama 跑開源模型）兩種實作；預設關閉，沒有設定就不顯示助手。你只需要決定**公司內部頁面能不能送到外部 API**：能 → 用 Claude；不能 → 給我自架端點的網址與模型名稱。
   - B. 只做 Claude API。
   - C. 只做自架模型。
2. **送給模型的內容**：可存取性樹摘要＋定位器測試結果，**不送截圖**、輸入框的值一律遮罩（推薦）／也送截圖（判斷版面較準，但資料更多）。
3. **金鑰**：放在「登入與憑證」的 Secrets（例如 `ANTHROPIC_API_KEY`），不另做設定頁（推薦）／環境變數。

## 一、套件與元件

- `packages/rpa_generator`（架構文件早就預留）：
  - `Provider` 介面：`complete(messages, tools) → 文字或工具呼叫`；`AnthropicProvider`、`OpenAICompatibleProvider`、測試用 `ScriptedProvider`（照腳本回覆，不連網）。
  - 工具（只有這些，沒有任意 Shell、檔案系統、網路）：
    | 工具 | 做什麼 |
    |---|---|
    | `read_draft` | 讀這個場景最新版本的場景檔（或指定的一段） |
    | `validate` | 用 `rpa validate` 同一套規則校驗一份 YAML，回傳 `--format json` 的問題 |
    | `observe` | 調試工作階段的目前網址、標題、可存取性樹摘要 |
    | `locate` | 測試一個 DSL 定位器：找到幾個、前幾個的文字（沿用 M4 的定位器測試） |
    | `run_step` | 在調試工作階段執行一步；有副作用而且執行過的步驟要使用者在頁面確認 |
    | `save_draft` | 存成這個場景的新版本（草稿），回傳版本號碼；不能發布 |
  - 預算：每次對話最多 N 次工具呼叫與 token 上限；超過就停下來回報。
- `rpa_server`：`/api/assistant/...`（對話、工具執行、紀錄），頁面元件在逐步調試頁與錄製頁。

## 二、流程

1. **一句話生成**（錄製頁新增「用描述產生」）：描述＋起始網址＋選用的登入角色 → 開一個調試工作階段 → 模型用 `observe`、`locate` 看頁面 → 產生 DSL 草稿 → `validate`，有問題就把問題回給模型修正（最多 3 輪）→ `save_draft` 存成新場景 v1 → 使用者在調試頁逐步確認、驗證、發布（同 M4 的門檻）。
2. **對話調試**（逐步調試頁右側「AI 助手」）：使用者描述問題或要改的地方，助手觀察頁面、測試定位器，提出修改（顯示差異），使用者按「套用」才 `save_draft`。
3. **校驗失敗自動修正**：存檔或錄製轉換有校驗問題時，「讓助手修正」把問題（行號、步驟、欄位）交給模型，回傳修正後的草稿差異。
4. **選擇器自癒**：驗證時某一步找不到元素 → 在執行頁按「讓助手找替代定位器」→ 開調試工作階段重播到那一步 → 模型用 `observe`、`locate` 找到候選 → 寫成那一步的 `fallback`（DSL 已有）存成新草稿；一樣要重新驗證、人工發布。

## 三、安全

- 沒有發布工具；草稿一律走 M3 的驗證與發布門檻（驗證的版本必須就是發布的版本）。
- 只能碰這一個場景的草稿與這一個調試工作階段。
- 不送 Secrets 的值；`observe` 的輸入框值遮罩；對話與工具呼叫存在資料目錄 `assistant/<對話>/`（只有本人能讀），可以在頁面查看。
- 助手的輸出是資料，不當成指令執行（頁面內容可能含有誘導模型的文字）。

## 四、測試

- `ScriptedProvider` 照腳本回覆：生成 → 校驗失敗 → 修正 → 存成草稿的完整流程；確認沒有發布、沒有碰其他場景。
- 測試網站上的真實瀏覽器（模型是腳本）：一句話描述「建立一筆標題 X、數量 3 的紀錄並取得紀錄編號」→ 產生的草稿通過驗證。
- 真實模型的驗收手動執行（CI 沒有金鑰、不連外部 API）。

## 五、驗收

- 助手只改草稿：API 與頁面上都沒有發布路徑；測試確認。
- 一句話描述生成可通過驗證的場景（真實模型，手動驗收；自動測試用腳本模型）。
