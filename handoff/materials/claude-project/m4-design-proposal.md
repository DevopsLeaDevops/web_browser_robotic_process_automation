# M4 場景生產與登入：設計提案（2026-10-10，待確認）

依據：路線圖 v2 的 M4（原始錄製稿 → DSL 草稿 → 調試工作階段 → 候選版本驗證 → 人工發布；登入憑證、每個角色獨立的登入狀態、needs_login）、MVP 原型「場景生產」與「建置指引」、M3 延後的入參出參表單編輯。M4 建在 M3（PR #11）之上，**PR #11 合併後才開工**。

驗收：錄製一段操作後，經過調試、驗證、發布並執行成功；兩個角色的登入狀態互不干擾；登入失效時執行停在 needs_login，人工重新登入後可以重跑。

## 開工前需要你提供的資訊（不是選擇題）

1. **目標系統的登入方式**：帳號密碼、公司 SSO、驗證碼、手機或 App 二次驗證？登入狀態大約多久失效？
2. **需要哪些角色**：例如「一般使用者」「主管」，各自用哪個測試帳號（只要名稱，不要密碼）。
3. **管理 Portal 會跑在哪裡**：你自己的電腦（錄製與登入時直接跳出瀏覽器視窗），還是一台遠端主機（要把瀏覽器畫面傳回網頁，工作量大很多）？

## 一、錄製 → DSL 草稿

- 用 **Playwright codegen** 錄製：在 Portal 按「錄製」，伺服器所在的電腦跳出瀏覽器視窗，使用者操作完關掉視窗即結束。也提供 `rpa record 網址` 命令。
- **原始錄製稿**（codegen 產生的 Python）原封保存，只當來源，永遠不會直接發布。
- **轉換器**把常見寫法轉成 DSL：goto、click、fill、press、select、expect，以及 get_by_role／label／placeholder／text／test_id、css、nth、filter(has_text) 定位器。轉不了的行以註解留在草稿裡並列出警告。
- **自動參數化**：每個 fill 的值變成一個入參，預設值是錄到的值，名稱取自欄位的 label 或 placeholder；使用者可以再改名。
- **密碼不落地**：填入密碼欄位的值換成 Secret 引用，原始錄製稿中的值也遮罩後才保存。
- 轉換結果存成場景的新版本（草稿），之後走 M3 的「驗證 → 發布」門檻。

## 二、調試工作階段

- 伺服器啟動一個長時間存在的子程序，握有一個獨立的瀏覽器（在伺服器的電腦上顯示視窗）。
- Portal 的調試頁：步驟清單可以「單步執行」或「執行到這一步」，每一步之後的截圖與頁面網址，**定位器測試**（輸入定位器 → 找到幾個、反白、截圖），右側直接編輯 YAML 並存成新版本。
- 有副作用的步驟不會因為重跑而自動重複，要使用者明確按下。
- 閒置 15 分鐘自動關閉；同一時間每個場景最多一個工作階段。
- M5 的 AI 助手會用同一組操作（觀察頁面、測試定位器、修改草稿）。

## 三、登入與角色

- **角色**：在 Portal 登記角色（id、名稱、目標網址、「已登入」的判斷方式，例如某個元素存在）。場景用 `login: { role: 角色 id }` 宣告要用哪個角色，**一個場景一個角色**。
- **登入狀態**：每個角色一份 Playwright storageState，存在 `data/roles/<角色>/`（檔案權限只限本人；M8 加密）。每次執行開新的瀏覽器上下文並只載入該角色的狀態，角色之間不會混用。
- **人工登入**（預設）：Portal 按「登入」→ 跳出瀏覽器 → 使用者自己完成登入（可處理 SSO、驗證碼、二次驗證）→ 儲存狀態。
- **自動登入**（選用）：適合單純帳密的系統，角色附一段登入步驟，帳密用 Secret（credentialRef），狀態失效時自動重新登入。
- **needs_login**：執行前先檢查是否已登入；沒登入就停在新狀態 `needs_login`，不執行任何有副作用的步驟，Portal 提示重新登入後可一鍵重跑。

## 四、入參與出參的表單編輯（M3 延後）

- 場景頁的入參、出參表格改成可編輯：新增、刪除、改名、型別、預設值、限制、說明、出參的取值。
- 存檔時只替換 YAML 裡 `inputs:`、`outputs:` 兩段（依載入時記下的行號），其他內容與註解保持不變；一樣建立新版本、經過校驗與 409 檢查。

## 五、請確認的決定（我推薦第一個選項）

1. **錄製用 Playwright codegen，在伺服器那台電腦跳出視窗**／把遠端瀏覽器畫面串流進 Portal（伺服器在遠端時才需要，建議放到 M9）。
2. **fill 的值自動變成入參（預設值是錄到的值）**／保留原本的固定值，由使用者自己參數化。
3. **密碼欄位自動改成 Secret，原始錄製稿也遮罩**／原始錄製稿原樣保存。
4. **人工登入為主、自動登入選用**／只做自動登入。
5. **調試工作階段用伺服器電腦上的瀏覽器視窗 + 單步執行與定位器測試 + 截圖**／完整的即時畫面串流。
6. **一個場景一個角色**／一個場景可以切換多個角色。

## 六、測試

- 轉換器：用 codegen 風格的範例檔做單元測試（不需要瀏覽器），包含轉不了的寫法與密碼遮罩。
- 測試網站加上登入頁與兩種角色（看到的資料不同），以及讓登入失效的端點；驗收「兩個角色互不干擾」與 needs_login → 重新登入 → 重跑。
- 調試工作階段：真實瀏覽器，單步執行、定位器測試、閒置關閉。
- 錄製本身需要人操作：自動測試用預先錄好的原始稿走「轉換 → 驗證 → 發布 → 執行」；另外寫一份手動驗收步驟。
