資料目錄裡有什麼、哪些要保留

結構見管理 Portal › 資料
路徑（資料目錄下）內容要不要保留
rpa.dbSQLite：領域、場景、版本、執行紀錄、角色、錄製、序列、遠端 worker（權杖只存雜湊）、設定必須保留，而且要和 scenes/ 一起保留（版本雜湊要對得上，發布門檻才成立）
scenes/<場景>/<版本>/每個版本的場景檔與腳本（不可變）必須保留
runs/<執行編號>/每次執行的報告、截圖、Trace、日誌（遠端執行也上傳到這裡）想保留歷史報告才需要；可以只留近期的
roles/<角色>/state.json角色的登入狀態（只有本人能讀寫；敏感）保留就不用重新登入；不要複製到別處或提交到 git
secrets.jsonSecrets 的值（只有本人能讀寫；敏感）保留；不要提交到 git
recordings/、debug/遮罩過的錄製稿；調試截圖（結束就刪）可選
  • 升級前先備份：停掉 Portal，把整個資料目錄複製一份。Portal 啟動時會自動把資料庫升級到最新的遷移（M9a 是 0007）；倉庫沒有提供降級的命令。
  • 手動改過資料庫或設定嗎：Claude 沒有直接改過你的資料（它碰不到你的電腦）；結構變更都經由 Alembic 遷移 0001～0007。你自己是否改過：需你補充。
  • 已累積的場景與角色：範例領域「測試網站自動化」有 BA-001～BA-005，角色 testsite-user、testsite-manager（第一次啟動時自動匯入）。你自己建立的場景、領域、角色、序列：需你補充（Portal 的「場景管理」「登入與憑證」「自由試驗場」可以看到）。

憑證放在哪裡、怎麼取得

憑證放在哪裡怎麼取得或更換
Secrets（場景與自動登入用的帳密）Portal 的 secrets.json；沒設定的從同名環境變數讀（遠端執行時，從 worker 程序的環境變數讀）Portal「場景管理 › 登入與憑證 › Secrets」設定；值不會再顯示
角色的登入狀態roles/<角色>/state.json；遠端執行時隨任務送到 worker，用完刪除「登入與憑證」按「登入」人工登入，或角色設定自動登入
遠端 worker 的權杖Portal 資料庫只存雜湊；worker 那台放在環境變數 RPA_WORKER_TOKEN 或 --token-file 的檔案「場景生產 › 遠端 Worker」新增時顯示一次；遺失就按「重新產生權杖」
測試網站的示範帳號寫在測試網站的登入頁（不是機密）打開 http://127.0.0.1:8765/login
M5 的模型金鑰尚未使用（提案：放在 Secrets）待 M5 決定
