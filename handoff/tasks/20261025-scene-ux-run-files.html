需求（使用者原文摘要）

  1. 不分端 1：baseUrl 提高優先級：場景頁的「運行設定」放最上面；自主腳本錄製也放最上面。
  2. 不分端 2：每個場景一個「場景詳情頁」：由上到下 運行設定、腳本區（自動化腳本、斷言腳本）、入參與出參、版本、驗證、最近運行；卡片的連結統一跳到詳情頁對應的區域；運行報告不外跳，跳到「最近運行」。
  3. 不分端 3：場景卡片的連結順序：自動化腳本、斷言腳本、入參設定、出參設定、運行報告。
  4. 不分端 4：「完整場景檔」和兩個腳本放在一起、點了外跳回不來；改成在詳情頁另外以外部連結的樣式出現。
  5. 不分端 5：點「專案空間」功能正確，但選單沒有變成藍底的選中狀態。
  6. 錄製端 1：輸入 demo-001 會被自動改成 Demo-001。
  7. 場景運行 1：input.json、output.json、result.json 等檔案中文亂碼（例如「CG-001鑴氭湰鍒涘缓…」）。
  8. 場景運行 2：錄製端、伺服器網站點 video.webm 都不能播放或下載。
  9. 場景運行 3：automation.log 看不懂，要重新設計。
  10. 場景運行 4：運行報告與運行回看重複的話，保留運行報告。
  11. 場景運行 5：運行報告附上錄影回看的連結。
  12. 熱部署：這次能否用更新檔升級，給驗收教學。

進度、決定與下一步

  • 已完成（逐項，原因與做法）：
    1. 起始網址：場景詳情頁第一區是「運行設定」，起始網址（baseUrl）是第一個欄位；自主腳本錄製的「起始網址」移到表單最前面。
    2. 場景詳情頁 /scenes/{id} 改成落地頁：運行設定 → 腳本（自動化腳本／斷言腳本切換，原本的單段編輯頁併進來，一起存成一個新版本：新 API PUT /api/scenes/{id}/sections）→ 入參與出參 → 版本 → 驗證紀錄 → 最近運行；上方固定一排區域連結；同一頁內的 # 連結只捲動、不留下上一頁紀錄。兩個編輯區存檔後互相接著用新版本當基準（避免 409）。舊網址 /scenes/{id}/edit?part=steps|verify 轉到 #steps、#verify。
    3. 卡片連結順序：自動化腳本、斷言腳本、入參設定、出參設定、運行報告，都跳到詳情頁的區域（運行報告 → #runs）；「執行報告」字樣統一為「運行報告」，「執行設定」「最近執行」改為「運行設定」「最近運行」。
    4. 「完整場景檔 ↗」從兩段腳本的分頁移出，放在腳本區右上，以外部連結樣式另開視窗（錄製端在 App 內開新視窗）；完整場景檔頁的「返回場景詳情」回到 #script；版本表的「內容」也另開。
    5. 專案空間選單：伺服器端畫出的選單是對的（有專案時）；找到兩個會標錯的情況並修正：沒有專案時 /workspace 轉到管理後台的專案管理（選單標在管理後台）→ 改成留在專案空間並說明；屬於專案的組合場景畫布與執行頁用 page="playground"（選單跳到場景生產 › 自由試驗場）→ 改成那個專案。使用者看到的是哪一種沒有截圖可確認，人工驗收時確認。
    6. 自動大寫：原因推定為 macOS WKWebView 依系統的「自動將字首大寫」改寫輸入框；portal.js 對所有文字輸入框（含之後才加入的對話框）設定 autocapitalize="off"、autocorrect="off"、spellcheck=false；錄製端與 Worker App 自己頁面的文字欄位也加上。沒有 Mac 可以重現，待人工驗收。
    7. 亂碼：application/json 沒有標 charset，簡體中文系統的瀏覽器用 GBK 讀 UTF-8（「腳本」變「鑴氭湰」）。檔案路由對 JSON 也標 charset=utf-8；順便修正「每個檔案都被快取一天」（原本的判斷恆為真），只有 .webm 快取。
    8. 錄影：執行目錄檔案的 CSP default-src 'none' 沒有 media-src，直接打開 video.webm 時瀏覽器自己的播放頁被 CSP 擋住（Chromium 實測：「violates … default-src 'none'」）。加上 media-src 'self'；檔案清單改成表格：每個檔案一行說明、另開視窗查看、「下載」（download 屬性＋?download=1 回 Content-Disposition: attachment）；影片的檔名連到回看頁。
    9. automation.log：原本只是子程序的標準輸出（DSL 場景只有一行「自動化完成」或一段 Playwright 原文）。新 rpa_runner/steplog.py：開頭說明這份檔案、執行編號、瀏覽器、有頭或無頭、起始網址、開始時間（執行那台的當地時間與 UTC 偏移）；每一步一行（時間、第幾步、名稱與動作、通過或失敗、耗時；打開網頁與出錯時加網址，步驟截圖列檔名）；失敗時寫停在哪一步、略過哪些、證據在哪，最後附完整錯誤原文。網址與錯誤遮罩 Secrets，不寫入參的值。Python 腳本場景的 automation.log 照舊是腳本自己的輸出（#82 另行設計）。
    10. 運行回看清單與運行報告清單重複（同一份運行、同樣的篩選，只差「只列有錄影的」與錄影設定）：移除「場景運行 › 運行回看」選單，運行報告多「錄影：只看有錄影的」篩選與「錄影設定」；/replay 轉到 /runs?video=1（保留其他篩選）。回看頁 /runs/{id}/replay 保留（播放器），麵包屑改成 運行報告 › 這次運行 › 錄影回看。
    11. 回看連結：運行報告清單的「錄影」欄寫成「▶ 回看 mm:ss」；Portal 送出的 report.html 最上面加一列「回到運行詳情」「錄影回看」（檔案本身不改，離線開啟不受影響）。
    12. 熱更新驗收教學：Claude 專案對話裡的文件「v0.6.1 熱更新驗收指引」（前提、發版、升級伺服器、裝置跟著更新、12 項驗收清單、出問題時）。這次沒有改 Python、第三方套件、打包設定或 rpa_update，環境代號不變，可以用更新檔；沒有資料庫遷移。
