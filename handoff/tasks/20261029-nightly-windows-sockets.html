原因（issue #99：run 40581792306，2026-10-27 13:51 America/Los_Angeles（PDT，UTC−07:00），main 30f2290）

  • Ubuntu 3.13 第 2／3 遍：test_replay_flow.py::test_replay_switches_pages_and_returns_to_main 的「Target page, context or browser has been closed」。點了執行 window.close() 的按鈕，Playwright 在點擊收尾時才發現頁面已關。產品的問題，PR #101（e61d8d5）已修。
  • macOS 3.13（Firefox）：test_portal.py::test_create_validate_publish_run_report 等不到「發布」。驗證通過已提交、驗證紀錄還沒寫的空檔。產品的競態，PR #101（ef728bb）已修。PR #101 於 2026-10-28 02:06 America/Los_Angeles（PDT，UTC−07:00）合併；10-28 的排程（run 40767854003，main b559285，含 PR #101）Ubuntu、Windows 都通過，macOS 沒有排到機器，所以 macOS 上還沒有在排程裡驗證。
  • Windows 3.13 第 3 遍：packages/rpa_runner/tests/test_login.py::test_capture_saves_only_a_verified_state[chromium]，_verify 開第二個瀏覽器打開確認網址時 Page.goto: net::ERR_NO_BUFFER_SPACE（Windows 的 WSAENOBUFS，10055：建立連線時系統的連接埠／socket 資源用完）。判斷是 CI 機器的環境：同一個子程序幾秒前才用第一個瀏覽器打開同一個網址（才發出 ready），網站沒開會是 ERR_CONNECTION_REFUSED；前兩遍與 10-28 都通過；之前 8 次失敗的排程（2026-10-22～26，issue #74、#80）都沒有這個錯誤；發生在連跑約 50 分之後。Windows 的動態連接埠預設 49152～65535（16384 個），連線關閉後要等 TIME_WAIT 才放回去。產品在 Windows 用 taskkill /T 結束程序樹，測試沒有直接殺子程序，沒看到會留下瀏覽器的寫法。日誌與產物下載不了，不能確定用完的是連接埠還是其他 socket 資源：所以同時放大範圍與加上診斷。
  • macOS 桌面 App（程式碼層）兩個工作：「The job was not acquired by Runner of type hosted even after multiple attempts」，GitHub 的 macOS arm64 容量不足（2026-10-22 14:13 America/Los_Angeles（PDT，UTC−07:00）的排程 run 39855480410 也有）。代碼修不了。
  • 漏報：10-28 的 run 40767854003 只因 macOS 完整測試排不到機器而失敗；那個 job 的結論是 cancelled，「失敗時開 issue」的 failure() 不成立而略過，issue #99 沒有收到留言。
