進度、決定與下一步

  • 現況（main 9dc68be）：沒有畫面時「開始錄製」已停用，但只有頁面上方的說明、沒有滑鼠提示；逐步調試仍可用無頭模式開始，而 setup-linux.sh 裝的伺服器沒有下載瀏覽器，無頭調試其實也跑不起來；場景卡片與場景頁的「調試」照常是連結。
  • 401 的原因（已向使用者說明）：錄製的起始網址填了 http://215.192.222.14:8081/（伺服器的對外埠）。錄製開的是全新的瀏覽器，沒有錄製端的權杖，對外埠回 recorder_unauthorized。起始網址要填被測試的網站，例如錄製端自己的測試網站 http://127.0.0.1:8765/。
  • 決定：
    • （使用者 2026-10-20 00:29 PDT，已確認）照 Claude 的建議改上面兩項。
    • （使用者 2026-10-20 00:29 PDT，已確認）錄製端不執行場景：錄製端只負責錄製、逐步調試、人工登入，執行仍交給伺服器或 Worker（維持 ADR 0014 的分工）。
    • （實作選擇）「自主腳本錄製」這一頁照樣能進入，因為「貼上錄製稿」不需要畫面；只有「開始錄製」變灰。
    • （實作選擇）逐步調試只改頁面，API 仍接受無頭模式。
  • 另外提醒使用者（不在這個任務）：使用者用 nohup … rpa serve --host 0.0.0.0 --port 8080 啟動，管理頁面沒有登入保護，伺服器是公網 IP；已建議改回 --host 127.0.0.1（或直接用 .venv-server/bin/rpa-server／systemd），從 Mac 用錄製端或 SSH 通道操作，並把 8081 的防火牆限制在自己的 IP。
  • 下一個具體動作：使用者審閱並合併 #47；合併後在 Linux 伺服器 git pull、重新啟動，照下方「人工驗收」做一次。
  • 人工驗收（未執行）：(1) 用 SSH 通道從 8080 打開伺服器的 Portal：場景卡片與場景頁的「逐步調試」、錄製清單與錄製詳情的「調試」、調試頁的「開始調試」、「開始錄製」、角色的「登入」都是灰的，滑鼠移上去有提示；「貼上錄製稿」可以用。(2) 透過 Mac 的錄製端打開：都照常可用。(3) 錄製的起始網址填 http://伺服器:8081/：「開始錄製」顯示「是管理 Portal 自己的位址」；改填 http://127.0.0.1:8765/ 可以錄製。
