進度與發布順序

  1. 使用 tools/release_version.py bump 0.4.0 統一版本；完成版本、安裝檔與建置資訊的測試，建立版本 PR。
  2. PR 的桌面端 CI 先產生 0.4.0 安裝包，可供試用。這些是 PR 產物，正式 Release 會從 main 的標籤重新建置。
  3. 使用者合併版本 PR 後，核對 main 的版本與 CI，在該提交建立並推送 v0.4.0；依 發布流程產生草稿 Release。
  4. 把本頁的已知問題補到 Release 說明，確認三個安裝包、SHA256SUMS.txt 與版本，再由維護者發布。
  5. 升級 Linux 伺服器與桌面端到同一版。停止服務後備份實際資料目錄，再更新至 v0.4.0、執行 scripts/setup-linux.sh 並依原有參數啟動；0013 錄影資料庫遷移由伺服器啟動時執行。Windows／macOS 安裝對應 0.4.0 套件，重新連線並核對裝置版本。

使用者已確認：先交付新版本，錄影問題另修；不把延後處理寫成已修復或人工驗收通過。PR 合併仍由使用者操作。
