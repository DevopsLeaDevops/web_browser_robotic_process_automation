為什麼是 v0.7.0

  • 不是 0.6.4：有新功能，不只是修正。新的場景寫法（upload 步驟、type: file 入參，裝置的 DSL 擴充多了 upload、fileInputs）、資料庫遷移 0017_uploaded_files、新 API（/api/files、Agent API 的 files:write、匯總報告與合併回看）、Worker 任務的 inputFiles。前例：0.5.0 是多個功能 PR 一起發；0.6.1～0.6.3 只有修正。
  • 不是 1.0.0：還沒有使用者權限（M8），上傳的檔案能進 Portal 的人都看得到；這批功能還沒人工驗收。
  • 升級只要更新檔：#97 的 CI 比對過環境代號都和 v0.6.3 相同：server-linux-x64 b93be424f1f8ff3a、recorder-macos-arm64 cd64b7d227542315、worker-windows-x64 e4985fdde881ea71；錄製端與 Windows Worker 也用快取的外殼加上新程式碼層跑過自我測試與端到端。linux-arm64 與 Worker（macOS）看發布流程的 Release 說明。沒有新的第三方套件。
  • 先草稿、後發布：Worker 與錄製端的新程式只能由伺服器發簽過正式金鑰的更新檔，所以要先有草稿 Release 才能驗收。驗收沒過就不發布，修好出 v0.7.1。
