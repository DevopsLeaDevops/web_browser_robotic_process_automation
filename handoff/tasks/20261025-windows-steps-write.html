進度、決定與下一步

  • 原因：子程序每一步都用 files.write_json 寫 steps.json（先寫暫存檔再 replace）。Windows 上目標檔被別的程序開著時（Python 的 open 不帶 FILE_SHARE_DELETE），改名丟 PermissionError（WinError 5），例外從 on_progress 傳上去，子程序以 EXIT_FAILED 結束。讀取的一方：test_cancelled_run_keeps_a_playable_video 每 0.1 秒讀進度；伺服器回看（rpa_server/replay.py）也讀執行中的 steps.json，所以 Windows 本機執行時有人在看進度也可能讓執行失敗。CI 日誌只有 'failed' == 'cancelled'，沒有子程序的錯誤訊息；這個原因是推斷，由新的 Windows 測試先確認「開著時改名真的會失敗」。
  • 已完成：Windows 上改名遇到 PermissionError 時每 20 毫秒重試，最多 50 次（約 1 秒）後照舊丟出；其他系統不重試（那是真的沒有權限）。測試：Windows 上另一個執行緒開著目標檔 0.2 秒，先確認直接改名會失敗，再確認 write_json 成功；重試上限與「其他系統不重試」各一個測試。錄影取消、逾時測試的狀態斷言附上 result.error，下次失敗能看到原因。
  • 決定（實作選擇）：Windows 專用的測試不需要瀏覽器，PR 上的「Worker 測試（Windows）」只跑瀏覽器測試，所以加進桌面端建置（desktop.yml）Worker 的單元測試清單，和 test_commands.py 一樣在 PR 上的 Windows 跑；每晚完整測試也會跑。
  • 未完成／阻礙：無。取消測試本來就偶爾失敗，一次通過不能證明不會再失敗；之後失敗時斷言會附上子程序的錯誤訊息。
  • 下一個具體動作：使用者審閱、合併 PR #84；合併後 PR #83 從 main 更新再跑 Windows 檢查。
  • 未提交／stash／ignored 產物：無；.venv 可用 uv sync --locked 重建。
