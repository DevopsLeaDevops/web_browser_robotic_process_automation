設計與實作摘要

完整內容見 設計：對外 Agent API、ADR 0017 與 Agent 使用指南。

  • 架構：對外埠（預設 8081）新增 /agent-api/v1，每個 Agent 系統一個「API 用戶端」，Authorization: Bearer 金鑰只存雜湊。Agent 只連伺服器；錄製端與 Worker 照舊經 Client API、Worker API 主動連進來。新路由只轉接 Services，業務規則與發布門檻不變。不直接開放 /api。
  • 指定錄製端：依 recorderId 用 use_recorder(…) 設定目前的錄製端，DebugManager 與 RecorderHub 幾乎不用改。錄製端加「允許 Agent 調試」「只允許無頭」開關，預設關閉；場景已有別人在調試時回 409 debug_in_use，不搶走；Agent 只看得到自己開的工作階段。
  • 權限範圍：scenes:read、scenes:write、debug、runs:validate、scenes:publish（預設不勾）、runs:execute、runs:read；另有可用領域、錄製端、執行位置與 Worker、限額（預設 2 個調試、20 個排隊，超過回 429）、回傳頁面內容（預設關，關閉時回 403 content_disabled）、到期與來源 IP。每個寫入請求寫稽核紀錄。
  • 讀頁面結構（第一期）：調試子程序加 snapshot 命令：無障礙樹、表單欄位、iframe 與分頁，值遮罩，可帶 within，過大時截斷並標 truncated。錄製端上線時回報 debugSnapshot，舊版回 422 recorder_outdated（沿用 M7a 的狀態碼）。要出新版錄製端 App。
  • 運行過程：第一期 GET /runs/{id}、列表、結束後的步驟與產物。第二期 steps.json 經心跳回報步驟進度、run_events 長輪詢、Webhook（HMAC）、錄製端的 Agent 通知。
  • 專案（2026-10-23 晚加入）：另一個模組 agent_projects.py：專案的列出、新增、修改；組合場景用代號指定，建立、存版本（baseRevision，409 stale_workflow）、移到另一個專案、檢查定義、驗證、發布、執行；POST /projects/{id}/runs 把專案裡的組合場景逐一排入，排不進去的列在 skipped；/composite-runs 讀狀態、進度與每個節點的運行，取消自己的、重跑（可從停下的節點繼續）。權限範圍多 projects:read（新用戶端預設勾）、projects:write、projects:publish（預設不勾）；用戶端多「可用的專案」，限定時不能新增專案。組合場景要在可用的專案與領域，節點的場景也要在可用的領域；不屬於任何專案的不給 Agent。回應帶 portalPath 給人看同一筆資料。
  • 測試方案與測試報告（文件，不是平台功能）：測試方案指南教 Agent 用 TestCase 方法設計（一個組合場景就是一個 TestCase，測試資料寫在定義裡），交出 test-plan.md、test-plan.xmind、test-plan.json；測試報告指南教 Agent 執行、跟蹤、判定結果、回溯到每一步，交出 test-report.md、.json、結果的 XMind 與證據資料夾。XMind 同時寫 content.json 與 content.xml，範例程式已用 xmind2testcase 1.5.0 與 xmindparser 1.2.2 讀回確認；沒有用 XMind 軟體打開過。
  • 冪等與稽核：驗證、執行、重跑的 idempotencyKey 加上用戶端雜湊後存在運行紀錄；建立場景與存版本的放在伺服器記憶體 24 小時。稽核是子應用的 ASGI 中介層，每個非 GET 請求一筆，管理後台只能看。
  • 資料庫：第一期遷移 0016_agent_api（接在 #78 的 0015_projects 後面）：api_clients（含 projects）、api_audit、runs.client_id、workflow_runs.client_id、recorders.allow_agent／agent_headless_only；第二期 run_events、runs.step_index／step_count。只用通用型別（ADR 0008）。
  • 分期：第一期 Agent 可從空白走到正式執行，含讀頁面結構；第二期即時步驟進度、事件、Webhook、錄製端通知；專案與組合場景已併入第一期；第三期剩請人登入的流程。不做 MCP。
