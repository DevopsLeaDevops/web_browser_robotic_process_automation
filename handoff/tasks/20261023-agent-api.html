設計摘要（建議，未確認）

  • 架構：對外埠（預設 8081）新增 /agent-api/v1，每個 Agent 系統一個「API 用戶端」，Authorization: Bearer 金鑰只存雜湊。Agent 只連伺服器；錄製端與 Worker 照舊經 Client API、Worker API 主動連進來。新路由只轉接 Services，業務規則與發布門檻不變。不直接開放 /api：它沒有認證、跟著 Portal 介面改動。
  • 指定錄製端：現在互動子程序開在「請求經過的那台錄製端」（rpa_server.context）。Agent API 依 recorderId 用 use_recorder(…) 設定目前的錄製端，DebugManager 與 RecorderHub 幾乎不用改。錄製端加「允許 Agent 調試」「只允許無頭」開關，預設關閉；場景已有人在調試時回 409，不搶走。
  • 權限範圍：scenes:read、scenes:write、debug、runs:validate、scenes:publish、runs:execute、runs:read；另有可用領域、錄製端、執行位置與 Worker、限額、回傳頁面內容、到期與來源 IP。每個寫入請求寫稽核紀錄；版本說明與運行紀錄標出用戶端。
  • 端點：探索（/meta、/dsl/schema、/dsl/check、領域、角色、Secrets 名稱、錄製端、Worker）；場景與版本（建立、讀、存新版本帶 baseRevision、段落、入參出參表格、匯入 Playwright 腳本）；調試（開工作階段帶 recorderId、執行一步、執行到、定位器、截圖、第二期的頁面結構 snapshot、換版本、重來、結束）；驗證、發布、執行、取消、重跑（加 workerId，對應內部的 required_worker）。會建立東西的 POST 都接受 idempotencyKey。
  • 運行過程：第一期 GET /runs/{id}、列表、結束後的步驟與產物。第二期：子程序每一步已寫 steps.json，本機 worker 讀檔、遠端 Worker 在心跳附上目前步驟並在變化時立即送出；新表 run_events，GET /runs/{id}/events?after=&wait= 長輪詢；Webhook（HMAC 簽章、重試）。舊版 Worker 只有階段進度。
  • 資料庫：api_clients、api_audit、runs.client_id、recorders.allow_agent／agent_headless_only（第一期）；run_events、runs.step_index／step_count（第二期）。只用通用型別（ADR 0008）。
  • 分期：第一期只改伺服器，Agent 可從空白走到正式執行；第二期即時步驟進度、事件、Webhook、頁面結構、錄製端的 Agent 通知（要更新 App）；第三期專案（組合場景）執行、請人登入、MCP 轉接。
