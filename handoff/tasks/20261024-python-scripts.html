0. 一頁摘要

  • 新的場景種類「Python 腳本場景」。一份 scenario.yaml 加幾支 .py：入參、出參、Secrets、總期限與獨立斷言 verify 都和 DSL 一樣；python: 區塊指出自動化腳本。不開瀏覽器、沒有登入角色。運行報告的格式（result.json、steps.json、facts.json、output.json）也一樣。
  • 舊的「Python 自己呼叫 Playwright」改叫「Playwright 腳本場景（已封存）」。寫一份封存文件；不能再新建；既有的照常執行、不加功能；範例移到測試資料。錄製網頁、把 Playwright 錄製稿轉成 DSL 都不受影響。
  • RPA Python 運行環境。倉庫裡定義一份清單（Python 3.13＋處理 Excel、Word、PDF、資料的常用套件，版本與雜湊鎖死），CI 為每個系統建好、測過，放進 Worker App、錄製端 App 與 Linux 分發包。第一次用到時解壓到快取資料夾（實測 2.4 秒），之後直接沿用；不碰電腦上的 Python，也不在 Worker 上安裝套件，所以不會遇到版本或套件裝不起來的問題。
  • 腳本介面 rpa_script。with run.step("merge", "合併報表"): 標出步驟、run.facts 寫事實、run.output_dir 放產出檔案（報告裡可以下載）、run.preview() 留一份資料預覽、run.watch() 記下資料夾的檔案變化。
  • 錄製改成「腳本工作台」。本機操作 Excel 沒有可以錄的畫面，也沒辦法跨系統錄桌面；工作台讓作者拿範例檔案一格一格執行程式或套用範本（合併 Excel、轉 CSV、合併 PDF…），每一格就是一步，選中的值可以「改成入參」「記成事實」「加成斷言」，從頭重跑通過後存成場景。工作台也是腳本的調試工具。
  • 運行過程：入參 → 運行環境 → 自動化 → 斷言 → 出參 → 上傳，照 ADR 0009；路徑是 Worker 上的路徑，所以可以指定由哪一台 Worker 執行。
  • 報告與回看：報告列出步驟、事實、斷言、出參、產出檔案、檔案變化、資料預覽、主控台與運行環境；回看是步驟時間軸的播放器，失敗的運行打開就停在失敗的步驟。
  • 分五期交付（第 12 節）：P0 封存 → P1 運行環境＋模型＋運行 → P2 報告＋回看 → P3 腳本工作台 → 之後的擴充。

4. 場景模型：沿用現有的契約

Python 腳本場景是 DSL 場景的同類：同一份 scenario.yaml、同一套入參與出參、同一個發布門檻；差別只在「自動化」那一段是 Python，而且不開瀏覽器。schemaVersion 維持 1，python: 是增加的欄位，舊場景不用改，雜湊也不變。steps、script（已封存）、python 三擇一。

# scenes/merge-monthly-sales/revisions/1/scenario.yaml
schemaVersion: 1
id: merge-monthly-sales
name: 合併每月各分店銷售報表
category: 報表
inputs:                                    # 入參：和 DSL 相同（型別、限制、動態值）
  sourceDir: { type: string, format: directory, description: 各分店報表所在的資料夾（執行的 Worker 上） }
  targetDir: { type: string, format: directory, description: 合併後的報表放到哪裡 }
  month: { type: string, pattern: '^\d{4}-\d{2}$', default: '{{today:yyyy-MM}}' }
  sheet: { type: string, default: 銷售 }
outputs:                                   # 出參：和 DSL 相同，from 取自事實
  rowCount: { type: integer, minimum: 1, from: '{{ facts.merge.rowCount }}' }
  total: { type: number, from: '{{ facts.merge.total }}' }
  outputFile: { type: string, from: '{{ facts.merge.outputFile }}' }
deadline: 600000                           # 總期限，和 DSL 相同（上限 1 小時）
python:
  runtime: "1"                             # 用哪一個主版本的 RPA Python 運行環境（第 5 節）
  automation: automation.py                # 自動化腳本
  files: [helpers.py, templates/summary.xlsx]   # 選用：腳本會用到的其他檔案（可以是二進位）
  platforms: [windows, macos, linux]       # 選用：只在這些系統執行；沒寫是不限
verify:                                    # 獨立斷言：和 DSL 完全相同（也可以改用 python.assertion）
  - name: 至少讀到一份分店報表
    value: '{{ facts.merge.fileCount }}'
    matches: '^[1-9][0-9]*$'
  - name: 產出檔名有月份
    value: '{{ facts.merge.outputFile }}'
    contains: '{{ inputs.month }}'

自動化腳本DSL 的 steps:；卡片與場景頁的「自動化腳本」python.automation 指的 .py；同一個「自動化腳本」入口改成編輯這支檔案（和 files 裡的 .py）。腳本負責處理檔案、把結果寫成事實 facts，不判定成功。
斷言verify:（獨立斷言，「斷言腳本」入口）預設就是 verify:，編輯器、檢查方式、報告完全相同。需要程式判斷時（例如重新打開產出的 Excel 核對總額）改用 python.assertion 的 .py，兩者二擇一；有出參就必須有其中一個（ADR 0009 不變）。
入參inputs:：型別、限制、預設值、動態值；開始前校驗完全相同，另加選用的 format: directory／file：在 Worker 上執行前先檢查路徑存在而且讀得到，執行表單提示「執行的 Worker 上的路徑」。腳本從 run.inputs 讀到校驗後的值（和 input.json 同一份）。
出參outputs:＋from；獨立斷言通過後才發布完全相同；用 assertion.py 時由它回傳候選出參、不寫 from（現有規則）。產出的檔案不是出參，而是附件（第 9 節）；出參可以回傳檔名或路徑，串給下游場景。
運行報告執行目錄：input.json、facts.json、steps.json、output.json、result.json、report.html同一份格式；steps.json 由腳本介面寫，多出的檔案（產出檔案、檔案變化、資料預覽、主控台、運行環境）都是增加的（第 9 節）。

校驗規則（rpa validate、Portal 存檔、rpa pack check 相同）

  • python 場景不能有 browser、login；defaults.timeout 是每一步的預設逾時（沒寫就只受總期限限制）。
  • runtime 是這版伺服器認得的主版本（目前只有 "1"）。platforms 是 windows、macos、linux 的子集。
  • assertion 與 verify 恰好一個（沒有出參時兩個都可以不寫，和 DSL 一樣）；verify 與 outputs.from 只能引用 inputs、secrets、facts、env。腳本會寫出哪些事實在校驗時看不出來，所以不檢查事實的名稱，執行時找不到就在那一條斷言報「沒有這個事實」。
  • 路徑都相對於場景檔的資料夾，不能用 .. 或絕對路徑；automation、assertion 沿用 ScriptPath 的規則，files 可以是任何副檔名。最多 50 個檔案，單一檔案 1 MB 內（git 推送的上限，ADR 0015）。
  • 每支 .py 在存檔時以 Python 3.13 的語法檢查，錯誤指出檔案與行號；同時檢查 import：不是標準函式庫、運行環境的套件、rpa_script 或場景自己的 .py 時提醒「RPA Python 運行環境 1 沒有 xxx」（伺服器帶一份運行環境的套件與模組清單），在存檔時就發現套件問題，而不是到 Worker 上才失敗。

雜湊與檔案

  • scenario_sources 對 python 場景依序是場景檔、automation、assertion（有寫才加）、files。沒有 python 的場景，檔案清單與雜湊完全不變（ADR 0015）。
  • 運行環境不算在場景的雜湊裡（它是 Worker 的一部分，就像瀏覽器版本）；驗證紀錄與每次執行都記下實際用的運行環境版本，報告看得到「驗證時 1.2.0、這次 1.3.0」。
  • 伺服器的場景種類多一個 kind="python"（介面「Python 腳本場景」、卡片標「Python」）；場景清單、運行報告可以依種類篩選。

5. RPA Python 運行環境

平台自己建置、自己測試的一套 Python：一個 python-build-standalone 直譯器，加上固定的一組套件，所有 Worker 用的是位元組都相同的同一份。它就是使用者說的「專門構建的虛擬運行環境」：和電腦上的 Python、Worker App 自己的 Python 都分開；Worker 上不安裝、不升級任何套件，所以三台電腦不會因為各自的版本與套件而結果不同。

6. 腳本介面 rpa_script

新套件 packages/rpa_script（套件名稱 rpa-script），只用標準函式庫，裝在運行環境裡。它負責腳本與平台之間的一切：讀入參與 Secrets、記錄步驟、寫事實、產出檔案、資料預覽、檔案變化、主控台輸出與錯誤。腳本不寫讀參數、寫結果的樣板。

# automation.py（工作台產生，之後可以手改）
import shutil
from pathlib import Path

import pandas as pd

from rpa_script import Run, StepError, automation


@automation
def main(run: Run) -> None:
    source = Path(run.inputs["sourceDir"])
    month = run.inputs["month"]
    run.watch(run.inputs["targetDir"], "目標資料夾")  # 報告與回看列出這個資料夾的檔案變化

    with run.step("find", "找出這個月的分店報表"):
        files = sorted(source.glob(f"*{month}*.xlsx"))
        if not files:
            raise StepError(f"{source} 沒有 {month} 的報表")  # 只顯示訊息，不顯示呼叫堆疊
        run.log(f"找到 {len(files)} 個檔案")

    frames = []
    for path in files:
        with run.step("read", f"讀取 {path.name}"):  # 迴圈裡同一個 id，報告顯示第 n 次
            frames.append(pd.read_excel(path, sheet_name=run.inputs["sheet"]).assign(分店=path.stem))

    with run.step("merge", "合併並計算總額"):
        merged = pd.concat(frames, ignore_index=True)
        run.preview("合併結果", merged)  # 報告與回看顯示前 50 列

    with run.step("write", "寫出合併報表"):
        name = f"銷售合併-{month}.xlsx"
        merged.to_excel(run.output_dir / name, index=False)  # output_dir 的檔案成為產出檔案
        target = shutil.copy2(run.output_dir / name, run.inputs["targetDir"])  # 最後才放到目標資料夾
        run.facts["merge"] = {
            "fileCount": len(files),
            "rowCount": len(merged),
            "total": float(merged["金額"].sum()),
            "outputFile": str(target),
        }
介面說明
@automation標出進入點。平台以 python -E -s -X utf8 -m rpa_script automation automation.py --session session.json 載入並呼叫它。一支檔案只能有一個。
run.inputs、run.secrets運行態入參（唯讀，和 input.json 同一份）；場景 secrets 宣告的 Secrets（例如加密 Excel 的密碼）。Secrets 經由標準輸入交給腳本，不寫進檔案、不放環境變數；它的值出現在主控台、錯誤、步驟名稱、資料預覽時自動遮罩。
run.facts事實（可以轉成 JSON 的 dict），結束時寫成 facts.json；失敗時也寫出已經有的部分。
with run.step(id, name=None, *, timeout=None)標出一步：開始與結束的時間、結果、錯誤、原始碼行號、這一步寫入的事實。id 的格式同 DSL；迴圈裡重複的 id 記成同一步的第 n 次；可以巢狀（報告縮排顯示，回看的時間軸畫最外層）。逾時（這一步的、defaults.timeout 或總期限剩下的時間，取最小）由背景的看門狗處理：記下逾時、寫出步驟與事實，再結束程序。
run.output_dir、run.attach(path, name=None)產出檔案的資料夾：裡面的檔案在結束後上傳，報告可以下載（每次合計 200 MB 內，D9）；attach 把其他地方的檔案複製進來。
run.work_dir這次運行的暫存資料夾，也是腳本的工作目錄；暫存檔也放這裡（TEMP、TMPDIR 指到它），結束後刪除。
run.watch(path, name)記下這個資料夾在每一步前後的檔案變化（新增、修改、刪除；名稱、大小、修改時間），output_dir 與 work_dir 自動記。最多 5000 個檔案，超過就只記數量。
run.preview(name, value)留一份資料預覽：pandas DataFrame、list、openpyxl 的工作表、.xlsx／.csv 檔的路徑（第一個工作表）或文字。只存前 50 列、30 欄，每格 200 字。只有腳本呼叫時才有。
run.log(訊息)、print()都進主控台輸出，記下時間與當時的步驟（console.jsonl，上限 5 MB）。
StepError(訊息)預期中的失敗（找不到檔案、資料格式不對）：報告只顯示訊息。其他例外顯示訊息與呼叫堆疊（只保留場景自己的檔案的那幾層）。
run.remaining_ms、run.platform、run.runtime、run.lang總期限剩下的毫秒；windows／macos／linux；運行環境版本；介面語言。
  • 步驟以外的程式照樣執行；在步驟外拋出的錯誤記成一個失敗的「步驟外的程式」，附行號。
  • 結束碼：0 成功、1 自動化失敗、3 逾時（同 DSL）、2 腳本載入失敗（語法錯誤、沒有 @automation）。
  • 本機試跑：rpa run 場景檔 -i sourceDir=… 用同一套運行環境；Portal 可以下載 rpa-script 的 wheel 與型別檔，讓作者的編輯器有提示。

獨立斷言用 Python 時（assertion.py，選用）

from pathlib import Path

from openpyxl import load_workbook

from rpa_script import Check, assertion


@assertion
def check(c: Check) -> dict[str, object]:
    merge = c.facts["merge"]
    sheet = load_workbook(c.output_dir / Path(merge["outputFile"]).name, read_only=True).active
    c.equals("產出檔案的列數和事實相同", sheet.max_row - 1, merge["rowCount"])
    c.true("總額大於 0", merge["total"] > 0)
    return {"rowCount": merge["rowCount"], "total": merge["total"], "outputFile": merge["outputFile"]}
  • 在另一個程序執行，只讀入參、事實與產出檔案（唯讀），不能改檔案。每一條 equals、contains、matches、not_empty、true 都記成一條斷言結果，和 DSL 的 verify 同一個格式，報告與回看的「斷言」完全一樣。
  • 回傳的 dict 是候選出參，照舊經過出參校驗才發布。

7. 腳本錄製：腳本工作台

網頁的錄製是錄瀏覽器裡的操作；本機自動化沒有這樣的畫面可以錄。錄 Excel 或檔案總管的滑鼠鍵盤既做不到跨系統（Linux 沒有 Excel，三個系統的桌面介面都不同），錄到的東西也很脆弱。所以這裡的「錄製」是錄下作者實際跑過、確認可行的每一步：作者拿範例檔案在工作台裡一格一格執行，每一格就是一步，執行結果馬上看得到；存檔時把這些步驟寫成 automation.py 與 scenario.yaml。

  1. 「場景生產」多一個「腳本工作台」（在「自主腳本錄製」旁邊）：新建，或打開既有的 Python 腳本場景的某一版，或匯入一支 .py。選擇在哪裡執行（錄製端 App 或伺服器本機，D8）。
  2. 左邊是入參：名稱、型別、試跑值。路徑的試跑值用資料夾選擇器挑那台電腦上的範例資料夾。
  3. 中間是一格一格的步驟：每一格有步驟名稱與程式，可以從範本插入（見下表），也可以直接寫。按「執行」只執行這一格，下面顯示主控台輸出、最後一個運算式的資料預覽（DataFrame 是表格）、檔案變化、耗時與錯誤。前面各格留下的變數都還在，可以反覆修改、重跑這一格。
  4. 右邊是變數、事實與檔案。選中程式裡的一個值或一個變數，可以「改成入參」（換成 run.inputs["…"]，加一個入參，原值成為試跑值）、「記成事實」（加一行 run.facts[…] = …）、「加成斷言」（依目前的值建議 equals／matches／notEmpty）、「加成出參」（from 取這個事實）。
  5. 「從頭重跑」：重新啟動、依序執行所有格，確定腳本不靠工作台裡殘留的狀態。存檔前沒有從頭重跑通過會提醒。
  6. 「存成場景」：每一格寫成一個 with run.step(…)，加上入參、出參、斷言，存成新場景的 v1 或既有場景的新版本；之後照舊交給 Worker 驗證、人工發布。

  • 執行的地方：工作台是運行環境裡一個常駐的 Python 程序（python -m rpa_script workbench），一行一個 JSON 命令與回覆，和現在的逐步調試子程序（rpa_runner.debug）同一種做法；在錄製端時經由 Client API 交給錄製端 App（錄製端可以執行的模組多一個 rpa_script，只用伺服器送來的程式）。用的是和 Worker 同一版的運行環境，所以工作台跑得通的，Worker 上也跑得通。
  • 在 Worker 上開工作台等於在那台電腦遠端互動地執行程式、讀它的檔案，所以預設不允許，要 Worker 的「設定」打開「允許腳本工作台」才可以（D8）。
  • 中斷：一格執行太久可以「停止」：結束程序並重新啟動，畫面說明之前的變數已經不在，要從頭重跑（Windows 不能可靠地中斷執行中的 Python）。每一格預設 5 分鐘上限。
  • 存什麼：工作台的草稿（每一格的名稱與程式、入參與試跑值、執行的地方）自動存在伺服器；資料預覽、主控台與產出只在畫面上，關掉就沒有。範例檔案留在那台電腦，只有畫面上看的預覽經過伺服器。
  • 打開既有的腳本：用 ast 解析 @automation 函式，最外層的每個 with run.step 成為一格，前面的程式成為「準備」格；結構不是這樣的腳本整份當成一格，照樣能執行、修改、存檔。
  • 也是調試工具：打開某一版、填入參，一格一格執行，就是 Python 腳本場景的逐步調試；卡片的「調試」對 Python 腳本場景打開工作台。
  • 以後：M5 的 AI 可以在工作台裡「用一句話產生這一格」；這次不做。

13. 沒有選的方案

方案為什麼不選
第一版的三層環境：每個場景自己鎖定套件，Worker 用 uv 現場安裝每個場景、每台 Worker 的套件組合都可能不同，Worker 還要連得到套件來源——正是使用者要避免的版本與倚賴問題。保留成「之後」的可能（D4 的其他選項）。
用電腦上已裝的 Python、conda每台的版本與套件不同，結果不一致；Windows 常常沒有，macOS 的系統 Python 會跳出安裝開發工具。
用 Worker App 自己打包的直譯器（rpa-child）PyInstaller 打包的直譯器不能加套件，能用什麼取決於 App 剛好帶了什麼，App 升級就可能變。
Docker 或虛擬機Windows、macOS 的桌面不一定有；Worker 上的路徑要另外掛載；太重。
