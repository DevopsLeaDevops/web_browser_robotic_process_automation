Python 節點（第三版：統一的 Python 節點）

現有的 Python 腳本場景（script:）演進成統一的「Python 節點」：同一份場景契約、同一個發布門檻，可以單獨執行，也可以和瀏覽器場景串在同一個組合場景裡，補上瀏覽器做不到的檔案操作、資料處理、網路操作與（之後的）模型構建。加了 runtime 的節點跑在平台專門建置的「RPA Python 運行環境」，不開瀏覽器；沒有 runtime 的舊腳本照原來的方式執行，不封存。第一～第二版的內容分別留在 3c7df35、e5b585e。

0. 一頁摘要

  • 一種 Python 節點，兩種模式。場景檔寫 script:。寫了 runtime: "1" 是運行環境模式：跑在 RPA Python 運行環境，不開瀏覽器、不需要 Worker 有瀏覽器；沒寫是相容模式：和現在完全一樣（App 內的 Python，可以自己用 Playwright）。既有場景的雜湊不變、不用重新發布。
  • 契約不變。兩種模式都是 automation.py --input --facts --screenshot --target-url 寫事實、獨立斷言判定、出參校驗後才發布。運行環境模式另外可以用 DSL 的 verify 取代 assertion.py。
  • 組合場景裡的資料與檔案。同一次組合運行的節點本來就在同一台 Worker；再加一個共用工作資料夾 RPA_WORKSPACE（運行結束就清）、array／object 入參（結構化資料可以往下傳）、file 出參（接到 DSL 的上傳入參）、DSL 的 download 步驟（網頁下載的檔案交給 Python 節點）。
  • RPA Python 運行環境沿用第二版的設計：固定的 Python 3.13 與套件（Excel、資料、文件、網路），CI 建置測試，附在 Worker App 與 Linux 分發包，第一次解壓、之後沿用。
  • rpa_script：with run.step(...)、run.facts、run.output_dir、run.preview()，讓報告有步驟、資料預覽與產出檔案；回看是步驟時間軸。

1. 目標與驗收

  • 結合：一個組合場景「瀏覽器節點下載報表 → Python 節點合併、計算 → 瀏覽器節點把結果檔上傳到另一個系統」在同一台 Worker 驗證、發布、執行通過；中間的資料以出參（含 object、file）傳遞。
  • 相容：現有的 ba-001-script 不改一行照樣驗證與執行；既有場景的雜湊不變。
  • 不依賴瀏覽器：運行環境模式的節點交給沒有下載瀏覽器、不能顯示視窗的 Worker 也能執行。
  • 一致：同一個運行環境模式的場景，不改一行，在 Windows Worker App、macOS Worker App、Linux 的 rpa worker 結果相同；Worker 不需要事先裝 Python、不需要網路；第二次運行的「運行環境」階段在 1 秒內。
  • 本機自動化做得到：多個 Excel 合併並算總額、依欄位拆檔、Excel 與 CSV 互轉（含 Big5、GBK）、合併 PDF、用範本產生 Word、重新命名與搬移、壓縮、呼叫 HTTP API。
  • 報告：Python 節點的報告有步驟（名稱、結果、耗時、錯誤、原始碼行號）、事實、斷言、出參、產出檔案（可以下載）、資料預覽、主控台與運行環境；回看是步驟時間軸，失敗時停在失敗的步驟。

4. 場景模型

schemaVersion 維持 1，新欄位都是增加的，舊場景不用改、雜湊不變。

# scenes/merge-branch-sales/revisions/1/scenario.yaml
schemaVersion: 1
id: merge-branch-sales
name: 合併分店銷售報表
category: 報表

inputs:
  reports:   { type: file, multiple: true, accept: [.xlsx] }   # 上游下載或上傳的檔案
  months:    { type: array, description: 要合併的月份 }          # 新：array／object 入參
  options:   { type: object, default: { sheet: 銷售 } }

outputs:
  merged:    { type: file, from: '{{ facts.merged }}' }          # 新：file 出參
  total:     { type: number, from: '{{ facts.total }}' }
  byBranch:  { type: object, from: '{{ facts.byBranch }}' }

deadline: 600000

script:
  runtime: "1"                          # 新：用 RPA Python 運行環境 1；沒寫是相容模式
  automation: automation.py
  files: [helpers.py, templates/summary.xlsx]   # 新：腳本會用到的其他檔案
  platforms: [windows, macos, linux]            # 新：選用

verify:                                 # 運行環境模式可以用 verify 取代 assertion.py
  - name: 至少合併一份報表
    value: '{{ facts.fileCount }}'
    matches: '^[1-9][0-9]*$'

校驗規則（rpa validate、Portal 存檔、rpa pack check 相同）

  • runtime 是這版程式認得的主版本（目前只有 "1"）。有 runtime 時不能寫 browser、login；assertion 與 verify 最多一個，有出參時恰好一個；用 verify 時每個出參要有 from、用 assertion.py 時不能有。
  • 相容模式的規則不變：assertion 必要、不能有 verify 與 from。
  • files：相對於場景檔的路徑（不能用 .. 與絕對路徑），可以是任何副檔名，最多 50 個、單檔 1 MB（git 推送的上限，ADR 0015）；和 automation、assertion 一樣納入雜湊與快照。不能和場景附件的 files/ 資料夾重疊。
  • platforms 是 windows、macos、linux 的子集，不能重複。
  • 入參新增 type: array、type: object：值是 JSON 的陣列與物件；不能寫 enum、長度與數值範圍；預設值要符合型別。在 DSL 的 {{ inputs.x }} 裡代入成 JSON 文字。
  • 出參新增 type: file（第 7 節）。file 型別的入參現在 Python 節點也可以用（第二版禁止），腳本從 RPA_INPUT_FILES 拿到檔案路徑。
  • 擴充（features）：pythonNodes（runtime、files、platforms、Python 節點的 verify 與 file 入參）、jsonInputs（array／object 入參）、fileOutputs、download。舊版 App 不會領到用了它們的任務，執行頁說明要更新哪個 App。

雜湊與快照

scenario_sources 依序是場景檔、automation、assertion（有寫才加）、files。沒有新欄位的場景，檔案清單與雜湊完全不變。運行環境不算在雜湊裡（它是 Worker 的一部分，就像瀏覽器版本）；每次執行記下實際用的運行環境版本。

5. RPA Python 運行環境

平台自己建置、自己測試的一套 Python：一個 python-build-standalone 直譯器，加上固定的一組套件，所有 Worker 用的是位元組都相同的同一份；和電腦上的 Python、App 自己的 Python 都分開，Worker 上不安裝、不升級任何套件。內容、建置與沿用照第二版第 5 節，以下是摘要與這一版的調整。

5.1 版本

版本號 主.次.修。場景寫主版本（runtime: "1"）；同一個主版本只加套件、做相容的升級或安全修正；換 Python 的次版本、拿掉套件、套件有不相容的大改版才升主版本。每次執行記下完整版本，報告看得到「驗證時 1.0.0、這次 1.1.0」。場景要清單以外的套件時，提出後加進運行環境（新的次版本）；只有幾個檔案的純 Python 模組可以放進場景的 files。

  smoke.py              # 自我測試：import 每個套件；讀寫 xlsx／xls／csv；合併 Excel；docx 填值；合併 PDF；中文路徑與檔名
tools/build_python_runtime.py --platform windows-x86_64   # 也有 macos-arm64、linux-x86_64、linux-aarch64；--install 裝到本機快取

下載固定版本的直譯器並核對 sha256 → 只用 wheel、核對雜湊安裝套件（rpa-script 不裝，見 6.2）→ 拿掉 pip、tkinter、IDLE、測試資料夾，放 EXTERNALLY-MANAGED → 寫 rpa-runtime.json（版本、平台、套件版本與授權、建置的 commit）→ 用剛建好的運行環境跑 smoke.py → 打包成 RPA-Python-1.0.0-<平台>.tar.gz＋sha256。CI 在每個平台（Linux x64、arm64、Windows、macOS）各建一份並用它跑 Python 節點的測試，輸入（runtimes/python/、packages/rpa_script、建置工具、Runner）的指紋沒變時沿用（照 2026-10-26 同意的依層建置）；Worker App 與伺服器分發包建置時各自再建一份放進去。運行環境的版本屬於外殼：換套件要升 runtime.toml 的版本，App 與分發包的環境代號跟著變。

5.3 帶到 Worker、已經有就沿用

  • Worker App（Windows、macOS）與 Linux 伺服器分發包附上自己平台的壓縮檔；原始碼安裝用 tools/build_python_runtime.py --install。
  • 解壓到快取資料夾的 python/<版本>-<平台>/（Windows %LOCALAPPDATA%\rpa\cache、macOS ~/Library/Caches/rpa、Linux ~/.cache/rpa，RPA_CACHE_DIR 可以改）。有 .ready 標記、rpa-runtime.json 的雜湊和附帶的相同就直接用（幾毫秒）；第一次解壓到暫存資料夾、自我檢查、寫 .ready 再改名，同時要同一版的程序以檔案鎖排隊；損壞時下次重新解壓。
  • Worker 上線時回報有哪些運行環境（例如 ["1.0.0"]）與平台（例如 windows-x86_64）；「裝置」頁顯示。

5.4 派工

運行環境模式的任務只交給：回報了 pythonNodes、有這個主版本、平台在 platforms 裡的裝置；不檢查瀏覽器與顯示視窗。沒有可以執行的裝置時，執行頁說明缺什麼（例如「需要 RPA Python 運行環境 1」「這個場景只在 Windows 執行」），同 M7a。

5.5 模型套件的選用層（P3，這次不做）

模型構建要的套件很大（scikit-learn 約數十 MB，PyTorch 會讓運行環境多上 GB），不放進基本版（D4）。之後另建一個疊在基本版上的選用層，場景寫 runtime: "1-ml"，只派給有這一層的 Worker；Worker App 可以選擇要不要下載這一層。套件清單、下載方式與大小在 P3 設計。

6. 腳本介面

6.1 契約（兩種模式相同）

  • automation.py --input input.json --facts facts.json --screenshot screenshot.png --target-url 網址：讀入參，把觀察到的事實寫進 facts.json，不判定成功。運行環境模式的 --target-url 是空字串，截圖可以不寫。
  • assertion.py --input input.json --facts facts.json --output candidate.json：獨立比對，寫出候選出參；結束碼非 0 是斷言失敗。
  • 環境變數（兩種模式）：RPA_DEADLINE_SECONDS、RPA_LANG、Secrets（同名）。相容模式另有 RPA_BROWSER、RPA_HEADLESS、RPA_STORAGE_STATE（照舊）。運行環境模式另有 RPA_WORKSPACE（共用工作資料夾，也是工作目錄）、RPA_OUTPUT_DIR（產出檔案）、RPA_INPUT_FILES（file 入參的實際路徑，JSON 檔）、RPA_STEPS（步驟紀錄檔）、RPA_RUNTIME、RPA_PLATFORM；拿掉 PYTHON*、VIRTUAL_ENV、CONDA_*、PLAYWRIGHT_* 與 Worker 的權杖。
  • 運行環境模式由 python -E -s -B -X utf8 -c <啟動器> <rpa_script 所在> automation.py … 啟動（等於 python -m rpa_script automation.py …）：rpa_script 先準備好 Run，再以 __main__ 執行腳本；腳本有 @automation 函式就接著呼叫它。所以「照契約自己讀寫檔案的舊式腳本」與「用 rpa_script 的腳本」都能跑。相容模式的啟動方式不變。

6.2 rpa_script（選用的便利層）

新套件 packages/rpa_script（rpa-script），只用標準函式庫；隨 rpa-runner 一起裝，所以相容模式的腳本也能 import。不裝在運行環境裡（2026-10-29 實作時改）：Runner 把自己的那份 .py 放到快取的 python/rpa-script-<內容雜湊>/，啟動時加在 import 路徑最後。原因是程式碼層（ADR 0018）的更新檔不換運行環境：裝在運行環境裡的話，Runner 與 rpa_script 會在更新後錯開；這樣運行環境只在 Python 或套件改變時才換。打包後的 App 另外收進 rpa_script 的原始碼。

from pathlib import Path

import pandas as pd

from rpa_script import Run, StepError, automation


@automation
def main(run: Run) -> None:
    with run.step("read", "讀取分店報表"):
        paths = run.input_files["reports"]          # file 入參的實際路徑
        if not paths:
            raise StepError("沒有收到報表")         # 只顯示訊息，不顯示呼叫堆疊
        frames = [pd.read_excel(path).assign(分店=Path(path).stem) for path in paths]

    with run.step("merge", "合併並計算總額"):
        merged = pd.concat(frames, ignore_index=True)
        run.preview("合併結果", merged)             # 報告與回看顯示前 50 列

    with run.step("write", "寫出合併報表"):
        target = run.output_dir / "merged.xlsx"
        merged.to_excel(target, index=False)
        run.facts.update(
            merged=str(target),                     # file 出參取自這個事實
            fileCount=len(paths),
            total=float(merged["金額"].sum()),
            byBranch=merged.groupby("分店")["金額"].sum().to_dict(),
        )
介面說明
@automation標出進入點；一支檔案最多一個。
run.inputs、run.input_files、run.secrets運行態入參（唯讀，和 input.json 同一份）；file 入參名稱 → 實際路徑清單；場景宣告的 Secrets。
run.facts事實（可以轉成 JSON 的 dict），結束時寫成 facts.json；失敗時也寫出已經有的部分。
with run.step(id, name=None)一步：開始與結束時間、結果、錯誤、原始碼行號；迴圈裡同一個 id 記成第 n 次。寫進 steps.json，格式同 DSL（action 是 python，另加 source、occurrence）。
run.output_dir產出檔案的資料夾（執行目錄的 outputs/）：結束後跟著執行目錄上傳，報告可以下載。
run.workspace共用工作資料夾（第 7 節），也是工作目錄。
run.preview(name, value)資料預覽：pandas DataFrame、list of dict／list、dict、文字；只存前 50 列、30 欄，每格 200 字。
run.log(訊息)、print()進 automation.log，記下時間與當時的步驟；Secrets 的值遮罩。
StepError(訊息)預期中的失敗：報告只顯示訊息。其他例外顯示訊息與呼叫堆疊。
run.remaining_seconds、run.platform、run.runtime、run.lang總期限剩下的秒數；windows／macos／linux；運行環境版本；介面語言。

結束碼：0 成功、1 自動化失敗、3 逾時（同 DSL）。第二版的 run.watch()（資料夾的檔案變化）與 Python 寫的 Check 斷言 API 不在這次範圍：檔案變化改由 Runner 記錄共用工作資料夾與 outputs/ 在每一步前後的差異；Python 斷言照舊用 assertion.py。

7. 組合場景裡的資料與檔案

BA 系統下載報表（DSL）──file: report──▶ 合併分店報表（Python 節點）──file: merged──▶ 上傳到總部系統（DSL）
                                              └──object: byBranch、number: total──▶ 寄出摘要（Python 節點，requests）
  • 共用工作資料夾（D3）。每次組合運行在執行的那台 Worker 上有一個資料夾（<Worker 資料夾>/workspaces/<組合運行編號>/），所有節點看得到；單獨執行的場景用執行目錄旁邊的暫存資料夾。DSL 的下載步驟存到這裡，Python 節點的工作目錄也是這裡。組合運行結束（通過、失敗、取消）就刪除；只有宣告成 file 出參的檔案會複製進那個節點的執行目錄、上傳到伺服器。本機 Worker 由伺服器直接刪；遠端 Worker 在下一次領取或心跳的回應收到要清的清單；另有保險：超過 24 小時沒動的資料夾在 Worker 啟動時清掉。
  • array／object 入參。出參本來就有 array、object，現在可以接到同型別的入參；命令列 -i 名稱=JSON，Portal 的執行表單與畫布用 JSON 編輯框。
  • file 出參。值由事實（from）或 assertion.py 給出一個路徑，必須在共用工作資料夾或 outputs/ 裡。出參階段把檔案複製進執行目錄的 outputs/（報告可以下載），output.json 的值是 {"name", "size", "sha256", "path"}；接到下游的 file 入參時用 path（同一台 Worker，共用工作資料夾自動算在允許的資料夾裡）。單檔與每次合計的上限沿用 M7c（50 MB、200 MB，可調）。
  • DSL 的 download 步驟。- id: export, action: download, target: { role: button, name: 匯出 }, as: report：點擊並等待下載，檔案存到共用工作資料夾的 downloads/，事實 report 是 {"name", "size", "sha256", "path"}，出參 type: file, from: '{{ facts.report }}' 就能往下傳。錄製端把 codegen 的 expect_download 轉成這個步驟。
  • 網路操作。運行環境帶 requests；Python 節點呼叫 API 不用經過瀏覽器。要沿用瀏覽器的登入狀態（Cookie）呼叫內部 API，需要 Python 節點能用登入角色，這一項待你決定（D5），這次不做。
  • 扇出（P3，這次不做）。「Python 節點產出 N 筆資料，每一筆跑一次瀏覽器節點」需要組合場景的 foreach 節點；之後設計。

9. 報告與回看

  • 執行目錄和 DSL 相同，Python 節點另有 steps.json（用 rpa_script 時）、previews/、outputs/、files.json（共用工作資料夾與 outputs/ 每一步前後的差異）。result.json 多 python（模式、運行環境版本、平台、沿用或新解壓、準備時間）與 outputs（產出檔案），stages 多 runtime；讀 result.json 的程式不認得的欄位照舊忽略。
  • 報告頁（report.html 與 /runs/{id}）：結果 → 出參與產出檔案（可以下載）→ 階段（運行環境標「沿用」或「第一次準備」）→ 步驟（同 DSL 的表格，多了原始碼行號與第幾次）→ 事實 → 斷言 → 檔案變化 → 資料預覽 → 主控台。
  • 回看（/runs/{id}/replay）：沒有影片，沿用 v0.8.0 的章節軸，每一步一個章節，主畫面換成那一步的腳本原文（標出行號）、到那一刻為止的主控台、檔案變化、最近一份資料預覽與事實；失敗的運行打開就停在失敗的步驟。組合運行的合併回看裡，DSL 節點播影片、Python 節點播步驟時間軸。
  • 相容模式照舊沒有錄影；用了 rpa_script 就有步驟與時間軸。
