macOS 版 RPA Worker

Worker App 支援 Mac（Apple 晶片），功能和 Windows 版一致：狀態視窗、選單列圖示、登入時自動啟動、只執行一份、鑰匙圈、DMG。

做法

  • 同一份程式：rpa_desktop.gui 照舊是 Worker 的視窗版，系統的差別集中在 rpa_desktop.macos；打包設定的 macOS 部分（pywebview 的 cocoa 後端、鑰匙圈、PyObjC）改成兩個 App 共用；DMG 和錄製端一樣由 tools/build_desktop.py 產生（RPA-Worker-版本-macos-arm64.dmg）。
  • 選單列（實作選擇）：Windows 用 pystray；在 macOS 上 pystray 與 pywebview 都要在主執行緒跑 NSApplication 的迴圈，所以直接用 PyObjC 的 NSStatusItem 掛在 pywebview 的迴圈裡（介面和 Tray 相同）。AppKit 的呼叫一律經由 AppHelper.callAfter 排到主執行緒；選單動作在另一個執行緒執行（pywebview 的視窗操作在主執行緒呼叫會等不到自己）。沒有新增相依。
  • 視窗與結束：關掉視窗是縮到選單列並拿掉 Dock 圖示，叫出時恢復。⌘Q 當成「結束」：pywebview 把 ⌘Q 與關閉鈕都變成 closing 事件，用「主執行緒是不是在 applicationShouldTerminate_ 裡」區分；先取消 AppKit 的結束（否則程序立刻結束、來不及回報任務），確認後自己關。Finder 再打開或點 Dock 圖示時，在 pywebview 的 App 委派補上 applicationShouldHandleReopen:hasVisibleWindows: 叫出視窗。登出、關機前（NSWorkspaceWillPowerOffNotification）取消任務並在主執行緒等幾秒回報。開過視窗後直接結束程序（同錄製端）。
  • 自動啟動：目前使用者的 LaunchAgent（~/Library/LaunchAgents/io.github.devopsleadevops.rpa.worker.plist，RunAtLoad、只在 Aqua 工作階段）；介面和 Windows 的「登入時執行」相同，搬家後更新路徑。不用 SMAppService：需要 macOS 13 且對沒有簽章的 App 行為不確定，plist 可以在 Linux 的 CI 測。
  • 用詞：訊息目錄新增 window.darwin.*、worker.darwin.already_running（選單列、鑰匙圈、登入 macOS），platform_key 與頁面的訊息在 macOS 上選用；三個說明文字改成兩個系統通用。順便修正錄製端的提示：osascript 的字串原本用 json.dumps 的 ASCII 跳脫，中文會顯示成 \uXXXX。
