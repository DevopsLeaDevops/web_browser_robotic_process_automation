準備

本機 checkout 已在 m6/dag-composite-scenes。在專案根目錄執行以下命令，使用獨立 Portal 資料目錄；既有 8080 服務可保留。若 8090 被占用，改用其他空埠並修改開啟網址。範例目標網站在 8765，已在執行時會沿用，範例會新增測試紀錄。

~/.local/bin/uv sync --locked
~/.local/bin/uv run rpa serve --data data-dag-acceptance --port 8090

開啟 http://127.0.0.1:8090/playground。終端應顯示測試網站已啟動或正在執行；本機先前驗證所需 Chromium／Firefox 已安裝。換機後如提示缺少瀏覽器，執行 uv run playwright install chromium firefox。

  1. 確認選單與責任：場景生產前三項依序為自主腳本錄製、自由試驗場、運行報告；場景管理最後一項為組合場景自動化，進入後以卡片管理組合場景。
  2. 準備兩個已發布場景：在「測試網站自動化」開啟 BA-001／建立範例紀錄，用預設入參驗證成功後發布，從該次報告複製出參 recordId。再開啟 BA-002／查詢範例紀錄，以剛才的 recordId 驗證成功後發布。均選本機、Chromium、無頭模式；已有發布版本可略過。
  3. 建立分叉與匯合：自由試驗場新增「DAG 驗收」，依序加入 BA-001、BA-002、BA-002、BA-001，應為 n1、n2、n3、n4。先點來源節點右側輸出端點，再點目標節點左側輸入端點，建立 n1→n2、n1→n3、n2→n4、n3→n4 四條線。可拖成菱形；也可在右側節點設定選擇上游並連線。
節點場景右側入參來源配置預期效果
n1BA-001title：固定值「DAG 驗收」；quantity：固定值 7產生第一筆紀錄，發布 recordId、title、quantity
n2BA-002recordId：同名匹配匹配 n1.recordId

n4BA-001title：指定 n2.title；quantity：指定 n3.quantity匯合兩路資料，建立另一筆標題及數量相同的新紀錄
  1. 拖動與保存：把 n4 移到 n1 左側，再保存及重新整理。節點位置、四條線與入參配置均應保留；縮放／適應畫布只改視角。即使 n4 視覺上排最前，執行仍須等待 n2、n3。
  2. 執行與核對資料：點執行，選本機、Chromium、無頭。報告應顯示四個節點通過，n1 最先、n4 最後；n2、n3 的輸入 recordId 等於 n1 的輸出；n4 的輸入 title＝「DAG 驗收」、quantity＝7，輸出 recordId 與 n1 不同。回組合場景自動化，卡片能重新進入畫布，最近執行可開啟報告。需要觀察瀏覽器時，再選有頭模式執行一次。
  3. 保護檢查：嘗試 n4→n1，應提示循環且不新增這條線。將 n4.title 改成同名匹配，因 n2、n3 同時提供 title，應提示歧義並阻擋執行；恢復指定 n2.title。再刪除 n1→n2，必填 recordId 無來源時應顯示問題；重新連線後恢復。
  4. 失敗停止（建議）：將 n2.recordId 暫改為固定值 DEMO-NOTFOUND1 再執行，應在查詢失敗處停止，n4 不應執行。將畫布配置恢復後發起一次新執行應通過。舊執行保留原快照，修改畫布不會更改舊執行入參；不要以「續跑舊快照」代替這次新執行。
