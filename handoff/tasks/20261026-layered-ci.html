人工驗收

  1. Secret：Settings › Secrets and variables › Actions 有 RPA_UPDATE_CI_KEY（沒有就照 文檔產生並設定）。
  2. 本 PR 的運行：每個流程的「執行範圍」摘要有指紋表；桌面端建置的「測試更新檔用的金鑰」註記是固定金鑰（不是警告）。
  3. 手動觸發 desktop.yml（本分支，build=full）：三個 App 完整建置成功，「存進外殼快取」步驟執行。
  4. 再手動觸發 build=auto：三個 App 都是「程式碼層路徑」，摘要寫外殼來自哪一版；自我測試、視窗自我測試、端到端通過；macOS 工作的時間比完整建置短。
  5. 只改文件的推送：桌面端建置、伺服器分發包、一鍵安裝腳本的重工作都是「沿用」。
  6. 合併後：main 的推送沿用 PR 的結果（不再排 macOS）；下一個只改伺服器的 PR 不排 macOS；下一次發布 PR 只跑 CI 的 Linux。
  7. 當晚的每晚完整測試有「macOS 桌面 App（程式碼層）」兩個工作並通過；週六 22:47 UTC 之後有一次「桌面 App 每週完整建置」。
