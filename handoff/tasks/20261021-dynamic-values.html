設計（實作選擇，有意見再改）

  • 寫在哪裡：入參的值裡（場景的預設值、執行表單與 API、命令列、試驗場的固定值、逐步調試）。不是步驟裡的 {{ }}（那是 Jinja，引用 inputs、facts…）；步驟裡寫了 today、now、random 時，校驗提示改寫在入參。
  • 語法（{{ }} 內可以有空白）：today、today+N、today-N（天）；now（日期與時間）；兩者都可以加 :格式（yyyy／YYYY、MM、dd／DD、HH、mm、ss，其他字元照寫，例如 {{today:YYYY/MM/DD}}、{{today:yyyy年MM月dd日}}）；random:A:B（A 到 B 之間、含兩端的整數）；"文字"（原樣的文字，用來寫出 {{ 本身）。預設格式：today 是 2026-10-21，now 是 2026-10-21 07:30:00。
  • 何時、以哪裡的時間求值：每次執行開始（Runner 的入參階段，啟動瀏覽器之前），用執行那台電腦的本地時區；同一次執行的所有入參用同一個「現在」。執行紀錄保存原本的寫法，所以重新執行會重新求值；input.json、報告是實際的值。
  • 型別：整個值只有一個 random 時，整數／數字入參得到數字；求值結果是整數形式的文字時，整數／數字入參也轉成數字；其他都是文字。
  • 寫錯就擋：入參值裡任何 {{ … }} 都當成動態值，看不懂就是錯（不會把 {{tody}} 原樣打進頁面）。預設值在存檔時校驗，限制（maxLength、minimum…）用隨機範圍的兩端各檢查一次；執行時再以實際的值校驗。
  • 上游出參：試驗場把上游的出參交給下游時，文字裡的 {{ 先跳脫，出參永遠照原樣使用。
  • 隨機數的檢查：限制以範圍的兩端各檢查一次（預設值存檔、試驗場固定值、Runner 與 Portal 排入前的檢查都一樣），所以 maximum: 20 配 {{random:10:30}} 一律報錯，不會時好時壞。
  • 附帶：YAML 裡沒加引號的 {{ … }}（例如 default: {{today}}、value: {{ inputs.x }}）原本只報「鍵必須是字串」，改成提示加引號；步驟裡寫了 today、now、random 時提示改寫在入參；入參表格的預設值是動態值時標示「動態值」；JSON Schema 匯出用 x-dynamicDefault。
  • 舊的 App：用到動態值（場景的預設值或這次的入參）時需要 DSL 擴充 dynamicValues；沒回報的 Worker／錄製端 App 照 M7a 的做法說明要更新。
