1. 目標與驗收

  • DSL 場景的驗證、執行、試驗場節點（本機 worker 與遠端 worker、Windows Worker App）都錄影；有頭、無頭都有；Chromium、Firefox 都有。
  • 失敗、逾時、取消的運行也有可播放、可拖曳的影片（還原現場最需要的正是這些）。
  • 運行頁、運行報告、試驗場節點都能進入回看；選單有獨立的「運行回看」。
  • 播放器：播放、暫停、拖曳、逐格、變速；時間軸有縮圖、滑過有預覽；步驟清單跟著影片走，點步驟跳到那一步；失敗的運行打開就停在失敗步驟之前。
  • 錄影關閉時一切照舊；影片依保留規則自動刪除，運行紀錄本身不刪。

3. 錄影（rpa_runner、worker）

  • DSL 場景的自動化階段：rpa_runner.child 開 context 時加上錄影，畫面大小跟頁面一樣、寬度上限 1280（D2）。結束時先關 context 再關瀏覽器，存成執行目錄的 video.webm。Firefox 的預熱設定檔（持久化 context）同樣支援。
  • 步驟時間：steps.json 每一步加 startedAt、endedAt（UTC、毫秒）和 url（步驟結束後的網址，Playwright 已有的值，不多一次來回）。
  • 新檔 video.json：格式版本、檔名、錄影開始時間（從檔案標頭讀，讀不到才用開頁面的時間）、長度、寬高、大小、是否修復過、瀏覽器、保留到何時、是否釘選、刪除的時間與原因。
  • 失敗、逾時、取消：總期限到時子程序自己收尾（現在就有），影片正常存檔。被強制終止（取消、超過收尾時間）時：Linux、macOS 上 Playwright 把 ffmpeg 放在自己的程序群組，終止子程序的程序群組不會碰到它，ffmpeg 輸入斷了就自己收尾；Windows 上 taskkill /T 會連 ffmpeg 一起結束，只留下 ffmpeg 也不行（Node 的 Job Object，見第 2 節），所以錄影時先用 CreateToolhelp32Snapshot 列出子孫、只結束瀏覽器，等子程序自己結束（最多 15 秒），再等 ffmpeg 最多 8 秒；還沒結束才結束整個程序樹（rpa_runner.proctree、run._stop_browsers_first）。終止的經過記在 video.json 的 stop；被我們終止時，子程序寫的「頁面已關閉」不採用為錯誤原因。整理時影片還是沒有長度與索引，就用 Playwright 的 ffmpeg 重新封裝；修不了也保留原檔（能從頭播放、不能拖曳），video.json 的 complete 是 false。實作時試過「只結束子程序、讓 Playwright 的 driver 自己收尾」：在本環境 driver 一直沒把 ffmpeg 正常關掉，30 秒後 driver 結束時還把 ffmpeg 一起砍掉，所以不用這個做法；先只結束瀏覽器則是讓 Playwright 走它自己的「頁面關閉」流程。
  • Python 腳本場景：不錄（使用者 D5：暫不支援）。
  • 不錄：登入檢查與自動登入（已有 login.png）、逐步調試、錄製（D5）。
  • 設定：伺服器設定「錄影：開／關」。關閉時 child 完全不加錄影，和現在一樣。遠端 worker 從領取的任務得知要不要錄，舊版 worker 不認得就不錄（不擋執行）。
  • 遠端 worker：照舊把整個執行目錄壓縮上傳（上限 512 MB）；上傳後刪除本機副本的行為不變。

4. 存放、保留與檔案服務（rpa_server）

  • 影片在 資料目錄/runs/<運行編號>/video.webm；M11 的 run.json 檔案清單自然列入。影片不進領域資料夾，也不進 git（M11 D4 不變）。
  • 保留與清理（D1）：伺服器啟動時與每小時刪掉過期的影片。只刪影片，結果、報告、截圖、日誌都留著；video.json 記下刪除時間和原因，頁面顯示「錄影已依保留規則刪除」。總量超過上限時從最舊的刪起。釘選的不刪。設定放在「運行回看」頁。
  • 檔案服務：/runs/{id}/files/video.webm 沿用現有路由（Starlette 的 FileResponse 支援 Range，拖曳只抓需要的片段）。影片寫完就不會變，快取由 no-store 改成 private, max-age，拖曳時不重複下載。
  • 「下載錄影」就是這個檔案；之後歸檔（M11 D4）時一起上傳。

5. 回看播放器（/runs/{運行編號}/replay）

可操作的原型：prototype.html（單一檔案，影片和步驟時間來自一次真實執行：建立一筆紀錄後查詢不存在的編號，第 10 步逾時失敗；縮圖在瀏覽器裡從影片產生）。使用者另有同內容的 Claude artifact。

  • 版面（寬螢幕）：左邊是播放器（網址列、影片、控制列、時間軸），下面是階段條；右邊 372 px 是「步驟／斷言／運行資訊」三個分頁。1180 px 以下右欄移到下面；手機寬度一欄。
  • 網址列：影片只錄到網頁內容，沒有網址；播放器依步驟紀錄顯示「這一刻」的網址和「第 N／M 步」。
  • 影片上的標籤：左上角顯示目前的步驟（編號、狀態色、名稱、動作與定位器），不燒進影片。
  • 打開時的位置：失敗的運行停在失敗步驟開始前 1 秒、暫停，右邊展開那一步並提示「已定位到失敗的第 N 步之前 1 秒」；通過的運行停在開頭。
  • 時間軸：上排是縮圖條（寬度每 96 px 一張，依時間平均取樣），下排是步驟軌（每一步一段，長度＝耗時，通過綠、失敗紅、目前那一步藍框，太短的至少 3 px），再下面是刻度。已播放的部分加淡藍底。點或拖曳任何位置就跳過去（拖曳時暫停，放開後恢復原本的播放狀態）。滑過時出現大一點的預覽：先用最近的縮圖，停 120 ms 後換成那一刻的實際畫面，並標出時間和步驟。可以用鍵盤操作（滑桿）。
  • 控制列：播放／暫停、上一步、下一步、上一格、下一格（1/25 秒）、目前時間／長度（到百分之一秒）、速度 ¼×、½×、1×、2×（步驟通常很快，所以有慢放）、「步驟清單跟著跑」、快捷鍵說明、全螢幕。
  • 步驟清單：每一步一列：編號（狀態色；還沒到的是虛線圈、正在執行的是藍色）、那一步結束時的小縮圖、名稱（沒有名稱時用動作＋id）、動作與定位器、開始時間、耗時。播放時目前那一步反白並捲到看得到的位置（只在清單內捲動）。點一列：跳到那一步開始前 0.4 秒，並展開詳細。
  • 步驟詳細：錯誤訊息（失敗時）、結果與耗時、步驟後的網址、填入的值（Secrets 遮罩）、抽到的事實（extract）、場景檔快照裡那一段原文與行號；按鈕「從這一步播放」「複製這一刻的連結」（?t=秒&step=id）「在場景中開啟（第 N 行）」。
  • 影片結束時：失敗的運行顯示結束卡：哪一步失敗、錯誤、斷言與出參沒有執行；按鈕「回到失敗的步驟」「從頭播放」。
  • 階段條與斷言分頁：影片只涵蓋自動化階段，入參校驗、獨立斷言、出參在階段條與「斷言」分頁顯示，說明它們在瀏覽器關閉後才執行。
  • 運行資訊分頁：運行編號、入參、錄影的大小與長度、錄影開始時間、保留到何時、「釘選，不自動刪除」。
  • 快捷鍵：空白／K 播放暫停；←→ 1 秒（Shift 5 秒）；, . 逐格；J L 上一步、下一步；E 跳到失敗的步驟；[ ] 變速；F 全螢幕；? 說明。
  • 頁首：同一個場景的「上一次失敗」「下一次」、運行詳情、開啟報告、下載錄影。試驗場的節點另外有「上一個節點／下一個節點」。
  • 沒有影片時：說明原因（錄影關閉、Python 腳本沒錄、依保留規則刪除、舊的運行），仍然顯示步驟與階段。
  • 實作：資料由 GET /api/runs/{id}/replay 提供（運行摘要、video.json、步驟加上場景快照的原文與行號、斷言、階段、前後的運行、試驗場節點）。頁面的 JavaScript 放 static/replay.js，只在這一頁載入；文字用 replayjs.* 訊息鍵（三種語言），和試驗場的 wfjs.* 同樣做法。

6. 入口

  • 「場景生產」選單新增「運行回看」（/replay）：有錄影的運行，失敗的排前面，篩選沿用運行報告（場景、分類、結果、目的、執行的電腦）；錄影設定也在這頁。
  • 運行報告的清單多一欄「回看」：▶ 加上影片長度；影片已刪除時顯示「已刪除」。
  • 運行頁：頁首加「回看」按鈕。驗證運行的「發布」旁提示可以先看驗證錄影（多人驗證後發布時用得到）。
  • 試驗場的序列執行頁：每個節點一個回看連結。
