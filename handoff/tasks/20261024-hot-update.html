盤點：現在的打包與升級

  • 大小（v0.5.0 發布紀錄）：伺服器分發包 x64 約 103 MB、arm64 約 97 MB；Windows Worker 的建置產物合計約 136 MB；兩個 DMG 各約 84 MB（0.5.0 任務紀錄）。
  • 每版真正改變的程式：七個工作區套件的原始碼（不含 __pycache__）用 tar -czf - packages/*/src apps/*/src | wc -c 量得約 0.6 MB（main a8cde7f）；其中 rpa_server 約 0.3 MB（頁面、翻譯、遷移都算在內）。
  • 第三方套件的變動：比較各版本標籤的 uv.lock（只算來自套件庫的套件）：0.2.0 → 0.3.0 變 6 項（PyObjC），0.3.0 → 0.4.0 變 20 項（含 Playwright 1.63 → 1.64；部分是 pytest 等開發工具），0.4.0 → 0.5.0 與 0.5.0 → main 29176b1 都是 0 項。
  • 伺服器：install.sh 已有版本並排（releases/）、原子切換 current、保留 3 版、重新啟動後 60 秒內沒回應就停下並印出退回指令（不會自動退回）。bin/rpa 清掉 PYTHONPATH，子程序以 sys.executable -m … 啟動。
  • 桌面 App：PyInstaller 6.22.3 資料夾模式，rpa-worker／rpa-recorder 與 rpa-child 兩個執行檔各自內含程式封存；入口 rpa_desktop/entry.py 一開頭就匯入 rpa_runner.commands，所以啟動器必須是另一個更早執行的入口。程式指紋在建置時寫進 build_info.json。「下載新版」連 GitHub 最新 Release（rpa_desktop/release.py）。
  • 伺服器重新啟動時的遠端任務：Worker 回報失敗會重試最多 600 秒、領取連不上時退避重連（上限 30 秒，rpa_worker/remote.py）；租約 60 秒（rpa_worker/protocol.py），伺服器的背景執行緒會把過期的標成「worker 失聯」（rpa_server/dispatch.py），所以要在啟動時延長租約。
  • 依賴更新：uv-upgrade.yml 每週日執行 uv lock --upgrade 並開 PR。
