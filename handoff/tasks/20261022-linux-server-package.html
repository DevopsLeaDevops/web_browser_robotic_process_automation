做法

  • 分發包的內容（實作選擇）：RPA-Server-版本-linux-x64.tar.gz／linux-arm64，內含 uv 管理的 CPython（python-build-standalone，.python-version 的 3.13，glibc 2.17 以上就能跑、可以搬家）、照 uv.lock 匯出（含 sha256）並直接裝進這份 Python 的第三方套件、工作區六個套件的 wheel（不含 rpa-desktop）、bin/rpa、install.sh、範例場景 scenarios/demo、BUILD_INFO（KEY=值）。不用 PyInstaller：伺服器以 sys.executable -m … 啟動子程序、alembic 要讀遷移檔，真的 Python 最單純。不做 RPM：一般帳號就能裝、不挑發行版，和現有 setup-linux.sh 的使用方式一致。
  • glibc 2.28：建置機器（Ubuntu）比公司伺服器新，uv pip install --python-platform <arch>-manylinux_2_28 限定 wheel；裝好後逐一讀 *.dist-info/WHEEL 的平台標籤，需要更新 glibc 的就停止建置（例如 cryptography 有 manylinux_2_34 的版本）。最後由 Rocky 8（glibc 2.28）容器實際執行驗證。
  • 安裝與升級：預設 ~/rpa-server；版本並排在 releases/版本-提交/，新版本先複製到暫存資料夾、用包內的 Python 載入伺服器程式確認能執行，才改名、再原子地把 current 換過去；保留最近 3 個版本（使用中與上一版一定保留）。設定 rpa-server.env、資料目錄（預設 ~/.local/share/rpa-server，和 setup-linux.sh 相同）都不動。服務的 unit 指向固定的 bin/rpa-server，所以升級只要重新啟動；重新啟動後約 60 秒內管理埠沒有回應就停下並說明怎麼退回上一版。
  • 從 clone 改過來：第一次安裝時找 systemd 服務啟動的 .venv-server/bin/rpa-server 所在的 clone，再找預設的 clone 位置，沿用那份 .rpa-server.env（變數相同）；--import-env 可以指定。現有服務仍指向 clone 時不動它，加 --install-service 才換過去。
  • 系統套件：只補裝缺少的 libstdc++（必要）與 git（只有 git 同步要用）；所以升級通常不需要 sudo 裝套件。bin/rpa 清掉 PYTHONPATH 等設定、加 PYTHONUTF8；包內 OpenSSL 預設找 Debian 的憑證位置，沒有設定時改用 RHEL 的 /etc/pki/tls/certs/ca-bundle.crt。
