需求（使用者原文摘要）

  1. 點場景的「入參設定」「出參設定」跳過去後錨點不準確。
  2. 裝置頁（叢集管理）：錄製端升級後也還有警告「和 Portal 的程式版本不同：兩邊更新到同一個版本比較保險。要用完整的安裝包更新到 0.6.1」。
  3. mac-worker 重新啟動後沒有更新到 0.6.1；而且即使升級了，也覺得會繼續出現同樣的警告。

進度、決定與下一步

  • 原因：
    1. 錨點：入參與出參的原文是頁面載入後才向伺服器要的；拿到後 bindContract 自己再把原文框捲到畫面中間（scrollIntoView({block: 'center'})）。本機伺服器回得比第一次畫面更新快，所以測不出來；遠端伺服器慢一點，後面這次捲動就蓋掉區域連結的捲動，入參與出參的標題被往下推約 150 px。用 Playwright 把那個請求延遲 0.6 秒重現（1440 寬：面板停在 261 px，應該是 108 px）。另外，1100 px 以上入參與出參左右並排，「出參設定」跳到的位置和入參相同；區域連結列在窄視窗會換行，原本固定預留 52 px。
    2. 熱更新：下載 v0.6.0 與 v0.6.1 的更新檔比較清單裡的環境代號。伺服器兩版相同（de6e7107785c98ba、b93be424f1f8ff3a），所以伺服器能用更新檔；三個桌面 App 全都不同（錄製端 macOS 664ed2247e8081d1→4880b5543aa109b6、Worker macOS 6c5196fdccf828e0→c0e6750e5e85ff00、Worker Windows a393627ee81d9335→0a9b1477abe16480）。rpa_desktop.spec 用 copy_metadata("rpa-update") 把 rpa_update 的 *.dist-info 收進 App，而 rpa_update 屬於外殼、不在 ours 裡，shell_components 就把它的內容雜湊算進環境代號：資料夾名稱與 METADATA 帶著版本號，uv 從原始碼安裝時還寫下記錄時間的 uv_cache.json（uv 原始碼 crates/uv-install-wheel/src/wheel.rs），每次建置都不同。伺服器的代號只算套件名稱與版本、不算這些檔案，所以沒事。結果每台裝置都收到 full，不自動更新，也就一直是 0.6.0、一直顯示版本不同。
    3. 升級後還會不會有警告：不會。「程式版本不同」比的是程式指紋；0.6.1 更新檔的程式指紋（f3b941e8505c73fc）和原始碼算出的相同，裝置套用更新檔後回報的就是這個值，和 Portal 一樣。
  • 已完成：
    1. 錨點：捲動只在 bindSceneAnchors 做；跳過去後 4 秒內、使用者還沒自己捲動或操作之前，版面一變（ResizeObserver，入參與出參載入後另發 scene-layout）就重新對齊；bindContract 只把游標放進原文（preventScroll）。目標區塊閃一下外框，左右並排時看得出是入參還是出參。預留的高度改成區域連結列的實際高度（CSS 變數 --scene-jump-height），腳本區右欄的 sticky 也一樣。
    2. 環境代號：tools/build_desktop.py 新增 shell_files，spec 算環境代號前去掉工作區套件的 *.dist-info（rpa_update 的內容已由它的原始碼雜湊代表）。故意不改 rpa_update.build.shell_components：source_digest 涵蓋 rpa_update 的每個 .py，改了伺服器的環境代號也會變。
    3. 和上一次發布比較：新 tools/runtime_changes.py，拿這次建置的環境代號和最近一次已發布 Release 的更新檔比較。PR 上的桌面端建置與伺服器分發包寫成 annotation（不同是警告）；發布時寫進 Release 說明的「從 v上一版 升級」，標出哪些可以只用更新檔、哪些要完整的安裝包。0.6.1 那時有這個就會在發布前看到。
    4. 裝置頁：「要用完整的安裝包更新到 X」補上原因（執行環境不同，更新檔換不了），滑過去看這台與更新檔的環境代號（更新檔沒有這種裝置時另有說明）；已經有更新狀態說明（正在更新、要完整安裝包、退回、自動更新關閉）時，不再另外顯示「和 Portal 的程式版本不同」。伺服器記下裝置回報的環境代號與更新檔要的。
  • 對使用者的影響：修好的那一版（預計 0.6.2）伺服器照樣用更新檔升級；錄製端與兩個 Worker 要再用 0.6.2 的完整安裝包裝一次（App 裡帶的是舊算法算出的代號，換不掉）。之後環境沒變的版本，裝置會跟著伺服器自動更新，版本不同的警告也會消失。
  • 未完成／阻礙：審閱與合併；發 0.6.2。要確認修好之後同一份環境每次建置的代號相同：比較 bd60bda 與本紀錄更新提交兩次桌面端建置的 annotation（見驗證）。
  • 決定：使用者確認的是三項需求；以下是實作選擇，待審閱：過濾放在 spec／tools 而不改 rpa_update；比較只是提示，不擋 PR 與發布；裝置頁有更新狀態時隱藏版本不同的提醒。
  • 下一個具體動作：使用者審閱、合併 PR #88；合併後由 Claude 發 0.6.2，Release 說明會寫明裝置要用完整安裝包。
  • 未提交／stash／ignored 產物：無；重現用的 Playwright 腳本在容器的暫存資料夾，不在倉庫。
