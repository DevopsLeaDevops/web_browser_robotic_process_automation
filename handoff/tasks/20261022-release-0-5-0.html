進度與發布順序

  1. 執行 python3 tools/release_version.py bump 0.5.0 統一版本，本地檢查後開版本 PR（本頁）。
  2. PR 的桌面端建置與伺服器分發包先產生 0.5.0 的檔案，可以先試用；這些是 PR 的產物，正式 Release 會從 main 的標籤重新建置。
  3. 使用者合併版本 PR 後，確認 main 的 CI，在合併提交上建立並推送 v0.5.0：git checkout main && git pull && git tag v0.5.0 && git push origin v0.5.0。「發布」流程（.github/workflows/release.yml）確認版本與標籤、建置並測試，建立草稿 Release。
  4. 確認草稿有 RPA-Worker-Setup-0.5.0-windows-x64.exe、RPA-Worker-0.5.0-windows-x64.zip、RPA-Worker-0.5.0-macos-arm64.dmg、RPA-Recorder-0.5.0-macos-arm64.dmg、RPA-Server-0.5.0-linux-x64.tar.gz、RPA-Server-0.5.0-linux-arm64.tar.gz 與 SHA256SUMS.txt；把下方的已知問題補進說明，由使用者按「發布」。
  5. 升級：先停止伺服器並備份資料目錄。Linux 伺服器解壓分發包後執行 install.sh --install-service（之前用 setup-linux.sh 安裝的自動沿用設定與資料），其他系統 git pull 後重新執行安裝腳本並啟動；遷移 0014 在啟動時執行。錄製端、Windows 與 macOS 的 Worker 換成 0.5.0，配對保留；動態入參要用 0.5.0 的 Worker 才能在遠端執行。
  6. 發布後：設計文件「目前 v0.4.0」改成 v0.5.0（繁中、英文、簡中），回填本頁。

發布失敗（v0.5.0，執行 39900384051）

  • 現象：確認版本通過；Windows Worker、macOS Worker、macOS 錄製端、伺服器 x64、arm64 五個工作的建置、自我測試、端到端與 Rocky 8 安裝都通過，最後 actions/upload-artifact@v7 失敗：Failed to CreateArtifact: Artifact storage quota has been hit. Unable to upload any new artifacts.「草稿 Release」因此略過。標籤 v0.5.0 本身沒有問題，不用重打。
  • 原因：倉庫在 2026-10-22 改成私有。公開倉庫的 Actions 產物不計儲存額度，私有倉庫要計入帳號方案的額度（Free 500 MB、Pro 1 GB、Team 2 GB；超過要設 Actions 的預算）。2026-10-22 21:35 PDT 從 API 查到 693 個未過期產物、約 30 GB：worker-windows-latest 16.8 GB、舊名稱 recorder-macos-14 10.1 GB、recorder-macos-15 0.75 GB、伺服器分發包 1.4 GB、worker-macos-15 0.59 GB、測試報告與 Portal 軌跡 0.4 GB；都保存 14 天。單次發布要上傳約 504 MB（Windows 136、兩個 DMG 各 84、伺服器 103 與 97 MB），本身就超過 Free 的 500 MB。帳號方案查不到（工作階段只能用倉庫範圍的 API）。
  • runner 不再分配：2026-10-22 22:32 America/Los_Angeles（PDT，UTC−07:00）推送 474f588 後，五個流程的第一個工作都在 2 秒內失敗，runner_id 為 0、沒有日誌；重跑一次相同。這個提交沒有改 ci.yml，判斷是帳號層級的限制（私有倉庫的 Actions 分鐘數或支出上限），確切原因在執行頁面的註記，這個工作階段讀不到，請使用者到 Settings › Billing 確認（PR #75 的留言）。不解決的話清理產物與重跑發布都無法執行。之後使用者處理，23:04 起的執行都正常分配 runner（使用者怎麼處理的沒有記錄）。
  • 選項與決定：使用者 2026-10-22 22:27 America/Los_Angeles（PDT，UTC−07:00）在決定卡片上選擇維持私有（Claude 的建議），見決定。當時的兩個選項：(1) 改回公開：產物不計額度，重跑這次執行的失敗工作即可，從零安裝與 App 的「下載新版」也恢復。(2) 維持私有：刪掉舊產物（不能復原，要使用者同意）；在 Settings › Billing 設 Actions 儲存的預算；合併縮短保存期的 PR；額度重新計算後重跑這次執行的失敗工作。
  • 修正 PR（兩種選項都適用）：desktop.yml、server-package.yml 的產物保存期從 14 天改成 PR 與 main 3 天、標籤 1 天；release.yml 建立草稿後刪掉這次執行的產物（actions: write，刪不掉只留警告）；ci.yml、nightly.yml、setup-scripts.yml 的測試報告與 Portal 軌跡（診斷用）上傳失敗時不再讓工作失敗：PR #75 的「測試（Python 3.12）」就是測試通過、只有上傳報告時額度用完而變紅。新增手動的「清理產物」流程（cleanup-artifacts.yml，預設只列出；要刪時取消勾選「只列出、不刪」），CI 文件加上產物與儲存額度一節。workflow_dispatch 的流程要在預設分支上才能執行，所以要等 #75 合併後才能用它刪產物。

需帶入 Release 說明的已知問題

  • 錄影與回看：Firefox 有頭模式的畫面裁切、無頭模式的閃屏還沒有在受影響的電腦量測（0.4.0 的 A1）。#69 之後 Chromium 的對時測試在 CI 通過，但只驗證點擊前後 0.3 秒，不代表 0.4.0 的 A2、A3 已經人工確認排除。
  • 選單：錄製端「不顯示」叢集管理與管理後台只是選單，不是權限；直接輸入網址仍然打得開（使用者權限在 M8）。
  • 沒有人工驗收的新功能：macOS Worker（選單列、登入時自動啟動、Gatekeeper、本地網路權限）、Linux 分發包在公司主機（glibc 2.32、systemd、aarch64 實機）、新分頁、動態入參的實際採購場景、真的錄製端 App 上的選單。CI 通過不代替這些。
  • 下載需要權限：倉庫目前是私有的，Release 與 App 的「下載新版」（…/releases/latest）只有登入且有權限的 GitHub 帳號打得開；桌面端分發的設計文件還寫「倉庫是公開的，發布後任何人都下載得到」。main 的「一鍵安裝腳本」從零安裝（Rocky 8）在 clone 時要求帳號密碼而失敗，也是同一個原因。
  • 點擊會關掉分頁的按鈕：步驟點的按鈕本身會關掉分頁（例如 window.close()）時，Playwright 的 click 偶爾在分頁關掉後才回傳而拋出 Target page, context or browser has been closed，運行記成失敗。PR #75 的 CI 上 test_replay_switches_pages_and_returns_to_main 兩次撞到；修正建議（點擊後分頁已經關掉時當成成功）見 PR #75 的留言，還沒有修。
  • Windows 上的瀏覽器測試不穩定：CI 的「Worker 測試（Windows）」每次有不同的瀏覽器測試逾時或錄影讀不到（Firefox 的登入、iframe、腳本場景逾時；Chromium 取消後的錄影 unreadable、錄影對時取樣）；main 從 #68（e63559a）起的 CI 都是失敗或被取消。發布流程不跑這個工作，但 Windows Worker 執行 Firefox 與錄影的可靠度要人工確認。
  • 安裝與相容性：沒有程式碼簽章與 macOS 公證；錄製端與 macOS Worker 只支援 Apple 晶片，Windows Worker 只有 x64，Linux 分發包要 glibc 2.28 以上。伺服器、錄製端與 Worker 一起升級到 0.5.0。
