設計摘要

  • 現況：一次組合運行是 workflow_runs 一筆，每個節點是一筆 runs，各有執行目錄、report.html 與錄影。節點依 DAG 的拓撲順序一個一個執行，整次固定在同一台 worker，所以時間上是一條線。組合運行頁只列節點與三個連結，原因、步驟、斷言、錄影都要逐一打開。
  • 匯總報告（組合運行頁 /playground/runs/{id} 升級，網址不變）：結論（停在哪個節點的哪一步、錯誤、截圖，或全部通過）→ 數字列（節點、步驟、斷言的通過／總數，總耗時、實際執行時間）→ 摘要 → 流程與時間（依狀態上色的 DAG、甘特時間軸）→ 節點明細（入參的值與來源、出參的值與流向、階段、步驟、斷言、截圖、檔案；沒通過的預設展開）。「下載報告」是單一 HTML，可以離線打開。
  • 合併回看（/playground/runs/{id}/replay）：播放器把各節點影片依序接在同一條時間軸上播，不產生新檔案；節點之間的空檔（排隊、開瀏覽器、登入檢查、斷言，都沒有畫面）壓成 2 秒轉場卡，顯示上一個節點的出參與下一個節點的入參、實際間隔；沒有錄影或沒有執行的節點用卡片說明。時間軸多一條節點色帶，步驟清單依節點分組。
  • 入口：專案頁與試驗場的最近執行、運行報告頁的「組合運行」檢視、節點的運行詳情與單一回看頁、Agent API 的 reportPath／replayPath 與報告 JSON。
  • 只改伺服器：不加第三方套件、不需要資料庫遷移，發版時可以只發熱更新檔（ADR 0018）。
